# Bob's product rulings: reading documents and the file standard

**Status** · Bob's product rulings on reading documents and the file standard, by subject (Bob, K5323), read whole by the work that plans or changes how Civicsmith captures, reads or holds a document. Each line keeps its source ids; `build/rulings.md` is the full log. Moved from `rulings-active.md` when the process redesign was adopted; a ruling of Bob's on this subject is added here in the commit that records it.

- Reading is never silent or failing: a web capture is answered within 15 s up to about 8 MB, a larger one at once as fetched in the background (K4562). A document a member supplies or captures is read whole, any bound that must stay is stated to the member (Bob, K4571: "silent scanning is death!"). A file within the standard's per-kind bound is never refused for size; one above, refused with its size stated (K4630). Every document is held, read whole and searchable; structured data is interpreted selectively, what was interpreted stated on its page (K4632, K4636).
- The beta's file standard (Bob, K4628; tiers N1267; folded in the requirements): every type a public body publishes or a member likely holds, read whole, searchable, citable; each major data type gets a cause-family review, a generated corpus each round end, its subset live each redeploy (K4785, K4798).
- No reading cause is fixed piecemeal (Bob, K4812): changes follow only the architecture he confirmed (K4831; in the requirements and `build/plan/reading-for-bob.html`): Workflows carry every read, heavy kinds read by established tools in a container BOB caps; the alpha ships today's limits, each stated to the member.
- The beta's file types (Bob, K5435, on F1: "As recommended"): the ruled list (K4628, K4831) plus FILES' Tier 2 siblings (macro and template Office files with macros never run, .ics, .vcf, MBOX, MHTML, SVG, BMP, AVIF/HEIF, JPEG 2000, JSON Lines, GeoJSON, KML/KMZ, captions, text by content, other delimited data, single-file compression); the text bound is 100 MB (K5427).
- A file Civicsmith cannot yet read (Bob, K5436, on F2: "as recommened"): kept whole, its type named plainly, findable by name and details, read when a reader is added; RAR and programs, installers and disk images stay refused by name.
- Costly file types (Bob, K5437, on F3: "as recommened"): MBOX read in the beta; PST, Access and FILES' other Tier 3 types held and named until a real file shows they turn up, each then added by its own ruling.
- What is interpreted (Bob, K5445, on C1: "as recommended, with the understanding that C is the objective - even if we aren't able to support that until after the beta."): opened or cited parts, a member's deliberate marking, and Civicsmith's own proposals (the objective; accepted by a member before any interpretation); never everything up to a size.
- Limits shown first (Bob, K5446, on C3: "as recommended"): the add screen states each kind's limit before a file is added; over it, refused with size and limit, never half-read.
- Over the limit (Bob, K5447, on C4: "as recommended"): refused with the reason and a way in (a register by filter, N1259; else the part the member needs).
- Showing what was interpreted (Bob, K5495, on C2: "A, but perhaps also a visual indicator in the view of the document (a thin margin color, shading, or some other indicator) that shows what's been interpreted."): a plain line on the document's page and a search mark per investigation, and interpreted parts marked in the document view.
- Names found while reading (Bob, K5496, on C21: "as recommended"): finding names, organisations and dates for search is reading, not interpretation.
