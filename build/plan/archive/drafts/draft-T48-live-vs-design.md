# Draft T48: the live interface compared with its design (WALK-084 #2)

**Status** · Draft for BOB #171. Walked on 14 October 2026: live `biosmoke7` (release 0.84.0) against the design mock (`docs/development/ux-substrate/layouts.html`, built from `screens/mock-*.js` with the visual language), at 1280px and 390px. Read-only throughout: 2 sign-ins, no writes, signed out at the end (no session record left). Screenshots are in `build/plan/walk-084/`. Each `<screen>-<width>.png` there shows LIVE on the left and DESIGN on the right.

**Limits of this walk.**
- The supplied administrator credential (`sparky`) is a **member** on biosmoke7 (Members lists it as `member`, and `group.mjs:25` drew the read-only view, so the session did not administer). Acts only an administrator sees were therefore not drawn and are not judged here.
- The group has no projects or people, so subject screens (project, question, plan, case…) were opened bare.
- No response ≥ 400 and no console error appeared on any of the 60 screens walked.
- Direct access needed `undici` with the system CA. Global `fetch` went through the agent proxy, which replaces the token; that explains WALK-084 #1's sign-out.

## What fixes most of it

1. **C1, a requirement BOB owns:** move the mock's page CSS that real screens rely on into the shipped stylesheet, as a shell stylesheet beside `civicsmith.css`. Add a test that every class a screen module emits is defined in what is served. This one change addresses rows 3, 9, 10, 12 and 18, and most of the "jammed" look. The other route, asking the design stream to fold `mk-*` into `components.css`, is the UX stream's to do; BOB can only ask.
2. **C2:** build T48-69 (R53) and add the phone masthead and pinned tabs (rows 1–2: every screen).
3. **C3, C5, C6:** one compact wizard chip; DEC-219 folded into every screen module; keyed words for source notices.
4. **C7, C8:** the subject guard everywhere; never show a slug, tag, id or code.
