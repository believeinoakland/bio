## 0. Why 29 rows survived round 3, and the rules this round adds (BOB's addition)

Round 3's jobs reported "fixed, tests green" and the walk found the cause alive. Reading the code shows the three ways it happened, each present below:
1. **The fix was made in the wrong place or on one of two paths** (C9: the new `captureseenin` call sits in `doneAcquire`, but the screen's pre-flight `heldat` answers "held" and returns before any acquire, so the call never runs; C28: the stored `file_name`/`media_type` are right in `doorbell`, but the public screen that sends the knock, `screens-publish/doorbell.mjs`, never sends them; C81: `cs.row("", text, act)` squeezes the act at 390 px, round 3 fixed three screens and left `screens-publish` with the same helper call at `case-editor.mjs:176` and 10 other sites).
2. **A provider was tested against a scripted double** and the user against another, so the path between them was never run (acquisition's past-memory arm J6, "met against a scripted `putFromParts`"; C46, `findingWords` tested on hand-written front matter, not on a question concluded by `conclude`).
3. **A job stopped at "not met" or QUESTION** and the plan re-placed the same line (J6, J13, J18, J20; resolved in section 6, none re-placed unchanged).

**New rules for every START of this round (K4297 (3) stays):**
- **R-PROOF.** Each STILL row has a *proof case* (section 3): the walker's exact case (address, size, data, screen, width). The job writes it as a **failing test at its interface before it changes any code**, shows it failing in its record, and shows it passing after.
- **R-SEAM.** Where a cause spans modules, one job is the **seam owner**: the last-merged job on the path from the member's press to the stored result. Its proof test runs the **whole path with the real, merged providers**: no scripted double of a module merged earlier in the round, no hand-written answer shape (build the input by the member's own act through the real ops: `conclude`, `acquire`, `knock`). Providers test the same case at their own interface. A seam test that needs an unmerged provider is written first and stays red by name until the provider merges (BOB runs it at the merge).
- **R-NOTMET.** A job may not end with "not met", "deferred" or a QUESTION that holds a cause. It states the smallest thing it needs and BOB answers it in the plan (section 6) before the wave opens.
