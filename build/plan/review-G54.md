# Review of `draft-G54-plan.md` (independent; code opened at the cited lines, tranche/T51 at 887167c4c9)

## DEFECTS (11)

1. **A failure after the manifest is recorded is never owed, so it never heals.** `assembleCaseFile` records the manifest (`publication/worker.mjs:434-446`) and only then puts the manifest's own bytes (`:439-440`). The draft lists `manifest_put` as a step that records `failed`, but `caseFilesOwed` selects only `manifest_sha` null and `recordCaseManifest` (`publication/index.mjs:2229`) clears the four columns on success. After a `manifest_put` throw the row has `manifest_sha` set, so it is not owed, the page shows a download button, and `publishedbytes` for the manifest answers 404 for good. Fix: (a) `recordCaseManifest` does NOT clear the columns; a second step `recordcasefile state=built` is written only after the manifest bytes are put; (b) `caseFilesOwed` also returns editions with `manifest_sha` set and state not `built` (building over 2 minutes, or `failed`), and the sweep re-runs the idempotent put (the `head` guard at `:439`); (c) add a red test: `PUBLISHED.put` throws only for the manifest key.

2. **A missing bucket binding records a manifest over files that were never stored.** `assembleCaseFile` guards every put with `typeof env.PUBLISHED?.put === "function"` (`worker.mjs:424`, `:439`) and silently skips. With no bucket it still calls `recordcasemanifest` and answers built. Never silent means this is `failed` at step `bucket_put` (reason `NO_BUCKET`) and nothing is recorded. Add it to the step list, to the public-read change and to test (a).

3. **"Built" when a material is missing is undecided, and the repair of 4783 depends on it.** `buildCaseFile` names a missing material in `unheld` and still builds (`casefile.mjs:100-135`), and the manifest is write-once (`MANIFEST_EXISTS`, `index.mjs:2243`). So re-copying a `missing` material after the manifest exists changes nothing. Draft (b) says the sweep "re-copies" but does not say when. 4783's registered extracted text answers `OBJECT_MISSING`, so the first sweep tick would freeze a manifest with `unheld`. Fix the text: the sweep copies materials first (`heldMaterialsOf`, `publication/index.mjs:1363`, through `copyMaterials`), and builds only when none is missing; a material still missing after N attempts (state N, for example the third) builds with `unheld`, and the case file states it. Say what the P check expects for 4783 (the draft's "every listed file answers 200" is not reachable if the evidence store no longer holds the object). Name `heldMaterialsOf` as a read the sweep uses. Add a red test: complete edition, one material absent, sweep tick 1 copies and builds nothing, or builds with `unheld` after N.

4. **Public answer would carry internal error text.** (3)(a) stores `why = {reason, step, detail, error name and message}` and (c) puts `reason` into `publishedcase`, a public op for a caller with no credential (`publication/worker.mjs:458`). The error message of a bucket or stub failure is not for a reader. Fix: the public `case_file` carries `state`, `attempted_at`, `attempts` and a reason CODE from a closed set only; `step`, `error` and `detail` stay in the row and the log. Test: `publishedcase` after a thrown error whose message contains a marker string never contains it.

5. **The reader's sentence is written twice and its `{why}` is a code.** (c) gives public-read `localize` stand-ins ("The case file for this edition is being prepared...") and also has screens-publish add keys with stand-in rows and "the page never writes a sentence". The two modules would each hold the sentence. `{why}` filled with `STORE_SILENT` or a step name is not plain (K4571 "stated"). Fix: public-read answers state + code only (no sentence); screens-publish owns one `screen.published.casefile.<state>` key per state and one per reason code, each a `localize`/word row, rows named in its COMPLETE for UX-DESIGN; the "being prepared" sentence also covers `building` older than 2 minutes (state it in the state table). Remove the sentences from public-read's START.

6. **Seam between ratification and public-read is unspecified; two failure points have no recorder.** Ratification wants to record `copyMaterials`' `missing` and a throw in `copyMaterials`/`copyFinding` "in the same attempt" (`ratification/ops.mjs:240-246`, `:410`; `index.mjs:1000-1015`), but `assembleCaseContainer`'s signature (`worker.mjs:161`) has no field for them, and a throw before it is reached is never recorded by the function the draft calls "the one writer". public-read merges first (112 < 116), so its START must carry the contract: a parameter `prior: {materials_missing, copy_error}` and a callable `recordCaseFileFailure({step:"copy", ...})` ratification can call from a `catch`. Add step `copy` to the step list. Add the signature to both STARTs.

7. **The owed read and the wake are under-specified.** `caseFilesOwed({now, limit, backoffMs})` takes one scalar, while (b) wants a per-edition backoff doubling 15 s to 1 h by `casefile_attempts`; and `caseFileWake` needs "the earliest backoff", which no publication read gives. State: publication computes `next_at = attempted_at + min(15 s * 2^(attempts-1), 1 h)` itself (one place), `caseFilesOwed({now, limit})` filters on it, and a second read `caseFileNextAt()` returns the earliest. Without it the R27 hold can strand the sweep or spin it. Also: a never-attempted edition is owed at once, so the sweep can race the very request that is still in `copyMaterials` (not yet `building`). Add a grace (`ratified_at` older than 2 minutes) or accept the race and say it is idempotent (tests: two concurrent assemblies of one edition record one manifest).

8. **No platform ceiling for the sweep is addressed.** The diagnosis proves CPU, subrequests and values are not the cause of the two failures, but the fix puts a build of up to two editions into the object's alarm, where the object was killed for memory five minutes before 4783 (`diagnosis-R6-g54-cause.md` section 3) and G26 measured memory kills. `assembleCaseFile` holds every file in memory (`worker.mjs:417-425`, bound `CONTAINER_MAX_BYTES`, `casefile.mjs:26`) and costs 2 R2 subrequests per file (a 1,002-file edition is 2,004+; limit 10,000). Add to (4): the sweep builds ONE edition per tick when the previous one's bytes passed a stated bound, a `building` left by a memory kill counts as an attempt and backs off (so a kill loop cannot recur every 15 s), and an L check with an edition of about 500 files and about 40 MB of material at the real limits (R-CLOCK: assert bytes pulled and subrequests counted, not time). The `casefile_why` value is small; say so against the 2,098,176 B bound in one line.

9. **The bundler change is not derived from the config as every other metadata field is.** `wrangler.jsonc:140` says `"observability": { "enabled": true }`; the draft hard-codes `{enabled: true, head_sampling_rate: 1}` in `deploy.mjs` (the `meta` object, `:237-250`), adding a rate the config does not state. Everything else in `meta` derives from `wranglerCfg` (bindings, `deriveLimits`, `deriveCrons`) and refuses a config that lacks it. Fix: `deriveObservability(wranglerCfg)` beside `deriveLimits` (in `derive-bindings.mjs`, the bundler's), refused when the config lacks `enabled: true`; the read-back (G1's `settingsNow`-style, `deploy.mjs:263`) compares against what was sent; `--dry-run` prints it. Also `newgroup/src/steps/uploads.mjs` contains no `observability` (grep, 2026-10-23): state that as a fact and bring it to BOB as a named CHANGE to INSTALLER now, not "if it finds".

10. **The P check uses "the job's test hook", which contradicts "never a production path".** (4) P: "one forced failure ... by the job's test hook". A hook in shipped code is a way to fail a real publish. Remove it: the forced failure is made on the test copy by an ordinary act (a case whose member bytes the evidence store lacks), or is left to L only. If neither is possible, say P covers the two repairs and a new case only.

11. **R-OLD is stated for the editions but not for the new columns' neighbours.** `scheduled_editions.case_file` is "additive" but old settled rows (every row settled before this) are null; the draft says null-and-silent is exactly what is wrong. Fix: (a) a null `case_file` on a settled row reads as `not_recorded` in the row's answer (new data only; no back-fill); (b) say the row records the state at settle, not the current state: after the sweep heals, the row still reads `failed` unless the answer also reads publication's current state (choose one and test it); (c) the same for `casefile_*` on `published_cases` rows of the 3 healthy editions (stay null, `built` derives from `manifest_sha`).
