## DEFECT (must change before START)

**D1 · The census is 18 sites, not 25.** `grep -rn "STORE.get(" bio-plane/src` gives 18; the plan's own list sums to 18 (watchdog 1, door 1, ask 2, control-plane 5, admission 1, setup 6, livefire 1, ai-runs 1). T1 ("red now: 25 sites") would be wrong on its first run. Also: T1's pattern `STORE.get(` misses an aliased namespace (`const ns = env.STORE; ns.get(ns.idFromName(..))`); use `idFromName(` and allow-list the two compare-only sites (`plane/store.mjs:766`, `ai-runs/index.mjs:2106`). `stewards/src/index.mjs:28` (`STORE`, name `"stewards"`) is another Worker's object; say so in the plan. I found no other creating site (`getByName`, `newUniqueId`, `idFromString`: none).

**D2 · `installer-steps` R35 forbids the import the plan adds.** R35 (`installer-steps.md:119`): "imports no module later than `signatures` and `instance-setup`... the module's files import nothing outside it but the two modules" (and a test says so). `locationHintFor`/`storeLocationBinding` in `installer-steps` need the allow-list from `runtime-limits`. The plan says only "gains the `uses` edge". Order is legal (runtime-limits is position 7, installer-steps 171; `modules.json` `uses` for runtime-limits is `['setup-words']`, so no cycle, and ai-runs, admission, control-plane, instance-setup already use it), but R35 and its import test must be amended by BOB, or the allow-list kept in `installer-steps` and duplicated with a parity test. Decide and state. `plane` also lacks the edge (its `uses` has no `runtime-limits`).

**D3 · The re-creation guard is not a guard (`--recreate-store`, route 2).** `deploy.yml`'s marker is circular: `.github/workflows/deploy-test.yml` sets `CIVICSMITH_TEST_INSTANCE=$copy` from the dispatch input (or from the pushed branch name `deploy-test/<copy>/deploy`), and the environment "has no reviewer" (file header). So `[NOT_A_TEST_INSTANCE]` (`deploy.mjs:61-66`) passes for any slug typed into that account, and a push of a branch would run a class deletion ("permanently, all stored data") with no human step. Required before START: the destructive flag must be a separate, explicit confirmation naming the slug and the object's counts, read from the live script (`INSTANCE_NAME` equals the slug), never reachable from the push trigger, and `--dry-run` must print what would be deleted. It also has no rollback, whereas R40's steps log a `rollback :` line. Also not planned: migration tags (`deploy.mjs:224-232` sends none; delete and create each need `old_tag`/`new_tag`; biosmoke8's current tag is not read). Also: the plan's "one redeploy" (K4428) is at least two uploads, and the plan's scratch-slug dry run needs a copy name nobody has marked, so it needs the same dispatch with a new name, which is Bob's/Actions act (P17: name the one act). Cheaper and non-destructive alternative to put to BOB: a second copy (biosmoke9) installed with the hint, leaving biosmoke8 as the rollback and the old/new comparison (R-OLD stays meaningful). HANDOFF P22 says "re-created there (a reinstall)", so both fit Bob's "B".

**D4 · Item 3 (data as upload parts) leaves the plane's parts unsigned and touches the installer's own build.** (a) The plane is signed on its own: `release-assemble.mjs:715-725` signs `planeSig` "over THIS asset"; `fleetSig`/`fleetStatement` cover members. The plan puts the plane's parts "inside `fleetStatement`"; they must be inside the plane's signed statement, else `case-checker`'s program and the word table (data the plane acts on) travel unsigned. (b) Sequence: a new release with parts installed by an old installer uploads one module and the plane fails to import. The plan's control covers old release/new installer only; require "installer with parts support deployed and verified before the first release that carries parts". (c) `newgroup/src/index.mjs:30,44` and `steps/*.mjs` import `setup-words` and `interface-assets`: turning `rows.mjs` or `interface-assets` into external Text parts changes the installer Worker's own bundle (and every fleet member bundle, `bundler` R38) too. The job table names none of that. (d) `deploy-test.yml:94` deploys only `dist/bio-plane.bundled.mjs`; the workflow, the committed `dist/` and `provenance.mjs` also change. Placement after (a) and items 1-2 is right; keep it a next-round entry unless the measured margin is thin.

**D5 · G84's run-share cause is "unknown" without the diagnosis K4426 requires, and plane R43/R54 are not cited.** R-FOUR allows unknown only with a diagnosis file of a reproduction at the platform's shape. The only figure is Node (P16); (a) and (a2) are cheap, local and read-only, so run them now and file the result as `diagnosis-R7-startup.md` before START. `plane.md` R43 and R54 (lines 158, 176) already state this requirement (500 ms budget, "it never raises the budget", 509 ms at T47's close, now ~1,100 ms in Node: a 2x regression since T48, itself worth saying) and are marked not met; the plan's requirement list (bundler R31, file-safety, setup-words) omits them, and an 800 ms hard stop must be reconciled with R43's "500".

- **G3 · "No place is named" rules.** `plane` R9, `runtime-limits` R25, `admission` R15, `control-plane` R33, `ai-runs` R39, `instance-setup` R31 and `installer` R31 all say it; the plan notices only installer R31. G84 item 3 omits `setup-words` (rows.mjs) from the owner table and the installer/signatures rows are "later" without positions.

Any R2 cleanup is a separate, explicit act on named buckets of account `20b5...` only.
- **G8 · Platform steps via the deploy token.** G84 (P) and G83's dry run say "BOB runs with the token the deploy workflow holds".
