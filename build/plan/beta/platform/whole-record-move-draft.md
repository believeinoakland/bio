# Moving a team's whole record: export and import (draft)

**Status** · **READY** for PLANNING (K5569, 2026-10-27: as it stands; no move down) (K5441, K5443 (4)). PLATFORM #1, 2026-10-27. Region is fixed at Level 1; a move is an export and an import into a new copy, said before the region is chosen (K5441). Inputs: `corpus-export` R1-R15 (today's export is of "the working corpus", verified, paged, logged), `installer`, `record-placement-draft.md` PL30-PL34.

## 1. What today's export is, and what a move needs beyond it

Today `corpus-export` exports every table `record-core.declaredTables()` answers by class (R7), in pages with digests (R8), bundles with file digests and inline or blob content (R1), and records each export in an append-only log (R1, R2). A move needs three things it does not state: the stored files themselves (the 8,000-12,000 documents, up to about 50 GB at Level 1, P17), a way to carry that much without one call or one machine's memory, and an importing side that builds a new copy from it.

**What a move cannot carry, by earlier rulings (a consequence to say before the move, not a new rule).** R7: tables declared `never` (member ties and the source-person link, K1489, K1490) travel with no row; a table declared derived is rebuilt, not carried; removed rows stay removed (R9). So after a move members' sessions and keys are the new copy's, not the old's. *Whether a move should carry members' sign-in material is Bob's (privacy doctrine); I assume not (K1489-K1490 stand) and say so in the words.*

## 2. Lines for `corpus-export` (layer 8)

- **PL50** `exportWhole({note})` (`op=exportwhole`, administrator only, as `export`) answers a **whole-record manifest**: R1's content, plus every stored file as an entry (path, SHA-256, bytes, kind) whether held inline or in R2, plus the copy's region, jurisdiction and generation as `placement`, plus the counts; in the same act it appends one `export_log` row with scope `whole-record`. Test: a seeded copy's manifest lists every held file; the log row's scope is `whole-record`; a member refused.
- **PL51** A whole-record export is read by parts and is resumable: the files travel as a list of parts of at most a stated size (not above the plane's per-call memory, `PLATFORM_FIGURES`), each with index, byte count and SHA-256 in the manifest, fetchable and checkable alone, so an interrupted move continues from the last verified part and never restarts; no call holds more than one part. Test: an export of a record larger than the part bound lists more than one part; a part fetched alone verifies; a lost part is refetched, the others untouched; memory held by the export is at most one part (byte-ledger).
- **PL52** The export names what it does not carry: each table class R7 withholds, listed in the manifest as `not_carried` with its owner and the reason (never, derived, expunged), and says in plain words that members' sign-in material is not carried. Test: the manifest of a copy with member ties names them `not_carried`.
- **PL53** The export is a **read**: it changes no record and holds no lock beyond a part; the copy keeps working while it runs, and the manifest states the instant it was taken so a later import can say what changed after it. Test: a write during the export does not change the manifest's counts; the instant is stated.

## 3. Lines for the installer (layer 11, `installer`, `installer-steps`)

- **PL54** The install can create the new copy **from a whole-record export**: it takes the export's manifest and parts (from where the administrator names, by a link or a file; the parts check themselves), and the region or jurisdiction the founder chooses for the *new* copy (PL32); it creates the room (PL30, PL31) and, with a jurisdiction, the R2 bucket in it (PL34) first, and then imports. Test: an import into a fresh install with `eu` creates the bucket with `eu`; a missing part leaves the install paused and resumable, not partly done and live.
- **PL55** The import trusts nothing the export asserts (`corpus-export`'s Purpose): every part is checked against its digest and every file against its own, the counts against the manifest's, and an import that finds a mismatch stops before the new copy is opened to members, naming the part. Test: one corrupted part stops the import naming it; every part intact, the counts equal, the copy opens.
- **PL56** The new copy states what it received and what it did not (PL52's list), the export's instant, and the old copy's placement; the old copy is untouched and stays the rollback until its administrator ends it (never deleted by the import). Test: the new copy's first screen reads PL52's list; the old copy's record is equal before and after.
- **PL57** Importing into a copy in a *different* region or jurisdiction than the export's is allowed and is the point; the new copy's placement is the founder's choice (K5441: fixed at install, no later change), and the install says this before asking for it. Test: an export from a hinted copy imported into a jurisdiction copy keeps the new placement.

*Screen needs (to UX-DESIGN through BOB):* the "move my copy" path at install (choose an export; progress by part; resume; "what was not carried"), the old copy's "ended by the administrator" act, and the sentence before choosing a region ("this cannot be changed; moving is an export and an import").

## 4. What must be measured, and on what copy

Export and import at the Level 1 record sizes of `load-test-draft.md` §3 (1, 5, 25 GB), on scratch copies: time per part, total, memory held, whether the 2 s act bar holds for other members while a move runs (the export is a read in the room's one thread; P24), and the cost in rows read and R2 operations. A whole-record export running in the room is a load item in the profile, not an exception to it.
