# N1257 and N1256: requirement lines for `jurisdictions` (draft)

**Status** · DRAFT, not READY; written by a worker for CAPABILITIES #1.
Companion of `N1257-places-in-layers.md` (analysis, points, needs); this file holds the `jurisdictions` lines of its section B. Draft ids follow the highest `**Rn**` in `build/requirements/jurisdictions.md` (R98); PLANNING renumbers. Lines marked *(per C1)* or *(per C2)* hold under the recommended answer of that point in the main file and change with BOB's choice.

Terms. A **layer** is a profile (`jurisdictions` R1) that states one level of a place. Its **origin** is `civicsmith` (shipped in the release, read-only) or `team` (written by a team, held in that team's record). A **chain** is the layers active together, one per level, each sitting in the one above.

**The layer** (DEC-404)
- **R99** (T53; N1257; DEC-404; amends R1, R10, R11) *(not yet met: T53)* **A profile may be a layer.** A profile may carry `layer: {level, place, within?, origin}`: `level` one of `LAW_LEVELS` (R31), `place` the place's name (1 to 200 characters, one line), `within` the `id` of the layer it sits in (absent on a federal layer), `origin` `civicsmith` or `team`. A profile with no `layer` is valid and read as today (the test profile, a whole-place profile). A malformed `layer` is `LAYER_INVALID`, naming the field. Test: a layer of each level validates; a level outside `LAW_LEVELS`, an empty `place`, an `origin` outside the two, and a federal layer with `within` are each `LAYER_INVALID`. Control: a profile with no `layer` validates exactly as before.
- **R100** (T53; N1257; DEC-404; amends R31, R88, R11) *(not yet met: T53)* **A layer holds only its own level.** In a layer of level L, every `records_laws` and `standard_sources` entry that carries a level (R31) carries L, and every counterparty's `level` (R24, R88) is L, or `district` in a city or county layer. Otherwise `LAYER_LEVEL_MISMATCH`, naming the entry. A fact that carries no level of its own (a deadline, a holiday year, a pointer) is placed by its citation and is judged by R113's test, not by `validate`. Test: a state law inside a city layer is `LAYER_LEVEL_MISMATCH`. Control: the same law in a state layer validates.
- **R101** (T53; N1257; DEC-404; amends R12) *(not yet met: T53; per C1)* **A chain is checked by `combine`.** When any profile combined carries a `layer`, `combine` also checks the chain: at most one layer of each level (`LAYER_LEVEL_TWICE`, naming both); each layer's `within`, when it has one, names a layer in the list (`LAYER_PARENT_MISSING`); a federal layer is present (`LAYER_NO_FEDERAL`, a refusal only when a state, county or city layer is present). Team-origin layers are checked the same way. `view.layers` lists `{id, level, place, origin}` in level order. Layers combine side by side; none overrides another. Test: federal, California and Oakland (county skipped) with Oakland `within` the county is `LAYER_PARENT_MISSING`; two city layers are `LAYER_LEVEL_TWICE`. Control: the four shipped layers in any list order give one view with `layers` in level order.
- **R102** (T53; N1257; DEC-404; amends R15, R29, R55) *(not yet met: T53; per C2)* **One key, two layers, two answers.** Where two layers give different values for one key (R15), the fact stays withheld and reported in `conflicts`, each conflict now carrying each giver's `layer` level and `origin`, so a screen can say which layers disagree. `combine` chooses nothing. Test: two layers giving different `locale` values give one conflict naming both levels. Control: two layers giving the same value give none.
- **R103** (T53; N1257; DEC-404; amends R46, R55) *(not yet met: T53)* **Two layers may state the same weekend.** The weekend compares equal when its `days` are equal; the citations are then joined, as `time_zone` and `locale` already agree on a value whatever the basis (measured 2026-10-27). Today `weekend` is compared whole, its `citation` included (`index.mjs:2158-2165`), so a federal layer citing 5 U.S.C. § 552(a)(6)(A)(i) and a California layer citing CCP § 12a for the same Saturday and Sunday would withhold the weekend and make every business-day count undetermined. Test: two layers with equal `days` and different citations give one `weekend` carrying both citations and no conflict. Control: different `days` still give a conflict. The same check is made for every other one-value fact (R55) before the layers are cut (F).
- **R104** (T53; N1257; DEC-404; amends R26, R47; `civil-time`) *(not yet met: T53; per C1)* **A rule may count on a closure list a layer above it holds.** A deadline's `closures` and `observed.closures` name a list held by its own layer or by a layer in its `within` chain, resolved in the combined view. `validate` of a layer alone accepts a name it does not hold only when the layer has a `within` (today `CLOSURES_UNKNOWN`, `index.mjs:1049`, 1076: "no holidays entry of this profile"); `combine` refuses a name no layer of the chain holds, `CLOSURES_UNKNOWN`. List names are unique across the chain (a second layer giving a list of the same name for the same year and offices is R102's conflict). Test: a California-layer deadline counting on a list the federal layer holds validates alone only with `within`, and combines; with the federal layer absent, `CLOSURES_UNKNOWN`. Control: a layer's rule naming its own list validates alone.
- **R105** (T53; N1257; DEC-404; amends R93, R55) *(not yet met: T53)* **Records-request help is one block per law, and each layer adds its own fields.** `records_help` becomes a list of blocks keyed by `law` (the law's name in `records_laws`); a block carries the fields R93 lists, and a block for the same `law` in two layers is merged field by field: the layer that holds the law gives `days`, `extra_days`, `extension_reasons` and `citations`; a city layer may add `portal` and `faster`. Two layers giving different values of one field are R102's conflict. Today the single block conflicts when two profiles give different blocks (`index.mjs:1883-1886`). Test: a California layer's CPRA block and an Oakland layer's block holding only `portal` and `faster` combine to the block the unsplit profile gives today, field for field; a federal block for FOIA appears beside it. Control: two layers giving different `days` for one law conflict.
- **R106** (T53; N1257; DEC-404; amends R7, R76, R96) *(not yet met: T53)* **A records law says whose records it governs.** A `records_laws` entry carries `governs`: a non-empty list of levels of office (`federal`, `state`, `county`, `city`, `district`), each from the statute's own definition of the bodies it binds (`citation` shows it). FOIA governs `federal`; the Public Records Act governs `state`, `county`, `city`, `district`; the Sunshine Ordinance governs `city`. A screen offering the laws a request may go under reads the office's level and this field, and offers no law that does not govern it. Missing `governs` reads undetermined (R27), and every law of the layer is then offered, labelled so. Test: a city office is offered the Public Records Act and the Sunshine Ordinance and not FOIA; a federal office is offered FOIA alone. Control: a law with no `governs` is offered with the label.
- **R107** (T53; N1256; DEC-401; DEC-404; amends R24, R88) *(not yet met: T53)* **An office may be federal.** `COUNTERPARTY_LEVELS` gains `federal`, first: `federal`, `state`, `county`, `city`, `district` (frozen, in that order). DEC-404 says offices carry a level (R88), but R88's list today has no federal level (`state`, `county`, `city`, `district`), so a federal office cannot be stated. `LEVEL_UNKNOWN` still refuses any other. Test: a counterparty at `federal` validates. Control: `national` is `LEVEL_UNKNOWN`.
- **R108** (T53; N1257; DEC-404; amends R44) *(not yet met: T53)* **A layer says how far its facts reach.** A layer carries `coverage: {as_of, holidays_through?}`: `as_of` the date its facts were last researched (`YYYY-MM-DD`), `holidays_through` the last calendar year every closure list it holds has a year for. `view.layers` gives both. A count reaching past a list's last year is undetermined (R33) and names the layer whose list ends. Test: a federal layer holding 2026 and 2027 gives `holidays_through: 2027`; a count into 2028 is undetermined and names it. Control: a layer with no holiday list gives no `holidays_through`.

**The shipped layers** (DEC-404; each fact keeps its basis, R2, R44; sources are listed in the main file's section A and are re-read at measurement, F)
- **R109** (T53; N1257; DEC-404; amends R21, R95, R96, R97) *(not yet met: T53)* **The federal layer.** Civicsmith ships a read-only layer `level: federal`, place the United States, holding: the Freedom of Information Act (`records_laws` with `stages`, `requesters`, `response: foia_response`, `governs: [federal]`); the deadlines `foia_response` and `foia_appeal_response` with their labels, extensions, tolling and consequences; the closure list `federal` (5 U.S.C. § 6103) for each year it holds; the weekend; the `records_request` kind with the laws `[FOIA]` and no venue; the federal `records_help` block. It holds no `time_zone`, no `locale`, no venue of any one office. Test: `combine` of this layer alone computes a `foia_response` due date from a received day, over the `federal` list, with the weekend; the due date for a fixed received day equals the one the unsplit profile gives today. Control: a request with no law named gets no federal due date.
- **R110** (T53; N1257; DEC-404; amends R21, R30, R56, R85) *(not yet met: T53)* **The California layer.** A read-only layer `level: state`, place California, `within` the federal layer, holding what the unsplit profile states at the state level: the Public Records Act (`records_laws`, `response: records_response`), the state's deadlines (`records_response`, the agenda and special-meeting notices, the claims periods, the Brown Act demand and cure, the grand jury comment periods, the anti-SLAPP period, as listed in R56, R85), `computation` `ccp_12`, the weekend, the closure list `judicial` (CCP § 135), the state offices' holiday years and the State Controller (`counterparties`), `legal_facts` of state law, `lawful_demands`, `standard_sources` of state law, `law_ranks` and codes it cites, `response_statuses` for the grand jury, the state's `time_zone` (`America/Los_Angeles`, all of the state) and the Public Records Act block of `records_help`. It holds the "state holidays" the decision names as the state's own list (Gov. Code § 6700) beside the court holidays; which of the two lists a deadline counts on stays the rule's `closures` (R26) and is not changed. Test: the layer with the federal layer computes the Public Records Act response for a fixed received day equal to the unsplit profile's, on the `judicial` list. Control: a team with this chain and no city layer has no `immediate_disclosure` rule.
- **R111** (T53; N1257; DEC-404) *(not yet met: T53)* **The Alameda County layer.** A read-only layer `level: county`, place Alameda County, `within` the California layer, holding the county facts the unsplit profile already holds (the Civil Grand Jury as a counterparty with its fiscal year; the Superior Court's forum, hours and venue; the county assessor's systems and parcel space; the county's pointers) and whatever county records or open-meeting law, deadline, holiday list, office and publication place research finds, each with its source; it holds a county fact only where a source supports it (R44). The unsplit profile has no county records law, no county deadline and no county holiday list, so this layer's new content is research to be named in the plan (F). Test: the layer validates and combines with the two above with no conflict. Control: no entry is placed in the layer for want of anywhere else.
- **R112** (T53; N1257; DEC-404) *(not yet met: T53)* **The City of Oakland layer.** A read-only layer `level: city`, place Oakland, `within` the Alameda County layer, holding every remaining fact of the unsplit profile: the Sunshine Ordinance and `immediate_disclosure`, the Municipal Code deadlines, the City's holiday list and offices (Controller, City Council, City Auditor) with hours, the portal venue and its receipt rule, `observed` practice, the `records_help` fields `portal` and `faster`, the vocabulary, spaces, systems, Legistar schemes, policy series, classification schemes, local names, pointers of the city, the Public Ethics Commission forum, the lobbyist `legal_fact`, `minutes_due_days`, `legal_organisations`. Test: R114's equality. Control: R113's.
- **R113** (T53; N1257; DEC-404; `build/layers.md`, rule 3) *(not yet met: T53)* **The shipped layers are checked as chains.** A build check combines every chain the release ships (federal alone; federal and California; those with Alameda County; those with Oakland) and fails on any `conflicts`, any `LAYER_*` or `CLOSURES_UNKNOWN`, and any fact a layer holds whose citation names another level's law (by the citation's body: 5 U.S.C. for federal, a state code for state, a municipal code for city; the list of citation prefixes per level is test data, not product code). Test: moving the Sunshine Ordinance into the California layer fails the check. Control: the shipped set passes.
- **R114** (T53; N1257; DEC-404; amends R21) *(not yet met: T53)* **The split changes no answer.** `oakland-alameda` remains a held id as a **package**: a profile of one field, `package: [federal, California, Alameda County, Oakland layer ids]`, which `get`, `list` and `combine` resolve to the four layers in that order, so every existing caller, setting and test that names `oakland-alameda` is unchanged. The tag `profile` on a fact then names the layer that holds it. Test, by fixture: the view of `combine(["oakland-alameda"])` taken at the commit before the split, saved whole as `oakland-alameda-presplit.view.json` with every `id`, `name`, `profile`, `profiles`, `bases` and `layers` field removed, equals the same view taken after, by deep equality, section by section (the list orders R14 keeps are kept); every test file that loads `oakland-alameda` (the T33 to T51 files and `budget-doctypes`'s helper) passes without a line changed; a recorded request, clock entry and filing in the test copies reads identically. Control: removing one fact from a layer fails the equality naming the section.

**A team's own layer** (DEC-404; DEC-151 (2) as amended)
- **R115** (T53; N1257; DEC-404; DEC-151 (2); amends R2, R44) *(not yet met: T53)* **A team layer is a layer of `origin: team`.** It has the shape of a profile with `layer.origin: "team"` and `level` `county` or `city` (a team's own state layer is not ruled, DEC-404 B), `within` the state layer or a county layer held. It is held in the team's record (`instance-setup`), never in the release. Every entry carries `basis` of the form `team:<capture sha>` (the held capture it was read from) and `status: researched`; an entry without a source is not written (R44). The module marks every fact it gives from such a layer `origin: team` in the view. Test: a city layer of `origin: team` validates and combines under a California layer; an entry with no source is `BASIS_MISSING`. Control: `origin: team` with `level: state` is `LAYER_INVALID`.
- **R116** (T53; N1257; DEC-404; DEC-151 (2); amends R83) *(not yet met: T53)* **What a team may write.** `TEAM_LAYER_SECTIONS` is exported, frozen: `records_laws` (with `stages`, `requesters`, `response`, `governs`), `deadlines`, `holidays` (with closure lists), `counterparties` (with `hours`), `action_kinds` (with `venue`: where requests go), `systems` (where records are published), `time_zone`, `weekend`. These are the matters DEC-151 (2) lists (records and open-meeting laws and their deadlines, holidays, office hours and time zone, offices, where records are published). Any other section in a team layer is `TEAM_SECTION_REFUSED`. A new section is a requirement change. Test: a team layer carrying `vocabulary` is refused. Control: each listed section validates.
- **R117** (T53; N1257; DEC-404; amends R12, R15) *(not yet met: T53; per C2)* **A team entry never replaces a shipped one.** `combine` keeps a team layer's value for a key a Civicsmith layer also gives only when they are equal; otherwise it is R102's conflict (withheld). The team is told at entry (`local-facts` R23), so the conflict arises only after an update brings a value for a key the team had written. Test: a team deadline `immediate_disclosure` with 5 days beside a shipped layer giving 3 is a conflict naming `origin`. Control: a team key no shipped layer gives is kept.

**Test layers** (`build/layers.md`, rule 3)
- **R118** (T53; N1257; DEC-404; amends R22, R36, R57) *(not yet met: T53)* **The test profile is also a chain.** The test fixtures supply a four-layer test chain (federal-like, state-like, county-like, city-like, all `test: true`, every basis `TEST`, values unlike the shipped ones, hosts under `.example`) and a team-origin layer, with one law and one deadline at each level, a closure list a lower layer counts on, one equal-value pair and one conflicting pair. Every module that takes the view is tested against the test chain as well as the test profile. Test: the chain combines; the conflicting pair is reported. Control: a module's test that passes only on the shipped layers fails the review of its job.

**Federal offices** (N1256; DEC-401 option B)
- **R119** (T53; N1256; DEC-401; amends R24, R25, R88) *(not yet met: T53)* **The federal layer holds the federal records offices of the government's own list.** The layer holds one `counterparties` entry per FOIA office the government's own list names (the FOIA.gov agency component list is the list to measure, F): `role` the component's name, `body` its parent agency, `level: federal`, `contacts` (the means it publishes for sending a request: its web form or portal address, e-mail, mail address), `source` (the list's address) and `basis` the dated read. Each office is under FOIA: its `law` is FOIA and its deadlines are the layer's. An office whose publication states a field not in this list adds it only through a requirement change. The offices are not seeded as entities at install (`instance-setup` R107). Test: the layer holds each office of a fixed copy of the list (a saved response, 3 offices including one with no e-mail) with its contacts, and each reads FOIA as its law. Control: an office the list does not name is not in the layer; a member names it as DEC-401 A does.
- **R120** (T53; N1256; DEC-401; amends R44, R108) *(not yet met: T53)* **The list is kept current by release, with its date.** The federal offices are a dated snapshot of the government's list, rebuilt by a script run by Civicsmith's makers before a release with the key the government's service requires, held as a makers' secret (never in a team's copy, never printed, never in the repository); the script writes the layer's data file and a diff against the previous snapshot (offices added, removed, renamed, contacts changed), which a person reads before it ships. `coverage.as_of` is that read's date. A team's copy never fetches the list. Test: the script run on two saved responses writes the diff naming an added, a removed and a changed office; the layer validates; with the key absent the script stops and names the missing key and prints no value. Control: a release is blocked by `proc` when the snapshot's `as_of` is older than a stated bound (the bound is measured, F).
