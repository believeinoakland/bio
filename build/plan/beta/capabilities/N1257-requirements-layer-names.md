## The rule these lines apply

Terms. A **stored name** is a name a record keeps so that it can later be read again: a law (by level and citation), a deadline's `rule`, a closure list's `list`, an office's `role` and `body`, a rule a team drafted. Its **layer** is the `id` of the layer that gave it (`jurisdictions` R99), never a package id (R114 there). An **unlayered** record is one written before this change: it carries no `layer`, and no row of it is ever rewritten (a column added empty, or a key absent, is not a rewrite; `local_fact_acts`, `local_rule_acts`, `settings` and every other append-only table is not touched). Four rules hold in every module below:

1. **New records store `layer` with the name**, the layer the name resolved to when the member acted (never the bare name alone, never a guess).
2. **Unlayered records resolve exactly as before**: against the layers that were active on the record's own date (R121), so a layer added later cannot change what a recorded request, clock entry or filing means.
3. **Display shows the layer** wherever two active layers give the same name, and in the answer's data always.
4. **`NAME_AMBIGUOUS` is surfaced, never guessed**: the act is refused, nothing is written, and the answer names each layer that gives the name (`layers: [{layer, level, place}]`) so the member picks one. Code that takes "the first one found" for a name (found: `entities` office match) is the defect these lines remove.
