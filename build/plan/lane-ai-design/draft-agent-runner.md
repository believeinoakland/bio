## Public

### Purpose

The container in which a team's test of an AI runs under Civicsmith's control: a digest-pinned image holding the Gate 1 suite's run entry, the harness and the adapters, with no shell and no Claude Code, that takes the provider host, key, model and plan declaration of one run, fetches a challenge from Civicsmith's issuer, runs the suite through `agent-model` against a stub plane, records the raw exchange, and emits only a plaintext manifest and a bundle sealed to Civicsmith's key. It reaches only the issuer and the one provider host under test; the key lives in memory for one run; nothing survives the run.

### Provides

Terms. The **caller** is `ai-gate`'s test flow (or Civicsmith's own canary and run service in `civicsmith` mode), through the Container Durable Object. A **run** is one execution for one declared plan; **the run's instance** is the one `AgentRunner` instance named by the run id. The **issuer** is `ai-issuer`'s Worker on Civicsmith's account. A **declared plan** is `ai-gate` R20's shape. The **run key** is an ephemeral key pair generated inside the container. The **manifest** and **sealed bundle** are `ai-gate` R54–R56's. A **deployment** is `team`, `civicsmith` or `machine` (R57).

**The run** (new)
- **R43** *(NEW)* The run's surface, all JSON, all refusals `{ok: false, code, trace, detail}` with `detail` read by key (R41):
  - `POST /run` takes `{declared, key, tiers, parts, ceiling, estimate}` (R44, R47, R51) and answers 202 `{ok: true, run, state: "running"}` once the challenge is fetched (R49) and the run has started; `run` is a UUID.
  - `GET /run/status` answers `{ok: true, state, tier, items_done, items_total, incomplete_reason?}`, a closed list of non-secret fields; `state` is `running`, `done`, `incomplete`, `approved`, `discarded` or `expired`.
  - `GET /run/manifest` answers the plaintext manifest once `state` is `done` or `incomplete`; `NO_MANIFEST_YET` before.
  - `POST /run/approve` records that the manifest was shown and approved (R54).
  - `GET /run/bundle` answers the sealed bundle bytes only after approval (R54).
  - `POST /run/discard` wipes the run (R55) and answers `{ok: true, state: "discarded"}`.
  A second `POST /run` on an instance answers 409 `RUN_IN_PROGRESS` (R55); any route on an instance with no run answers 409 `NO_RUN`. Test: each route against a stub issuer and stub provider answers the shape above; every refusal carries `trace` and a `detail` with no place word and no sentinel. Control: `GET /run/bundle` before approval answers `MANIFEST_NOT_SHOWN` with no bytes.
- **R44** *(NEW; AIR12; `ai-gate` R20)* `POST /run` refuses before anything starts: a body not JSON 400 `BAD_REQUEST`; a `declared` that `ai-gate` `checkDeclared` refuses 400 `BAD_RUN` (the host not a public DNS name over `https`, a wildcard, the issuer's own host, an address or a private name outside the `machine` deployment); `tiers` not within `T0`–`T2` (T3 is a series of runs, never one) 400 `BAD_RUN`; no `ceiling` of `{spend, calls, seconds}`, each positive, 400 `CEILING_REQUIRED`; a `key` that is not a non-empty string of at most 4,096 characters, where the declared plan needs one, 400 `BAD_RUN`. Test: one request per refusal answers its code and starts nothing (the stub issuer is not called). Control: a valid request starts.
- **R45** *(NEW; SR54; AIR15)* **Per-run egress.** At `POST /run` the egress allow-list becomes exactly two hosts, the issuer's (from R10) and the declared provider host, each by exact name, no wildcard and no address (but R58), and is fixed for the run: nothing widens it after the first call, and a host reached by redirect, by an item's record text, by a tool or by the provider's answer is refused. At rest, and after the run ends or is discarded, the list is the issuer alone. Test: a stub provider redirecting to another host finds the second request refused (R34's line) and the run's record counting it; a request to a third host is refused; the list after the run is one name. Control: the declared host and the issuer are reached.
- **R46** *(NEW; SR54)* **One door out.** Every outbound request of the image, the adapters' included, goes through a single in-process function that checks the host against R45's list before opening a connection, strips nothing and follows no redirect itself; the image opens no socket any other way. It is a second layer beneath the platform's list (R13). Test: a scan of `src/` finds no network call but through that function; a request to an unlisted host through it is refused before a connection and logged (R34); control: the listed host passes. Where the platform cannot vary the list per run (see For BOB), this function alone enforces R45 and says so in `capabilities`.
- **R47** *(NEW; SR54; AIR15)* **The key lives in memory for one run.** The `key` arrives only in `POST /run`'s body and is held as bytes in one object of the run's instance; it is never set in an environment variable, argument or file, never logged, never echoed, never in the manifest, payload or any answer, error or trace. It is handed to the adapters only through `agent-model`'s credential resolver for that run's account (BR16: no ambient credential, so a key of any provider in the container's environment is never used), and its bytes are overwritten when the run ends, is discarded or expires. Test: a sentinel key, its base64 and its percent-encoded forms appear in no answer, line, file under the writable paths, manifest or (opened) payload; a sentinel key placed in the environment under each provider's usual name is never sent. Control: the sentinel is found in the provider stub's received `Authorization` header, so the test can see it.
- **R48** *(NEW; BR30; SR50)* **Raw-exchange capture is a second logging mode, and exists only here.** The image is built with a constant `CAPTURE` true (the production adapters in `agent-worker`'s path never are); in it each call's request body as sent (credentials removed), response body, status and headers, timings, usage and outcome (`ai-gate` R55) go into one in-memory buffer that is bound for the sealed payload alone: never stdout, a log line (R29), a file, an answer, the manifest or a trace. Test: a sentinel in the provider stub's response body and request headers is found in the opened payload (bodies) and not found in the headers record, stdout, any file or any answer; the `Authorization` header is in no captured record. Control: an image built with `CAPTURE` false answers no `"capture"` capability and holds no buffer.
- **R49** *(NEW; SR80; PROCESS §8.3)* **The challenge.** At `POST /run`, before any provider call, the container generates its run key pair and asks the issuer (`POST /ai/challenge`, `ai-issuer` R9) for a challenge, sending `{provider, plan, entry_id?, declared_model?, image_digest, bank_version, run_public_key}`; the answer is `{challenge_id, nonce, bank_version, selection_seed, issued_at, expires_at}` (no items and no signature: the container draws its items from the public bank it carries with `ai-gate` `selectItems` over the `selection_seed`, and checks the challenge with `ai-gate` `verifyChallenge`). With no challenge there is no run: an unreachable issuer answers 502 `ISSUER_UNREACHABLE`, a refusal by the issuer 409 `CHALLENGE_REFUSED` with its code, a challenge `verifyChallenge` refuses (another bank version, expired, malformed) 502 `CHALLENGE_INVALID`, each calling no provider. A challenge is used by one run only. Test: a stub issuer's good challenge starts the run; a challenge for another bank version, an expired one, a refusal and an unreachable issuer each answer their code with the provider stub receiving no request. Control: the stub issuer receives the declared plan and the run's public key and no key of the team's provider.
- **R50** *(NEW; BR12; AIR18)* **Host pin and served identity, in the container.** Every call goes through `agent-model` with the pin its entry or declared plan requires (only the declared provider, no fallbacks, collection denied, zero-retention routing where offered); a response whose served identity (provider, host, model version) differs from the declared is refused, recorded with its provider request id as `identity_mismatch` in the run record and counted in the manifest, and the run stops where `ai-gate` R18 says. Test: a stub serving another model, or from another host, is refused and recorded, and the manifest's count is 1; control: a faithful stub records none.
- **R51** *(NEW; SR41; AIR16)* **Ceilings.** The run carries the ceiling of R44 and enforces it itself: before each call `ai-gate` `meter` answers `ok` or `stop`; on `stop`, or when `seconds` have passed or `calls` are made, it issues no new call, ends the run `incomplete` with `incomplete_reason` (`ceiling_spend`, `ceiling_calls` or `ceiling_time`) and still seals what it holds (R53). Maximum output is capped for each call so that the overshoot past `spend` is bounded by one call's high estimate, which the manifest states. Test: a stub provider whose reported cost reaches the ceiling stops the run with the reason and a sealed bundle marked incomplete; a stalled stub provider stops it at the time ceiling. Control: a run below every ceiling completes `done`.
- **R52** *(NEW; SR52; BR15)* **Scrub, then scan, before sealing.** The key and any resolved secret are scrubbed from bodies, headers and error text, in the forms R47 names, then `ai-gate` `scanForSecrets` scans the whole payload and manifest with the exact key, the `key_shapes` of the entry's host profile (`ai-catalogue` R53; for a declared plan, none) and the image's generic shapes. A hit after scrubbing ends the run `incomplete` with `incomplete_reason: "secret_in_payload"`, emits no bundle (R54 answers `SECRET_IN_PAYLOAD`) and wipes the run. Test: a stub provider echoing the sentinel key in an error body gives a payload where it is scrubbed and a clean scan; a stub whose scrub is disabled in the test gives `SECRET_IN_PAYLOAD` and no bytes. Control: a clean run seals.
- **R53** *(NEW; SR60–SR62; AD8)* **The bundle is built and sealed inside.** At the run's end the container builds the payload and manifest with `ai-gate` `buildManifest`, `sealPayload` and `signBundle`: the payload sealed to Civicsmith's public key, which the image carries with its key id, so the team cannot open it; the manifest and payload hash signed by the run key, which also signs the image digest declared (R59) and the nonce. It then drops the plaintext payload and the raw buffer (R48); what remains is the manifest and the sealed bytes. Test: with a test sealing key in the build, the bundle opens with its private half and with no other key; after sealing, a search of memory-reachable test hooks, files and output finds no plaintext of the payload. Control: a flipped byte of the manifest breaks the signature check of `ai-gate` R59.
- **R54** *(NEW; SR60; PROCESS §8.5)* **The manifest is shown first.** `GET /run/manifest` answers before the bundle is available, and `GET /run/bundle` answers the bytes only after `POST /run/approve` for that run; before it, 409 `MANIFEST_NOT_SHOWN`. The manifest lists exactly what the sealed payload holds and does not hold (`ai-gate` R54). The container sends nothing to the issuer or anyone after the challenge: delivery of the bundle is the person's (download, or an upload the caller makes). Test: bundle before manifest and before approval answer the refusal; after both, the bytes. Control: the manifest route is readable repeatedly and the stub issuer receives no request after the challenge.
- **R55** *(NEW; R25's pattern, kept for runs; R9)* **One run per instance, held awake, wiped after.** An instance holds at most one run (`RUN_IN_PROGRESS`); the container stays awake from `POST /run` until the run ends, and then for the **review window** (`REVIEW_WINDOW_MS`, BOB's value), so the person can read the manifest and take the bundle; the sleep timer never ends a run. The class records in its Durable Object storage only a closed marker `{run_ref, deadline, state}`, no key, content or manifest. At discard, at the window's end (`expired`) or at a platform stop, the run's memory is wiped and the container stops; a run lost to a platform stop answers `NO_RUN`, with `state: "expired"` in its marker, and the person starts again (nothing was persisted). Test, with a stubbed `Container` and a fake clock: expiries during a run stop nothing; one after the window stops it; discard wipes at once; the storage keys are exactly the marker's. Control: an instance that never saw `POST /run` stops at its first expiry.
- **R56** *(NEW; SR54; AT-14 ended)* **No Claude Code and no shell in the image.** The image holds no Claude Code, no `@anthropic-ai/claude-agent-sdk`, no pseudo-terminal helper and no shell or interpreter other than the one runtime that runs the entry (its base is a digest-pinned image without a shell); its entry is in exec form. Test: a listing of the built image's files finds no `claude` binary or package, no `sh`, `bash`, `busybox`, `script`, `curl` or `wget`; the `Dockerfile` has no `RUN` after the final copy that adds one. Control: a planted `/bin/sh` in the listing fails the test.
- **R57** *(NEW; AI-PROVIDER-REQUIREMENTS §5.3; AD8)* **Where it runs.** Three deployments, fixed by configuration and never by a request: `team`, in the team's own Cloudflare account, reachable only by the team's copy through the binding R14 names; `machine`, the same image run by the team on its own machine beside a local model (R58); `civicsmith`, in Civicsmith's account, reachable only through a service binding from Civicsmith's own Workers and refusing any run whose declared plan is not on its configured list of Civicsmith's sample accounts with 403 `NOT_A_SAMPLE_ACCOUNT`. Running it in Civicsmith's account for outside teams is deferred (Bob). The container does not grade itself: neither the manifest nor `/version` carries a grade; the issuer grades by the route a challenge was asked on (`ai-gate` R61). Test: the `civicsmith` deployment refuses a declared plan off its list and has no public route; the `team` deployment has no service binding. Control: a listed sample account runs.
- **R58** *(NEW; PROCESS §6.4; AIR12)* **The machine route.** For a local or private model (an OpenAI-compatible endpoint a Worker cannot reach), the same digest-pinned image runs on the team's machine; only there may the declared host be an address, `localhost` or a private name, and `http` is allowed for loopback only. R45–R47 hold unchanged. The documented run command passes the key by the request, never by an environment variable or a mounted file, mounts no volume, publishes one port, and runs the image read-only. Test: in `machine` a declared host `127.0.0.1` is accepted and R45's list is that address and the issuer; in `team` and `civicsmith` the same is refused (R44); the image's writable paths are the temporary directory alone. Control: in `machine` a third host is still refused.
- **R59** *(NEW; PROCESS §8 open item; OPEN)* **Attestation of the running image is OPEN.** Nothing read shows a way for Civicsmith to prove which image ran in a team's account or on its machine. The manifest therefore states `image_digest_declared` (what the deployment says it runs, or `null`) and `attestation: null`; the intake compares the digest with the released set and never treats it as proven; the evidence that remains is the nonce, the provider request ids reconcilable with the provider's own billing, and the run signature (`ai-gate` R59). If an attestation mechanism is found, it is added as a new line. Test: the manifest's `attestation` is `null` and its digest field is named `image_digest_declared`. Control: a manifest with `attestation` non-null and no mechanism fails `ai-gate` R59's check.
- **R60** *(NEW; SR21; AIR15)* **The container holds no expected answer.** The image carries the public bank only (`ai-gate` R2) and the challenge carries no items; a bank item carrying an `answer`, `expected` or `states` key is refused 409 `CHALLENGE_HAS_ANSWERS` before the first call. The container scores only answer-free checks (`ai-gate` R32) and labels those figures `preliminary`. Test: a bank fixture with an item carrying `expected` is refused with the provider stub receiving no request. Control: a clean item runs and its preliminary figures carry `preliminary: true`.

**Logging and words**
- **R29** *(AMEND; was the sign-in and conversation lines; BR30)* Each run step writes exactly one JSON line to stdout: `{event: "gate.runner", trace, run_ref, step, outcome, code?, status, ms, cold, uptime_s}`, `step` one of `start`, `challenge`, `tier`, `ceiling`, `seal`, `manifest`, `approve`, `bundle`, `discard`; `tier` adds `tier`, `items_done`, `items_total`; `ceiling` adds `incomplete_reason`. `trace` is the `x-civicsmith-trace` header the caller sent, else one minted here; `run_ref` the first 12 hex of the run id's SHA-256, never the id; `outcome` is `ok`, `refused` or `failed`. This is the **production-safe mode**: it has a closed field list and never carries content. **Never logged:** a key, nonce, challenge, item, prompt, request or response body, header, record text, manifest value other than step names, or bundle byte (the raw exchange is R48's second mode, which writes to the sealed payload only). Test: a run with sentinels in the key, a provider body and header, an item and the nonce writes exactly one line per step with the named fields and no sentinel. Control: a refused request writes its line with `outcome: "refused"` and its code.
- **R30** *(AMEND; was lifecycle and egress lines)* The Worker class logs its lifecycle and its egress, one JSON line each. **Lifecycle** `{event: "runner.lifecycle", instance_ref, what, ms?, error_head?, run_hold}`, `what` one of `start`, `started`, `activity_expired`, `held_awake`, `stop`, `error`, `run_hold` saying whether R55's hold was in force. **Egress** `{event: "runner.egress", instance_ref, host, method, path_template, status, ms}` for each request to a host of R45's list, `path_template` the path with each segment longer than 24 characters replaced by `:id` and never a query, header or body; a refused request is R34's line. Test: a stubbed base fires each hook and finds one line each; an egress request carrying a sentinel in its query, headers and body logs none of them and passes unchanged. Control: the hosts logged equal R45's list for the run.
- **R34** *(KEEP)* Every outbound request that the egress gate refuses (a host outside R45's list, or a denied host) is logged by the Worker side as one JSON line `{event: "runner.egress.refused", instance_ref, host, method, path_template, status}`, never its query, headers or body, and is refused exactly as before (status 520, nothing forwarded). Text unchanged; R46's in-process refusals write the same line.
- **R41** *(AMEND; was the sign-in sentences)* **The image's member-facing sentences are read by key, from rows the image carries.** Every sentence a person reads from this image's answers, the `detail` of each refusal (R43–R60's codes and `RUNNER_NOT_STARTED`), is read by its key in the plane's word table (`gate.runner.refused.<CODE>`), and the image holds no English literal for one. The image cannot import `setup-words`, so it carries the rows it reads as data of its own, one generated file of `{key: sentence}` rows written from the word table by a command and bundled in; a code with no carried row fails the build. The rows say "team", never "group", and no place word (R11), at most 300 characters. Test: every key the image reads is in the carried data and the row equals the table's (stale data fails); each refusal answers the carried row of its code as `detail`. Control: a scan of `src/` finds no English string literal as a `detail`.

## Private

### Uses

At build, `bundler.writeMember` (its committed bundle) and the run entry of `ai-gate` with the modules it needs; at run time nothing of the plane. It reaches the plane through no path: the stub plane is in-process and synthetic.
