## Public

### Purpose

How a model turn reaches whichever AI provider an account names, through one neutral interface. Given the account that serves one member's act (R1) and a catalogue entry id, `turn` sends one neutral request through the adapter for the entry's host profile (R37–R43), resolves the account's credential at call time by its means (R46), checks the host and identity that answered (R45), classifies any failure (R50), and returns one neutral outcome with a neutral usage record (R5, R26). `capabilities`, `estimate` and `health` answer what an entry can do, what a task will cost and whether the account's path is up. `converse` keeps a segment within its bounds, built only on `turn`. The module holds no credential and names no provider, host or model: every provider fact arrives as `ai-catalogue` data, and a provider differs only inside its adapter.

### Provides

Terms. An **account** is what `ai-accounts` hands the call: `{account_id, level, owner, provider, plan_id, means, gateway_id?, secret?, ref?, personal_choice?}`; `level` is `member`, `project` or `group` (code identifiers; words people read say "team", K3472); `means` is `gateway`, `sealed`, `reference`, `issued` or `none` (the built-in binding holds nothing, For BOB B5). An **entry** is `ai-catalogue`'s record for an `entry_id` (a model at a host): its host profile, provider model string, `model_version`, accepted served identifiers, capabilities, effort set and `effort_classes`, prices with date, zero-retention support, lifecycle and measured cost of standard tasks. Only an adapter sees the provider's model string. A **host profile** is catalogue data (R38). An **outcome** is exactly one of `{result}`, `{silent: {detail}}`, `{refused: {type, message?, control?}}`, `{limit: {...}}`, `{error: {class, ...}}` (R26). `now` is handed in, else the wall clock.

**Roles and entries**
- **R1** (was `agent-worker` R40, amended; K1502, K1755; AIR5, AIR8; BR1, BR3) A run's model turns run under the account that serves the act of the member who started the run (a standing question's, its author's), as `credentials.accountFor` answers it (its R35), with the skill pack the run names, within the segment bound. The module names no model. `MODE_NEEDS`, a reviewed edit (as `agent-worker` R42), holds for each mode the table runs (`ask`, `draft`, `transcribe` and the rest) what it needs of an AI: capabilities (tool calling; schema output; image input for `transcribe`), an `effort_class` (`low` or `medium`) and a `cost_class`. `serves(entry_id, mode)` answers `{ok: true}` or `{ok: false, lacks: [control names]}` from R30; an entry lacking a need is refused for the mode by name (R29). `ai-accounts` chooses the entry from the account's allow-list; `turn` and `converse` take it as `entry_id`; no request body or judgement chooses it. Test: over a fake entry lacking image input, `serves(fake, "transcribe")` answers `lacks` naming `image_input`, and `serves(fake, "ask")` answers ok; a scan of the module's source and tests finds no `claude-`, `opus-` or `sonnet-` string. Control: a fake entry with image input serves `transcribe`.

**modelCall → `turn(request)`; one turn**
- **R25** (BR1) `turn(request)` takes `{account, entry_id, messages, tools?, tool_choice?, output_schema?, effort?, max_output, session_key?, cache_hints?, data_handling, runtime, timeout_ms, idempotency_key, interactive?, onProgress?}`. `messages` are neutral: `system`, `user`, `assistant` (text, tool calls, an opaque `continuation`, R28) and `tool_result` (text, `search_result` and image blocks, R12, R14). `entry_id` is never a provider model string: a value that is not an entry the catalogue holds is refused `ENTRY_UNKNOWN`; a retired entry `ENTRY_RETIRED`. A missing account, a `level` other than `member`, `project` or `group`, an empty `idempotency_key`, `max_output` or `timeout_ms` that is not a positive integer, or a field outside this list is refused `REQUEST_INVALID` (naming the field) or, for the account, `ACCOUNT_REFERENCE_UNUSABLE`; none makes a call. Test: each malformed request is refused with its type and the fake provider receives nothing; an `entry_id` equal to the fake's provider model string is `ENTRY_UNKNOWN`. Control: the well-formed request is sent.
- **R26** (BR2; was R3's outcome shapes) Every outcome carries, beside its one key, an envelope `{usage, served, limits, events, entry_id}`. `usage` is R5's record, or null if the request never reached the provider. `served` is `{provider, host, model_version, request_id, fingerprint}`, each null where the provider did not state it. `limits` is `{remaining, reset_at, retry_after}`, null where not given. `events` is a list of content-free records (`retry`, `circuit`, `pin_violation`, `payer_unverified`, `continuation_dropped`) for the caller to record; nothing in an event is a secret or record text. `{result}` carries `{text, tool_calls: [{id, name, input}], stop, continuation}`. Never throws (R3). Test: a fake answer with no served host, no request id and no rate-limit headers yields those fields null, not empty strings or zeros; a fake that throws inside the adapter yields `{silent}`. Control: a fake that states all of them yields them.
- **R27** (BR2) The provider's stop reason maps to a neutral set: `end`, `tool_call`, `length`, `refusal`, `filtered`. `refusal` and `filtered` yield `{refused}` with that type, the provider's words unchanged (R3). A stop reason the profile does not map yields `{silent}` with detail `stop_unmapped`, never a guessed `end`. Test: each fake provider reason in the profile's table yields its neutral stop; an unlisted reason yields `silent`. Control: `length` yields `{result}` with `stop: "length"` and is not an error.
- **R28** (BR1) A provider's own state that must come back unchanged (reasoning items, thought signatures) travels as an opaque `continuation` on the assistant message: tagged `{adapter, entry_id}`, never read above the adapter, returned by the caller unchanged on the next turn. A continuation tagged for another entry or adapter is dropped, an event `continuation_dropped` recorded, and the turn made without it (a run resumed on another AI carries none; the run record is the source of truth, AIR7). Test: a fake echoing a reasoning blob receives it back unchanged on turn two; presented on a turn for a different fake entry it is absent from the request and the event is present. Control: a continuation for the same entry is sent.
- **R29** (BR3; AIR5, AIR8) An unsupported control is refused at the boundary by name, before any call: `{refused: {type: "UNSUPPORTED_CONTROL", control}}` with `control` one of `tools`, `parallel_tools`, `schema_output`, `schema_with_tools`, `image_input`, `streaming`, `session`, `cache_hints`, `zero_retention`, `effort` or `effort_value`. `effort` is accepted only if it is a member of the entry's effort set; an entry with no dial refuses any effort (`effort`); the entry's default is used when none is given. Test: an effort outside the fake entry's set, any effort on a dial-less entry, an image block on an entry without image input and `schema_output` combined with tools on an entry saying it cannot each refuse naming the control, with nothing sent. Control: each is accepted on a fake entry that has it.
- **R30** (BR3) `capabilities(entry_id)` answers, from the entry and its profile: `tools`, `parallel_tools`, `schema_output`, `schema_with_tools`, `image_input`, `streaming` (`none`, `text` or `tool_calls`), `session` (`none`, `provider_state` or `resend_only`), `caching` (`none`, `automatic` or `explicit`), `batch`, `effort_set` and default, `context_window`, `max_output`, `zero_retention`, `lifecycle`. A figure the catalogue does not state is `null` (OPEN), never false or zero; a control answered `null` is refused by name as unsupported only if the request needs it. Unknown entry: `ENTRY_UNKNOWN`. It makes no call and never throws. Test: a fake entry with `image_input: null` answers null and a request with no image is accepted; a request with an image is refused `image_input`. Control: an entry stating `image_input: true` accepts it.
- **R31** (BR1, BR25; AIR6, AIR7) `session_key` and `cache_hints` (the append-only prefix boundary) are passed to the adapter only if the entry's `session` and `caching` answer them. `data_handling` is `{retention, zero_retention (required, if_offered, off), host_pin (required, off), provider_state (forbidden, allowed)}`: `zero_retention: required` on an entry without it is refused `zero_retention` (R29); `provider_state: forbidden` sends no session key and asks the host to hold no conversation state, whatever `session_key` says; `host_pin: required` is R45's. Test: with `provider_state: forbidden` the fake provider's received body carries no session key and no state flag, with `allowed` it carries the key where the entry has `session: provider_state`; `required` zero retention on a fake entry without it is refused. Control: the same request on an entry with it is sent with the host's zero-retention setting.
- **R32** (BR1, BR27) Every attempt of one `turn` carries the same `idempotency_key`, passed to the host where the profile says the host honours one (`idempotency`: `honoured`, `not_honoured` or OPEN). A turn that needed retries returns exactly one outcome: the first complete answer; a late answer from an abandoned attempt is discarded, and no tool call from it is returned. Test: a fake that answers the first attempt after its timeout and the second at once yields one outcome, both attempts show the same key, and the late answer's tool call is absent. Control: with no fault, one attempt, one outcome.
- **R33** (BR5; K3602; AD37) `onProgress` receives `{kind}` events (`reading`, `composing`, `checking`, `turn_started`, `turn_done`) and never any text the model produced. Where `capabilities.streaming` is `none` the adapter emits only `turn_started` and `turn_done` and its capability answer says so (turn-level progress). Test: a fake streaming a sentinel string yields progress events not containing it, in order; a non-streaming fake yields exactly the two turn-level events and `capabilities` answers `streaming: "none"`. Control: the sentinel is present in the `{result}` text.
- **R34** (BR6; AIR26) `estimate({entry_id, task: {kind, count?}})` answers `{low, high, unit, basis}` from the entry's measured all-in cost of standard tasks, times `count` (default 1), `basis: "measured"`; with no measurement but a price, `basis: "price_only"` with `low`/`high` null; with neither, `"not_known"`. A unit the catalogue does not state is null. It makes no call, never throws, and never answers zero for an unknown. Test: a fake entry with a measured range answers it scaled by `count`; one with neither answers `not_known`, not 0. Control: the unpriced entry's `low` and `high` are null.
- **R35** (BR6, BR28) `health(account, entry_id)` answers `{state, since, reset_at?, last_error_class?, uptime_evidence?}` with `state` one of `ok`, `degraded`, `open`, `half_open`, `auth_failed`, `payer_unverified`, `retired`, `unknown`, read from the circuit state (R53) and the entry's lifecycle; the catalogue's uptime evidence sets the defaults when nothing has been observed. It makes no call, carries no content or secret, and never throws. Test: after five counted failures on a fake, `open` with a `reset_at`; a never-called pair answers `unknown`. Control: a success after the cooldown answers `ok`.
- **R36** (BR14; AIR37) `runtime` (`team_worker`, `member_runtime`, `member_device`) is checked against the plan's allowed runtimes: a call whose deployment the plan does not allow is refused `RUNTIME_CONSTRAINT_UNMET`, naming `runtime`, with nothing sent, except an account marked `personal_choice` (the member's recorded choice governs, AIR41; `ai-accounts` enforces that it serves only its owner's acts). Test: a fake plan allowing only `member_runtime` refuses `team_worker`; the same account with `personal_choice` is sent. Control: an allowed runtime is sent.

**Adapters** (BR8–BR12)
- **R37** (BR8, BR11) An adapter is `{family, encode(neutral, entry, profile, credential) → http request, decode(http response) → neutral outcome, classify(response or fault) → error class}` and nothing else: no policy, no retry (R51 is the module's), no retention, no choosing among accounts; a credential is used for the call and kept nowhere. The module selects the adapter by the entry's host profile `family`; a profile naming a family or mapping option this copy lacks makes the entry `needs a newer release` (AIR33): refused `ADAPTER_MISSING`, nothing sent. Test: a fake adapter that records what it was handed is called with neutral inputs only (no provider model string before `encode`); a profile naming an unknown family is refused `ADAPTER_MISSING`. Control: a known family is selected.
- **R38** (BR9; AIR20) The **generic OpenAI-compatible adapter** serves every host of that family from its **host profile**, catalogue data: allowed hosts and base URL; auth style (`bearer`, `header:<name>`, `binding`, `none`); parameter and usage-field mappings (including `reasoning_billing`: `in_output`, `apart` or OPEN); which features exist; the `pin_map` (how R45's pin is expressed); where the served host and model are reported; `idempotency`; and quirks drawn from a closed set the adapter implements (for example `return_reasoning_unchanged`). A mapping a profile needs but the adapter lacks is R37's `ADAPTER_MISSING`. Test: two fake profiles over one fake server (different base URL, auth style, field names) both yield the same neutral outcome for the same request; a profile with a missing mapping is refused. Control: the first profile's request body differs from the second's.
- **R39** (BR9, BR12; AD9, AD10, AD24, AIR18) Profile **`openrouter`** (built first, Bob's sequencing): each request carries the pin `only` the vetted provider, `allow_fallbacks: false`, `data_collection: "deny"`, `zdr: true` where the entry has zero retention, and `require_parameters: true` (AIR18's controls). Whether a response names the serving host, and whether a pinned request whose host is unavailable fails rather than falls through, are **OPEN** until live test L2; until the catalogue records them, the entry's check P5 is OPEN and R45 treats `host_pin: required` as unmet when the response does not name the host. Test: the fake OpenRouter receives all five controls; a fake that answers from another host is refused (R45); a fake pinned host made unavailable and answering from another is refused, not returned. Control: a response naming the pinned host is returned.
- **R40** (BR9; AD17, AD26, AD29) Profile **`workers_ai`** (Cloudflare Workers AI through the team's own binding, `means: none`): no credential is read or sent; the call goes through the binding the account's profile names. What usage and served identity the binding reports is **OPEN** (L3/characterization): every figure it omits is null, never zero. Test: a fake binding answering no usage yields usage fields null with `unstated` naming them; the request carries no Authorization header. Control: a fake stating usage yields numbers.
- **R41** (BR9, BR13; AD16, AD30, AIR45; L1) Profile **`ai_gateway`**: a request goes through the account's gateway binding (R48) in the OpenAI-compatible shape the profile names. Under `means: gateway` the adapter sends **no provider key header** (the gateway adds its stored key only when the provider authorization header is absent) and no key-choice header it relies on (R48). Under `sealed`, `reference` or `issued` the key goes in the header the profile names, as a passthrough. Test: under `gateway` the fake gateway sees no Authorization header (a fake that would use a sent key proves it); under `sealed` it sees the key in the profile's header only. Control: a gateway-means request carrying a key header fails the test.
- **R42** (BR9; AIR12; AD10) Profile **`custom`** (a team's own or local endpoint) is usable only through the test flow (`ai-gate`) until a release lists it: a `turn` for an entry whose host profile is `custom` and whose `listed` flag is false is refused `ENTRY_NOT_LISTED` unless the request carries `test_flow: true`, which only `ai-gate`'s callers set. Test: refused without the flag, sent with it. Control: a listed entry on any profile needs no flag.
- **R43** (BR10; AIR23, AD19) **Bespoke adapters** exist only where an API genuinely differs (expected: Google native, Cohere, a Responses-style API). The **Anthropic adapter** is the first, carrying today's API-key path (R2, R4) and its held-token flow (R16) unchanged in behaviour behind R37's contract. Adding a provider needs one adapter and one catalogue entry; adding a model at a supported host needs only an entry. Test: the existing R2/R4/R5 tests pass unchanged through `turn` with the Anthropic fake; control: a scan finds no provider name outside the adapters and test fixtures.
- **R44** (BR11, BR32) The **adapter test kit** `adapterKit(adapter, profile, fake)` runs every adapter against the **fake provider** (a scripted server recording each request; scripts set status, body, headers including `retry-after`, delay, served host and model, and echoed secrets) and checks: field mapping both ways against golden requests and answers; one error class per scripted fault (R50); usage null-not-zero; no secret in any returned value, event or log; refusal of each unsupported control (R29); host-pin and served-identity checks (R45); idempotent retry (R32, R51). Test: the Anthropic and generic adapters pass the kit; a deliberately broken adapter that echoes the sentinel secret in an error and reports 0 for an unstated figure fails the kit on exactly those two checks. Control: removing either defect makes the kit pass.
- **R45** (BR12; AIR18, AIR24) **Host pin and served-identity check.** The adapter sends the pin its profile's `pin_map` defines when `data_handling.host_pin` is `required`. For every answer the module compares `served` with the entry: a served host other than the entry's host, or a served model version not among the entry's accepted served identifiers, is refused `{refused: {type: "PRIVACY_PIN_VIOLATION", field, expected, got}}` with its text withheld, an event `pin_violation` recorded and the usage kept. An unstated host or version passes only where `host_pin` is `off`; with `required` it is refused (`got: null`). Test: a fake answering from a non-vetted host, one answering a different model version, and one stating neither with `required` are each refused and recorded; with `off` the last passes with `served` nulls. Control: a response naming the pinned host and an accepted version is returned.

**Credentials at call time** (BR13–BR16)
- **R46** (BR13, BR14; AIR32, AIR37) The credential is resolved **per `turn`, by the account's `means`**, held for that call only (shared by its retries) and dropped when it returns; none is cached across turns. `sealed` and `issued`: the secret arrives in the account (as today). `reference`: the caller-supplied resolver is called with `ref`; a reference resolving to nothing is class `auth` (detail `reference_unresolved`) with no call. `gateway`: no secret (R47). `none`: no secret. A `means` the plan does not allow (the catalogue's `means_allowed`) is refused `MEANS_NOT_ALLOWED`, nothing sent. Test: a fake resolver called once per turn, not per attempt; a `reference` resolving to null yields `auth` with the fake provider unreached; `issued` on a plan allowing only `sealed` is refused. Control: an allowed means is sent.
- **R47** (BR13, BR16; AD16, AD30, AIR45; L1) **Gateway means: the payer is checked on every call.** After each `turn` under `means: gateway` the module reads the call's gateway log record (by the log id the binding returns) and accepts it only if the log shows the account's own stored key served the call (`byok` naming the stored alias, `wholesale` false, the shape L1 observed) and that no Cloudflare credit paid for it. Anything else (a fall-through to Cloudflare's credits, which a missing `default` key on a Unified Billing endpoint causes; a log that cannot be read) is `payer_unverified`: an event is recorded, `health` shows `payer_unverified`, and every later turn on that (account, gateway) is refused `PAYER_NOT_VERIFIED` until a call's log verifies. Whether the mismatched call's answer is kept or withheld is Bob's (For Bob F1); until he answers, it is kept and flagged. The gateway log's per-call cost fills `usage.cost_reported` (source `gateway_log`) where the provider states none. A gateway with logging off is refused at the first call (`PAYER_NOT_VERIFIED`). Test: a fake gateway whose log states `byok: default` returns the answer; one whose log states Cloudflare credits (or an unreadable log) records the event, flags, and the next turn is refused with the fake gateway unreached. Control: after a verified call the pair is `ok` again.
- **R48** (BR13; AIR45; L1) **One gateway per account holding a stored key.** The account names its `gateway_id`; a gateway-means account without one is `ACCOUNT_REFERENCE_UNUSABLE`. The module relies on no key-choice header (through the binding it did not select a key, L1): the stored key is the gateway's `default`. A log naming another gateway than the account's is `payer_unverified`. Test: two fake accounts on two fake gateways each reach their own; a log from the other gateway fails R47. Control: a log naming the account's gateway verifies.

**Errors, retries, limits** (BR23, BR26, BR27)
- **R50** (BR26; AIR28; was R3's 429 and status rule) Every adapter classifies a failure into one class, and the module handles each the same way:
| Class | Handling | Outcome |
|---|---|---|
| `rate_limit` | bounded retry honouring `retry-after` (R51), then counted by the circuit (R53) | `error` after the bound |
| `provider_limit` (spend cap, quota, plan window) | not an error, not retried, not counted (R52) | `limit` |
| `overload` (5xx), `timeout` | bounded retry with backoff, counted by the circuit | `error` after the bound |
| `auth` (revoked, removed, reference unresolved) | stop, no retry, event so the caller revokes run credentials and tells the owner; health `auth_failed` | `error` |
| `model_gone` (not found, retired) | stop; event for the caller to move the entry to lapsed (failover is `ai-accounts`' hop rules, BR18) | `error` |
| `content_refusal` | the model's refusal, never reworded | `refused` |
| `malformed` (a body not JSON or lacking required fields) | detail at most 200 characters | `silent` |
| `pin_violation` | refuse, record (R45) | `refused` |
| `unsupported_control` | refuse by name (R29) | `refused` |
| `request_rejected` (another 4xx) | no retry, not counted; provider message cut to 300 characters | `error` |
| `circuit_open` (made by the module, no call) | R53 | `error` |
  Provider text in an error is cut and scrubbed (R49). Test: the fake provider scripts one fault per row; each yields its class, handling and outcome, and the retry counts in the table; `provider_limit` and `request_rejected` are never retried. Control: a 200 answer yields `result`.
- **R51** (BR26; AIR28) **Bounded retry.** Only `rate_limit`, `overload` and `timeout` are retried, at most 3 attempts in all, with exponential backoff (500 ms base, doubling, 20% jitter, 8 s cap) and `retry-after` honoured where given, waited up to 30 s (5 s when `interactive: true`); a longer `retry-after` is not waited: the outcome is `error` `rate_limit` carrying `retry_after`. All values provisional, BOB's (B3). Attempts share the idempotency key (R32). Test: a fake answering 429 with `retry-after: 2` then 200 is retried after at least 2 s (a pinned clock) and returns the result; `retry-after: 600` is not waited and returns `error` with `retry_after: 600`; a 4xx other than 429 is not retried. Control: three 5xx answers end in `error` after exactly 3 attempts.
- **R52** (BR23, BR26; AIR27) **A provider-side limit is a limit reached, not an error**: a spent cap, an exhausted quota or rate window, a plan allowance window. A 429 or other answer the profile maps to `provider_limit` (for example `enforced_spend_limit_reached`) yields `{limit: {kind (spend, quota, rate_window, plan_window), scope (account or entry), resets_at}}`, `resets_at` null where the provider gave no time; it is not retried, not counted by the circuit, and `health` is not changed. Scope is `account` for `spend` and `plan_window`, else `entry` unless the adapter states account. Test: a fake spent-cap 429 yields `limit` with its reset time, one attempt only, the circuit unchanged; a plain rate-limit 429 yields retries. Control: five spent-cap answers do not open the circuit.
- **R53** (BR26, BR28; AIR28) **Circuit breaker per (account, entry).** `rate_limit` (after its retries), `overload` and `timeout` count; 5 consecutive counted failures open the circuit for a 30 s cooldown (provisional, BOB's, B3), during which `turn` makes no call and answers `error` `circuit_open` with `retry_at`; after it one probe turn is allowed (`half_open`): success closes, failure reopens. `auth` sets `auth_failed` and `model_gone` sets `retired`; neither is counted. State is kept in a handle the caller supplies (`{get, put}`), holding no content or secret; with none supplied `health` answers `unknown` and no circuit opens (B4). Test: five scripted 5xx outcomes open it, the sixth call reaches the fake zero times, after the cooldown (pinned clock) one probe reaches it and a 200 closes it; a failure of the probe reopens. Control: four failures then a success leave it closed.
- **R54** (BR22; R5, R6) **Usage across attempts.** A turn's `usage` sums every attempt that reached the provider, with null where any attempt's figure is null; `calls` counts each attempt sent (an attempt that timed out with no stated usage counts one and nulls its figures), a request refused before sending counts none. Test: a fake that fails once with a stated usage and then succeeds yields `calls: 2` and summed figures; a timed-out first attempt yields figures null and `calls: 2`. Control: a refused request (R29) yields `usage: null`, `calls` 0.

**Existing lines, amended or moved**
- **R2** (ADAPTER, API-key half; K1429, K1502; amended) The Anthropic adapter (R43) sends the turn to the host its profile names, the key in the header the profile names (today `x-api-key`) and nowhere else. An absent account, one whose `means` is not one the plan allows, or one with an empty secret answers `refused` `ACCOUNT_REFERENCE_UNUSABLE` and makes no call. **Retired within R2:** the `signin` kind, the runner, `RUNNER_NOT_CONFIGURED`, and the runner's `NOT_SIGNED_IN` and `NOT_THIS_MEMBER` (parked with K3718; types never reused). Test: the fake receives the key in that header only; no secret, or a wrong means, refuses with no call. Control: a valid account is sent.
- **R3** (AMEND; K1429) Never throws. A call that throws, or an answer that is not JSON, is `silent` with a detail of at most 200 characters. A status other than 200 is classified by R50 (no longer a plain refusal; a 429 is retried under R51, or, for a spent cap, a `limit`, R52); the provider's message is cut to 300 characters and scrubbed (R49). A model's own refusal (`stop` `refusal`) is `refused` type `refusal`, never reworded.
