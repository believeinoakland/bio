## 0. In short

**Why a document "works, then fails".** For these kinds the reason is one step earlier than for PDF: *they were almost never tried.* No walk, in nine walks of biosmoke8 and its predecessors, uploaded or captured a DOCX, DOC, ODT, RTF, PPTX, ODP, email or ZIP (H18, H19: the walks used PDFs, JPEG photographs, TXT, CSV/TSV, xlsx/ods safe views and web pages; the coverage map rates the office-format row "NEVER" and is a draft). No T51 cause (G5 to G90, C/E/F/L before them) names one of those kinds (H13, H14, H15). Every cause that touches them is a *shared mechanism* that a PDF, a text or a CSV walked into first (the reading tick, the pieces, the 24 MiB line, the ledger). So the code for these kinds has been fixed only where another kind forced it, and its tests feed it its own builders' kind of file: well-formed, small, UTF-8, text-heavy (H02, H20).

**What running them finds at once.** Probes through the real plane harness and the real readers, with no repository change (H20, H02, H12, H07, H11), are enough to show the state:
- a DOCX of 0.48 MB declaring 12 MiB of body text **kills the object** (heap out of memory in tick 1); 24 MiB does too; 2-6 MiB read whole in 22 ticks; an 8 MiB body takes 13.3 s for its first tick (H20, ran);
- a 69 KB DOCX of one-cell tables (19 MiB declared, under the 20 MiB whole bound) **runs out of memory in a 128 MB worker**; a 45 KB file of `<w:p/>` does the same at 29 MiB (H02, ran);
- a 60 KB DOCX with about 7,000 table cells **loses all its text**, paragraphs outside the table included, and the member sees "too large to keep whole" (H12 D1, H11 D11, ran);
- a 953-byte DOCX takes 8 s to read; a 1.5 KB PPTX 4.3 s; a 96 KB `content.xml` 9.7 s; an 800 KB part in doc-clean 21 s: one regular expression, scanned from every `<` (H02 D3, H03 D2-D3, ran);
- a Latin-1 or Windows-1252 page or text reads as `U+FFFD` text and is reported **complete**; a UTF-16 capture reads as NUL-interleaved text whose last line search cannot find; the same file *uploaded* is refused with "non-textual or too large" (H01, H08, H12, ran);
- an RTF is read as raw control words (`text/rtf`) or refused with a false sentence (`application/rtf`); an `.eml` is indexed as raw MIME with its base64 body; `.doc` is refused; each carries "non-textual or too large", and a "Read it" repair button that cannot succeed (H11 D6/D12, H08 D2, ran);
- **an uploaded ZIP is never opened**: `uploadCapture` profiles it and stops, no screen act opens it, and the archive screen shows every entry `waiting` for ever (H07 D1, H08 D5, code, probe: the upload answer has no `unpack` key);
- a ZIP whose central directory is in shuffled order costs 9,180 8-MiB part reads (73 GB, 106 s of node, before any R2 latency) where the same bytes in physical order cost 25 reads (H07 D2, ran).

**The failure classes** (§3) are the PDF plan's fourteen (MEM, WORK, ENC, PIECE, STATE, SHAPE, IDENT, SILENT, INTAKE, UI, FORMAT, STALEFAIL, LIVE, PATH) plus the ones these kinds forced: **NEST/ZIPBOMB** (archives and containers: member count, depth, ratio, names), **RENDER** (the visitor view's cost and fidelity), **DROP** (content the reader never emits, with no marker), **BIN** (binary taken for text), **STORE** (a stored value over its row bound), **CEIL** (a ceiling set by a constant with no requirement), **VOCAB** and **MEASURE** (the producer's vocabulary is not the consumer's; the instrument times the wrong interval), **SEC** (a safety verdict that does not gate, or says `clean` of what it could not read), **SUPPLY** (the scanner's image cannot be pulled) and **MISCLASS** (a profile that claims what the file is not). Three findings recur across almost every class, as for PDF: *no stated envelope* (in all but about five of some thirty round-7 causes the entry's invariant is "none stated", H15), *fixed on the path the test used* (G88 fixes plain text only; G68 text and CSV only; G41 sheets only; G2 the fetch arm only), and *measured outside the shape*.

**The envelope** (§4): 61 bounds in seven groups. Most are unstated, or stated only as a code constant or a test bar, and none of the stated ones is stated against the 128 MB object. The same file is judged at four unrelated sizes by four modules (acquisition 8 MiB, file-safety 20 MiB, reading-pipeline 24 MiB, capture and the scanner 256 MiB), and none is Bob's 100 MB tier. 27 rows are marked **Bob's**; they are put to him as eleven questions (§4.3).

## 1. The architecture (K4798 (1))

### 1.1 The flow, step by step

One document of these kinds reaches a member as a searchable, citable passage by one of four **entry paths**:

- **U, upload.** The member's browser sends the bytes: `capture.uploadCapture`.
- **F, fetch.** The member (or a monitor) gives an address: `acquisition.acquire` fetches the page or file, as sent.
- **V, visitor view.** The same address rendered in a browser: `acquire` with `render` asks the Browser Rendering binding for the DOM; the page as served stays the *shell*.
- **M, member of an archive.** `acquisition.unpack` cuts an archive's entries into captures of their own (only `acquire` calls it; §2.2 X3).

Every path then runs the same chain. Each step names the module, the code, and the requirement it serves. "—" means no requirement states it.

### 1.3 What is carried between ticks

Only the PDF open-document slot is held in the object between ticks (`openedPdf`, 1907). Text and CSV re-open a *window*. DOCX, ODT, PPTX, ODP and HTML re-open the whole object: ran, 13 ticks of a 90 KB DOCX are 13 parses and 13 × the file's bytes from the store; an 18 MB-text DOCX is 72 ticks, median 1.45 s each, 115 s of compute (H11 D2). The durable state is the cursor, the text state row (`capture_text_state`: `state`, `more`, `cursor`, `words_read`, `over_bound`, `truncated`) and the ledger row (`keeps_pending`).

### 1.4 What partial means today

A read is marked partial by: `more=1`, `over_bound`, `unaddressable`, `skipped_named`, `truncated`, `words_read < words_total`, `state="partial"` (`extraction/index.mjs:1399,1528`). The word *whole* has three meanings (H11): `bytesOf(...).whole` (the object under its own digest was read as one object), the index `state`, and `completeness.state`; `unitsOf().state` can say `whole` while `completeness` says `partial` (X14). A read that ends because a later tick failed is `partial` *with no reason and no retry* (X13).

## 2. The state of the code (K4798 (2))

### 2.1 Module by module: mature, fragile, duplicated, legacy, untested

**Mature (tested, consistent with its requirement, and survived a probe):**
- The text window path for single-part UTF-8: `textWindowCursorOf`/`textWindowTick`, `completeRunsEnd` (`reading-pipeline/index.mjs:1665-1716`). 180 randomised windowed reads equalled the one-shot unit list; 3 MiB ASCII, CJK, CRLF and BOM texts reached their last line; a 12.6 MB text: first tick 0.5 s, later ticks 6-11 ms (H01, H11, ran).
- Units, `seq`, `para` continuity and the 128 Ki chunking for text and `doc-para` (1282, 1344); the reading's provenance and hash in slices (`readingprov.mjs`); `hooks.mjs`; text-chain's grammar (all R1-R104 named by a test; H01).
- The ZIP container walk with ZIP64, verified inflate with CRC and size, MCE branch selection, hidden-slide and speaker-note *evidence*, VBA read (`ooxml.mjs:337-618`, `docx.mjs:214`); `listArchive`/`streamMember` with range sources and bounded windows (`ooxml.mjs:1478,1758`).
- No entity expansion is possible in the OOXML or ODF readers: only the five predefined entities and numeric references are decoded; DOCTYPE is not matched (H02, H03).
- The visitor view's timeouts and "a page that never settles is an answer" (`browserrender.mjs:604-618`; capture-sources R23, R50), the best-stated part of the module (H10).
- file-scanner's refusals are *stated*: over 256 MiB `not_scanned/TOO_LARGE`; ClamAV limit hits `unknown LIMIT:<name>` (H05).
- Every in-force requirement id of text-chain (104), office-readers (31), odf-reader (48), doc-clean (10), acquisition (63), capture (60), file-safety (52) is *named* by some test (H20; naming is not coverage; H20 §3).

**Fragile (works on its builder's file, breaks on the next shape):**
- **The office entries' memory model**: bounded by *declared bytes*, allocating per paragraph, per cell and per hyperlink (`docx.mjs:354-356,629-631,1006-1017`). Memory ≈ 10 × the decoded text (H11 D1), and the ceilings (20 MiB whole, 32 MiB in pieces) were measured on 600-character random paragraphs (`large.mjs:63-94`), the cheapest shape per byte.
- **The XML tokenizer**: one regex (`TOKEN_RE`, `docx.mjs:196` = `pptx.mjs:197`; `odf.mjs:359`; a variant in `doc-clean/xml.mjs:130`) tries an attribute group from every `<`; an unterminated tag rescans to the end. Quadratic; no validity check; no yield.
- **`visibleTextOfHtml`**: per-element RegExp construction and rescans (`1023-1045`, `1090-1121`); closed nested `<div>` depth 8,000 (88 KB) took 15.8 s; link-only blocks are dropped as furniture by design (a document index page loses its link text); whole page each tick (H11 D3-D4).
- **Charset**: nothing reads one (§2.2 X9).
- **The text size ladder**: single part ≤ 8 MiB; multipart 8-20 MiB with no window cursor (every tick pulls and decodes the whole file: 10 MiB → 111 ticks and 1.1 GB served; 19 MiB → 211 ticks, 4.0 GB); 20-24 MiB a `transient` failure that cannot resolve; over 24 MiB `final`. It exists only as code constants and comments (H01 D4/D5, ran).
- **Profiling**: three regular expressions in `client-rendered.mjs` and `staff-directory.mjs:96` are quadratic (§2.2 X22).
- **The visitor view's accounting**: a failed render is charged its full 25 s reservation and `RENDER_FAILED` is final for every cause (§2.2 X23).
- **unpack's listing** is redone on every 100-entry tick because the entry rows do not keep method, CRC or offsets (`unpack.mjs:259-272`).

### 4.1 How to read the table

Each row is a bound a read of these kinds depends on. **Today** is the value in the code, with file:line (checked at the tip for the load-bearing ones; the rest from the shares). **Stated** names the requirement that states it, or **unstated** (also: "code constant only", "test bar only"). **Recommended** is the bound this plan proposes and what a file over it gets: always a named statement, `final`, nothing owed for ever, never silent (I3, I7). **Who:** "BOB's" is decided under P17, recorded in `rulings.md`, reported as done; "**Bob's**" changes what a member may do (K1881) and is put to him in §4.3. A bound that is only a protective limit against a hostile or broken file is BOB's.

Platform figures used (H16, H17, measured): the object has 128 MB; the plane idles at 85-86 MB as built (49 MB with the ASCII bundle, G39), leaving 42 MB (78-79 MB) to a read; a stored value is at most 2,098,176 B (record-core); `limits.cpu_ms` is unset so the platform default of 30 s of CPU a request governs; the door answers in 25 s (`ACQUIRE_BOUND_MS`); a proxy hop costs 1.0-4.0 s to first byte on a new connection and uploads run at about 8 MB/s through it (R-PROXY); an object call costs 110-160 ms; a large fetch runs at ~0.7 MB/s; workerd freezes `Date.now()` in synchronous work (R-CLOCK) and returns zeros from `process.memoryUsage()`; node timings are 1.2-1.5 × faster than the job's machine and are not workerd's. Bob's beta tiers (K4628): documents 100 MB or 5,000 pages, spreadsheets 50 MB, images 50 MB, archives 500 MB.

### 4.3 For Bob (K1881; each with an explanation, options and a recommendation, rendered when brought to him)

- **Q1 The largest document Civicsmith reads, by kind (A1, A4, A5).**
  - **Today:** a text or CSV is read in pieces up to 24 MiB (the first tick loads the file); a Word, PowerPoint or OpenDocument file is read whole up to 24 MiB; a web page up to 8 MiB; larger: kept and stated "too large", never read. Your beta tier is 100 MB.
  - **Options:** (a) keep 24 MiB and state it per kind; (b) reach 100 MB by reading in pieces from the store (text and web pages first: windows; Word and OpenDocument files by reading the zip's directory and only the parts needed); (c) raise the in-memory line (the object has 42-78 MB free after the plane's idle, so it cannot go much higher).
  - **Recommendation:** (a) now in the member's words, (b) built in this order: text, then Word/PowerPoint/OpenDocument by parts, then web pages with a streaming cleaner.
- **Q2 The most text one Word or OpenDocument file may hold (A2, A3).**
  - **Today:** 20 MiB of text whole, 32 MiB in pieces; a 40-69 KB file declaring 19 MiB already kills the object.
  - **Options:** (a) keep 32 MiB of text and add a count of paragraphs/cells/links (250,000) the file may hold; (b) 100 MB of text; (c) lower to 8 MiB.
  - **Recommendation:** (a). Over either, the file is kept and stated with the figure.
- **Q3 Pages and slides (A6, E3).**
  - **Today:** no limit except the safe view's 500 pages; a Word file has no page count.
  - **Options:** (a) 10,000 slides, no page limit for Word (bounded by Q2), the safe view stays a 500-page *view* and says so; (b) a 5,000-page safe view; (c) no limit.
  - **Recommendation:** (a). A safe view of 5,000 pages at 150 dpi is about 1.9 GB of pictures.
- **Q4 Which text encodings Civicsmith promises (C1).**
  - **Today:** UTF-8 only. A Latin-1, Windows-1252 or UTF-16 text or web page is read as damaged text and said to be complete, or refused with a wrong sentence.
  - **Options:** (a) UTF-8, UTF-16, and the page's or file's own declared charset (ISO-8859-x, Windows-125x); anything else stated; (b) UTF-8 and UTF-16 only; (c) UTF-8 only, stated.
  - **Recommendation:** (a). Old public-body pages and exports are in these.
- **Q5 Formats beyond today's (C3, B8).**
  - **Today:** RTF, legacy Word/Excel/PowerPoint (`.doc/.xls/.ppt`), email (`.eml`, `.msg`) and TAR/GZ/7z/RAR are not read, and the member is told "non-textual or too large". Your N1266 lists `.doc` and RTF as missing.
  - **Options:** (a) now tell the truth for each ("RTF is not read yet"), then add RTF and `.eml` (body decoded, attachments as members), then `.doc`, then GZ/TAR; (b) tell the truth only; (c) add them all before the beta.
  - **Recommendation:** (a).
- **Q6 What counts as the text of a document (C4, C5).**
  - **Today:** the body only. Footnotes, endnotes, headers, footers, comments, tracked deletions, text boxes, speaker notes are in the file and never searchable, and the reading says "whole". For a web page only the main region is read.
  - **Options:** (a) read every text part and mark each unit with its kind (a footnote, a comment, a deleted wording), so a member can include or exclude them in search and a citation names the kind; (b) read them but not offer them in search by default; (c) leave as is, but name what was not read.
  - **Recommendation:** (a). A footnote in a staff report is often where the dollar figure is.
- **Q7 What "as a visitor saw it" promises (A11, F4, F7).**
  - **Today:** the page's DOM at first load, not scrolled, without banners dismissed, without frames or shadow content; the daily render allowance (1,200 s) is charged the full 25 s for a failed render.
  - **Options:** (a) state exactly that in the copy's words now; bounded scroll and frames later; charge failures their real time and show the day's account; (b) add a bounded scroll now; (c) leave unstated.
  - **Recommendation:** (a).
- **Q8 The archive tier (A10, B3, B6, B7, E1).**
  - **Today:** ZIP only; 256 MiB for the file, for the expanded total and for a tree; 10,000 members; depth 3; 1 GiB and 40,000 entries a day when opened automatically. An uploaded ZIP is never opened. Your tier says "archives 500 MB".
  - **Options:** (a) a 500 MB archive *file*, expanded total ≤ 2 GiB at ratio ≤ 1,100, depth 3, 10,000 members, an uploaded ZIP opened like a fetched one, the daily budget lifted by a member act; (b) 500 MB expanded; (c) keep 256 MiB.
  - **Recommendation:** (a).
- **Q9 How long "being read" may last (D6).** As the PDF plan's B-3: 15 minutes for the largest text or Word file on a quiet copy, the member told when a large read starts. **Recommendation:** (a), shared with PDF.
- **Q10 Password-protected files (B9).**
  - **Today:** the scanner calls an encrypted ZIP, Word or PDF `clean`; Civicsmith then lets the original be opened.
  - **Options:** (a) "encrypted" is its own state: not clean, not opened without the scan's say, the reading stated "needs a password"; (b) also let the member type the password (a secret the record must never keep); (c) leave.
  - **Recommendation:** (a).
- **Q11 Read before or after the scan (E5).**
  - **Today:** a document is read, indexed and searchable whatever the scan says; only opening the original waits.
  - **Options:** (a) keep, and say it; (b) read only after a clean scan (a document waits "being scanned", but the scanner has never had signatures, FR-SCAN); (c) read at once but quarantine a found threat's text from search.
  - **Recommendation:** (a) for the alpha, (c) when the scanner has signatures.

### 4.4 The invariants (the "always", stated once; each corpus file is judged against all of them)

I1-I14 are the PDF plan's (every unit once; progress; never silent; memory; work per tick; pieces equal whole; a refusal is stated, final and finite; state loss is harmless; every path owes what it leaves; search finds the last line; the reading pages to its end; stored values bounded; contention; same bytes, same answer), read for *units* (paragraphs, slides, lines, members) instead of pages. The kinds here add:
- **I15 Declared is not allocated.** A bound is on what the read allocates and walks (objects, buffers, tokens), with ArrayBuffers counted; a file whose declared size passes and whose walk would not fit is refused *before* the walk, by name. Requirements: office-readers R12, ooxml R35 (rewritten), reading-pipeline R36.
- **I16 An encoding is named.** Every text read states the encoding it was decoded in; a decode that replaces more than the tolerance is partial with the count; nothing is `U+FFFD` and `failure: null`. Requirements: reading-pipeline R1, R32; docprofile R18.
- **I17 Every part is read or named.** A part of a file that is text is a unit; a part not read is named by kind and count in the reading and in the member's statement; the units of a document are never lost to a bound on something else (cells, links, comments). Requirements: office-readers R11; extraction R91, R97; K4571.
- **I18 Every member is accounted for.** An archive's members are each `filed`, `read`, `refused with a cause`, or `waiting for a named act`; none is `waiting` for ever; an uploaded archive is opened like a fetched one. Requirements: acquisition R38/R40.
- **I19 A copy says what it is.** A visitor view carries its fidelity ("first load, not scrolled"), a failed one carries its detail and its retry class, and a copy that did not render is not filed as the document. Requirements: capture-sources, acquisition R100.
- **I20 A deterministic failure is final, with its reason.** A throw on the file's own bytes, or a refusal by a bound, is never `transient`; a transient failure is retried under R77 until it ends or becomes final with its reason. Requirements: reading-pipeline R37; plane R77.
- **I21 A verdict that was not reached says so.** A file the scanner could not look inside (encrypted, over a limit, unrarred) is never `clean`; the member is told which. Requirements: file-scanner R3; file-safety R51.
- **I22 The statement names the cause.** The sentence for a refusal is the one for its cause, with the figure; "Read it" is offered only where it can succeed. Requirements: reading-pipeline R37; screens-inquiry; setup-words.

Corpus files are judged against I1-I22. Lines in §5 say which are particular to the file.

## 5. The corpus (K4798 (5), as K4785 (3))

### 5.1 How it is made

**One generator, seeded, that knows its own truth** (the PDF plan's design, so one runner serves both). A new `docgen.mjs` in **test-support** (`bio-plane/test/` beside `make-zip.mjs` and `pdfgen.mjs`; BOB adds the path to `modules.json`). It writes through the **one** ZIP writer, `make-zip.mjs`, which already makes hostile and conforming ZIPs byte-exactly, plus `zipBomb` and `nestedZip`, and has two external oracles (`unzip -t`, Python `zipfile`) (H20). The six independent ZIP writers in module tests (office-readers `fixtures.mjs`/`large.mjs`, odf-reader `pkg.mjs`, ooxml `zip.mjs`, doc-clean, file-safety, `xlsx-gen.mjs`'s `zipChunks`) and the eighteen inline ones are moved onto it as each module's job touches its tests (P7: the module owner does it). Two things the shared writer lacks and must gain: **ZIP64** in the streaming writer (`zipChunks` has none; needed for archives over 4 GiB declared and 65,535+ entries) and a **lazy streaming mode** so a 100 MB or 500 MB file is never in the generator's memory (H20 ran: 500 MiB-declared ZIP 2.9 s, 100 MiB RTF 0.25 s, 5,000-slide PPTX 0.8 s, 10 MiB random-text DOCX 1.9 s: generation is cheap).

Its input is a spec of these axes:
- **kind** (text, html, docx, odt, pptx, odp, rtf, eml, doc/ole, zip, a served page);
- **size axes**: bytes, decoded characters, paragraphs/slides/cells/links/tables, entries, entry-name length, nesting depth, compression ratio, requests, DOM size;
- **content axes**: part kinds present (footnote, header, comment, deleted, notes, hidden slide, text box, image-only), unit length (one 3 MB line; 25-byte lines), line endings, the encoding (UTF-8, UTF-8 BOM, UTF-16LE/BE with BOM, Latin-1, Windows-1252, a bad byte), a charset declaration (header, `<meta>`, XML declaration), markup shape (nesting depth, unterminated tags, `<main>` present/absent, link-only lists);
- **package axes**: classic vs ZIP64, central directory in physical or shuffled order, a lying directory, an encrypted member, trailing garbage, macro-enabled flavour, a polyglot prefix;
- **served-page axes** (for the loopback origin of §5.2 path W): status, content type, `Content-Encoding`, redirects, a delay, a body that never settles, a client-rendered shell and its hydrated DOM;
- **a seed**.

Its output is the bytes (or the origin's script) plus a **truth file**: each unit's expected text with its part kind (every paragraph/slide/line carries `<seed>-u<n>-k<part>` and a word from a small vocabulary with accents, ligatures, CJK, RTL and a combining mark, so a unit is checkable alone); the first, middle and last markers; the units expected *unread* with their named reason; the **expected statement** for a refusal (its code and its figures: `TOO_LARGE {size, bound}`, `UNSUPPORTED_FORMAT {kind}`, `ENCODING_UNSUPPORTED {name}`, `ENCRYPTED`, `STRUCTURE_OVER_BOUND {part, bound}`, `TOO_MANY_OBJECTS {n}`); the archive's expected member table (name, state, bytes, sha); the visitor view's expected fidelity statement. The generator is deterministic in its seed; large files are written once to `BIO_FIXTURE_CACHE` by spec hash and never committed. Real public files (the four government pages in `reading-pipeline/fixtures/`, plus N1268's fixed set once chosen) stay as they are, SHA-pinned.

**Two oracles, never the reader's own past output** (pdf-pixels R40's rule).
- The generator's truth, for every file.
- An independent reader: **LibreOffice** (`soffice --headless --convert-to txt`, present on the build machine and in the file-scanner image) for DOCX, ODT, PPTX, ODP, RTF, DOC; `unzip -t` and Python `zipfile` for every archive and package (as `make-zip` does); **Chromium** (`/opt/pw-browsers`, Playwright) for the visitor view's visible text and the HTML visible-text truth; ClamAV with EICAR for the scanner files. Where the oracle and the truth differ the generator is wrong and the file is fixed. Cases where the reader is *deliberately* stricter than LibreOffice (a tracked deletion is a unit with part kind `deleted`, not dropped) are listed in the truth file.

### 5.6 What running this costs (to be measured by the first run)

The M set is each module's own tests and adds seconds. Only the first run says the total; this plan does not guess it.
