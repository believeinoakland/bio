## 2. The state of the code (K4798 (2))

### 2.1 Module by module: mature, fragile, duplicated, legacy, untested

**Mature (tested, consistent with its requirement, and survived a probe):**
- The text window path for single-part UTF-8: `textWindowCursorOf`/`textWindowTick`, `completeRunsEnd` (`reading-pipeline/index.mjs:1665-1716`). 180 randomised windowed reads equalled the one-shot unit list; 3 MiB ASCII, CJK, CRLF and BOM texts reached their last line; a 12.6 MB text: first tick 0.5 s, later ticks 6-11 ms (H01, H11, ran).
- Units, `seq`, `para` continuity and the 128 Ki chunking for text and `doc-para` (1282, 1344); the reading's provenance and hash in slices (`readingprov.mjs`); `hooks.mjs`; text-chain's grammar (all R1-R104 named by a test; H01).
- The ZIP container walk with ZIP64, verified inflate with CRC and size, MCE branch selection, hidden-slide and speaker-note *evidence*, VBA read (`ooxml.mjs:337-618`, `docx.mjs:214`); `listArchive`/`streamMember` with range sources and bounded windows (`ooxml.mjs:1478,1758`).
- No entity expansion is possible in the OOXML or ODF readers: only the five predefined entities and numeric references are decoded; DOCTYPE is not matched (H02, H03).
- The visitor view's timeouts and "a page that never settles is an answer" (`browserrender.mjs:604-618`; capture-sources R23, R50), the best-stated part of the module (H10).
- file-scanner's refusals are *stated*: over 256 MiB `not_scanned/TOO_LARGE`; ClamAV limit hits `unknown LIMIT:<name>` (H05).
- Every in-force requirement id of text-chain (104), office-readers (31), odf-reader (48), doc-clean (10), acquisition (63), capture (60), file-safety (52) is *named* by some test (H20; naming is not coverage; H20 §3).

**Fragile (works on its builder's file, breaks on the next shape):**
- **The office entries' memory model**: bounded by *declared bytes*, allocating per paragraph, per cell and per hyperlink (`docx.mjs:354-356,629-631,1006-1017`). Memory ≈ 10 × the decoded text (H11 D1), and the ceilings (20 MiB whole, 32 MiB in pieces) were measured on 600-character random paragraphs (`large.mjs:63-94`), the cheapest shape per byte.
- **The XML tokenizer**: one regex (`TOKEN_RE`, `docx.mjs:196` = `pptx.mjs:197`; `odf.mjs:359`; a variant in `doc-clean/xml.mjs:130`) tries an attribute group from every `<`; an unterminated tag rescans to the end. Quadratic; no validity check; no yield.
- **`visibleTextOfHtml`**: per-element RegExp construction and rescans (`1023-1045`, `1090-1121`); closed nested `<div>` depth 8,000 (88 KB) took 15.8 s; link-only blocks are dropped as furniture by design (a document index page loses its link text); whole page each tick (H11 D3-D4).
- **Charset**: nothing reads one (§2.2 X9).
- **The text size ladder**: single part ≤ 8 MiB; multipart 8-20 MiB with no window cursor (every tick pulls and decodes the whole file: 10 MiB → 111 ticks and 1.1 GB served; 19 MiB → 211 ticks, 4.0 GB); 20-24 MiB a `transient` failure that cannot resolve; over 24 MiB `final`. It exists only as code constants and comments (H01 D4/D5, ran).
- **Profiling**: three regular expressions in `client-rendered.mjs` and `staff-directory.mjs:96` are quadratic (§2.2 X22).
- **The visitor view's accounting**: a failed render is charged its full 25 s reservation and `RENDER_FAILED` is final for every cause (§2.2 X23).
- **unpack's listing** is redone on every 100-entry tick because the entry rows do not keep method, CRC or offsets (`unpack.mjs:259-272`).

**Duplicated:**
- ZIP code in six places (`ooxml.mjs`, `doc-clean/package.mjs`, `case-checker/zip.mjs`, `file-scanner`, `image-cover/png.mjs`, `test-support makeZip`) and **six independent test ZIP writers plus eighteen inline ones** (H20 §2.3); `decodeEntities` three times and they differ (`docx.mjs:171`, `pptx.mjs:175` bound U+10FFFF; `ooxml.mjs:722` does not: X12); `TOKEN_RE`, `attrsOf`, `classifyUri`, `sha256Hex`, `resolveRelTarget`, `toBytes` copied between `docx.mjs` and `pptx.mjs`.
- Two text-versus-binary rules and two decodes: acquisition's `textTypeOf` (strict UTF-8, no NUL, for uploads; `index.mjs:150-160`), `profilesAsText` (type only; 135), `utf8TextOf` (reading-pipeline 2321, multipart only), the lenient decode for fetched text (`index.mjs:1902`, `reading-pipeline:2388`) (H08, H11, H12).
- The 8 MiB constant five ways with no single source (`PART`, `PROFILE_TEXT_MAX`, `ODF_DIGEST_MAX`, the keep line, subresource body max) (H09).
- Two "continuation drivers" for archives (H07).
- Two A1 range grammars in text-chain (`A:C` accepted for position, `null` for the canonical extent; H01 D13).
- reading-pipeline's R43 is two requirements (its own `wants` and pdf-reader's ranges; tests cite "R43" for both; H11).

**Legacy and stale text:**
- `docxRenumbering` (`docx.mjs:716`) and `pptxRenumbering` (`pptx.mjs:564`), "retired once it has run"; `csv.mjs` a re-export (H02).
- Legacy DOC/XLS/PPT: deliberately deferred (MEASUREMENTS.md:1280-1300), trigger "a group needing one"; Bob's own N1266 now lists them as missing from the beta.
- capture-sources R26 says the quiet-window rule is off; the code has it on at 4 s (`browserrender.mjs:125`) (H10).
- Stale lines: the diagnoses' `src/` line numbers; two cited paths (`pdf-worker/src/index.mjs`, `docprofile/readtext.mjs` for `CLASSIFY_WHOLE_MAX_CHARS`) were not where cited (H17).

**Untested (for these kinds):** a real DOCX/ODT/PPTX/ODP in *pieces* (the tests use scripted entries, `pieces-formats.test.mjs:27,77`); any office document over 1 MB through the plane; memory of any non-PDF kind (R36 is PDF only; `memory.test.mjs` is PDF; the office memory test counts JS heap only, not ArrayBuffers, `large-text.test.mjs:98-117`: ran, an embedding bomb of 252-525 MB of buffers passed under the same limit); HTML over 103 KB (the largest HTML any test reads); non-UTF-8 text or HTML (capture: no test uses a non-UTF-8 page, a redirect chain, a gzip bomb, or a DOCX or RTF served under a wrong type); RTF, email, DOC; a tick ≥ 2 that fails (R37's tests are first-tick); ZIP listing order, long names, memory, transient failure, promotion failure, upload of a ZIP, operations per tick; polyglots, UTF-16 files, files over 20 MiB, and the real renderer for file-safety; the file-scanner's real scan tests are skipped when `clamscan` is absent and no test covers a ClamAV limit, an encrypted container or RAR; polyglot macros; the visitor view with scroll, banners, iframes, shadow DOM (the fake browser returns a 60-byte page).
