## case-carriage (own requirements)

Status: in force; split from `publication` for size, BOB's (N532, K617, K1332), meaning unchanged; amended T35, T37, T39, T40, T46, T47, T51 fix round 6 (G9: R15 `copyNow`, met); every requirement met (K2004) save those the Status marks not yet met at T37, T39, T40, T46, T47; no requirement carries a `*(not yet met: T<n>)*` mark. Size (P6) about 270 lines.

Purpose: what a case edition carries at its commit, prepared for `publication`'s commit, which calls it inside its own transaction: it holds by SHA-256 the materials the signed document includes, so `public-read` carries them from the published projection alone (DEC-112); it re-reads what may have changed since preparation (a source's publishable detail, N364; accepted work, N522); (T37; DEC-180) it holds members' marks on a photo and the copy derived from the standing marks (only covered pixels); a published case carries every photo only as this copy; a mark is withdrawn, never erased (DEC-183); (T39; N806) it derives and holds the cleaned copy of each member document (supplied, not fetched; `doc-clean`), carried only as that copy, or whole when it carries no details; a fetched document is carried as captured; inside the group everything stays as it came. The refusals and every other write to the published projection are `publication`'s. It owns the two held-materials tables, the marks table, and the queue and record of member documents' copies.

Terms: a **material** is a row of the case document's `materials:` block (`case-grammar` R12); **included** when `included` is `true` (or `"true"`).

- R1 · `holdMaterials(fm, {caseId, edition, at})` writes inside the caller's transaction, opening none. For each included material it holds by SHA-256: an observation's whole inline text; a document's captured bytes (inline text, else `evidence` with the register's byte count); its extracted text (`case-grammar.extractedTextOf` over `extraction.unitsOf(sha)`, only when the index is `whole`, non-empty, untruncated, and the text's SHA-256 is the row's `text_sha`); each timestamp token the capture's home `data/provenance.json` names (`timestamp.token_file`, `attestations[].file` of kind `rfc3161`; inline else `evidence`); co-archives hold no bytes. A `files` entry of kind `attestation` carries `capture_sha` (null when two captures named that token; G47t, K4677, K4678). Photo test (K5148): provenance image type, else profile image format, else path extension. A row `included: false` whose `obscured` names a `copy` is carried as its copy only (`held` `derived`, kind `obscured`; missing: `unheld` why "the obscured copy is not held"). An `included: true` photo is not held (`unheld` `kind` `document`, why "a photo travels only as its copy"); an `included: true` member document whose R16 state is not `clean` is not held (why "a member's document travels only as its copy"). Texts written once to `published_material_texts` (`sha256`, `kind`, `text`, byte length, `at`); `[{sha, held}]` (`inline`, `evidence`, `derived`) written once per `(caseId, edition)` to `published_case_materials`. Answers `{materials, unheld, files}`: `unheld` `[{ref, kind, sha256, why}]` at most 1,000; `files` `{sha256, ref, path: "materials/<sha>", kind, bytes}` per held item. A material it cannot hold is answered, never refused. Never throws.
- R8 · (N688; K1844) An included archive member (home entry `capture.method` `"unpacked"` with a `container` block) is carried with its `container` record (canonical JSON, kind `container`), its archive (kind `archive`) and the archive's tokens (kind `attestation`), recursively to the outermost archive, each at `materials/<sha>` (the outsider checks `manifest-sha256.txt`, `unzip -p … | sha256sum`, `openssl ts -verify`). `unheld`, never refused: a container not naming the document (why "the container record does not name this document"); archive not held ("the archive is not held"); token not held. ## Used services

setup-words (`build/requirements/setup-words.md`): the interface's word list as frozen data: each word the screens show, with key, English, note, meaning and protected mark, as the design stream's `words.json` gave them at a named commit; pure data, imports, reads and writes nothing; `instance-setup` reads it for the translation workspace (its R68).

test-support (`build/requirements/test-support.md`): a test sandbox and a tally-safe standard output; in-memory ZIPs, conforming or hostile (`make-zip.mjs`); fix round 9's shared generators, ZIP64 writer, loopback origin, alarm double and job-registrar stub.

record-grammar (`build/requirements/record-grammar.md`): the record's shared grammar below every module reading or writing a document: id and type vocabulary, restricted front-matter parser, canonical JSON, actor identity, grade vocabulary, public-locator test and the one SHA-256; no store, network or clock.

record-core (`build/requirements/record-core.md`): owns the record's storage: id allocation, leases, the append-only history and manifest of every promotion, and purge; no member, capability or fence (`membership`'s), no promotion write path (`promotion`'s).
- record-core R13 · `readFile(bundleId, path)` returns the file's live content when stored inline (`{text, sha256}`), or its blob reference, never its bytes, when stored as a blob (`{blobSha, bytes, sha256}`), read from this module's own tables alone.
- record-core R14 · `readFile` returns `null` when the bundle or the path is not held. Errors: never throws.
- record-core R21 · Tables are declared once at start through `declareTable(module, entries)` with classes `purge`, `expunge`, `export`, `sight`, `derive`, `version_chain` (a missing or unknown class refused `TABLE_CLASS_MISSING`/`TABLE_CLASS_UNKNOWN`, nothing registered); `declarePurge(module, tables, {exempt?})` is its default form (`exempt` when listed, else `clear`; `expunge` `none`; `export` `admin-only`; `sight` `bundle` or `group`; `derive` `stored`; `version_chain` `false`); a table declared twice or by two modules is refused `TABLE_DECLARED`; `declaredTables()` lists them.
- record-core R46 · A declared table is a name (keyed by `bundle_id`) or `{name, keys, whole}`; under `declareTable` the same fields sit beside the classes (`clears?` too).

membership (`build/requirements/membership.md`): owns who the members are and what each may do, and projects as working groups at setup (inviting, joining, leaving, removing, visibility, participation record, sight of a project, the fence); roster reads, votes, rescue, directory and join requests are `project-roster`'s; no record integrity and no credential (`credentials`').

promotion (`build/requirements/promotion.md`): the one write path by which a bundle enters or changes in the record: compare-and-swap, append-only history, the document's own bytes as the record's word; refuses a whole promotion when any rule fails (one transaction or nothing); runs the check catalogue over a bundle or case document at ratification (the gate) and reopens a set-down inquiry; does not decide what a document must say to be true.

provenance (`build/requirements/provenance.md`): the record's trust root: the register (the one home of each captured byte sequence), the plane's acquisition receipts (which bytes from which address, by which route, when), the capture grade a route earns, and a member's firsthand observation. Hop chains and the route marker are `provenance-routes`'; timestamps and the instance's key `attestation`'s (N512). A hop attests bytes, address and time, never credibility.
- provenance R47 · `onReceipt(module, fn)` (K49; K31's pattern, promotion R39): a module registers `fn` once at start; a second registration by the same module is refused `LISTENER_DECLARED`. After each receipt write, every registered `fn` runs inside the same transaction, in the modules' total order, with `{address, address_norm, capture_sha, via, retrieval_locator, retrieved, observation}` (R14). A listener that refuses or throws does not undo the receipt; `recordReceipt`'s answer names each listener's outcome. This module calls no later module. Errors: never throws.
