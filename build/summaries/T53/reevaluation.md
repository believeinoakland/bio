## reevaluation (own requirements)

Status: in force (K102; DEC-102, K1019). Changed T34 (R34, R36; K1624, K1626), met (K2000); T50 (R37, R38; K3635), met (K3721). Size: about 700 lines move; well under 4,000.

Purpose: when something a finding rests on changes, this module says which findings are affected and how, and changes nothing itself (Content Framework §18.1; State Rules §5.4). It derives the re-evaluation obligation on read from the record's facts about each target (superseded, set down, reopened, dismissed, published at a later edition), tells a member when a newer version of a document affects a passage they reference, lets that member adopt the newer version or keep the earlier one, audits the "changed from" sentences already written against the version chain, and tells later modules when a finding's basis changed.

Terms: a dependent is a bundle with a basis leg naming the target (`inquiry_basis`). A cause is `{source, since, detail, …}`, `source` one of `supersession`, `edition`, `deferred`, `reopened`, `dismissed`, `corrected` (R27; N345), `source` (R28; N364), `attribution` (R29; DEC-102, K1019), `withdrawal` and `contested` (R30; DEC-116, N520), `cited_case_moved` (R33; DEC-101 (3)). An obligation is `{bundle_id, title, object_type, current_state, target, target_state, legs, reeval, causes, stored, strength, superseded_by?}`.

reevaluations({target, viewer}) (`op=reevaluations`; admin, member, probe):
- R1 · A target absent or unseen by the viewer is refused `NO_SUCH_BUNDLE`. With no target, every id any basis leg names is asked. Writes nothing. An imported finding reference is a target: one `accepted-work.acceptedFinding` answers null for this viewer at every edition a leg names (or no leg names) is refused `NO_SUCH_BUNDLE`; one it answers at any such edition is seen. With `accepted-work` not registered such a target is refused and the answer states `accepted_work_absent`; when its read fails, refused, stating nothing more (R20); with no target, a ref so refused is withheld whole. A machine credential is not filtered, as for a bundle. A ref is never a `deletion` cause (DEC-96 item 1; N522; K1312).
- R2 · Causes are facts about the target's own row: `supersession` when something supersedes it (`since` the latest superseder's `last_updated`; an unseen superseding id leaves `superseded_by` (key left out when none is left), the cause stands, the answer states `out_of_view: true`, R20); `deferred` or `dismissed` from its state; `reopened` when `open` with a prior state that is a disposition or `concluded`; `corrected` by R27; `edition`, per leg, when the target's latest edition (the greater of latest ratified and the document's authored edition, only above 1) exceeds the edition the leg names or the leg names none, carrying `cited_edition`, `latest_edition`, `latest_ratified_edition`. A dependent with no cause is not listed.
- R3 · A dependent the viewer may not see is withheld whole, with no count; the answer states `out_of_view: true` when one was (R20). A withdrawn leg is listed with `status: severed` and a sentence saying it supports nothing and is listed because the connection still informs a second look (DEC-70); every other leg is `confirmed` (`connections.edgeSevered`).
- R4 · Each obligation carries `reeval: {flag: true, since, source}` from its first cause; `stored`, the dependent's own authored `reeval_pending` triple (null where unstated), beside it, never merged; and `strength`, the dependent's pair per axis with its depth bound (`strength.strengthOf`), unaltered.
- R5 · Each leg is `{ord, role, grade, grade_axis, grade_source, target_edition, status, grade_authored, grade_why}`: a capture-axis letter on a leg whose target is not an inquiry is bounded by what the target earns (`inquiry.legCapped`), `grade_authored` the letter as written, `grade_why` null when not bounded. Both fields always present.
- R6 · Obligations ordered by dependent id, then target; the answer carries `count`.
