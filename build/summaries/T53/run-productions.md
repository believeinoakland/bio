Purpose: what an AI run produces, and the only way it produces it. The investigative session's one write is a suggestion: a version of a question's basis in state `suggested`, carrying its run, checked plane-side before it is written and never accepted, hidden, rejected or made current here (INVESTIGATIVE-SESSION §4, §9, §10). The EXTRACT role's production is a proposed reading of a document the record already holds, labelled machine work, making a passage citable only within the run's `mints` bound and never counted as extraction coverage (Roles §7.3). Each production names a running run the caller holds; the run, its gates and bounds are `ai-runs`'.
Terms: a run and its bounds are `ai-runs`'; `ai-runs.runFor` answers a run or null; `run-rules` R5 (`runPrincipalGate`) decides whether the caller holds it. ## Used services

record-grammar (`build/requirements/record-grammar.md`) Purpose: the shared grammar (ids, types, front-matter parser, canonical JSON, actor identity, grades, public-locator test, SHA-256); no store, network or clock.

text-chain (`build/requirements/text-chain.md`) Purpose: the transcription provenance CHAIN: what a derivation step may claim, a chain only weakens as it grows, per-region confidence, the image-region anchor of a machine reading, member attestation and its extent, the position/extent geometry bounding an extraction or citation; pure, never throws.

record-core (`build/requirements/record-core.md`) Purpose: the record's storage: id allocation, leases, append-only history and manifest, purge; no member, fence or promotion path; every storing module writes through it.
- record-core R21 · `declarePurge(module, tables, {exempt?}) → void`. A module that owns tables declares them once, at start, through `declareTable(module, entries)` (S0-3), one entry per table, each naming its classes: `purge` (`clear` or `exempt`), `expunge` (`tombstone`, a row may be removed under R79, or `none`), `export` (`yes`, `admin-only`, `never`; read by `corpus-export`), `sight` (`group`; `bundle`: the sight of the bundle its keys name; `source`: the sight of the capture or source a row cites; `owner`), `derive` (`stored` or `derived-rebuildable`, R77), `version_chain` (`true` when a change appends a version and never overwrites). A missing class or a value outside these is refused `TABLE_CLASS_MISSING` or `TABLE_CLASS_UNKNOWN`, naming table and class, registering nothing. `declarePurge` is kept as `declareTable`'s default form: each table `purge` `exempt` when listed in `exempt`, else `clear`; `expunge` `none`; `export` `admin-only`; `sight` `bundle` when keyed to a bundle, else `group`; `derive` `stored`; `version_chain` `false`; a module with a T33 job declares its tables explicitly. `purge` clears every declared table whose `purge` is `clear`; this module's own tables are declared by it. `declaredTables()` answers every declaration in order. A table declared twice, or by two modules, is `TABLE_DECLARED`.
- record-core R46 · A declared table is a name, keyed to a bundle by its `bundle_id` column when it has one, or `{name, keys: [columns], whole: "<WHERE clause>"}`: keyed by the named columns (any matching), cleared by the whole-store form only where the clause holds. (K61) Under `declareTable` the same fields sit beside the classes, `{name, keys?, whole?, clears?, purge, expunge, export, sight, derive, version_chain}`.
- record-core R32 · `transact(fn) → fn's result`: runs `fn` as one transaction over the whole store: when `fn` throws or returns a refusal (`ok:false`), every row written inside it, in any module's tables, is rolled back, and no id allocated inside it is spent. A nested call joins the outer transaction; a nested call that throws or refuses rolls back its own writes and ids (a savepoint), the outer deciding the rest. Errors: rethrows what `fn` throws, after the rollback.
