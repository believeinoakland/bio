## ai-gate (own requirements)

Status: new module, BOB's (K5457), layer 6 after `agent-worker`; every requirement not yet met (T53). Never called "conformance". Container `agent-runner`; issuer and key `ai-issuer`'s; catalogue and lifecycle `ai-catalogue`'s. The gate record (extended `ai-runs` R75) is computed here, written by `ai-runs`, handed to `run-rules` as `held.gateRecords`.

Purpose: decides, with evidence, whether an AI at a host can do Civicsmith's work, part by part: the Gate 1 suite (signed bank, scorer, thresholds) run through production's `agent-model` adapters on a stub plane with synthetic cases, a verdict per (entry, part); tiers, characterization, cost and ceiling, canaries, the bundle and its verification, the library rows. Judgement is code against known answers; a person's reading is a separate note.

Terms: a **part** is one of `ask`, `draft`, `read`, `transcribe`, `run`, `account` (`ai-catalogue` R14; `run-rules` `GATE_PART_OF`'s values); a **role** the canon's name for people (FIND, PURSUE, EXTRACT, CHECK, ask, draft, read, transcribe, standing question); an **entry** a catalogue entry; an **item** one scored case; a **run** one plan executed against one entry; a **stub plane** the in-memory synthetic plane; a **challenge** `{challenge_id, nonce, bank_version, selection_seed, issued_at, expires_at}` issued by `ai-issuer` (its R9); a **tier** `T0`, `T1`, `T2` or `T3`. Every function is pure unless it says otherwise: no state, writes nothing, never throws (a broken precondition answers `{ok: false, code}`). Parameters in capitals live in one exported table, `GATE_PARAMS`, in the suite version; none carries a number that is Bob's (AD13).

The suite and its versions:
- R1 · *(not yet met: T53)* Four independent versions `bank`, `scorer`, `thresholds`, `image` (the digest the release names), each a string; `suiteVersions()` returns all four and every result, record and bundle names all four. The bank and threshold table are signed data in their own `signatures` namespace (`NS_GATE_SUITE`, a new compiled constant distinct from every other) delivered on `ai-catalogue`'s channel; `loadSuite(signed, allowedKeys)` answers `ok: true` only when the signature verifies in that namespace.
- R2 · *(not yet met: T53)* The bank has a public part (item id, group, parts, tiers, content kind, token profile, the fixture shown) and a private part (expected answers, Civicsmith's only); `publicBank()` has no `answer`, `expected` or `states` key.
- R3 · *(not yet met: T53)* Every fixture is Civicsmith-authored and marked `synthetic: true`; `loadSuite` refuses an item without the mark (by name); a lint over fixtures finds no id of the shape a team's records, members or addresses take.
- R4 · *(not yet met: T53)* `GROUPS` names ten groups: `G0` Connect and identity, `G1` Tool use, `G2` Structured output, `G3` Grounding, `G4` Restraint, `G5` Reading, `G6` Consistency, `G7` Honest absence, `G8` Efficiency, `G9` Civic work not refused. Each item names exactly one group; each group names its scorer, a plane check (module and R id) or `suite-only`; every scorer named exists as a callable.
- R5 · *(not yet met: T53)* `GROUP_NEEDS` is the table of which groups each part needs (● needed for the verdict, ○ measured only), versioned with the bank; `G9` is needed for every part that reads records (`ask`, `draft`, `read`, `run`, `account`; not `transcribe`); every part id has a row. `rolesOf(part)` maps a part to roles; the record keeps the part name. A part whose mode does not run end to end (`investigate`, `extract`, `agent-harness` R2) is tested at the level the harness can run and carries `partial_coverage: true`.
- R6 · *(not yet met: T53)* `selectItems(publicBank, selection_seed, tier, parts)` returns item ids and order, deterministic in bank version, seed, tier and parts; a tier's list is a subset of the next tier's pool.
- R7 · *(not yet met: T53)* An item carries `uses`; `rotate(bank, usage, {ROTATE_AFTER_USES})` returns the bank with items used that many times in verified bundles moved to `retired_items` (kept for re-scoring, never selected again); one below the limit stays selectable.

Running:
- R8 · *(not yet met: T53)* A run calls a model only through `agent-model`'s `turn` by entry id, with the adapter and host profile production would use; no HTTP client, provider URL or model string here.
- R9 · *(not yet met: T53)* Each item runs on a stub plane built from the item's synthetic case and the real harness, worker loop and checks (`agent-harness`, `agent-worker`), reachable only in-process, no real record, project A only where the item says so. `runItem` returns `{outcome, exchange, stub_log}`; the stub log is every op the model's tool calls reached.
- R10 · *(not yet met: T53)* `planRun({entry, tiers, parts, nonce, suiteVersions, declared})` fixes before the first call the item list, its order, the repeats `N` per item and the sampling settings (as the role uses them in production). Never extended or cut short to reach a result except by R50's ceiling or R18's early stop, both recorded; no item added after `planRun`.
- R11 · *(not yet met: T53)* `GATE_PARAMS.REPEATS` is `{T1, T2, consistency, canary}`, four named parameters. Every repeat runs on a fresh session: no shared cache key, no provider-held state; repeats 1 gives one exchange.
- R12 · *(not yet met: T53)* An item's outcome is `pass`, `fail`, `not_run` or `not_applicable`. `not_run` is the infrastructure's (after `agent-model`'s bounded retries, BR26, a rate limit, spend or quota cap, overload, timeout or revoked key remains, or R50's ceiling stops the run); a `not_run` item leaves the denominator and counts in CH3. `fail` is the model's: a malformed answer, a failed check, a refusal where the item does not expect one. `not_applicable` is for an item needing a capability the entry declares it lacks (the verdict names the limit, R36). A served-identity or host-pin mismatch is neither: recorded as `identity_mismatch`, counted apart, and stops the run (R18).
- R13 · *(not yet met: T53)* Tiers run in order `T0`, `T1`, `T2`, `T3`; `nextTier(result)` allows the next only when the one before completed and its early stops (R18) did not fire; `T3` refused for an entry that passed no part at T2 (R17).
- R14 · *(not yet met: T53)* T0 Connect: one call per capability the entry declares (`tools`, `schema_output`, `image_input`, `streaming`), the two-turn tool round trip ("echo", then "done", generalising `agent-worker` R111 to every adapter) and, through an aggregator, a pinned request; served identity and host pin checked (BR12) and capability answers compared with the catalogue's.
- R15 · *(not yet met: T53)* T1 Screen: one pass of every group at short context, repeats `REPEATS.T1`, a cheap first look per role; no long-context or image probe for a role that does not need it.
- R16 · *(not yet met: T53)* T2 Full: all groups with repeats (R11, `REPEATS.T2`), long-context and image probes only for parts that need them (R5); this tier yields the verdict (a plan for `ask` holds no transcription item; one for `transcribe` does).
- R17 · *(not yet met: T53)* T3 Characterize: R41–R48's timed and repeated runs over days; only on an entry that passed at least one part at T2 (`passes` or `passes_with_limits`), else refused by name. A team's single run is a snapshot labelled with its window.
- R18 · *(not yet met: T53)* Early stops, each recorded with its reason: at T0 a wrong served identity, a host pin not honoured, or no tool calling where every listed role needs it stops the run; at T1 a group failing every item stops the probes depending on it.
- R19 · *(not yet met: T53)* `connectCheck(account, entry)` runs T0 only, in a team's copy, for an entry the catalogue lists: public T0 items (no challenge, no answers), no verdict, no bundle, answering `{connected, identity_ok, capability_mismatches}`; an unlisted entry answers `ok: false`.
- R20 · *(not yet met: T53)* A declared plan for an entry the catalogue does not list is `{provider, host, model, plan, scope_declared, terms_page?, price?, route}`; `checkDeclared` refuses a host that is not a DNS name over `https`, a wildcard, Civicsmith's issuer, or (unless `route` is `machine`) an address or a private name. It reaches the assistant only after a release lists it; until then only `agent-model.turn` as a declared entry with `test_flow: true` (`agent-model` R42).

Item groups (`SUITE-REQUIREMENTS.md` §4, §16):
- R21 · *(not yet met: T53)* G0 scores served identity equal to the entry (BR2, BR12), host pin, usage present with null where unstated (`agent-model` R5), stop and refusal reasons mapped (BR2, BR26); a G0 failure stops the run (R18).
- R22 · *(not yet met: T53)* G1 scores every tool call's arguments against the tool's JSON schema (suite-only; the tools of `agent-model` R17, R20, R22–R24), allow-list obedience on `stub_log` with refusals returned as tool results (`agent-worker` R37, R53, R55), a result for every call (`agent-model` R6), and the end step and close reason against the item's (`agent-harness` R1, R3).
- R23 · *(not yet met: T53)* G2 scores `checkReport` (`agent-harness` R5), `checkCondition` on the raw output (`observation-log` R2, R33), the answer tool's `ANSWER_FIELDS` (`agent-worker` R89), the plan option shape with no score or rank key (`agent-steps` R18) and the draft endings (`agent-worker` R59, R68–R70). First-try and after-one-hand-back rates are reported apart (`agent-model` R18).
- R24 · *(not yet met: T53)* G3 scores citation resolution as the collect step does it (`agent-steps` R8, R9, R36), the ask answer check (`agent-worker` R54, R113), PRESENT-after-PRESENT (`observation-log` C-22.10), and two suite-only checks: every quoted span appears in its cited passage after R25's normalisation, and no planted-token figure, name or date absent from every record appears in the output.
- R25 · *(not yet met: T53)* `normaliseQuote(text)` is the one normalisation of the quote check (Unicode compatibility form, whitespace runs to one space, typographic quotes and dashes to plain, case kept); the quote check is suite-only and does not reuse `answers.checkSentences`. A curly quote and double space pass; a changed word fails.
- R26 · *(not yet met: T53)* G4 scores, on `stub_log`, the four assertions of `agent-worker` R62 as a callable scorer, `applyJudgement` refusing `JUDGEMENT_OVERREACH` (`agent-harness` R4, R19), the ask and draft reach (`run-rules`), determination words refused at the write (`conformance` R8, R12 and `answers` R32's rules, carried as data in the signed bank, never imported). Items: injected documents, page pictures (`agent-worker` R75, R77), project-A fences urged toward B (`agent-steps` R37), determination bait.
- R27 · *(not yet met: T53)* G5 scores needle recall at `NEEDLE_DEPTHS_MIN` or more depths up to the stated window (exact match) and transcription of synthetic page images by character error rate against the fixture, `[illegible]` expected where the fixture is unreadable (`agent-worker` R73); it feeds R45. Invented text for an unreadable region fails.
- R28 · *(not yet met: T53)* G6 scores agreement of answer sets and verdicts per item across its repeats and the variance of citations (suite-only), with `agent-harness` R15 `planDedup` and `agent-steps` R11–R13 duplicate signals. Ten identical repeats give agreement 1.
- R29 · *(not yet met: T53)* G7 scores the report state against the item's (`LOOKED_ABSENT`, `LOOKED_INDETERMINATE`, `partial`; `agent-harness` R5), an absence kept only if the compose-time read confirms it (`agent-steps` R10, R32, R40), `levelEmptyHolds` over an empty scope (`run-rules` R35), ask items answered "not found" and `[illegible]` honesty. G8 records per item and part input, output, cached and reasoning tokens, calls, turns, hand-backs, verbatim resubmits, cost reported and estimated and the bounds consumed (`run-rules` `checkBound`, `ASK_BOUNDS`); measured, never pass or fail until Bob sets a threshold (no `pass` key).
- R30 · *(not yet met: T53)* (Bob 2026-10-21) G9 scores that the model does legitimate civic research without refusing it: synthetic records and ordinary tasks on elections and their officials, lobbying and campaign finance, police and court records, public benefits rules, and named public officials' recorded acts. A neutral stop reason `refusal` or `filtered` (BR2) where the task is legitimate, or an incomplete task, fails the item; kept apart from G4, where refusing a bait is right.

Scoring and verdicts:
- R31 · *(not yet met: T53)* `scoreItem({item, exchange, stub_log, scorerVersion})` is pure: the same input gives a byte-identical result, and a new scorer re-scores stored exchanges with no model call. Civicsmith's own runs and bundles use this one scorer.
- R32 · *(not yet met: T53)* Checks needing no expected answer (shape, citation resolution, allow-list, schema validity) are answer-free; `scoreAnswerFree(item, exchange, stub_log)` runs without the private bank, so the container can show preliminary figures, its result carrying `preliminary: true`. Answer-bound checks need the private part and run on Civicsmith's side only (called without it: `ok: false`).
- R33 · *(not yet met: T53)* `groupFigures(outcomes)` returns per group and part `{k, n, wilson_low, wilson_high, not_run}` with the Wilson interval at `GATE_PARAMS.CI_LEVEL`; no function returns a bare percentage; `not_run` items are outside `n`.
- R34 · *(not yet met: T53)* `GATE_THRESHOLDS` is a signed table keyed (group, part) giving `floor` and `FLOOR_COMPARES` (`rate` or `lower`); it ships empty and no number appears in code. With no table, or no floor for a needed group, every verdict is `not_yet_rated`, shown with its figures, counts and intervals. Bob sets the floors after measurement (AD13).
- R35 · *(not yet met: T53)* `partVerdict({entry, part, figures, thresholds, caps})` answers `passes` when every needed group meets its floor, `passes_with_limits` when it does with at least one limit named (R36), `not_suitable` otherwise, `not_yet_rated` per R34, plus `partial_coverage` (R5). Never one score for the model: `verdictsFor(entry)` lists one per part.
- R36 · *(not yet met: T53)* A limit is `{kind, value}`, `kind` from a closed list in the suite version (`context_depth`, `no_image_input`, `no_streaming`, `no_parallel_tools`, `output_cap`), derived from `not_applicable` outcomes and R45's effective window, never typed by a person (no image input yields `no_image_input` for `read`, none for `run`).
- R37 · *(not yet met: T53)* (D14, D11; BOB's shape) `gateRecord({entry_id, part, verdict, limits, partial_coverage, figures, suiteVersions, tier, run_ref, grade, source, at})` returns the extended test-bar record (the entry's `gate[part]` in `ai-catalogue` R14) that `ai-runs` R75 writes and `run-rules` R19/R29 read per entry, with `set`, `set_version`, `false_alarm_rate`, `graded_by` where Civicsmith's set was run (R38); without an entry id refused.
- R38 · *(not yet met: T53)* Civicsmith's runs use Civicsmith's set (`run-rules` R19's frozen matters, with the false-alarm rate) and the synthetic bank; a bundle's runs the bank only (the set travels in every copy with its answers). `itemSources(runKind)`: `bundle` bank only, `civicsmith` both; a bundle selection never holds a matter of the set.
- R39 · *(not yet met: T53)* A new bank or scorer never rewrites a stored verdict; an entry tested under an older version reads `tested_on: <bank version>` until Civicsmith's schedule re-runs it. A new threshold table re-rates stored figures (`rerate(figures, thresholds)`) with no model call; the old verdict record is unchanged.
- R40 · *(not yet met: T53)* (Bob 2026-10-21) The reasonableness reading is a note `{entry_id, part, rubric_version, sample_ids, outcome, reviewer, at, words: "gate.note.reasonableness"}` kept apart from every verdict: `partVerdict`, `groupFigures` and `gateRecord` take no note and read none. `readingNote(...)` returns it labelled with grade `REPORTED`, carrying its reviewer and date.

Characterization (each property a procedure, a stated sample, conditions stamped and a grade; unmeasured is OPEN, never inferred):
- R41 · *(not yet met: T53)* A characterization record is `{property, value, method, samples, conditions, ev}` (`ev` `{grade, source: run_ref, date}`, `ai-catalogue` R1), `conditions` region or endpoint, UTC window, adapter and profile version, entry id or declared plan, the four versions; a missing condition is refused. Re-measured (stale) when model version, host profile or adapter version changes, or on `GATE_PARAMS.REVIEW_DAYS`; no samples reads `OPEN`.
- R42 · *(not yet met: T53)* Session start: per role, cold and warm, `GATE_PARAMS.CHAR_SAMPLES` each (tokens, cost, time to first byte, cold minus warm); levers (caching, session key, batch) with and without, `GATE_PARAMS.LEVER_RUNS` runs each. Grade `REPRODUCED` (`REPORTED` from a bundle).
- R43 · *(not yet met: T53)* Turn latency: at least `GATE_PARAMS.LATENCY_TURNS_MIN` turns per entry over at least `GATE_PARAMS.LATENCY_WINDOWS_MIN` UTC windows on different days; median, 90th percentile and spread, streaming and non-streaming apart, with window and region. Short of either: `OPEN` with the shortfall.
- R44 · *(not yet met: T53)* Error behaviour over all T2 calls: rates of rate limits, overload, timeouts, truncation, refusals, malformed answers and identity mismatches, each `k of n` with interval, with G6 agreement.
- R45 · *(not yet met: T53)* Effective context window: the largest G5 depth at which recall stays at the group's floor, beside the provider's stated window with the depth curve; with no floor (R34) the curve and no effective value. It is the entry's `limits.context_effective` (`ai-catalogue` R4).
- R46 · *(not yet met: T53)* All-in cost of standard tasks: each role's standard task (a fixed T2 case through the harness on the stub plane) over `GATE_PARAMS.COST_RUNS` runs, priced at the dated catalogue price plus retries and session start, reconciled against the provider's figures where reported; a range with the difference, recorded as the entry's `standard_task_costs.by_part` (`ai-catalogue` R4). Unreconciled: grade `REPRODUCED (estimated price)`. No money reported: tokens, calls and the words `not measurable in money`.
- R47 · *(not yet met: T53)* Uptime is evidence with its period, never a bare "99.9%": SLA text `STATED`; status-page history `REPORTED`; canary probes (R52) `REPRODUCED`; `uptimeEvidence` refuses a value with no source or period.
- R48 · *(not yet met: T53)* Plan-scope limits (`STATED`) and privacy and training answers are linked from `ai-catalogue`, never re-measured; a missing answer reads `OPEN`.

Cost estimate and ceiling:
- R49 · *(not yet met: T53)* `estimateRun({entry, tiers, parts, price, declaredPrice?})` returns `{low, expected, high, unit, basis}` before any call from item token profiles × the dated catalogue price, with repeats, `GATE_PARAMS.RETRY_ALLOWANCE`, session start, the claimed cache effect and any long-context tier. An unlisted plan's price is the person's (`basis` says so); no money reported: calls, tokens and allowance, never zero or "free".
- R50 · *(not yet met: T53)* A run carries a ceiling `{spend, calls, seconds}` the person sets (default: the high estimate); `meter(usage, ceiling)` answers `ok` or `stop` from provider-reported spend, else estimated spend, with maximum output capped so one call past the ceiling is bounded by the entry's high estimate for one call, a bound the screen shows. A stop is an incomplete run with its reason, never a failed model. A ceiling below the low estimate is accepted and shown with the words `gate.warn.ceiling_low`.
- R51 · *(not yet met: T53)* `consentRecord({who, at, estimate, ceiling, plan, tiers})` returns the record the caller stores; after the run `estimateError(estimate, actual)` returns the difference for the item profiles. No record and no run start without an explicit consent value from a person (never from a script); without `who`: `ok: false`.

Canaries and lifecycle:
- R52 · *(not yet met: T53)* (AIR24; K5480) A canary is a small fixed subset of T1 and T2 items (`GATE_PARAMS.CANARY_ITEMS`, repeats `REPEATS.canary`) run on a schedule on Civicsmith's own accounts only, never through a bundle or a team's account; `canaryPlan(entry)` returns it. `canaryCompare(baseline, figures)` answers `same` or `diverged` with the groups that moved and the intervals: interval overlap, not a bare difference, decides. A canary on an entry the catalogue marks lapsed is refused, and a canary runs only when `ai-use.retestAllowed` answers `true` (`ai-use` R28: per-AI monthly cap, administrator's switch).
- R53 · *(not yet met: T53)* `lifecycleSignal` returns `{entry_id, proposed: "watch" | "lapsed", reason, evidence}` from: canary divergence (`watch`); a served model different from the entry's (`watch`); divergence between verified bundles and the baseline (`watch`); a provider's deprecation date ahead (`watch`, with the date); the teams' shared health counts (`ai-issuer` R26) whose error or refusal rate over `HEALTH_WINDOW_DAYS` lies, by interval, wholly above the T2 baseline (`watch`, reason `health`; never `lapsed`); model not found or retired from the provider (`lapsed`, BR26). It changes nothing: `ai-catalogue` applies and signs the advisory (lapsed only through Bob's decision or BR26's fact, never drift alone). A lapsed entry refuses new runs and never alters results already produced.

The bundle:
- R54 · *(not yet met: T53)* A bundle is one file of two parts. The manifest is plaintext: bundle schema version; the four suite versions; image digest as declared; nonce and challenge id; provider, host, plan and model as declared and as served; region; dates; tiers run and whether each completed; spend estimate, ceiling and actual; declared plan scope and terms page (optional); the payload files with sizes and hashes; the run's public key; the id of the Civicsmith key sealed to; `attestation` (always `null`, `agent-runner` R59); and what the payload does and does not contain. `buildManifest` returns it as `record-grammar` canonical JSON. It carries no grade (a `grade` key is refused), no payload key and no secret.
- R55 · *(not yet met: T53)* The payload holds, per call, the request body as sent (credentials removed), the response body as received, status and headers (request id, rate-limit and retry headers, served model and host), timings, usage as reported and normalised (BR22), the adapter's normalised outcome and error class, and the item id, repeat and nonce; per run, digest, versions, entry or declared plan, the challenge (unsigned), estimate, ceiling, actual, times, region, early stops, refused egress, the stub-plane log of each item (for R31's replay), and the container's preliminary figures labelled `preliminary`. Nothing else: an extra member, or one from a team's records, fails `checkPayload`.
- R56 · *(not yet met: T53)* (BOB's formats) `sealPayload(payload, sealingKey)` seals the payload to Civicsmith's published public key so nobody holding the bundle can open it; `signBundle(manifest, payloadHash, runKey)` signs the canonical manifest and payload hash with the run's key; the run also signs its image digest and the nonce. Formats documented, versioned (`bio-gate-bundle/1`), checkable with standard tools.
- R57 · *(not yet met: T53)* `readManifest(bundleBytes)` returns the manifest without any key; it never decrypts; no function opens the payload without an injected `open`.
- R58 · *(not yet met: T53)* A bundle's name is `<provider>-<model>-<date>-<first GATE_PARAMS.NAME_HASH_HEX hex of its hash>.bundle`, carrying no secret; a bundle never holds the key or any resolved secret (scrubbed from bodies, headers and error text, then scanned), any text of a team's records, any member name or address beyond a declared team id the person chose to include, or an expected answer. `scanForSecrets(payload, keyShapes, exactSecrets)` finds an exact secret (also base64 and percent-encoded) and the `key_shapes` of the catalogue's host profile (`ai-catalogue` R53).
- R59 · *(not yet met: T53)* `verifyBundle(bundle, ctx)`, `ctx` supplying `open`, `issuedNonce(id)`, `nonceUsed(id)` and `releasedDigests`, answers `rejected` when the file is unreadable, of the wrong schema, or its opened payload holds a secret; else `verified` only when every check holds: signatures good with the run key the challenge recorded; the nonce issued by Civicsmith for this declared provider and plan and not used; the image digest in `releasedDigests`; payload hashes match the manifest; request ids unique and usage consistent with the sum of calls and timings in order; else `unverified` with the failing checks listed (never "failed"). Scoring runs only on `verified`; an `unverified` one may be read, its results never shown as REPORTED.
- R60 · *(not yet met: T53)* `verifyChallenge(challenge, {bank_version, at})` checks a challenge is well-formed (a nonce of at least `GATE_PARAMS.NONCE_BITS_MIN` bits and a `selection_seed`), unexpired and for the container's bank version; its item list is then `selectItems` (R6) of its seed.

Grade and the results library:
- R61 · *(not yet met: T53)* A result is `REPRODUCED` only when Civicsmith ran the same suite versions on an account it controls; a verified team bundle is `REPORTED`. `gradeOf(source)` is the only place a grade is assigned, from the run's source (`civicsmith` or `bundle`), never a manifest field. A REPRODUCED result replaces a REPORTED one, which is kept beside it, never edited; Bob chooses reproductions; `awaitingReproduction()` lists them with verdicts.
- R62 · *(not yet met: T53)* `divergence(reported, baseline)` compares a verified bundle's figures with the entry's baseline by interval overlap, answering `same` or `diverged`; a divergence feeds R53. Test and control as R52 on bundle figures.
- R63 · *(not yet met: T53)* (K5482) `resultRow({subject_id, verdicts, speed, task_cost, grade, suiteVersions, tested_at, tested_by})` returns the row the results library publishes through `ai-catalogue`'s channel in that module's closed schema (its R43): `parts: {part: {verdict, limits}}`, `speed` (CH2), `task_cost` (CH7), `tested_by` `civicsmith` or `team`, `grade`, `suiteVersions`, `tested_at`; group figures stay in the gate record and private result (`ai-issuer` R16), reaching the library only joined (R67). No transcript, raw exchange or, without the team's `consent_ref` (`team_name`), team name. A row is built for every result `ai-issuer` recorded from a `verified` bundle (R59) or a Civicsmith run, listed or not (K5482), needing no decision of Bob's; a row never makes an AI offerable (`ai-catalogue` R54). An `unverified` bundle's result builds no row.
