## Uses: setup-words

- **R10** `WORD_ROWS` is generated by the module's own generator (`node bio-plane/src/setup-words/build.mjs`; `--check` exits non-zero on difference); `WORDS_COMMIT` is kept as the list's version (first 10 hex digits of the SHA-256 of the file's bytes). R3: `WORD_ROWS` and each row are frozen. R15: rows gain a sixth field, origin `"design"` or `"code"`; code rows come from `localize(id, en)` calls. (R10, R3, R15)
- **R11** `word(key, vars)`: the English of `key` with each `{name}` filled by `vars[name]` (String or number); throws `UNKNOWN_WORD` (naming the key) when the list lacks the key, `WORD_VAR_MISSING` (naming key and placeholder) when a placeholder's name is absent from `vars`; extra names in `vars` are ignored; never falls back to the key or an empty string. (R11)
- **R12** `hasWord(key)`: `true` exactly when the list holds `key`; tests assert each key a module reads exists without reading any English. (R12)
- **R13** A module that draws or answers member-facing words reads each sentence through `word` (a row the design stream wrote first) or `localize` (R14, a sentence written first at its use, with a fixed id); it holds no sentence otherwise; a module's tests never hold a sentence's text: they assert an id with `hasWord` or compare an answer with `word`'s or `localize`'s. A drawn-screen module reads through `word` only. (R13)
- **R14** `localize(id, en, vars)`: the list's sentence for `id` when it holds one, else `en`, placeholders filled as `word` does (`WORD_VAR_MISSING`); `id` is a dotted key (at least two segments; letters, digits, `_`, `-`), malformed throws `BAD_WORD_ID`; `id` and `en` are string literals at the call. The list always wins. (R14)
- **R19** When a value of `vars` is itself a reason `{key, vars}` the placeholder is filled with that reason's words, to any depth; an unknown inner key throws `UNKNOWN_WORD`. R4: the module has no I/O, store, registration, time or randomness. (R19, R4)
