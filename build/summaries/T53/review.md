## Used services

`record-core` (`build/requirements/record-core.md`) Purpose: owns the record's storage: id allocation, leases, the append-only history and manifest of every promotion, and purge, the tables and services no later module owns; holds no member, capability or fence (`membership`'s) and no promotion write path (`promotion`'s); every module that stores anything writes through and reads from it.

mintOpaqueId(prefix, year, tail, taken) → id or null:

- record-core R6 · Returns `<prefix>-<year>-DDDD<tail>`, DDDD four digits drawn uniformly at random (rejection sampling over a CSPRNG so 0000–9999 are equally likely), checked against both the caller's own `taken(id)` and every id this service has ever handed out; a collision draws again.
- record-core R7 · Every id returned is recorded, before it is returned, in the same transaction as the call that asked for it, never one of the service's own, so a caller whose transaction rolls back takes its drawn id back with it.
- record-core R8 · An id once recorded is never drawn again by this service, for any caller, purged store or not (D-432): its record of what has been minted is exempt from `purge`, in both forms.
- record-core R9 · Returns `null` only when 64 draws in a row all collide. Errors: never throws.

mintExhausted(prefix, extra?) → refusal (a module-level function):

- record-core R62 · The one answer when no free opaque id could be drawn (R6 answered null, R9; or R76's 64 hits): `{ok: false, reason: "MINT_EXHAUSTED", code: "MINT_EXHAUSTED", check, translation, prefix, detail}`, `prefix` the prefix asked, `detail` one fixed sentence per prefix naming the id it could not draw (a draft, a grant, …) and saying nothing was written, the same for every caller. `extra` adds caller fields, never replaces these. Every act answering this condition answers through it (`review` R27 among them); its one row is C-59.6, and review's C-87.12 gives way to it. Writes nothing, never throws. (T48) Also `WCD` and `OUTC` with their own sentences.

declarePurge(module, tables, {exempt?}) → void:

- record-core R21 · A module that owns tables declares them once, at start, through `declareTable(module, entries)` with classes `purge`, `expunge`, `export`, `sight`, `derive`, `version_chain` (missing/unknown: `TABLE_CLASS_MISSING`/`TABLE_CLASS_UNKNOWN`, nothing registered). `declarePurge(module, tables, {exempt?})` is its default form: `purge` `exempt` when listed, else `clear`; `expunge` `none`; `export` `admin-only`; `sight` `bundle` when keyed to a bundle, else `group`; `derive` `stored`; `version_chain` `false`. `purge` clears every declared `clear` table. A table declared twice or by two modules is `TABLE_DECLARED`.
- record-core R46 · A declared table is a name, keyed to a bundle by its `bundle_id` column when it has one, or `{name, keys: [columns], whole: "<WHERE clause>"}` (keyed by the named columns, cleared by the whole-store form only where the clause holds); under `declareTable` the same fields sit beside the classes.

transact(fn) → fn's result:

- record-core R32 · Runs `fn` as one transaction over the whole store: when `fn` throws or returns a refusal (`ok:false`), every row written inside it, in any module's tables, is rolled back, and no id allocated inside it is spent. A nested call joins the outer transaction; a nested call that throws or refuses rolls back its own writes and ids (a savepoint), while the outer call decides the rest. Errors: rethrows what `fn` throws, after the rollback.
