## capture-requests (own requirements)

Status: in force (K102); the requests left `capture` for this module (K58). T41 R55 and T47 R56 not yet met; every other met (K1993); T48 test-only; T51 R57, R58 met (K4214). Size (P6): about 1,050 lines.
Purpose: the AI does not capture: it requests, and the daemon captures with provenance preserved (INVESTIGATIVE-SESSION §4). This module is the request door and the drain: a run files a request (a row that carries no bytes and fetches nothing) for a public address under its question; the drain alone turns a row into a fetch, through `capture`'s trusted in-process arm, after DEC-47's conduct (legible agent, purpose, rate) and the attribution naming both principals; it reports every request's fate to the run, members and operators.
Terms: a request row: `request`, `run`, `target` (the inquiry), `address`, `host`, `purpose`, `ua_mode`, `principal_plane`, `principal_claude`, `state`, `code`, `detail`, `capture_sha`, `attempts`, `requested_at`, `updated`, `expires`, `captured_at`, `lead_inquiry`, `run_woken_at`, `render`, `sweep` (R45), `co_archive` (R50). State `requested`, `draining`, `captured`, `refused`, `expired`; the last three terminal. Caller and viewer are control-plane stamps, never body fields. A refusal is `{ok: false, reason, code, check, translation, detail}`, never a throw.

`captureRequest(args, {viewer, caller})` (`op=capturerequest`); `args` `run`, `address`, `target`, `lead_inquiry` (alias `lead`), `purpose`, `ua_mode` (default `civicsmith`; `civicos` the same), `render`:
- R1 · Run absent, unseen (run sight) or not `running`: `CAPTURE_REQUEST_NO_RUN` (C-28.1), alike but for the id; caller not principal: `runPrincipalGate`'s `AI_RUN_NOT_PRINCIPAL` (C-22.12) relayed field by field. Sight, then position, then status.
- R2 · The address must pass `isPublicHttpsLocator` with a readable host, else `CAPTURE_REQUEST_NOT_PUBLIC` (C-28.2); host lower-cased and stored; no credentials unless supplied for the scope (R41, K103). (T35) Then judged by R49 before anything is written.
- R3 · `target` a visible inquiry, else `CAPTURE_REQUEST_NOT_AN_INQUIRY` (C-28.3); `lead_inquiry` another visible inquiry (`CAPTURE_REQUEST_LEAD_NOT_AN_INQUIRY`, C-28.14), not the target (`CAPTURE_REQUEST_LEAD_IS_THE_TARGET`, C-28.15).
- R4 · Any non-empty `capture_sha`, `sha256`, `bytes`, `content`, `provenance_chain`, `via`, `retrieved`: `CAPTURE_REQUEST_CARRIES_A_CAPTURE` (C-28.4), naming them.
- R5 · `render` absent/`null`/`false` the served document, `true` the rendered page, else `CAPTURE_REQUEST_RENDER_MALFORMED` (C-28.16).
- R6 · Idempotent on (run, address, render): with a row in `requested`, `draining` or `captured` for that key, the answer is that row's `request`, `target`, `purpose`, `ua_mode`, `lead_inquiry`, `render`, `state` and principals, with `requested: false, already: true`, and nothing is written. Otherwise one row is written in `requested` with `attempts` 0, `requested_at` and `updated` now, `expires` now + 24 h, and answered with `requested: true, already: false` and the values as written (never as sent). `now` is the caller's stated instant when an in-process caller gives `at` (a test, the scheduler's replay), else this module's clock; `expires` is that instant + 24 h, so each request's expiry follows its own `at`. The op never reads `at` from a body.
- R7 · Id minted here (`CR-<instant>-<random>`); never throws.
- R8 · `principal_plane` the caller stamp, `principal_claude` the run's; `purpose`, `ua_mode` recorded as sent, judged at the drain.
- R9 · The door makes no outbound request and runs no conduct or attribution check.
- R10 · `captureRequestAttribution(row)`, the one composer: both principals non-empty, else `CAPTURE_ATTRIBUTION_ONE_PRINCIPAL` naming which is present; success `{ok: true, actor: "token:daemon", machine_attributed: true, at_the_request_of: {run, inquiry}, principals: {plane, claude}, statement}`, statement "the daemon captured this, at the investigative session's request (run <run>), under <plane>, paid by <claude>"; used by every surface stating attribution (R15, R25, R26's notifications).

`captureRequestDrain({limit, actor, now})` → `{configured, actor, at, drained, captured[], refused[], held[], expired[], remaining}`, the sole fetcher (`op=capturerequestdrain`, the scheduler's consumer):
- R11 · Inert (`configured: false`, pending 0) unless unattended capture is configured; not re-entrant (`busy: true`).
- R12 · A tick acts on at most 10 rows (`limit` lowers it, never raises it). It first releases render rows past their `expires` (R20), before selecting, so an expired row never takes a slot; then takes `requested` rows oldest first (`requested_at`, then `request`). Given the scheduler's rank (`drain({…, rank})`, scheduler R10), the tick reads at most ten times its batch of `requested` rows, oldest first, and takes its batch in the rank's order, each offered as `{kind: "request", id, waitingSince: requested_at, cadenceMs}`. The rank itself puts work waiting longer than one cadence (`cadenceMs`) first. Without `rank`, it takes oldest first.
- R13 · A refusal writes `code`, `detail`, `attempts + 1`, `refused` if terminal else stays `requested`; every refusal and hold is logged `LOOKED_INDETERMINATE` for the address, `governed` exactly when the reason is this instance's pacing or renderer.
- R14 · Conduct, first failure decides: attribution (R10, terminal, C-28.11); then R49 again (terminal); `purpose` in `investigate`, `acquire` else `CAPTURE_CONDUCT_NO_PURPOSE` (terminal, C-28.8); `ua_mode` in `civicsmith`, `member-browser` (`civicos` read as `civicsmith`) else `CAPTURE_CONDUCT_UA_ILLEGIBLE` (terminal, C-28.6); `member-browser` needs the target's recorded agent (`memberUserAgent`) else `CAPTURE_CONDUCT_UA_UNRECORDED` (terminal, C-28.7); `civicsmithUserAgent(...)` must pass `userAgentIsLegible` else C-28.6; host in cool-off (`isHeld`) `CAPTURE_CONDUCT_HOST_HELD` (held, C-28.9); host already fetched this tick `CAPTURE_CONDUCT_TICK_SPENT` (held, C-28.10). No `robots.txt` (BOB-3).
- R15 · A passing row goes `draining` (`attempts + 1`), counts one host fetch, and fires `capture`'s in-process arm with only address, purpose, agent (`member-browser`), render, R41's credential, `heldSha` (R39), `origin` `{matched_sweep, deeming_actor}` and `co_archive` (R50). Filed: `captured`, `code` null, `detail` the statement, `capture_sha`, `captured_at`; log `PRESENT` (`result_kind` `capture`); answer `{request, address, sha, grade, attribution}`.
- R16 · Only this drain fetches for a request; `op=acquire` refuses `via: "capture-request"` (`CAPTURE_NOT_DRAINING`, C-28.13).
- R17 · A render refused before fetching (C-83.3, .4, .5, .8) holds the row `requested` under that code, gives the slot back, logs `governed` `render-deferred`, answered in `held` with `render: {state, content: "undetermined"}` (`waiting` for C-83.8, else `deferred`); the shell is never filed.
- R18 · After fetching: `RENDER_NOT_A_PAGE` (C-83.6) terminal; `RENDER_FAILED` (C-83.7) holds; both spend the slot.
- R19 · Any other failure holds the row `requested` under a code catalogued in C-28 with its check and translation, appended `LOOKED_INDETERMINATE`, not governed, and answered in `held`. Every code this module writes to a row is catalogued in C-28, C-83 or C-108.
- R20 · Every non-terminal row past its `expires`, plain or render, is released: state `expired`, its last code kept, `detail` saying what it was held under and that nothing was filed, appended `LOOKED_INDETERMINATE` (for a render, `governed`, condition `render-deferred`), answered in `expired` (a render with `render: {state: "expired", content: "undetermined"}`), and never fetched. At most one tick's batch is released per tick.
- R21 · A row left `draining` returns to `requested` next tick, or is released by R20 past `expires`.
- R22 · `remaining` is the `requested` count after the tick.
- R38 · A requested capture is promoted at `collected`, never higher, `origin: sweep`, run and both principals deeming, the target as matched scope (DEC-47; K102).
- R45 · (K1036, K1099) A request may name a sweep (`"<bundle>#<id>"`): filed with `matched_sweep` and the run deeming only when `link-sweep`'s once-registered `registerSweepScope(module, fn)` check answers `{ok: true, scope}` (else refused with optional `reason` `unknown`, `unratified`, `held`, `out-of-scope`; none registered, refused): `CAPTURE_SWEEP_OUT_OF_SCOPE` (C-28.19, terminal).
- R39 · One fetch per version of an address (K103 (1)): a held address is fetched conditionally; unchanged or identical bytes file nothing new; the row becomes `captured` with the held digest and the answer says so.

## Used services

record-grammar (`build/requirements/record-grammar.md`) Purpose: the shared grammar (ids, types, front matter, canonical JSON, actors, grades, public-locator test, SHA-256); no store, network or clock.

record-core (`build/requirements/record-core.md`) Purpose: the record's storage: id allocation, leases, append-only history and manifest, purge; no member, fence or promotion path.
- record-core R21, R46 · `declarePurge(module, tables, {exempt?})`, the default form of `declareTable(module, entries)`: each entry names `purge` (`clear`/`exempt`), `expunge` (`tombstone`/`none`), `export` (`yes`/`admin-only`/`never`), `sight` (`group`/`bundle`/`source`/`owner`), `derive`, `version_chain`; missing or unknown class `TABLE_CLASS_MISSING`/`TABLE_CLASS_UNKNOWN`; declared twice `TABLE_DECLARED`; defaults: `exempt` if listed else `clear`, `expunge` `none`, `export` `admin-only`, `sight` `bundle` when keyed else `group`. A table is a name keyed by `bundle_id`, or `{name, keys, whole?, clears?, …classes}`.
- record-core R32 · `transact(fn)`: one transaction over the whole store; a throw or `ok:false` rolls back every row and spends no id; nested calls are savepoints; rethrows after rollback.
- record-core R34, R35 · `bundleInfo(bundleId)` answers `{id, type, title, project}` (project as the last commit named, null for none) or null; `listBundles({project, after, limit})` ids in order with `cursor`; neither throws.

promotion (`build/requirements/promotion.md`) Purpose: the one write path into the record (compare-and-swap, append-only history, whole promotion refused on any failing rule); runs the catalogue at ratification; reopens a set-down inquiry.

membership (`build/requirements/membership.md`) Purpose: members and what each may do; projects, their visibility, what a caller may see and the fence for acting; no record integrity, no credential.

runtime-limits (`build/requirements/runtime-limits.md`) Purpose: runtime facts a Worker cannot get otherwise: capture CPU by counts and the probed ceiling; token hygiene and which instance credential unattended work spends; reader ceilings and the byte ledger; no store, no network.

host-governor (`build/requirements/host-governor.md`) Purpose: paces outbound fetches per host (token bucket and cool-off), learning capacity only by refusal; its refusal is a fact about this instance, never the source.

capture-sources (`build/requirements/capture-sources.md`) Purpose: source-specific halves of capture with no store (rendered pages, web archives, Google Drive), and the credentials members supply for a refused capture (K103), held encrypted, its one store.
- capture-sources R55 · `credentialSupply({kind, host, secret, scope, project, by})` → `{ok: true, credential}` (the listing entry, never the secret); `host` exact, lower-cased. Refusals in order, nothing written: `CAPTURE_CREDENTIAL_NOT_A_MEMBER`, `_BAD_KIND`, `_BAD_HOST`, `_OWN_HOST` (the group's own hosts; F16, K1881), `_BAD_SCOPE`, `_NO_PROJECT`, `_NO_SECRET`, `_NOT_PERMITTED` (R63), `_NO_KEY` (never stored in clear); `CAPTURE_CREDENTIAL_SUPPLY_FAILED` (C-105.10) on an encrypt or write failure, detail never the error's words.
- capture-sources R56 · `credentialsForFetch({host, principalPlane, target})` → `{credentials, reason}`: at most one unwithdrawn credential for that exact host: `member` only when supplied by `principalPlane`, `project` only when `bundleInfo(target).project` is its project, `group` any; narrowest scope, then newest. Entry `{credential, kind, secret, supplied_by, scope, project}`; the caller records its use in provenance and marks the capture not reproducible. `[]` with a `reason` when none admitted, no key, an undecryptable secret, or an own host. Never throws.
