## admission (own requirements)

### Public

Purpose (§ Public Purpose): who may call an op, judged before it runs: namespace, class, an agent credential's confinement and task scope, a session's reach and capabilities, and the bearer fences. It decides whether a caller is admitted and as whom and answers a refusal that names why; it never runs or answers an op.

Terms (§ Provides): namespaces are `bio` and `scratch`; a bearer is any caller not arriving by a session; "is refused" means this module's gate answers with the code's `check` and `translation` from its row (R14), the door at the status named, and nothing is read or written.

Namespaces, before any credential is judged (`namespaceGate`, `confinedNamespaceGate`, `pinnedNamespaceGate`)
- **R1** A `store=` present and not exactly `bio` or `scratch` is refused 400 `NAMESPACE_UNKNOWN` (C-78.1), naming the namespaces. Every caller and the page at `/`.
- **R2** An `ai` credential minted confined to `scratch`: a named `store=` other than `scratch` is refused 403 `NAMESPACE_CONFINED` (C-78.3); an absent one is set to `scratch`.
- **R3** A public op that answers only from `bio` refuses `store=scratch` with 400 `NAMESPACE_PINNED` (C-78.2). Public ops that address scratch are declared: `invitelook`, `enroll`, `instancegroup`, `groupidentity`, `websiteinvite`, `joinlinkinvite`, `groupdescription`, and (T40; N797; K2394) `handlecheck` (reads an invitation as `invitelook` does); every other public op is pinned.
- **R4** Landing: `probe` in `scratch` (a named other namespace refused 403 `SCOPE_REFUSED`, C-38.6); every other class in `scratch` when `store=scratch` is given, else `bio`. Every forwarded answer carries `store`.

Authentication (`classify`, the agent credential's and the session's resolution)
- **R5** A presented credential (R20: the `Authorization` header's, else the body's `token`) equal to the `ADMIN_TOKEN`, `MEMBER_TOKEN`, `PROBE_TOKEN` or `DAEMON_TOKEN` binding (checked in that order) gives that class only while the binding is live: set, and not a value ever published (`runtime-limits.liveToken`). Any other credential gives no binding class. (T35; F12) Comparison is of the SHA-256 digests, constant time, and all four bindings are compared for every presented credential, so the time tells neither whether a binding matched, nor which, nor where two values first differ. (T36) No binding class `member`: a credential equal to a live `MEMBER_TOKEN` gives no class and is refused 401 `MEMBER_TOKEN_RETIRED` (C-38.11), whose sentence says the shared member key is retired and a member signs in with their own password; nothing read or written. With no `MEMBER_TOKEN` bound a value once held is answered as any unknown credential (R7). The refusal is counted as R22 counts kind `credential`.
- **R6** A presented credential (R20) shaped `aik-<64 hex>` is resolved once per request against `bio`'s credential rows. Known: class `ai` with principal, scope and confinement (refused by R10 when revoked or expired). A 64-hex credential is resolved as a session through `credentials.session` (its R5) against `bio`; the `aik-` lookup is `credentials.aiCredentialLook` (its R15). Each lookup carries the credential to the store in a request body or as its SHA-256, never in the address (R20). A store that does not answer either lookup is answered 502 `STORE_DID_NOT_ANSWER`, never a statement about the caller.
- **R7** A caller with no class is refused 401 `NOT_AUTHENTICATED` (C-38.1).
