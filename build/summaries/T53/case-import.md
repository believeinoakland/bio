## case-import (own requirements)

Status: in force, a new product module placed by BOB (K1256, K1257); folded at T28 (N520, DEC-96); N534 reviewed (K1369). Changed T34 (R5), T41 (R22, R23), T46 (R4: `group_fields`), T47 (R17 wording; R24), T48 (R16 wording), T50 (R25, R26), T51 (R27–R33; R31 `title`, K4259; the withdraw act tested at R7). R34–R36 new at T53, not yet met. Size (P6): about 1,600–2,300 lines; acceptance split out if it grows.

Purpose: a Civicsmith copy imports another group's case file into a new, read-only project; confirms each finding by recreating it from the case file and shows each against the importing group's own bar. The group may accept an edition, by a reasoned act, for the findings that recreated, and flag and clear issues on it. Recreating is not endorsing. (DEC-112 (6); DEC-96; Publication §5C)

Terms (compressed): an **import** is the read-only project an imported case lands in, one per source group, case and lens (K1134 reading 4; DEC-46 (3)); its id is the SHA-256 of canonical JSON `{group, case, lens}` (`group` the manifest's slug, `lens` the bias manifest's fingerprint the signed document states). An **imported edition** is one case edition held in an import; editions sit side by side, a later never replaces an earlier. A **result** is `case-checker`'s (its R11). Every refusal names `reason` and carries its catalogue row (R14). The words a member sees (origin marks, the not-endorsing statement) are the UX stream's, never decided here. Watch, docket read, entry seen, regrade, rerun, pairing and publisher move as the source defines them (R17–R20, R27–R30).

**importCaseFile({parts, by, viewer})** (`op=caseimport`; member session; mutating)
- R1 · Refusals, in order, each writing nothing: an empty or machine `by`, or an operator token, is `MACHINE_CANNOT_IMPORT`; a `viewer` who is not an active member of this group is `IMPORT_NOT_A_MEMBER`; parts whose manifest fails `case-grammar.caseFileManifestCheck` (its R13) are `IMPORT_NOT_A_CASE_FILE`, naming each departure; a part over the part bound (`public-read` R5's 64 MiB) is `IMPORT_PART_TOO_LARGE`; an edition already held in this import with different bytes (another manifest SHA-256) is `IMPORT_EDITION_DIFFERS`, naming both hashes (an edition is immutable, so the difference is reported, never resolved). The same edition with the same bytes answers `existed: true`. Otherwise the act creates the import if absent and stores every file of the case file by its SHA-256; records the edition with its source group, case, edition, lens, `by` and instant; then runs `case-checker.checkCaseFile` and records each finding's result, with the checker's versions (R3). (DEC-112 (6); Publication §5C; K1134 reading 4) [amended by R34; R-111 concerns "naming each departure"]
- R2 · Read-only: nothing an import holds is a record bundle; no act edits, promotes, ratifies or publishes it; no act changes an imported file. The only later writes are R5's completion, R6's acceptance and withdrawal, and R8's flags.
- R3 · Recreation is recorded per finding: the result, what is missing, what differs, the recomputed pair, and the checker's grading and checks versions; and per calculation the case carries, as R21 records it. It is recomputed only by R5. (DEC-112 (6))
- R21 · (K1448) At import and completion each calculation the case carries (`case-grammar` R18) is recreated, never trusted: `calc-grammar.evaluate` over the carried inputs, each checked against its stated SHA-256; recorded `recreated`, `differs` (each result, source's value and recomputed) or `not_recreated` (input missing or differing, or method version not held, each named). The source's results are only the source's statement: no `CALC-`, money fact or record row written from them.

## Used services

record-grammar (`build/requirements/record-grammar.md`): the record's shared grammar below every module (ids, types, front-matter parser, canonical JSON, actor identity, grades, public-locator test, SHA-256); no store, network or clock.

record-core (`build/requirements/record-core.md`): owns the record's storage: id allocation, leases, the append-only history and manifest of every promotion, and purge; no member, capability, fence or promotion write path; every storing module writes through and reads from it.
- record-core R21 · **declarePurge(module, tables, {exempt?})**: `declareTable`'s default form, declared once at start: each table `purge` `exempt` when listed else `clear`, `expunge` `none`, `export` `admin-only`, `sight` `bundle` when keyed to a bundle else `group`, `derive` `stored`, `version_chain` `false`; class faults `TABLE_CLASS_MISSING`/`TABLE_CLASS_UNKNOWN`; declared twice `TABLE_DECLARED`; `purge` clears every `clear` table.
- record-core R46 · A declared table is a name keyed by `bundle_id`, or `{name, keys: [columns], whole: "<WHERE clause>"}`.
- record-core R32 · **transact(fn)**: one transaction over the whole store; a throw or refusal (`ok:false`) rolls back every row in any module's tables and spends no allocated id; a nested call joins as a savepoint; rethrows after rollback.
- record-core R47 · **stampInstant(precision, when?)**: UTC ISO 8601, `"second"` `YYYY-MM-DDTHH:MM:SSZ`, `"millisecond"` `YYYY-MM-DDTHH:MM:SS.sssZ`; another precision throws, naming it.
- record-core R48 · `instantOrder(a, b)` compares instants as instants, never strings; NaN when unreadable; never throws.

membership (`build/requirements/membership.md`): who the members are and what each may do; projects at setup, sight and the fence; roster reads are `project-roster`'s; no record integrity or credential.
- membership R78 · **noSuchProject(projectId, extra?) → refusal** (module-level): the one answer when no project answers to `projectId` or the caller's sight is not `FULL` (after R77's existence answer), answered as absent: `{ok: false, reason: "NO_SUCH_PROJECT", code: "NO_SUCH_PROJECT", check, translation, project, detail}`, `project` as asked (null when none), `detail` one fixed sentence for every caller, `check` and `translation` its row's; `extra` adds fields, never replacing these. Every module answers this condition through it (one minting site, one row, this module's); writes nothing, never throws.

strength (`build/requirements/strength.md`): strength as a derived pair (weakest capture, weakest connection) with testimony beside, never composed (DEC-21, DEC-44); the bar a project declares and the group default (DEC-17, DEC-72).

case-grammar (`build/requirements/case-grammar.md`): the case document's grammar, one spelling: formats and predicates, `/5` blocks, tension section, locators, attribution run text, signed citations, the "rests on" edge set; text in, values out.

case-checker (`build/requirements/case-checker.md`): the one checker: anybody can check a published case and recreate its findings without a copy (DEC-112 (3); Publication §5C); a pure function Civicsmith runs on import, from the same check code, and a standalone offline program. Recreating shows a case intact and consistent, not true.
