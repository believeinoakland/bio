# file-safety — requirements

**Status** · In force: a new product module (layer 3, directly after `capture`), by Bob's K1913, K1928, K1929, K1939 and K1949 (with DEC-173), packaged by BOB (K2008, K2063), entering at T36's opening; every requirement not yet met (T36). Last changed T37 (T37-8: R12, R15, R21, R27, R28, R31, R33, R35, R36 amended; R39–R41 new; K2099, K2129, K2130, K2153, K2155, K2160, K2161).

**Size (P6).** About 1,500–2,200 lines with tests for R1–R26; the security tools, safe copy, reputation and forwarding (R27–R37) add about 800–1,200.

## Public

### Purpose

Keeps every captured file safe to open without touching its bytes, digest or grade: verdict notes beside each capture naming tool, engine and version; a per-file threat grade from its source and contents (an archive's from its members); a safe view, and a safe copy when the group adds a safe-copy maker; a scan hold on a "found" verdict released by two members or a second, different engine; the weekly re-scan and one before first opening; a member's deeper check, or the member's confirmed warnings (DEC-173), before a high-risk original opens. It holds which security tools the group enabled, with their stated handling, and forwards security counts to the group's log tool. It keeps no record of who opened which file (K1888, K1890, K1892, K1929).

### Provides

**Terms.** A **file** is one capture the record holds, named by its digest. A **note** is `{note_id, kind, tool, engine, engine_version, signatures, scanned_at, result, findings, reason?, checks?, vendor_ref?}`, `kind` one of `scan`, `deeper`, `sandbox`, `reputation`, `copy`, the other fields `file-scanner`'s verdict (its Terms); a `reputation` note's `result` is `listed` or `not_listed`, with `findings` the categories. The **threat** is `"low"` or `"high"`. A **tool** is one outside tool the group enabled: `{tool_id, provider_id, kinds, use, state, handling, handling_digest, monthly_limit, added_by, added_at, tested_at, off_reason}`. Settings come from `record-core`; the scanner is `FILE_SCANNER` (`file-scanner`).

**Intake**
- **R1** (K1888 (2)) Every acquisition receipt (`provenance.onReceipt`) puts its capture in the scan queue and, when it has a safe-view route (R11), the render queue: a direct, Drive, archive or render fetch, a pulled knock, and each member of an unpacked archive, which is its own capture (K1852 (1), K1882). One row per digest. A receipt carrying a reputation answer (`reputation`, which `acquisition` records on the receipt) adds a `reputation` note (R34). Nothing here delays, changes or refuses the capture or its answer, and a failure here never fails the receipt.

**Notes**
- **R2** `verdictNotes({captureSha, viewer})` → `{ok:true, notes}` oldest first, or `FILE_NOT_HELD`, or membership's sight refusal when the viewer may not see the capture. Here and wherever this module names the sight refusal, a capture the viewer may not see answers exactly as an absent one, `FILE_NOT_HELD`, so no answer tells a hidden capture from one never held (DEC-36; as acquisition's `ARCHIVE_NOT_HELD`; K2098). Every refusal code this module raises is its own: none shares a code another module's row holds (K231; K2103: `FILE_NOT_HELD`, `MACHINE_CANNOT_RELEASE_HOLD`, `HOLD_NO_REASON` in place of sources', ratification's and progressions' codes).
- **R3** Notes are append-only: none is changed or removed but by the purge of the capture's bundle (R25). A re-scan adds a note. `unknown`, `suspicious` and `not_scanned` are never read as `clean` by any service here.

**Scanning**
- **R4** `scanBatch({limit, at})` (`op=scanbatch`; the scheduler's daily wake, an administrator or daemon) sends the due files, oldest due first, at most `limit` and `SCAN_BATCH_MAX`, to `/scan` in one request, and writes one note per verdict. Due: never scanned, or the newest ClamAV note older than `RESCAN_INTERVAL_MS` (7 days; K1888 (4)'s weekly re-scan). (K1949) Each tool `on` with `use:"routine"` and kind `scan` also scans each due file (`/provider/scan`), one note per verdict, within its monthly limit. Answer `{ok:true, scanned, found, not_scanned, remaining}`. With no scanner bound: `{ok:false, code:"SCANNER_ABSENT"}` and no note (K1928 Q4).
- **R5** `scanStatus({viewer})` (administrators) → `{scanner, renderer, signatures_age_ms, queued, overdue, held, tools:[{tool_id, state, used_this_month, monthly_limit}], reputation_list_age_ms}`: `overdue` counts files due for more than a day, so a lag is stated, never silent.

**The threat grade** (K1888 (3), K1890, K1928 Q1, K1929 (Q1), S13)
- **R6** `threatOf({captureSha, viewer})` → `{ok:true, threat, reasons, source, format, active, scan_hold, latest_scan, latest_deeper, safe_view, safe_copy, archive}`, computed at the call from the capture's receipts, its reader's `active` list, its notes and, for an archive, `acquisition.archiveList`; never stored as a fact of the capture. Each reason is `{code, translation}` from this module's table (R24), the member words DEC-169 shows. **A file other than an archive** is `low` only when every condition holds: some receipt's route is a fetch by this copy (direct, Drive, render, web archive) or the file is a member cut from an archive whose own grade's source condition holds (K1949: any one such receipt suffices); the format is one with an `active` list (`pdf-reader` R36, `office-readers` R32–R33, `odf-reader` R47) and it is `[]`, or the format is an image or plain text, or HTML (by source alone); it is not encrypted; it is under no scan hold; it has no `reputation` note with `result:"listed"` (S13). **An archive** (`format` `zip`) is `low` only when every condition holds (K1929 (Q1)): the source condition above; `archiveList` answers `opened:true`, `refused:null`, no `waiting` entry and no `not_filed` entry; it has no `link` entry (K1949); every `filed` and `already_held` entry's file is `low` by this rule (a nested archive by this same archive rule); it is under no scan hold and has no listed reputation note. Otherwise `high`, with each reason named: `source_not_fetched`, `active:<kind>` (one per kind), `unread`, `encrypted`, `format_unchecked`, `scan_hold`, `bad_reputation`, and for an archive `archive_not_opened`, `archive_refused` (with the refusal's code), `archive_waiting`, `archive_entry_not_filed` (with the count), `archive_link`, `archive_member_high` (with the count of members graded high), `archive_cycle` (a digest met twice on one path down the tree, which ends that path as high). `archive` is `{opened, entries, members_low, members_high}` for an archive, else `null`.
- **R7** The same capture and notes always give the same answer; no note or grade changes the capture's grade letter (`provenance.captureGrade`), its state or its provenance document.

**Opening the original** (one click from the safe view, K1888 (4); DEC-173)
- **R8** `openOriginal({captureSha, viewer, override, warned})` (`op=openoriginal`; served also as `op=openwithwarning`, with `warned`) answers the capture's bytes exactly as `capture.getCapture` serves them, digest header equal to `captureSha`, or the first refusal that applies: `FILE_NOT_HELD`; the sight refusal; `SCAN_HOLD` (R16); then, for a `low` file with no ClamAV `clean` note newer than `RESCAN_INTERVAL_MS`, an on-demand scan first (the scan before first opening): `found` places the hold and answers `SCAN_HOLD`, `not_scanned` or `unknown` answers `NOT_SCANNED` with the reason (K1928 Q4: with no scanner bound the bytes open, stated `not_scanned:"SCANNER_ABSENT"`), and a scan not finished within the call answers `SCAN_PENDING`; for a `high` file, in order: `SCAN_HOLD` (R16; no path opens a held file); the deeper path: with `override` `true`, a deeper check (R13–R14) that ended `clean` less than `DEEPER_CHECK_FRESH_MS` (24 h) ago with no `found` note since opens it to any member who may see it; the warned path (DEC-173): `warned` must be exactly `{own_device: true, no_macros: true}`, else `WARNING_NOT_CONFIRMED`, and the original opens when no hold applies and a ClamAV `clean` note is newer than `RESCAN_INTERVAL_MS`; else the scan before first opening runs on demand, a scan not finished within the call answering `SCAN_PENDING`, a `found` placing the hold and answering `SCAN_HOLD`, and a `clean` verdict opening it; a scan that cannot run (no scanner bound, or `not_scanned` or `unknown`) answers `SCAN_STALE` when the file has a ClamAV `clean` note older than `RESCAN_INTERVAL_MS` (a week), else `NOT_SCANNED` with the reason; K1928 Q4's opening with no scanner bound is not extended to a `high` file; a `high` file reached by neither path answers `SAFE_VIEW_ONLY`.
- **R9** `originalState({captureSha, viewer})` → `{may_open, path, why}`: what R8 would answer now, without opening, scanning or serving anything (the warning before opening, the screens' share). `path` is the way the original opens: `plain` (a `low` file), `deeper` (a `high` file with a fresh `clean` deeper check, R8's deeper path, which R8 tries first), `warned` (a `high` file R8's warned path opens once the member gives both confirmations), or `null` when no path opens it (a scan hold, or a `high` file with neither); `why` names the refusal R8 would give. DEC-169 and DEC-173 draw "Open the original" for a `high` file only when `may_open` is true, on the warned path behind the two confirmations.
- **R10** (K1892; DEC-173 (4)) No record of who opened, downloaded or asked about which file is kept: no table, note, counter or log line of this module holds a member's identity beside a file for R2, R6, R8, R9, R11, R12, R13 or R33, and no record R35 forwards names a file. The confirmations (`warned`'s statements, R8) are never stored: nothing keeps who confirmed, or that anyone did. A test opens files as two members, one by the warned path, and finds neither member's id nor any confirmation in any row this module wrote, any line it logged or any record it forwarded.

**The safe view** (K1888 (1), (4))
- **R11** `safeView({captureSha, viewer})` (`op=safeview`) → by route: PDFs and office documents (Word, presentations, ODF text) `{kind:"pdf", derived:true, of, sha256, pages, source_pages, truncated, original}`, the image-only PDF of `file-scanner` R7; spreadsheets (OOXML and its twins, ODS, CSV) `{kind:"data", derived:true, of, sheets:[{name, cells:[{ref, value, type}]}], original}`, the cached values the readers read, no formula computed, no link followed; `original` is R9's answer. Refusals: `NO_SAFE_VIEW` (another format), `SAFE_VIEW_PENDING`, `SAFE_VIEW_FAILED` with the renderer's reason, `RENDERER_ABSENT`, and R8's first two.
- **R12** `renderBatch({limit})` (`op=renderbatch`; the scheduler's wake) renders queued files after their capture, never inside the capture's act. A rendered view is stored under its own digest outside `captures/`, labelled derived and naming its original; it is never registered (`provenance`), never a capture, never graded and never in a provenance chain. A file under a scan hold still gets and serves its safe view (K1892: "any flag keeps the safe view"). (T37) `renderBatch`'s answer is `{ok: true, rendered, failed, none, data, copies: {made, failed, queued}, remaining}`, `copies.queued` the safe copies still queued after the batch and `remaining` the files still queued to render.

**The deeper check** (K1888 (1), K1892, K1895, K1929)
- **R13** `requestDeeperCheck({captureSha, viewer})` (`op=deepercheck`; any member who may see the file) → `{ok:true, state, check_id}` (`queued`, `running`, or `done` with its note), or the sight refusal, or `NO_OUTSIDE_TOOL` when no tool of kind `scan` or `sandbox` is `on`, or `DEEPER_CHECK_BUDGET_SPENT` when every such tool has spent its `monthly_limit` this calendar month (UTC). A check already queued or running answers it. Who asked is not kept (R10).
- **R14** The check runs on the same bytes: the structure check (the file's reader reads it whole: K1928 Q2: it flags a refusal, an `unread` item, encryption, an ambiguous container, and the kinds `launch`, `activex`, `ole-object`, `embedded-file`, `xl4-macrosheet`, `external-target`, or a VBA project with any `suspicious` keyword or `undetermined` module); ClamAV, on demand; and (K1949) every tool `on` of kind `scan` (`/provider/scan`) or `sandbox` (`/provider/sandbox`) with budget left, a tool past its limit skipped and named. Its note `kind:"deeper"` lists `checks:[{check, tool, engine, result, detail}]` and `result`: `clean` only when every check that ran is `clean` and at least one outside engine with `differentEngine` from ClamAV's (`file-scanner` R31) answered `clean`; `flagged` when any check answers `found` or `suspicious` or the structure check flags (the safe view stays); `incomplete` otherwise (a check that could not run, `unknown`, `not_scanned`, no different engine); `incomplete` never opens an original. A `PRIVATE_MODE_NOT_HONOURED` answer switches that tool off (R31) and counts as a check that could not run.
- **R36** `deeperBatch({limit})` (`op=deeperbatch`; the scheduler's wake, every few minutes while checks are queued or running) starts queued checks and asks each running sandbox for its result no sooner than its `poll_after_ms`, writing a `sandbox` note per verdict; a check is `done` when every check in it has a result. (T37) It answers `{ok: true, started, polled, done, running, queued}`, `running` and `queued` the checks left in each state; when its checks cannot be read it answers `DEEPER_CHECKS_UNREADABLE` with its row (C-140.42), starting and asking nothing, never counts of null.

**Scan hold and release** (K1888 (4), K1892, K1928 Q3, K1929)
- **R15** `scanFindings({after?, since?, limit?, viewer})` → `{ok: true, findings: [{captureSha, note_id, tool, engine, findings, at, held}], cursor, truncated}`: every `found` note (a `copy` note excluded) in the order written, after `after` (a cursor this read answered), at most `limit` (default 200, clamped to 1–1,000), for the notices of a finding; no member is named. With `since` (an instant), only notes whose `at` is at or after `since` are answered, the order, `after`, `limit` and `cursor` unchanged; a `since` that is not an instant answers no finding and says so (`since_invalid: true`), as `following` R21's. `held` is `true` exactly when an open hold (R16, not released under R17–R19) covers that note's finding names at the call, read in the same synchronous call, else `false`. `cursor` is the last note answered when more follow (`truncated` true), else null. A note on a capture the viewer may not see is left out. It writes nothing and never throws.
- **R16** A `found` note from any engine of any tool places the file under a scan hold: its original does not open (R8); its safe view, its place in the record, its promotion state and its grade are unchanged. A hold names the finding names and engines it covers.
- **R17** `releaseScanHold({captureSha, by, reason})` (`op=releasescanhold`; an act of record, not a download log): refused `MACHINE_CANNOT_RELEASE_HOLD` for a machine or AI identity, `HOLD_NO_REASON` for an empty reason or one over 2,000 characters, `NOT_HELD`, `SAME_MEMBER` when `by` made the hold's pending act. The first act answers `{state:"pending_second"}`; a second by a different member releases it, `{state:"released", by:[a, b]}`.
- **R18** (K1928 Q3, K1929) A hold whose findings all come from the built-in ClamAV (`tool:"clamav"`) is released by a second, different engine when a deeper check on the same bytes ended with the structure check passing and a `clean` verdict from an engine with `differentEngine` from ClamAV, `{released_by:"second_engine", note_id, tool, engine}`. (K1949) A hold with any finding from any other engine, one engine of a multi-engine tool included, is released only by R17.
- **R19** A release covers the finding names its hold named; a later note finding another name places a new hold.

**Findings explained** (DEC-169, DEC-99)
- **R38** `findingKind(name)` → `{file_kind, threat_kind, variant, words}`: a scanner's finding name (R15, R16) explained in member words, as DEC-169's card and its "What this is" panel show it. `file_kind`, `threat_kind` and `variant` are the name's parts (the file kind, the kind of threat, the scanner's own label for the variant), as the scanner's naming gives them (`Xls.Downloader.Agent-917`: `Xls`, `Downloader`, `Agent-917`), each `null` when the name does not give it. `words` comes from this module's one table of finding kinds (one table, DEC-99): each row is a kind of threat with plain words, held for translation, saying what that kind of threat does and that scanners report what a file resembles, not a certainty; the table holds a row for each kind DEC-169 names (downloader, dropper, trojan, macro, exploit, phishing, potentially unwanted, heuristic or suspicious), and DEC-169's list is open ("and others"). When no row matches the name's kind of threat, `words` is exactly "Civicsmith has no plain description of this name". The answer depends on the name alone; pure; never throws.

**Archives** (K1852 (1), K1882, K1929 (Q1))
- **R20** Each file cut from an archive is scanned, graded, held and released as its own file; its source for R6 is the archive's. The archive is also scanned as itself; a finding in it holds the archive only. The archive's own grade is R6's archive rule: a member graded high, a member not filed, or a refusal makes the archive high, and a member's hold does.

**Security tools** (K1929 (1)–(3), DEC-168, DEC-169; the ops `securitytooladd`, `securitytooltest`, `securitytoolremove`)
- **R27** `securityToolCatalogue({viewer})` (administrators) → `{offered, refused, held}` from `file-scanner` R29, each offered entry with its `handling` and `handling_digest` (SHA-256 of its canonical JSON), each refused or held one with its reason in member words ("services not offered"). `securityTools({viewer})` (administrators) → the group's tools, each a tool (Terms) without credentials. Anyone else is refused `NOT_AN_ADMIN` (`membership.notAnAdmin`). (N777) Each offered entry, a generic template's included, carries its `config` list as `file-scanner` R29 answers it (`[{name, label, required}]`, an empty list when the tool reads none), so a settings page asks each field by name; a generic template's list names `engine_family` and `handling`, which the tool's maker states.
- **R28** `securityToolAdd({providerId, template?, config, credentials, handlingDigest, confirmRetention, use, monthlyLimit, by})` (`op=securitytooladd`), an active administrator's act; a machine credential refused `NOT_AN_ADMIN`. Refusals, each writing nothing: `PROVIDER_REFUSED` or `PROVIDER_HELD` (with the reason); `PROVIDER_UNKNOWN`; for a generic template, `file-scanner.validateDescriptor`'s refusal of the descriptor it makes; `CONFIG_MISSING` naming the field, when a `required` field of the entry's `config` list (R27) is absent from `config` or empty; `CONFIG_UNKNOWN` naming the field, when `config` holds a field the list does not name (`host` and `region` excepted, which are the spec's own fields (`file-scanner` R21), not `config` fields); `host` (from `config`, or a generic template's `template.host`) and `region`, where the entry's list names them, are read as those spec fields and count as given for `CONFIG_MISSING`, so a required `host` or `region` that is given is never refused *(not yet met: T38)*; `HANDLING_NOT_SHOWN` unless `handlingDigest` equals the entry's current `handling_digest` as the catalogue (R27) answers it (its handling stated before it is enabled); for a generic template, whose handling the administrator states in `config` as structured values (`file-scanner` R19), that is the template entry's catalogue `handling_digest`, and the tool's own `handling_digest` is computed by this module from the handling so stated (the page never computes it) *(not yet met: T38)*; `RETENTION_NOT_CONFIRMED` when `sample_sharing` is `vendor_internal_research` and `confirmRetention` is not `true` (S10); `CREDENTIALS_MISSING`; `USE_NOT_ALLOWED` for `use:"routine"` on a tool that is not on the organization's own servers (K1949); `LIMIT_INVALID` for a `monthlyLimit` not a whole number from 1 to 100,000 (default `DEEPER_CHECKS_PER_MONTH`). Success holds the credentials through `credentials.keyedServiceSet` (service `security:<tool_id>`), writes the tool `state:"added"` (off) with `handling` and `added_by`, and answers `{ok:true, tool_id, state}`.
- **R29** `securityToolTest({toolId, by})` (`op=securitytooltest`; administrators) runs `file-scanner`'s `/provider/test` with the tool's spec; `passed:true` sets `state:"on"` and `tested_at`; otherwise the state is `"test_failed"` with `detail`, and the tool stays off. A tool is used by R4, R14, R33, R34 and R35 only while `on`.
- **R30** `securityToolRemove({toolId, by})` (`op=securitytoolremove`; administrators) sets the tool `removed`, removes its credentials (`credentials.keyedServiceSet` with no key) and keeps its notes; a removed tool is never called again. Unknown ids answer `NO_SUCH_TOOL`.
- **R31** A tool answering `PRIVATE_MODE_NOT_HONOURED` (`file-scanner` R22) is set `state:"off"` with `off_reason`, and `securityToolEvents({after?, limit?, viewer})` (administrators) → `{ok: true, events: [{tool_id, event, at, reason}], cursor, truncated}`, one per switch off, test, add and removal, in order, after `after`, at most `limit` (default 200, clamped to 1–1,000), for the administrators' notice; `reason` is the tool's `off_reason` (`PRIVATE_MODE_NOT_HONOURED` today) for a switch off, else null; `cursor` is the last event answered when more follow, else null. No file is named in an event.
- **R32** (K1949) A tool's `use` is `on_request` (default) or `routine`. `on_request` scan and sandbox tools run only in a deeper check (R14), `on_request` CDR tools only on a member's ask (R33). `routine` scan tools also scan every due file (R4); `routine` CDR tools also make a safe copy of every queued file of a type they rebuild (R33). `routine` is accepted only for a tool whose `handling.recipient` is `"the organization"` (its own servers: `metadefender-core`, `icap`, `defender-storage`, a self-run Glasswall).

**The safe copy** (K1929 (4))
- **R33** `requestSafeCopy({captureSha, viewer})` (any member who may see the file; a `routine` CDR tool also queues it) asks the first `on` tool of kind `cdr` for a rebuilt file (`/provider/cdr`), and stores it under its own digest outside `captures/`, labelled derived, naming its original and the tool, never registered, never a capture, never graded, never in a provenance chain; it is then scanned by ClamAV and a `copy` note written. `safeCopy({captureSha, viewer})` → `{kind:"copy", derived:true, of, sha256, content_type, removed, tool, original}` and its bytes, or `NO_SAFE_COPY` (no `cdr` tool on), `SAFE_COPY_PENDING`, `SAFE_COPY_FAILED` with the tool's reason, `SAFE_COPY_WITHHELD` when its ClamAV note is not `clean`, and R8's first two. A safe copy opens for a `high` file without a deeper check (it is the derived document, not the original), and stays available under a scan hold. Who asked is not kept (R10). (N753) The copy's scan reads it where it is stored (`file-scanner` R2's `area: "derived"`, `${store}/derived/<sha>`); a `clean` verdict releases it (`safeCopy` serves it), and a `found`, `unknown` or `not_scanned` verdict withholds it (`SAFE_COPY_WITHHELD`).

**Web reputation** (S12, S13)
- **R34** A receipt's reputation answer (R1) becomes a `reputation` note `{tool, result: listed | not_listed, findings: categories, scanned_at}`; a listed answer makes the file `high` with `bad_reputation` (R6) and keeps it to the safe view until a deeper check under R8; the capture is never refused, delayed or changed for it. `reputationTool()` → the tool spec of the first `on` tool of kind `url_reputation`, with its credentials, or `null`: an in-plane call reached by no route, answered to no viewer, for the control plane to hand to `acquisition`.
- **R41** (N762; S12; `file-scanner` R26) `refreshReputationLists({at})`, an in-plane call reached by no route (the scheduler's wake), asks `file-scanner`'s `POST /provider/refresh` for each `on` tool of kind `url_reputation`, with that tool's spec and credentials as R34 hands them (read from `credentials` for that call only) and nothing else, and answers `{ok: true, refreshed: [{tool_id, list_version, fetched_at}], failed: [{tool_id, code}], skipped: [tool_id]}`: a tool answering `NO_LOCAL_LIST` is skipped and not asked again until it is tested again (R29); a failed refresh is named and keeps the last good list (`file-scanner` R26). With no scanner bound it answers `SCANNER_ABSENT` and asks nothing. It writes no note, names no file, address or member (R23), and never throws.

**Log forwarding** (K1892, K1929 (4))
- **R35** `forwardSecurityCounts({from, to})` (`op=securityforward`; the scheduler's hourly wake) builds one counts record for the period, its keys exactly `LOG_COUNT_KINDS`: this module's `files_scanned`, `files_found`, `holds_placed`, `holds_released`, `deeper_checks`, `sandbox_submissions`, `safe_views`, `safe_copies`, `reputation_listed`, and `credentials` R44's `signin`, `credential`, `rate`, `handover`, `through` summed over countries; and sends it to every `on` tool of kind `log_sink` (`/provider/forward`). Answers `{ok:true, sent:[tool_id], failed:[{tool_id, code}]}`. A figure that could not be read is sent as absent, never as zero (record-core R63's rule). (T37) Called with neither `from` nor `to` (the scheduler's wake), it forwards the period from the end of the last period it forwarded with `ok` (never more than 24 hours back; at the first, the start of the previous whole UTC hour) to the start of the current whole UTC hour, records that end when it answers `ok`, and answers `{ok: true, sent: [], failed: [], record: null}` when that period is empty, so no period is sent twice.

**Its cadences** (N762; K2129, K2153)
- **R39** (N762; K2129, K2153) This module states when each of its batches next wants to run, from its own durable state, so the scheduler holds no interval for it (`scheduler` R7, R24). `scanWake(now)`, `renderWake(now)`, `deeperWake(now)`, `forwardWake(now)` and `reputationWake(now)` each answer an instant, the batch's due and wake alike, or null when it wants none: **scan** (R4), null with no scanner bound or no file held, `now` while the last `scanBatch` answered `remaining` above 0, else the earliest instant a file falls due (R4: a newly queued file at once, so a new capture is scanned at the next wake, not the next day); **render** (R12, R33), null with no renderer bound (the scanner binding `FILE_SCANNER`, R12's `RENDERER_ABSENT`) or while no file's view and no safe copy is queued *(not yet met: T38)*, else the later of `now` and the last `renderBatch` plus `FILE_SAFETY_POLL_MS` (300,000); **deeper** (R36), null while no check is queued or running, else the earliest of the last `deeperBatch` plus `FILE_SAFETY_POLL_MS` for a queued check and each running sandbox's next poll (`poll_after_ms`), never before `now`, and the last `deeperBatch` plus `FILE_SAFETY_POLL_MS` while its checks cannot be read; **forward** (R35), null while no tool of kind `log_sink` is `on`, else the start of the first whole UTC hour after the end of the last period forwarded with `ok` (at the first, the start of the current hour); **reputation** (R41), null while no tool of kind `url_reputation` is `on` with a local list, else the last refresh that answered `ok` plus `REPUTATION_REFRESH_MS`, or `now` when none has. The instants each reads (each batch's last run, the last period forwarded, each list's last refresh) are kept in this module's own tables and survive a restart. Each writes nothing and never throws. `FILE_SAFETY_POLL_MS` and `REPUTATION_REFRESH_MS` are exported (R21).
- **R40** (N762) `onFileWork(module, fn)`: a later module registers once at start (a second registration by one module, or a `fn` that is not a function, is refused through `membership.listenerRefusal`, its R81, `LISTENER_DECLARED` or `LISTENER_MALFORMED`).
