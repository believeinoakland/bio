## Public

### Purpose

How a model turn reaches the AI provider an account names (today Anthropic's Claude only). Given the account reference that serves one member's act (the member's own, a project's or the group's API key, K1755; T40, N812, D34), it sends a conversation's turns either to the Messages API (an API key) or to Claude Code running unmodified in the `agent-runner` container (a Claude subscription), returns each turn's outcome and its `usage`, and keeps the segment within its turn and byte bounds. It holds no credential: the reference arrives per call and is never kept.

### Provides

Terms. An **account reference** is `{kind: "apikey", key}` or (T38; K2200) `{kind: "signin", member}`, one member's own (K1502) or, for an `apikey` only, a project's (T40; D34) or the group's (K1755), with its `level` (`member`, `project` or `group`) as `credentials.accountFor` answers it (its R35); an `apikey`'s secret is its `key`; a `signin` reference carries none. A **meter** is `segmentMeter({turnsBound, bytesBound})`'s plain object. An **outcome** is exactly one of `{result}`, `{silent: {detail}}`, `{refused: {status, type, message}}`.

- **R1** *(not yet met: T53)* (T53; K1502, K1755; AIR5, AIR8; BR1, BR3; amends `agent-worker` R40) A run's model turns run under the account that serves the act of the member who started the run (a standing question's, its author's), as `ai-accounts.accountFor` answers it (its R7), with the skill pack the run names, within the segment bound. Test: over a fake entry lacking image input, `serves(fake, needOf("transcribe"))` answers `lacks` naming `image_input`, and `serves(fake, needOf("ask"))` answers ok; a scan of the module's source and tests finds no `claude-`, `opus-` or `sonnet-` string. **converse({reference, runner?, mode, meter, system, messages, tools, finalTool, onTool, maxTurns, trace?, memberRef?}) → `{answer, usage, calls}` | `{stopped}` | `{exhausted, usage, calls}` | outcome** (one conversation)
- **R6** *(not yet met: T53)* (T53; AMEND; D-611; `agent-worker` R40, R41; BR4; N588, K1621; amends R6) `converse({account, entry_id, runtime, data_handling, mode, meter, system, messages, tools, finalTool, onTool, maxTurns, trace?, memberRef?, role?, session_key?, idempotency_base, onProgress?}) → {answer, usage, calls, served, label, effort, entry_id} | {stopped} | {exhausted, usage, calls} | outcome`. It is built only on `turn` (an injected `turn` shows it touches no adapter). It ends when the model calls `finalTool` (its input is the `answer`), or `stopped: "turns"` or `"bytes"` when sending the next request would take the meter past `turnsBound` or `bytesBound` (bytes are the serialized length of the neutral request, so a bound means the same for every adapter), or `exhausted` after `maxTurns` (`MAX_TURNS_DEFAULT` by default), or with a turn's non-`result` outcome. Every other tool call is performed by `onTool` (the harness's table decides every call: the AI is a callee, the idea of retired R7) and its result returned; every tool call gets a result. `usage` is the sum over the turns, null where any turn's is null; `calls` is the sum of R54's. Turn `n` uses `idempotency_key` `<idempotency_base>:<n>`. Test: a fake `turn` shows the four endings and `calls` equal to the fake provider's requests; two runs with the same base send the same keys; a stubbed adapter-free run proves no adapter is touched. Control: a `finalTool` call on turn one ends it with one call.

**The provider interface (T53)**

- **R25** *(not yet met: T53)* (T53; BR1) `turn(request)` takes `{account, entry_id, messages, tools?, tool_choice?, output_schema?, effort?, max_output, session_key?, cache_hints?, data_handling, runtime, timeout_ms, idempotency_key, interactive?, test_flow?, onProgress?}`. `messages` are neutral: `system`, `user`, `assistant` (text, tool calls, an opaque `continuation`, R28) and `tool_result` (text, `search_result` and image blocks, R12, R14). `entry_id` is never a provider model string: a value that is not an entry the catalogue holds is refused `ENTRY_UNKNOWN`; a retired entry `ENTRY_RETIRED`. Test: each malformed request is refused with its type and the fake provider receives nothing; an `entry_id` equal to the fake's provider model string is `ENTRY_UNKNOWN`. Control: the well-formed request is sent.
