Fix round 9 (T51; G123, S9; K4831, K4835 (6), K4837): R19-R28 new (the platform-shaped generators, the lazy ZIP64 writer, the truth function, the loopback origin, the alarm double, the registrar stub); R9 amended; marked not yet met (T51).

## Public

### Purpose

Gives any test process a temporary-file sandbox it owns and removes, and standard output that cannot lose a test's final tally when the process exits. A test takes both by importing the sandbox module. It also writes ZIP archives in memory, conforming or deliberately hostile, for the tests of every module that reads one (`bio-plane/test/make-zip.mjs`; importing it has no side effect). Fix round 9 adds the library every reading module's tests share at the platform's shape: seeded generators of PDFs, pictures, spreadsheets and documents with the truth of each, a lazy ZIP64 writer, a loopback origin, the platform-shaped alarm double and the job registrar's stub.

### Provides

**Importing the sandbox (a side effect).**
- **R1** On import, one directory is created under the host's temporary directory, named with the process id, and the process's temporary directory (`$TMPDIR`, and so `os.tmpdir()`) points inside it for the rest of the process.
- **R2** When the process exits by any path that runs exit handlers (a normal end, `process.exit()`, an uncaught error), the directory and everything in it are removed synchronously before the process ends, including a subdirectory or file a test left read-only, also when the process does not run as root: a removal refused for permission (`EACCES`) makes that part of the tree writable and is retried, so the directory never outlives the process.
- **R3** Importing it more than once in one process creates one directory and removes it once, and never throws.

**`SANDBOX` → string.**
- **R4** The absolute path of the directory R1 created.

**`sweepSandbox()` → void.**
- **R5** Removes the directory at once; a later exit does not fail because it is gone. Never throws.

**`synchronousStdio()` → `{streams, already}`.**
- **R6** Makes the process's standard output and standard error write synchronously where the stream allows it, so everything written before `process.exit()` reaches the reader, including through a pipe. `streams` names the streams it changed.
- **R7** A second call changes nothing and returns `already: true` with the same `streams`. A stream that cannot be changed (a file, which is already synchronous, or an absent stream) is left as it is and is no error. Never throws.
- **R8** Importing the sandbox module also applies R6.

**`makeZip(entries, options = {})` → `Uint8Array`** (N688; K1844, K1852)
- **R10** `entries` is an array of `{name, data, method = 8}`: `name` a string or the raw name bytes (a `Uint8Array`), `data` a `Uint8Array` or a string (written as UTF-8), `method` 0 (stored) or 8 (deflate; any other number is written as declared over the data as given). With no override (R12), the answer is one conforming archive in APPNOTE 6.3's form: for each entry in order a local header and its data, then the central directory, then the end-of-central-directory record; each entry's CRC-32 and sizes true; general-purpose bit 11 set exactly when a string `name` is not ASCII; one fixed MS-DOS time when none is given.
- **R11** A conforming archive (R10) with at least one entry passes both oracles (K1917; Info-ZIP refuses an empty archive, which R10 and `zipfile` still cover): Info-ZIP `unzip -t` exits 0 over it, and Python's `zipfile` lists the entries in order with their names and gives back each entry's `data` byte for byte.
- **R12** Every hostile shape below is written by an override and nothing else changes: the bytes say exactly what the override names, and the rest stays as R10 writes it.
  - **Duplicate names:** two entries with one `name` are written as two entries; nothing is merged or renamed.
  - **Unsafe and non-UTF-8 names:** a `name` is written verbatim (`../`, a leading `/`, a drive letter, `\`); `utf8: false` on an entry clears bit 11 over non-ASCII raw bytes (a CP437 name).
  - **Central directory and local header disagree:** an entry's `local: {name, method, flags, crc32, compressedSize, uncompressedSize}` (any subset) is what that entry's local header states; its central-directory record keeps the true values. `central: {…}` (the same fields, and `localOffset`) does the reverse, and a `localOffset` past the archive's end writes an entry out of range.
  - **Bit 3:** `dataDescriptor: true` sets bit 3, writes zero CRC and sizes in the local header and a data descriptor after the data; `descriptor: {crc32, compressedSize, uncompressedSize, signature}` overrides what the descriptor states, and `signature: false` omits its optional signature.
  - **ZIP64:** an entry's `zip64: true` writes its sizes and offset as `0xFFFFFFFF` with the true values in a `0x0001` extra field; `options.zip64: true` also writes the ZIP64 end record and its locator, with the end record's 16- and 32-bit fields at their sentinels. `zip64Record: {…}` overrides what the ZIP64 end record states.
  - **Encrypted:** an entry's `encrypted` is `"traditional"` (bit 0), `"strong"` (bits 0 and 6), `"aes"` (method 99 with a `0x9901` extra field) or `"directory"` (bit 13); the data is written as given, never actually encrypted.
  - **Overlap:** an entry's `sameDataAs: <index>` points its central-directory record at the local header and data of an earlier entry, so two entries' byte ranges coincide.
  - **The end record:** `options.eocd: {entries, diskEntries, cdSize, cdOffset}` (any subset) is what the end record states; `options.comment` is the archive comment (a string or bytes); `options.secondEocd: true` writes a second, well-formed end-record candidate inside the comment.
  - **Nesting:** an entry's `data` may itself be `makeZip`'s output.
- **R13** Deterministic: the same `entries` and `options` give the same bytes on every call. No clock, no randomness, nothing written to disk. A spec it cannot write (an entry without `name` or `data`, a `sameDataAs` naming no earlier entry, an unknown `encrypted` value) throws an `Error` naming the field.

**`zipBomb({kernel, entries})` → `Uint8Array`, `nestedZip({depth, fanout, leaf})` → `Uint8Array`** (N688; F7)
- **R14** `zipBomb` writes one deflated kernel of `kernel` zero bytes once and `entries` central-directory entries that all point at it (R12's overlap), each declaring `kernel` uncompressed bytes, so the declared total is `kernel × entries` while the archive stays near one kernel's compressed size. `nestedZip` writes an archive `depth` levels deep (1 is a plain archive of leaves): each level holds `fanout` entries, each the next level's archive, and the deepest holds `fanout` copies of `leaf` (bytes, written stored or deflated as R10). Both are deterministic and built on `makeZip` alone (R13).

**The platform-shaped generators (fix round 9, G123d, G123e; S9, S-41; `bio-plane/test/pdfgen.mjs`, `imggen.mjs`, `sheetgen.mjs`, `docgen.mjs`)**
- **R19** Each generator takes a recipe `{shape, size, seed}` and its options and answers the file's bytes (or, for a file too large to hold, a lazy stream of chunks) together with its **truth**: what an independent reader finds in it (for a text kind the text of every unit and the position of every mark; for a sheet each cell and row; for a picture its pixels; for a PDF each page's text). The same recipe gives the same bytes and the same truth on every call: no clock, no unseeded randomness. A file is built on demand into the directory named by `BIO_FIXTURE_CACHE`, keyed by its recipe, and never committed. A recipe that names a boundary (a bound minus 2, the bound, the bound plus 1) builds exactly that size.
- **R20** `pdfgen` and `imggen` build the PDF and picture shapes the corpus names, at the shape the platform sees, not the reader's own builder's: non-ASCII text, several fonts, long pages, a heavy page among light ones, encrypted files (empty password and user password), scans, mixed pages, a stream or a header that declares more than its data holds, a polyglot, a wide or tall frame and a hostile count. For a picture the truth is its pixels.
- **R21** `sheetgen` builds CSV, TSV, XLSX and ODS at any size to the standard's 50 MB and 1,048,576 rows and at either side of each alpha bound: UTF-8, UTF-16 and legacy-charset text, CRLF, CR-only and LF endings, quoted newlines, a stray quote, ragged rows, a title block, empty cells, wide rows to 16,385 columns, long cells, merged cells, dates under a date format, annotations, and shared strings or inline strings. It marks a cell in the first data row, a middle row and the last row, never in the header row, as `<seed>-R<row>-C<col>`. For CSV its truth is an RFC 4180 reading made inside the generator.
- **R22** `docgen` builds DOCX, PPTX, ODT, ODP and HTML (and text, JSON and XML) with every part kind (body, footnote, endnote, header, footer, comment, tracked deletion, text box, speaker note, master text), tables of any row count, a paragraph of any length, a shape ladder at equal bytes (one-cell tables, empty paragraphs, many tiny paragraphs, many hyperlinks, nested tables), an encoding matrix, templates and macro flavours, an encrypted member, a package that declares more than it holds, and deep or unterminated markup. Its truth is the text of each part, which LibreOffice headless agrees with on a small file.
- **R23** `zipChunks64` writes a ZIP lazily, as an async stream of chunks, with the ZIP64 end record and extra fields that entries of any declared size need, so an archive of the alpha bound plus 1 or of the standard's 500 MB, and a member set whose declared unpacked total passes 2 GB, is declared without being built in memory. Its output opens in both oracles of R11 on a small instance. `makeZip` (R10-R14) stays the whole-archive writer.
- **R24** `truthOf(recipe)` answers the truth R19 describes without building the file, and a test pins that each generator's truth agrees with its independent reader on a small file (pdf.js (the library the committed pdf-worker bundle carries, from bio-plane's `pdfjs-dist`) and poppler's `pdftotext`; Pillow or libtiff for pixels; an RFC 4180 parser for CSV; `unzip -t` and Python `zipfile` for packages; LibreOffice headless for office text). A generator that disagrees with its reader is the defect.
- **R25** `loopbackOrigin(routes)` starts an HTTP origin on the loopback interface that serves the given generated files with the given headers and statuses, for the tests of `acquire` and the doorbell pull, and closes with the sandbox (R2). It makes no request to any host but the loopback.

**The platform-shaped doubles (fix round 9, G123c; S9; rB D3; `bio-plane/test/alarm-double.mjs`, `bio-plane/test/job-registrar-stub.mjs`)**
- **R26** `alarmDouble(opts) -> {storage, getAlarm(), setAlarm(t), deleteAlarm(), run(fn), retries}` models a Durable Object's alarm as the platform does: `getAlarm()` answers `null` while a `run` is in flight; an alarm that has been spent stays set until `deleteAlarm()`; a `run(fn)` whose `fn` fails is run again, up to 6 retries, and `retries` counts them. Its file imports nothing from the plane, so `scheduler` (which does not use `plane`) takes it through its own `uses: test-support` edge. `storage` keeps values (`get`, `put`, `delete`, `list`) and logs each call; `opts.maxRetries` (6) bounds the retries and `opts.rerunAfterSuccess` re-runs a completed handler once with retryCount 1 (`PLATFORM_FIGURES`). The scheduler's `r8-budget` and `r8-stale` tests and the plane's harness use it.
- **R27** `jobRegistrarStub() -> {registerJob, armJobs, rows(), armed(), transact(fn)}` implements, in memory, the contract of `registerJob({kind, sha, session?, cursor?, owed?, carrier?, parts?, detail?, verdict?, priority?}) -> {ok:true, existed, state} | {ok:false, reason}`: synchronous and never throwing; `kind` one of `keep`, `reading`, `ocr`, `subresources`, `unpack`, `fetch`, `scan`, `safe_view`, `grade`, `ingest`; `sha` the whole digest (64 lowercase hex), except `fetch` and `subresources`, keyed by capture `session`; idempotent on `(sha or session, kind)`, a second registration re-arming, updating `cursor`, `owed`, `detail` and `parts` only when given, never resetting counters, and `priority: "raised"` meaning "Read it". `rows()` lists the job rows written (a row written inside a transaction that rolled back is not listed) and `armed()` whether `armJobs()` has been called since the last row changed. `transact(fn)` is the transaction a row commits or rolls back with. The acquisition, capture, doorbell and extraction tests count rows on it.
- **R28** Every generator and double above is importable by a test of any module with no side effect on import, and none is imported by product code.

**`declaredOpHolds({op, declaration, call, refusedNaming})` → Promise, `declaredOpsOf(root)` → Promise** (`bio-plane/test/declared-ops.mjs`; K4168, K4189)
- **R15** `declaredOpHolds` holds an owner's op declaration (`DECLARED_OPS[op]`: `fields: {accepts, requires}`, a `requires` entry a field name or a list of alternatives) true against the op as the door runs it. `call(fields)` runs the op and answers what the door answers (a `Response` is read as `{status, ...body}`); `refusedNaming(answer, field)` says whether an answer is a refusal naming that field (default: the answer's `code` or `detail` names it as a whole word). It (a) calls with only the `requires` satisfied (the first alternative of each list) and expects no refusal naming any declared field, (b) calls once without each required entry (without every alternative of a list) and expects a refusal naming that field (any alternative of a list), (c) calls once with a field outside `accepts` and `requires` (`outside`, default one generated name) and expects the op to drop it (the answer equals (a)'s, by `same`, default JSON equality) or refuse it naming it. Optional keys: `values` (a sample value per field name; default a string made from the name), `outside`, `same`. A breach rejects with an `Error` naming the op and the field; a declaration without `fields.accepts` and `fields.requires` arrays rejects naming the op. The helper is test tooling: only tests import it.
- **R16** `declaredOpsOf(root)` reads `build/modules.json` under `root`, takes the source files (`.mjs`, `.js`) of every module's `paths` (a path ending in `/` is a directory, read recursively, `node_modules` skipped) whose text contains `export const DECLARED_OPS`, imports each and answers `{ops, owners, duplicates}`: `ops` the declarations by op name, `owners` the module id of each op, `duplicates` every op declared by two or more modules as `{op, owners}` (`ops` and `owners` keep the first in `modules.json` order). A file without the text is not imported; a file that has it and does not export an object `DECLARED_OPS` rejects naming the file. It lists no module by hand (K3268) and is called only from tests, never from product code, because it imports later modules' files by path (P4; K4189).
- **R17** (T51; K4240, K4245) `registerDeclared(root, ...registrations)` calls each registration function once per process with every owner's declaration as `[owner, DECLARED_OPS]` pairs, read from the same files by the same rule as R16 (duplicates included, `modules.json` order); a registration already called (by function identity) is skipped by a later call, and a registration's refusal propagates, naming what it refused, leaving the rest of that call's registrations uncalled. Test tooling: only tests call it.
- **R18** (fix round 6, G41; K4631, K4666) `bio-plane/test/platform-sqlite.mjs`, loaded as `node --import <it>` (or `NODE_OPTIONS=--import=<it>`), makes `node:sqlite` refuse, as Durable Object SQLite does, any statement run through `run`, `all`, `get` or `iterate` (and a tag store's) whose single bound string (judged by its UTF-8 bytes) or blob is over 2,098,176 B, or whose bound strings and blobs sum over it, before the statement runs, with an `Error` of message `string or blob too big`, `code` `ERR_SQLITE_ERROR`, `errcode` 18, `errstr` as node's own SQLITE_TOOBIG; it judges no number, bigint or null, no literal in SQL text, no computed value; importing it twice wraps once. Test tooling: only the test commands load it (`.github/scripts/module-tests.mjs` does). Test: `platform-sqlite.test.mjs`.

### Invariants

- **R9** Nothing outside the sandbox directory is created or removed by this module, except the generators' files in the directory named by `BIO_FIXTURE_CACHE` (R19), which this module creates and never removes; when it is unset, they are built inside the process's temporary directory (the sandbox).

### Suggestions

- A test of R2 spawns a child process that imports the module, writes a file, and exits through `process.exit()`, then checks the directory is gone; R2's read-only case is tested by running that child as a non-root user (`setpriv` or `runuser`) with a read-only subdirectory left in the sandbox, and at the interface with an injected `EACCES` (N22); a test of R6 floods a pipe from a child and checks the final line arrives.
- `make-zip.mjs` runs only in Node tests, so deflate may be Node's `zlib.deflateRawSync`. R11's oracles run as child processes (`unzip -t`, `python3 -I -c` with `zipfile`); a host lacking either skips that check by name rather than passing it. A test of R12 reads each hostile fixture back at the byte level (Python's `zipfile` or `struct`) and checks the one field the override names.
- The ooxml job (T35-8) checks its `listArchive` verdicts against the same two oracles over these fixtures (K1844's oracles): where `unzip -t` or `zipfile` extract other bytes than the central directory states, `listArchive` must not answer `ok`.
