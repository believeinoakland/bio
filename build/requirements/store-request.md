## Public

### Purpose

The request the store is asked, made from the page's. One function takes an admitted caller and a page's request and makes the store's: every stamp set from the caller and none taken from the request, every credential in a header, the actor written into the body where the owner reads it there. It holds no door arm, gate or answer. Over `store-assembly`'s world it also publishes the door a screen's test talks to, the real sign-ins and the recipes of real acts.

### Provides

Terms. **Stamp**, **declared stamps**, the **families** (`EDGE_ACTIONS` and the rest) and `OP_STAMPS` are `op-declarations`' (its R10 to R33, R75); the **caller** is what `admission.admit` answers. M, T, I, A, AI, P name expressions in R7. A **world** is `store-assembly`'s (`store-assembly` R90).

**The function: `innerRequest`**

- **R1** *(not yet met: T51)* (was `control-plane` R17, R29's mechanism and the store-request construction at `control-plane/index.mjs:1384-3881`; K5046 (b), K5052 (1)) `innerRequest({op, url, method, body, caller, source?, country?, userAgent?, resolving?, replay?, deferred?})` makes the store's request from a page's request, in one function. `op` is the op's name after `op-declarations`' alias resolution; `url` the request's address; `method`; `body` its body text, or absent; `caller` the caller `admission.admit` admitted (`cls`, `viaSession`, `member`, `viewer`, `identity`, `rights`, `caps`, `aiCred`, `storeName`, with the presented session token as `token`). The door computes and hands in what needs the store or the clock: `source` and `country` (`admission`'s `sourceOf`, `countryOf`), `userAgent` (the request's header), `resolving` (true when the door re-routed a knock resolved to `pulled` as `inboxpull`), `replay` (the door's verdict on a promotion's asserted replay, `control-plane` R16: `{asserted, proven}` with `proven` the verified record or none) and `deferred` (true when the door found a `readheld` capture's reading will not fit the bound, `control-plane` R120). It answers `{url, body, headers}`: the store route's in-process address (`http://x/<route>`), the body text to pass (absent when none was sent) and the internal headers of R5; or `{refusal}` when a promotion creating a project is refused by `admission.projectCreationGate` (R11), which the door answers as given. It is synchronous and never throws, reads no clock, writes nothing, and gives the same answer to the same arguments. `control-plane`'s door calls it for every request it makes to the store (`control-plane` R136) and the world's door for every store request it makes (R17), so one implementation decides what reaches the store (P5). The door arms between its inputs and its output (gates, refusals, the signing-in relays, the forward and the answer) stay in `control-plane`. Test: R2 to R13 over every op `OPS` declares, with each stamp name sent as a sentinel in the address and the body, once for each kind of caller (a founder's session, a member's, an `ai` credential, each binding class).
