## Public

### Purpose

The request the store is asked, made from the page's. One function takes an admitted caller and a page's request and makes the store's: every stamp set from the caller and none taken from the request, every credential in a header, the actor written into the body where the owner reads it there. It holds no door arm, gate or answer. Over `store-assembly`'s world it also publishes the door a screen's test talks to, the real sign-ins and the recipes of real acts.

### Provides

Terms. **Stamp**, **declared stamps**, `OP_STAMPS` and the **families** (`EDGE_ACTIONS` and the rest) are `op-declarations`' (its R10 to R33, R75); the **caller** is what `admission.admit` answers; a **world** is `store-assembly`'s (its R90). A session's three halves are `admission`'s (its R30): the **member** is the member id (`ruth`; the founder's is `admin`), the **viewer** the form a visibility gate reads (`admin` for the founder, else `member:<id>`), the **identity** the positional name (always `member:<id>`; the founder's is `member:admin`). Each is none for a caller that is not a session. **C** is `class:<cls>`; `token:<cls>` is `MACHINE_AUTHOR_PREFIX` with the class. The **actor** is a session's viewer, an `ai` caller's `class:ai/<tokenId>`, else C. These expressions are named once here and used by letter in every requirement: **M** a session's member, else C. **T** a session's member, else `token:<cls>`. **I** a session's identity, else C. **A** a session's member, an `ai` caller's `class:ai/<tokenId>`, else C. **AI** a session's identity, an `ai` caller's `class:ai/<tokenId>`, else C. **P** a session's identity, an `ai` caller's `<principal>/<tokenId>`, else C. **N** a session's identity, an `ai` caller's principal, else C. **V** a session's viewer, an `ai` caller's the viewer `admission` answers (its R30: the principal's viewer carrying the project its credential was minted for), else C. **Order.** The rules apply in the order R3, R4, R6, R7, R8, R11, R12, R23; a key that a later rule sets replaces what an earlier one set, and a key no rule sets is absent.

**The function: `innerRequest`**

- **R1** (was `control-plane` R17, R29's mechanism and the construction at `control-plane/index.mjs:1384-3881`; K5046 (b), K5052 (1)) `innerRequest({op, url, method, body, caller, source?, country?, userAgent?, origin?, length?, resolving?, replay?, deferred?, secretSha?, bySecret?, mint?})` makes the store's request from a page's, in one function. `op` is the op's name after `op-declarations`' alias resolution; `url` the request's address (its search parameters are the page's); `method`; `body` the body as the door read it, text, or the bytes or stream of an upload, or absent; `caller` the caller `admission.admit` admitted (`cls`, `viaSession`, `member`, `viewer`, `identity`, `rights`, `caps`, `aiCred`, `storeName`, with the presented session token as `token`). The door computes and hands in what needs a header, the store or the clock: `source`, the keyed digest `admission`'s `sourceOf` makes of the `cf-connecting-ip` header (never the address); `country`, `countryOf` of the request's `cf.country`; `userAgent`, the `User-Agent` header; `origin`, the origin (scheme and host) of the request's own address; `length`, the `Content-Length` header when it is a whole number, else absent; `resolving` (true when the door re-routed a knock resolved to `pulled` as `inboxpull`); `replay` (the door's verdict on a promotion's asserted replay, `control-plane` R16: `{asserted, proven}`, `proven` the verified record or none); `deferred` (true when the door found a `readheld` capture's reading will not fit the bound, `control-plane` R120); and `secretSha`, `bySecret` and `mint` (R23). It answers `{url, body, headers}`: the store route's in-process address (`http://x/<route>`), the body to pass (absent when none was sent; any body that is not JSON text of an object passes as it came, for the owner to refuse in its own words) and the internal headers of R5; or `{refusal}` when a promotion creating a project is refused by `admission.projectCreationGate` (R11), which the door answers as given. It is synchronous and never throws, reads no clock, writes nothing, and gives the same answer to the same arguments. `control-plane`'s door calls it for every request it makes to the store (`control-plane` R136) and the world's door for every one it makes (R17), so one implementation decides what reaches the store (P5). The door arms between its inputs and its output (gates, refusals, the signing-in relays, the forward and the answer) stay in `control-plane`. Test: R2 to R13 and R23 over every op `OPS` declares, with each stamp name sent as a sentinel in the address and the body, once for each kind of caller (a founder's session, a member's, an `ai` credential, each binding class).

- **R16** (K5046 (d); `op-tables.md` §5.3) **Real sign-ins over a world.** `signIn(world, handle, {admin?, capabilities?, device?})` answers a signed-in member `{handle, member, token, session, act, read}`: the founder by the real `login`; any other member by the real acts that make one, the founder's `memberadd`, the invitation's `enroll` with a password, then `login` (with `adminendorse` for `admin: true` and `membercaps` for `capabilities`; the ops as `op-tables.md` §5.3 names them, their arms read at the job's START). `token` is the session token the real `login` issued and `session` the record the shell keeps (`{t, e, d, w}`, `interface-shell` R32).
