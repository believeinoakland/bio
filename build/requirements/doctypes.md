## Public

### Purpose

The content types: what kind of document a capture is (a meeting calendar, minutes, an agenda, a staff report, an ordinance or resolution, a policy, a staff directory, or none recognised), what is in it, and whether a change between two readings of it is meaningful. Each type recognises a document by the vocabulary the active jurisdiction profiles supply, never by vocabulary held in code. The `regulation` type also reads an instrument's or a code's sections, headings, definitions and exceptions; the `policy` type (T35) a policy's header block, sections, definitions, applicability, responsibilities and timeframes.

### Provides

**DOCTYPES and registerDoctypes(register)**
- **R1** `DOCTYPES` lists the eight types in their registration order, which is load-bearing (`docprofile` R4's first CERTAIN match wins): `meeting_calendar`, `meeting_minutes`, `meeting_agenda`, `staff_report`, `regulation`, `policy` (T35-12), `staff_directory`, `generic`. `generic` alone carries `fallback: true`. `policy` follows `regulation`, so an ordinance or a code section is read as `regulation` and a staff report that cites a policy as `staff_report`. *(not yet met: T35)*
- **R2** `registerDoctypes(register)` calls `register` once per type, in R1's order (eight since T35-12); it is how the plane wires the types into `docprofile`'s registry (A §(c)). Called twice on one registry, it registers nothing the second time. *(not yet met: T35)*

**Each type: `{key, label, version, contract, fallback?, detect(ctx), parse(ctx), assess(before, after, ctx)}`.** `ctx` is `docprofile`'s (`doctypeFor`'s and `readText`'s), carrying `text`, `view`, `locate`, `at`, `now` where the caller gives them.
- **R3** (was `docprofile` R6) Every type's own `detect`, `parse` and `assess` takes every LOCAL fact it tests for (furniture, bodies, member titles, enactment kinds, forms and markers, codes, file numbers, report titles and sections, recommendation openers, template blanks, practice deadlines, and since T35-12 the policy series of `standard_sources` and the policy header labels, `jurisdictions` R63, R69) from `ctx.view`, under the keys `jurisdictions` defines, and holds none in its own code. Place-free language, a publishing system's own page and link shapes, and measured structural floors stay in code. When `ctx.view` is absent, the view is `jurisdictions.combine` of every non-test profile (K39, K880), through `docprofile`'s reader view. *(not yet met: T35)*
- **R4** (was `docprofile` R29) Each type declares its `contract`, one of `docprofile`'s `CONTRACT` values: `SUBSTANCE` or `MEMBERSHIP`; `generic` is `SUBSTANCE`.
- **R5** (was `docprofile` R14, the types' share) Every event a type's `assess` emits is drawn from `site-profiles`' catalogue through `event()`; `meaningful` is always `isMeaningful(events)`, never a second fact beside them.
- **R6** (was `docprofile` R15, the types' share) Every connection a type emits is either `referential` (`{connection, from, to, relation, why}`) or `temporal` (`{connection, from, to, relation, at, expected_by, why}`); the two are never collapsed.
- **R7** (was `docprofile` R20 and R34, the reader's share) A type places a reference only where `ctx.locate` says, for the offset it actually read it at; with no locator, or a `null` answer, the entity carries no `source`, never a composed one. A reference read more than once is one entity, `source` its first sighting's, with `occurrences` every place it was read, in reading order, each what `ctx.locate` returned (D-454; K754).
- **R8** (was `docprofile` R31's exception) `meeting_calendar`'s forward-looking connection ("minutes not yet published") reads `ctx.now` when given and the wall clock only when it is not.
- Errors: a type's `detect`, `parse` or `assess` may throw only on a defect in itself; `docprofile` catches and states it (its R5, R13, R17, R19).

**`regulation`: sections, definitions and exceptions** (A LAW 1a, 2; ladders §6.4)
- **R9** `parse` gives `form`: `instrument` for an ordinance or resolution (as today), or `code` for a codifier's section of a jurisdiction's code (a code page carries no enacting formula; `measures-T33/time-law.md` §5 measured 0 of 50 detected today). `detect` matches a code section at CERTAIN only when its heading matches a section-number form of a code the view names (`vocabulary.codes`) followed by a title.
- **R10** `parse` gives `sections`: one entry per section read, in document order, each `{path, number, heading, start, end, source}`. `path` lists the section's number parts from the code's or instrument's top level down (for example title, chapter, section, then subsection markers); `start` and `end` are offsets of its extent in the text read; `source` is R7's. These are the `portion` extents `standards` keys on.
- **R11** Section numbers, their part separators and the order of subsection markers (letters, numerals, parenthesised letters) are read from the view's code vocabulary, never from code; an instrument's own "SECTION n." headings are place-free and stay in code. Where the text read cannot be divided (no heading matched), `sections` is empty with `sections_why`, never one section standing for the whole.
- **R12** A captured codifier document that holds exactly one section (the codifier's per-section form, time-law §4) gives that one section with its boundaries exact; one that holds an article's sections (a charter article) gives each section the article's text divides into.
- **R13** `parse` gives `definitions`: each passage defining a term in the definitional voice ("'X' means …", "'X' includes …", "as used in this chapter, 'X' …"), as `{term, start, end, source, section}`, `section` the path of the section holding it. A term defined twice gives two entries.
- **R14** `parse` gives `exceptions`: each passage that excepts ("except as provided in …", "notwithstanding …", "does not apply to …", "shall not apply"), as `{start, end, source, section, cites}`, `cites` the section numbers the passage names, read by R11's forms, or `[]`.
- **R15** Definitions and exceptions are readings, never law relations: nothing here records `defines` or `excepts`; a member does, in `standards` (K1446; ladders §2 LAW).
- **R16** A section whose heading, text, definitions or exceptions differ between two readings gives `instrument_changed` from `assess`, naming the section path; a section present in one reading only gives it too, naming which. A reading with no sections read on either side reports nothing about sections and says why (R23).
- **R17** Tested on captured codifier sections (about 50 sections of one code and about 10 charter sections, captured as the plane captures them, with their provenance, under the module's test tree; time-law §5), on the two measured instruments, and on the test profile's code: every section boundary of a per-section document is exact, and each fixture's definitions and exceptions are as a member read them.
- **R18** The new readings change no verdict the type gave before: the existing fixtures of every type give the same `type`, `confidence`, entities and events they give in `docprofile` today, apart from the added `form`, `sections`, `definitions` and `exceptions`.
- **R19** `sections`, `definitions` and `exceptions` each carry a stated count of what was read and, where a passage looked definitional or exceptive but could not be placed in a section, list it with `section: null` and why, never dropping it.

**`policy`: a policy's header, sections and provisions read** (T35-12; N640; POLICIES L2, PO13, Capability Ladders §6B.4; K1713, K1740, K1862)
- **R25** `policy` is the type of a document a body or organisation issues as one item of a policy series: an administrative instruction, a general or special order, a training bulletin, a board policy or regulation, a company's policy. `detect` matches at CERTAIN only when the document's header block (R26) names one of the view's series (`jurisdictions` R63) by its `label` or its `cite`, with a number that series reads; otherwise never CERTAIN. With no series or no header labels in the view it is never CERTAIN, and says the active profiles supply none (R24). Its `contract` is `SUBSTANCE` (R4). *(not yet met: T35)*
- **R26** `parse` gives `header`, the header block as the document states it: `type`, `number`, `title`, `effective`, `supersedes`, `reference` (the authority or related instruments named), `coordinator` (the owner or evaluation coordinator), `review_due` and `revision_cycle`, each, where read, `{text, start, end, source}`, `text` as written and `source` as R7, each field found by the labels the view's `policy_headers` give for it (`jurisdictions` R69), never by labels held in code; `type` also carries the `key` and `series` of the view's series it names, and `number` the series' `normal` (`jurisdictions` R63). A date field also carries `date`, `YYYY-MM-DD`, when its text is a whole calendar date, else `date: null` with `why`: a placeholder ("Effective Date: XX XX 21") is kept as written, never completed or guessed. A field not read is absent, and `header.missing` names it. The header is what the document claims; whether this copy is in force, a draft or superseded is `standards`' `copy` (T35-31), never this reader's. *(not yet met: T35)*
- **R27** `parse` gives `sections` as R10 states them for `regulation` (`{path, number, heading, start, end, source}`, document order), `path` the outline numbering from the top down (I., A., 1., a., 1)), which is place-free and read in code; where no heading is matched, `sections` is empty with `sections_why` (R11). *(not yet met: T35)*
- **R28** `parse` gives `definitions` in R13's form (`{term, start, end, source, section}`), from the definitional voice and from the entries of a section headed as definitions ("DEFINITIONS", "Definitions"), a term given twice giving two entries. *(not yet met: T35)*
- **R29** `parse` gives `applicability`: each passage stating to whom or what the policy applies (a section headed "Applicability" or "Scope", "This order applies to …", "applies to all …"), as `{start, end, source, section}`. A passage is an extent, never resolved to an office, unit or person. *(not yet met: T35)*
- **R30** `parse` gives `responsibilities`: each row of a two-column responsible-party and action table, as `{party, action, step?, start, end, source, section}` in row order, `party` and `action` the cells as written and `step` a row number the table prints. A table whose columns cannot be told apart is listed in `responsibilities_unread` with its extent and why, never dropped and never split by guess. *(not yet met: T35)*
- **R31** `parse` gives `timeframes`: each passage stating a period or time limit ("within 24 hours", "no later than 10 calendar days", "annually"), as `{text, amount?, units?, start, end, source, section}`, `amount` and `units` (`minutes`, `hours`, `days`, `business_days`, `weeks`, `months`, `years`) only where the text states them plainly, else absent. A timeframe is a reading, never a deadline: nothing here counts it (`civil-time`) or makes it a duty. *(not yet met: T35)*
- **R32** (K1722; DEC-145 (1)) The readings are never force: nothing `policy` gives labels a provision required, recommended, allowed or discretionary, or names who holds a discretion and on what criteria; a member confirms a force in `standards`, on the document's own words. Nothing here is recorded as a standard, a duty or a law relation (R15). *(not yet met: T35)*
- **R33** `sections`, `definitions`, `applicability`, `responsibilities` and `timeframes` each carry a stated count of what was read; a passage of one of these kinds that cannot be placed in a section is listed with `section: null` and why, never dropped (R19). *(not yet met: T35)*
- **R34** `assess` gives `instrument_changed` when a header field (R26) or a section's heading, text, definitions, applicability, responsibilities or timeframes differ between two readings, naming the field or the section path; a section present in one reading only gives it too, naming which. A reading with no header or sections read on either side reports nothing about them and says why (R23). A difference between two given readings is a reading; a change made without notice is `following`'s to notice (K1727), never claimed here. *(not yet met: T35)*
- **R35** (K1862 (1)) Measured first: the job captures 50 public policies of the City and the Oakland Police Department (Administrative Instructions, Departmental General Orders, Special Orders; posted under Penal Code §13650, `build/plan/study-policies/world.md` line 52) as the plane captures them, with their provenance, under the module's test tree; records, as a dated measurement, the reader's accuracy per header field (R26) and on section boundaries (R27) against a member's reading of each; and builds `policy` only if it reads the header block's fields correctly for at least 90% of the 50, then tests R25–R34 on those fixtures and on the test profile's series. Below that target, or if it cannot fetch them, R25–R34 wait as a measurement: `policy` is not registered, R1 lists the seven types as before, and no other requirement changes. *(not yet met: T35)*
- **R36** (amends R18) Adding `policy` changes no verdict another type gave: every existing fixture of every type gives the same `type`, `confidence`, entities and events, and none is read as `policy`. *(not yet met: T35)*

### Invariants

- **R20** (was `docprofile` R30) No place is named in this module's code. Every local fact a type tests for (R3) comes from the active profiles; the tests include at least one profile that is not the first profile, for every type.
- **R21** (was `docprofile` R31) Deterministic over its inputs, apart from R8; nothing in this module reads a store or the network.
- **R22** (was `docprofile` R32, the types' share) An unrecognised document is never assumed decorated, and a type applied without CERTAIN confidence never asserts "unchanged".
- **R23** (was `docprofile` R33) A reading, or a diff of two readings, that found nothing is a failed reader stated as such, never an emptied or unchanged document; a mass removal is never reported from a failed read.
- **R24** (was `docprofile` R35) Every "no" (no match, no confidence, no position, no section, no meaningful change) says which kind of no and why.
