## Public

### Purpose

The shape of every answer the plane gives: JSON with the open origin, a refusal decorated with its catalogue row, a store that did not answer told apart from a store that refused, a fault answered with a named code and a correlation id and never its stack, and the policy every served page carries. It holds the catalogue's family list (every module's own check table, read in `build/modules.json` order) that the decoration reads, and the rows of the checks the two doors raise. It routes nothing and admits no one: `control-plane`, `store-door` and `plane` call it.

### Provides

Terms. **The doors** are `control-plane`'s Worker entry and `store-door`'s `dispatch(req)`. A **row** is a catalogue row `{code, check, translation, where, …}` (DEC-49).

**The envelope** (`json`, `doAnswer`, `storeRefusal`, `storeSilent`, `relayAnswer`, `STORE_SILENT_*`, `planeInternalError`)
- **R1** (was `control-plane` R21) Every answer is JSON with `access-control-allow-origin: *`. A forwarded answer is the handler's, with `store` and `tokenClass` added and its HTTP status kept.
- **R2** (was `control-plane` R22) A refusal (`ok: false`, at the top level or in `result`) whose `reason` or `code` has a row, in the catalogue or in a module's own table the door reads (`capture`'s among them, N347), gains `code`, `check` and `translation` where absent. Only those two levels are decorated.
- **R3** (was `control-plane` R23) A store answer that is not JSON carrying a boolean `ok` means the store did not answer. It is refused 502 `STORE_DID_NOT_ANSWER` (C-69.2), naming the op, and is never read as an absence, a refusal or a success. A JSON answer with `ok: false` is the store's own refusal, relayed with its status, code and sentence (`store-door` R1's `BAD_JSON` among them). Every handler that relays a store answer, whichever module holds it, answers so: the plane hands it `storeRefusal` with `doAnswer` and `storeSilent`, and a `refused` answer is relayed through it, never as `STORE_DID_NOT_ANSWER` (N339); and a reply that is no answer is `STORE_DID_NOT_ANSWER` carrying the correlation id `doAnswer` read from the store's internal error, when it gave one (`store-door` R6; N349).
- **R4** (was `control-plane` R24) A public op relaying the store's answer answers the store's own status, and answers R3 on a store failure, never 200.
- **R5** (was `control-plane` R25, the Worker's half; the store's is `store-door` R6) An error thrown anywhere in the Worker's door is answered with a named internal-error code (`PLANE_INTERNAL_ERROR`) and a correlation id. It never carries the stack, the message, a path or a line, and the stack is logged server-side under the correlation id.

**The page policy** (`PAGE_POLICY`, `withPagePolicy`)
- **R6** (was `control-plane` R51; K1943) (DEC-122 (3); N528) Every `text/html` response the plane serves (the signer page and the setup page among them) carries a policy under which a browser loads no script, style, font, image or connection from another origin and sends nothing elsewhere. (T35; F17, K1881) Its `script-src` is nonce-based: each such response carries a fresh nonce (at least 128 bits from a CSPRNG), no two responses the same, and a `script-src` of `'nonce-<that nonce>'` alone, with no `'unsafe-inline'`, no `'unsafe-eval'` and no host; every inline `<script>` element of the page served carries that nonce (the setup page's `NONCE_SLOT`, `setup-page` R28, filled per response; the signing page's script elements given it as the page is served), so the pages run as before and a script they did not ship does not. A test fetches each HTML route twice and finds a policy naming no other origin and no `'unsafe-inline'` in `script-src`, two different nonces, and every script element of each body carrying its response's nonce.
