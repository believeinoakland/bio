## Public

### Purpose

Holds the jurisdiction profiles: every local fact the product uses, as data, each with the measurement it rests on. It lists, returns, validates and combines them. No other module names a place (`build/layers.md`, "No jurisdiction in the product").

### Provides

**The profile.** A plain, JSON-serialisable object. Every section is optional. An absent section means the profile supplies nothing there, never that nothing exists.
- **R1** Identity: `id` (matching `^[a-z0-9][a-z0-9-]*$`), `name`, `covers` (the jurisdictions it covers, a non-empty list of names), and `test` (`true` only for a profile whose facts are made up for tests).
- **R2** A **pattern** is `{re, flags?}`: `re` is a JavaScript regular-expression source, and `flags` is drawn from `i` and `u`. A **basis** is the evidence one fact rests on: a string naming a measurement (`M-157`, or a dated measurement entry such as `2026-07-30`) or a ruling (`D-149`, `DEC-13`, `K4`), or exactly `UNMEASURED` (held, never measured). `TEST` is a basis in a test profile, and only there. Every form, kind, floor, system, mixed host, crosswalk, vocabulary entry, `practice` value, search term and law (R3–R7) carries a `basis`. A basis matches `M-<n>`, `YYYY-MM-DD`, `D-<n>`, `DEC-<n>` or `K<n>`, each optionally qualified by a following word (`M-119 LEG`), several joined by `, ` or `; `; or is `UNMEASURED`; `TEST` only in a test profile.
- **R3** `spaces`: keys from `enactment`, `project`, `fund`, `parcel`, `account`, `object`, `vendor`, `proceeding` (a proceeding's number in its forum's forms, K1452) `person` (one form per person scheme: a Legistar `PersonId`, a filer id, a licence number, a bar number; B1b.3), and, since T34, `body` (a body's number in a legislative system, a Legistar `BodyId`; N569) `office` (an office record's number, a Legistar `OfficeRecordId`, one seat's holding; N613) and `institution` (an institution's number in a registry, one form per institution scheme the profile names, as `person` holds; N574, K1729), each `{label, forms, kinds?}` (`id-spaces` R1).
  - A form is `{form, pattern, normal, clean?, basis}`. `clean` is the formatting removed before matching: `strip` (patterns removed from the start of the value), `spaces` (`remove` or `collapse`), and `upper` (`true`). `normal` is a list of parts, each either a literal string or `{group, unpad?, upper?, default?}`: a capture group of `pattern`, with its leading zeros removed (keeping one character) or its letters upper-cased, and `default` used when the group did not match. So a normal form removes formatting and never changes a digit.
  - A kind (`enactment` only) is `{kind, prefix, floor?, basis}`. `prefix` is a pattern for the words naming the kind before a number, removed before the forms are tried. `floor` is `{first, system, basis}`: the first number of that kind that the system's record holds.
- **R4** `systems`: `[{origin, name, hosts, path?, republishes?, provenance_stated?, basis}]`. `hosts` are lower-case host names. `path` is a pattern over an address's path and query. `republishes: true` marks a publication of another system's material, and `origin` then names the system it republishes. `provenance_stated: false` marks a publication that does not say where its material came from. `mixed_hosts`: `[{host, why, basis}]`, hosts that serve many offices' publications, so an address there names no system.
- **R5** `crosswalks`: `[{space, forms: [a, b], pairs, source, basis}]`. `pairs` lists `[value in form a, value in form b]` as read from a captured crosswalk document. `source` is that capture's content hash (64 hexadecimal characters). A crosswalk is never a pattern (Framework §8.3 rule 2).
- **R6** `vocabulary`: a closed set of keys, each a list of `{pattern, basis}` entries unless noted:
  - `furniture`: lines that publishers repeat on every page (the names of the jurisdiction and its offices, and the legislative record's link labels);
  - `bodies`: how a line names a body that meets or enacts;
  - `member_titles`: the title printed before a member's name;
  - `enactment_markers`: the series marker printed with an enactment number in a caption;
  - `codes`: `{key, label, pattern, basis}`, a code of law cited by section. `pattern` matches the code's name or abbreviation, `key` prefixes the reference's key, and `label` is how the reference is shown;
  - `file_numbers`: `{pattern, system, basis}`, the legislative record's file numbers;
  - `report_titles`, `report_sections`, `recommendation_openers` and `template_blanks`: the staff-report template's titles, section headings, the words that open a recommendation, and unfilled template text that is no part of what a document says;
  - (T33-2) a `codes` entry may also carry `copy` (`official`, `codifier` or `undetermined`: whether the jurisdiction's own text or a codifier's copy is what is served; K1446) and `sections`: `{number, separators, markers}`, `number` a pattern for a section number of that code, `separators` the characters between its parts, and `markers` the order of subsection markers, each `letter`, `numeral`, `paren_letter`, `paren_numeral` or `roman` (`doctypes` R9–R11);
  - (T33-2) `amending`: `{pattern, relation, basis}`, the amending-clause vocabulary, `relation` one of `amends`, `adds`, `repeals`, `renumbers`, `recodifies` (K1446; ladders §2 LAW, D192's temporal relations);
  - (T33-2) `meeting_markers`: `{marker, pattern, basis}`, `marker` `cancelled`, `special` or `concurrent`, the words a legislative system's body or event name carries for each (`legistar-reader` R4); and `body_variants`: `{pattern, organisation, basis}`, the body names that are variants of one organisation, `organisation` its key (K1505 (10); `measures-T33/legistar-events.md` M-P2 (a));
  - (T33-2) `roster_words`: `{pattern, kind?, basis}`, the words that self-name a roster or org chart, `kind` `roster` or `chart` (absent: both; K1517); `staff_titles`: the titles printed with a staff member's name (`roster-reader` R1); `roster_headers`: `{role, pattern, basis}`, `role` one of `name`, `title`, `unit`, `start`, `end`, `as_of`, `employee_id`, `contact` (`roster-reader` R6; K1513);
  - (T33-2) `financial_report_titles`, `budget_book_titles`, `financial_headings` (statement and schedule headings) and `fiscal_year_forms` (how a fiscal year is written in a title or column); `budget_headers`: `{column, pattern, basis}`, `column` one of `fund`, `org`, `department`, `department_code`, `program`, `project`, `account`, `amount`, `period`, `phase` (`budget-doctypes` R1, R7, R12; K1513).
  The keys marked (T33-2) are new in T33 and known keys, never `UNKNOWN_VOCABULARY`.
- **R7** `practice`: `{minutes_due_days?: {value, count?, closures?, basis}}`, the days after a meeting at which absent minutes raise a question, `count` `calendar` (when absent) or `business` (T33-2: OMC 2.20.160 counts business days, K1504); `closures` names one of the profile's closure lists, the days a `business` count skips (an ordinance's holidays are the City's list, K1504 (5); the first profile names `city`), else `VALUE_INVALID`; a `business` count with no `closures` is held, and its due is undetermined (K1533). `search_terms`: `[{term, basis}]`, the terms a search uses when its caller names none. `records_laws`: `[{level, name, citation, basis}]`, the public-records laws that govern the jurisdiction's agencies, by level, one of the law levels of R31 (`federal`, `state`, `county`, `city`).

**The action sections** (added 2026-09-26 for layer 9, Action, `build/layers.md`; every entry carries a `basis`, R2).
- **R23** `standard_sources`: `[{source, kind, issuer, sector?, level?, cite, code?, key?, series?, basis}]`, where the standards an act is measured against come from (a government's, and since T35 an organisation's of any sector, K1713 (3)). `kind` is one of `statute`, `regulation`, `ordinance`, `court`, `policy`, `commitment` and (T35-1) `standard`: a documented standard set by a standards body, a profession, a regulator or an accreditor (Capability Ladders §6C.1; K1713 (1)). The exported `SOURCE_KINDS` stays the first six, unchanged, as `standards` reads it (its R1, R12); the seven, `standard` included, are exported as `STANDARD_SOURCE_KINDS`, which `validate` accepts and `standards` adopts in its own job (T35-31). `issuer` names the body or organisation that makes them; `sector` is its sector (R64). `level` is one of the law levels of R31, given as R31 says. `cite` is a pattern for how one is cited. `code` names a `vocabulary.codes` key when the source is a code of law cited by section. `key` is R50's issuer segment; `series` is R63's.
- **R24** `counterparties`: `[{role, body, level, elected, basis}]`, the offices an action is addressed to, named by official role and body, never by a person. `level` is `state`, `county`, `city` or `district`. `elected: true` marks an elected office, the kind stage 7 (political accountability) addresses. `oversight: true` marks an office that is an oversight or audit body; absent, whether it is one is undetermined (R27).
- **R25** `action_kinds`: `[{kind, label, tier?, laws?, venue?, template?, basis}]`, what a group can file or send. `kind` matches `^[a-z][a-z0-9_]*$` and names no place (a records request is `records_request`, not a law's name). `tier` is `1`, `2` or `3` (Design Requirement 8). `laws` names `records_laws` or `standard_sources` entries that govern it. `venue` is `{name, how, basis}`: where it is filed and by what means (`portal`, `mail`, `email`, `in_person`, `court`). `template` is the text a filing is pre-filled into, or a briefing to counsel is built on, with named blanks, carried with its attribution as R40 states; a Tier 3 kind has no `use: file` template (Design Requirement 8, amended 2026-09-26; K921). `tier` and `venue` are given only where the canon names one; absent, they are undetermined (R27). `advisory` is the advisory note a Tier 2 kind's filing carries, recommending legal review before filing (Design Requirement 8); it is given only on a Tier 2 kind, and absent it is undetermined.
- **R26** `deadlines`: `[{rule, applies_to, units, amount, count?, direction?, starts, roll?, closures?, computation?, extension?, tolling?, observed?, applies_on?, due_at?, citation, status, basis}]`, the periods the law sets, held as data only: `civil-time` counts them (T33-3; K1431, K1444, K1445). `applies_to` names an `action_kinds` kind, or `claim` for a period that binds a legal claim. `units` is `days`, `hours`, `business_hours`, `months` or `years`, and `amount` a positive integer of them; an entry written `days: n` with no `units` (R26 before T33) reads as `units: "days"`, `amount: n`. `count` (with `units: "days"` only) is `calendar` or `business`. `direction` is `forward` (when absent) or `backward` (a period before an event, as a meeting's notice). `starts` says what event starts it: `received`, `filed`, `act`, `known`, `entered`, `served` or `hearing` (the last three COURTS'). `received` is defined once: the counterparty's receipt of the group's request, counted from the group's own `sent` entry (§7 item 1). `roll` is `true` when a last day that is closed moves to the next day that is not (forward) or the previous one (backward). `closures` names the closure list (R47) the rule counts and rolls on. `computation` names a `computation` entry (R46). `extension` is `{days, count, when, citation?}` and is computed by `civil-time`, never ignored. `tolling` is `[{when, citation}]`, the conditions the law suspends the count on. `observed` is a body's practice held beside the rule (R47). `citation` is the provision the period comes from; `status` as R44.
  - (T33-2, K1514) `applies_on`: the anchor's local weekdays a rule applies to (`["mon"]` for OMC 2.20.070(C)'s Monday special meeting, held as its own entry beside the general rule; the later of the two answers is the safe harbour); `due_at`: `"close_of_business"` (the governing office's `hours` close on the due day) or `"HH:MM"` (a stated time on the due day). A deadline's cutoff and receipt rules are read from the `venue` of the `action_kinds` entry its `applies_to` names (R48).
- **R88** (amends R24, R28; T47; N971; `setup-page` R5, retired with no home at T47's L11 fold, K3100) `COUNTERPARTY_LEVELS` is exported: `state`, `county`, `city`, `district`, in that order, frozen, the one vocabulary of an office's level (R24), which `validate` reads (a counterparty `level` outside it is `LEVEL_UNKNOWN`) and a caller offering an office's level imports and repeats none of. It is not a law's level (R31).
- **R31** `LAW_LEVELS` is exported: `federal`, `state`, `county`, `city`, in that order, the one vocabulary of a law's level (K108: no level the profile already distinguishes is merged). D-149's `local`, on an action recorded before this vocabulary, is read as written and stated as "below the state, county or city not recorded"; nothing new is recorded as `local`. It is the vocabulary of `records_laws` (R7), of `standard_sources` (R23) and of an action's governing laws (D-149), which `actions` imports from here and holds no copy of. An office's level (R24) is not a law's level and keeps its own vocabulary. (T35-1; K1453, K1713 (3), K1742) The four levels stay the levels of law; they are not widened for issuers outside government. A `standard_sources` entry of kind `statute`, `regulation`, `ordinance` or `court` carries a level; one of kind `policy`, `commitment` or `standard` carries a level only when its issuer is a government at one of the four (a city's administrative instructions, `city`), and otherwise none: its `sector` (R64) says what issuer it is (a school district's board policies, `government` with no level; a standards body's standards, `association`; a company's code of conduct, `company`). An entry with no level is never read as `local`, nor as any level.
- **R32** `legal_organisations`: `[{name, evaluates, contacts, basis}]`, the legal organisations equipped to evaluate and file Tier 3 actions (Design Requirement 8). `evaluates` is a non-empty list of `action_kinds` kinds, each of Tier 3. `contacts` is a non-empty list of `{how, value}`, `how` one of `web`, `email`, `phone`, `mail`, `value` a non-empty string.
- **R33** `holidays`: `[{year, days, basis}]`, the days on which the jurisdiction's offices are closed, for counting business days (R26's `business` count). `year` is a four-digit year; `days` is a list of `{date, name}`, each `date` a `YYYY-MM-DD` in that year, no date twice. A year listed is complete: a business day is a Monday to Friday that is not one of that year's days. A business-day count that reaches into a year the profile does not list is undetermined (R27), never counted as though that year had no holidays.
- **R39** An `action_kinds` entry (R25) may carry `evidence: {standard, accepts, contestable?, basis}`: `standard` in words (at most 200 characters, naming the rule or practice, for example a rule of evidence by its number); `accepts` a non-empty list of `{grade, coattested?}` the venue admits, `grade` a letter of `BASIS_GRADES`, read from `record-grammar` (its R16; K624 (6)), and `coattested: true` requiring the capture's co-attestation (its trusted timestamp and co-archive); `contestable` a list in the same form of what the venue admits but the opposition may contest; `basis` as every fact's (R30). Refusals join R28. Combined as one value per kind (R29). Absent, the venue's standard reads undetermined (R27) and `filings` R25 shows the grades alone.
- **R40** (K921; K5510, K5527 (4), K5528 T2) An `action_kinds` entry's `template` (R25) is `{id, version, use, text, notes, authored_by, contributors, reviews, approved_by, approved_at, basis}`: `id` matching `^TPL-[a-z0-9][a-z0-9-]*$`, no id twice in the profile; `version` a positive integer; `use` `file` or `brief` (`filing-templates`' uses); `text` non-empty; `notes` text, possibly empty; `authored_by` and `approved_by` non-empty names, different; `contributors` a list of names; `reviews` `[{reviewer, kind, organisation?, credential?, scope, outcome, at, reviewed_text_sha?}]`, `kind` `member` or `professional`, `outcome` `no_concerns`, `concerns` or `changes_requested`; `approved_at` a `YYYY-MM-DD`; `basis` a ruling (`K<n>`), or `TEST` in a test profile. A template given as bare text or missing any of these is `TEMPLATE_UNATTRIBUTED`, naming the field; a value of the wrong form `VALUE_INVALID`. Its blanks are judged by `filing-templates` (its R15), not here. (T53) `reviewed_text_sha` is the lowercase hex SHA-256 of the text as reviewed (a template's `text` as UTF-8 bytes; a guide's `items` in `record-grammar`'s `canonicalJson`, K5528 T2); it is optional in the shape (a member review needs none) and **required for a review to count** as the professional review (R126). A review with any other field, or a `reviewed_text_sha` that is not 64 lowercase hex characters, is `VALUE_INVALID` naming it. Test: a review with a well-formed hash loads; one with a short or upper-case value is `VALUE_INVALID` naming `reviews[0].reviewed_text_sha`; a review without it loads and is not counted (R126). Control: a profile with no texts loads unchanged; R40's other rules are unchanged.
- **R41** (K921) `time_zone`: `{value, status, basis}`, `value` an IANA time-zone name (`Area/Location`, or `UTC`), else `VALUE_INVALID`. A known section. One value per key (R15).
- **R42** (K921) A counterparty (R24) or a kind's `venue` (R25) may carry `hours`: `{weekly: [{day, open, close}], status, basis}`, `day` one of `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`, `open` and `close` `HH:MM` (24-hour) with `open` before `close`, one day possibly listed more than once for split hours but never with overlapping spans; a day not listed is closed. Absent, the office's hours are undetermined (R27). `HOURS_INVALID` otherwise.
- **R43** (K921, K925 (1)) A `holidays` entry (R33) may carry `offices`: a non-empty list, each a counterparty `role` of the profile (R24) or a kind whose `venue` the entry closes (`{venue: <kind>}`); absent, the entry applies to every office. A year may then be listed once for all offices and once for each distinct `offices` list, never twice for the same list (`HOLIDAY_INVALID`, also for an `offices` entry naming no role or kind of the profile). A business-day count for an office uses the entries for all offices and those naming it; each such entry is complete for its year and its offices (R33).
- **R44** (K921) Every `holidays` entry, `hours` and `time_zone` carries `status`: `researched` (its basis a measurement, `M-<n>` or a dated entry; in a test profile, `TEST`) or `ruled` (its basis a ruling, `D-<n>`, `DEC-<n>` or `K<n>`). In a test profile, and only there, `TEST` stands for either status's basis (R22) (K934). A status outside these, or one whose basis is of the other form, is `BASIS_INVALID`. A fact without a source is not written (it stays absent, undetermined, R27); `UNMEASURED` is not a basis for these facts. (T33-2; the audit's R44 change, K1445) The same holds for every `deadlines` entry (R26) and for the calendar facts T33 adds (`weekend`, `computation`, a closure list, a channel's `cutoff`, `outages` and `receipt`, `fiscal_year`, `recurrences`, `lawful_demands`): each carries `status` and a sourced basis, and `UNMEASURED` is refused `BASIS_INVALID` there.
- **R27** An absent action section means the profile supplies nothing there. A module that needs one of these facts and finds none answers undetermined, never a default (R16).

**The pointers** (T48-2; N847; DEC-227 (3), (4); K3186, K3190; every entry carries `basis`, R2).
- **R89** (T48; N847; DEC-227 (3)) `pointers`: `[{kind, name, does, contacts, hours?, languages?, source, status, basis}]`, the places outside Civicsmith a member is sent to when what she needs is a matter hers alone (`wizard-scripts`' `elsewhere` route), researched per place like every other fact and never a member's data. `kind` is one of the frozen exported `POINTER_KINDS`, in this order: `legalaid`, `selfhelp`, `service`, `agency`, `representative`, `tipline` (a new kind is a requirement change). `name` is the body's own name, one line of 1 to 200 characters. `does` says what the body does and for whom, in the profile's words, 1 to 500 characters. `contacts` is a non-empty list of `{how, value}` as R32 has them, `how` one of `web`, `email`, `phone`, `mail` and `address` (a street address, for a pointer only). `hours` is R42's form. `languages` is a non-empty list of tags `isLocale` accepts (R37). `source` is the address or citation read, non-empty. `status` is `researched` and `basis` a dated measurement entry (`YYYY-MM-DD`, optionally qualified, R2), so the date read can be shown with the pointer; in a test profile, `TEST`. R44's rule holds: a pointer without a source is not written, and `UNMEASURED`, a `ruled` status or a basis with no date is `BASIS_INVALID`. A profile may hold several pointers of one kind and none of another. `pointers` is a known section, never `UNKNOWN_SECTION`.
- **R90** (T48; N847; R89; amends R14, R28, R35) `validate` names a malformed pointer by its field: a `kind` outside `POINTER_KINDS` is `KIND_INVALID`; an empty or over-long `name` or `does` is `VALUE_INVALID`; an empty `contacts`, a `how` outside R89's list or an empty `value` is `CONTACT_INVALID`; a malformed `hours` is `HOURS_INVALID`; a language `isLocale` refuses, or an empty `languages`, is `LOCALE_INVALID`; no `source` is `SOURCE_MISSING`; a `status` or `basis` outside R89 is `BASIS_INVALID`. In `combine`, `pointers` are unioned in the order given (R14): an entry equal to an earlier one in everything but its basis and `profile` is kept once, carrying both.

**isLocale(value) → boolean** (R37; T35-1, N700).

**`POINTER_KINDS`** (R89; T48-2): the frozen list of a pointer's kinds, exported for the modules that draw or group pointers.

**list() → `[{id, name, covers, test}]`**
- **R8** Lists every profile held, sorted by `id`. Never throws.

**get(id) → profile or `null`**
- **R9** Returns the held profile with that `id`, or `null` for any other input. Never throws.

**validate(profile) → `{ok, errors}`**
- **R10** `ok` is `true` exactly when `errors` is empty. Each error is `{path, code, detail}`, where `path` names the field (`spaces.parcel.forms[0].pattern`). Every error found is reported, not only the first. Never throws.
- **R11** The codes: `NOT_A_PROFILE` (not an object); `ID_INVALID`, `NAME_MISSING` and `COVERS_MISSING` (R1); `UNKNOWN_SECTION`, `UNKNOWN_SPACE` and `UNKNOWN_VOCABULARY` (a key outside R3–R7); `BASIS_MISSING` and `BASIS_INVALID` (R2, including `TEST` outside a test profile); `PATTERN_INVALID` (the source does not compile, or a flag is outside R2); `NORMAL_INVALID` (a group the pattern lacks, or a transform outside R3); `DUPLICATE_FORM` (one form name twice in a space); `SYSTEM_UNKNOWN` (a floor or file number naming an origin that none of the profile's systems has); `CROSSWALK_UNSOURCED`, `CROSSWALK_FORM_UNKNOWN` and `CROSSWALK_VALUE_INVALID` (no `source`, a form the space lacks, or a pair value its form does not recognise); `HOST_CONFLICT` (a host that is mixed and also in a system entry with no `path`); `VALUE_INVALID` (a field of the wrong type, such as a floor or `minutes_due_days` that is not a positive integer).
- **R28** The codes for the action sections: `SOURCE_KIND_UNKNOWN`, `LEVEL_UNKNOWN`, `KIND_INVALID` and `COUNT_UNKNOWN` (a value outside R23–R26); `TIER_INVALID` (a tier other than 1, 2 or 3); `TEMPLATE_TIER3` (a `use: file` template on a Tier 3 kind; a `brief` template may serve any tier, K921); `CODE_UNKNOWN` (a `code` no `vocabulary.codes` entry has); `LAW_UNKNOWN` (a `laws` entry no `records_laws` or `standard_sources` entry has); `DEADLINE_KIND_UNKNOWN` (an `applies_to` that is neither `claim` nor a kind of the profile); `DUPLICATE_KIND` (one kind twice); `GRADE_UNKNOWN` (an `evidence` grade outside `BASIS_GRADES`, R39) and `EVIDENCE_NO_STANDARD` (an `evidence` with no `standard`, or an empty `accepts`). `LEVEL_UNKNOWN` also covers a `records_laws` or `standard_sources` level outside R31, and a `standard_sources` entry with no level where R31 requires one (T35-1: a `statute`, `regulation`, `ordinance` or `court` entry; K1742). **combine(list) → `{ok: true, view, conflicts}` or `{ok: false, errors}`.** `list` is the active profiles, in order: each is a held profile's `id` or a profile object. Which profiles are active is an instance setting held by the record. This module takes the list and does not store it.
- **R12** An `id` that is not held gives `UNKNOWN_PROFILE`. An object that fails `validate` gives `INVALID_PROFILE`, with its errors. A profile given twice is combined once. Never throws. Two different profiles with one `id` in the list give `INVALID_PROFILE`; a list that is not an array gives `NOT_A_LIST`; an unknown field in an entry gives `UNKNOWN_SECTION`.
- **R13** `view` has the profile shape, so a consumer can use it wherever it can use a profile. It also has `profiles` (the ids combined, in order), `covers` (the union), and `test` (`true` when any profile combined is a test profile). Each fact in it carries `profile`, the id of the profile it came from, beside its basis. Its `id` is the combined ids joined by `+`, and it has a `name`.
- **R14** List facts are unioned in the order given. An entry equal to an earlier one in everything but its basis and `profile` is kept once, carrying both. Order is kept, because a consumer may take the first match (id-spaces R13). A space's distinct labels are joined with "; ". A merged fact carries the first giver's `basis` and `profile` and `bases: [{profile, basis}]` for every giver.
- **R15** A fact with one value per key is kept only when every profile that gives it gives the same value. Such facts are a kind's floor, a form's definition under its name, a `practice` value, and the origin named by a host and path. When the profiles disagree, the fact is withheld from the view, and `conflicts` gets `{at, values: [{profile, value, basis}], says}`. Two system entries conflict when they share a host, give the same `path` (or both give none), and name different origins. A host that one profile marks mixed and another puts in a system entry with no `path` also conflicts. **combine never chooses between profiles that disagree.** A consumer then finds no fact there, and answers undetermined.
- **R16** An empty list gives `ok: true` and a view with no facts. An instance with no active profile is valid, and every consumer answers undetermined wherever it needs a local fact.
