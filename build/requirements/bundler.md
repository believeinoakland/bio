## Public

### Purpose

Builds each member of the fleet (the plane and the workers) into one bundled artifact with a manifest of hashes, and verifies that a committed artifact is exactly what its source builds, so a stale artifact fails instead of shipping. It also holds the release tooling run from an operator's machine: one version across the fleet, a signed release assembled over the whole fleet with its signed release notice, and a deploy of a signed artifact believed only from the bytes read back.

### Provides

**`discoverMembers(repoRoot?)` → members.**
- **R1** Lists the fleet's members from the repository, each with its directory and entry point, in a stable order.

**`buildMember(member, {write?})` → built.**
- **R2** Bundles the member with one recipe (ES module output, platform-neutral, the declared externals), with the working directory pinned to the member's own directory and symlinks preserved, so the same source gives the same bytes from any checkout layout. (T51 fix round 6, G39; K4616, K4620) A fleet member's and the plane's bundle is pure ASCII: no byte over 0x7F. Comments are stripped (a licence banner is kept, its characters written as `\uXXXX` text), template literals are lowered, strings and identifiers are written ASCII, and every other non-ASCII character of a string or regex literal is written `\uXXXX` (`\u{X}` for an astral one in a `u` or `v` regex) by a pass over the output's tokens that changes no value and no regex pattern or flag. A non-ASCII character anywhere else, including the raw text of a template literal that was not lowered, refuses the build `[NON_ASCII_REMAINS]` naming the line. A descriptor that is neither a fleet member nor the plane (the standalone case checker's) keeps its form; a boolean `bundle.ascii` overrides either way. Provided beside the recipe: `asciiOptions()` (the esbuild options) and `asciiOutput(bytes)` (the pass), for a caller that builds with its own esbuild call (the installer's). Test: a fixture with a non-ASCII character in a comment, a string, an untagged, a tagged and a `String.raw` template and BMP and astral regexes builds to a bundle with no byte over 0x7F whose values and regexes equal the opt-out build's; an unlowered template or an identifier refuses; a descriptor with neither marker is unchanged; the plane and every real member build to no byte over 0x7F, and the plane boots and answers one Store op in raw workerd at `--max-old-space-size=60`.
- **R3** Writes the artifact only when `write` is true.

**`manifestFrom(member, built)` → manifest.**
- **R4** Records the SHA-256 of the artifact, of every first-party input file, and of the member's lockfile, and the pinned working directory. (T51 fix round 6, G39; K4620) The manifest's `recipe` also records `ascii`: R2's options, or `false` for an opt-out.

**`writeMember(member)`.**
- **R5** Builds with writing on and writes the artifact and its manifest.

**`verifyStatic(member)` → result.**
- **R6** With no dependencies installed, reports stale when any recorded input's hash, or the lockfile's, differs from the file now; reports which input. (T51 fix round 6, G39; K4620) A committed manifest whose `recipe.ascii` differs from the tree's is stale, naming `recipe.ascii`; the fleet gate also holds every committed bundle to no byte over 0x7F.

**`verifyFresh(member, committed)` → result.**
- **R7** Where the member's dependencies are installed, rebuilds without writing and reports stale unless the bytes equal the committed artifact exactly; where they are not installed, says it could not check, never that the artifact is fresh.

**`unresolvableSpecifiers(text, allowed?)` → list.**
- **R8** Lists every static `import` or `export … from` specifier in a built artifact that is neither bundled nor in the allowed externals (what a one-part upload must resolve at instantiation). A dynamic `import()` is not listed; `verifyFresh` checks those through the build's own metafile. (T51 fix round 6, G39; K4620) The scan accepts an `import` or `export` statement after `}` (a minified bundle).

**Provenance (`readGitProvenance`, `stateOf`, `classifyDiscovered`, `reportProvenance`).**
- **R9** For a set of files, states for each whether it is committed and unchanged, changed, or untracked in the repository, and reports it.

**Release tooling (T19 BOB-5).** The commands below are run by an operator and named by their usage line; each refusal prints `REFUSED [CODE]: …` to stderr and exits non-zero, before any write or upload unless stated.

**`stripJsonc(text)`, `parseJsonc(text, what?)` → string, object.**
- **R11** `stripJsonc` removes `//` line comments (keeping their newline) and `/* … */` block comments, and nothing inside a single- or double-quoted string (escapes honoured), so a `//` in a URL survives. `parseJsonc` returns the parsed object, and throws `Error` reading `<what> did not parse as JSONC: …` otherwise. One implementation serves every caller in the module.

**`versionSites(root?)`, `resolveVersion(root?)`, `resolveVersionOrExit(root?, label?)`.**
- **R12** The sites are, for the plane and then each discovered member (R1), `<dir>/package.json`'s `version` and `<dir>/wrangler.jsonc`'s `vars.VERSION`, each where present. `bio-plane/package.json` is the authority. `resolveVersion` returns `{ok:true, version, sites}` when every site equals the authority; otherwise `{ok:false, version, sites, findings}`, one finding per disagreeing site (behind or ahead) naming the file, the key and the edit, and `version: null` with one finding when the authority declares none. Never throws on skew. `resolveVersionOrExit` returns the version, or prints `REFUSED [VERSION_SKEW]` with the findings and exits 1.

**`deriveBindings(cfg, {slug, version, instanceClaudeToken?, instanceAiToken?})` → bindings.**
- **R13** From a parsed `wrangler.jsonc`: `plain_text` `VERSION` (the argument) and `INSTANCE_NAME` (the slug); each `vars` entry but `VERSION` as `plain_text`; each `r2_buckets` entry as `r2_bucket`; each `services` entry as `service`, a target of `bio-plane` replaced by the slug and any other kept as written; `browser` when declared; `secret_text` `INSTANCE_AI_TOKEN` only when given; never a Claude credential (K1502). No Durable Object binding is emitted.
- **R14** Throws `REFUSED [NO_SLUG]` or `[NO_VERSION]` when either is missing; `[UNKNOWN_BINDING_CLASS]` naming each other binding key the config declares non-empty (`kv_namespaces`, `d1_databases`, `queues`, `analytics_engine_datasets`, `ai`, `vectorize`, `hyperdrive`, `dispatch_namespaces`, `mtls_certificates`, `send_email`, `wasm_modules`, `data_blobs`, `text_blobs`); `[BROWSER_BINDING_UNNAMED]` for a `browser` with no `binding`; `[PHANTOM_TARGET]` if a derived service still targets `bio-plane`. `serviceTargets(bindings, slug)` lists the service targets other than the slug.

**`deriveLimits(cfg)`, `limitsReadBack(settings, want)`.**
- **R15** `deriveLimits` returns `{subrequests, cpu_ms?}` from `cfg.limits`; throws `REFUSED [NO_SUBREQUEST_LIMIT]` unless `subrequests` is a positive integer, and `[UNKNOWN_LIMIT_KEY]` for any key but `subrequests` and `cpu_ms`. `limitsReadBack` returns `{verdict, why}`: `UNDETERMINED` when the settings are unreadable or state no `limits.subrequests`, `MISMATCH` when it differs from `want.subrequests`, `MATCH` otherwise. Neither makes a request.

  (T51, G54; K4711) `deriveObservability(cfg)` returns `{enabled: true}` and throws `REFUSED [NO_OBSERVABILITY]` unless `cfg.observability.enabled` is `true`, and `[UNKNOWN_OBSERVABILITY_KEY]` for any key but `enabled`; `observabilityReadBack(settings, want)` returns `{verdict, why}`: `UNREADABLE` when the settings are unreadable, `MISMATCH` when they state no `observability` or an `enabled` that differs from `want.enabled`, `MATCH` otherwise. Neither makes a request.
**Build the plane (`npm run build` in `bio-plane/`, `scripts/build-plane.mjs`).**
- **R16** (T51; K3807, K3814 amend) Writes the plane's bundle and manifest by R5, and prints the artifact's size and SHA-256 and the manifest's input counts. The build renders and embeds no signing page: it calls no step that generates a source file, so the bundle is built from the committed sources alone.

**Deploy the plane (`node scripts/deploy.mjs <slug> <version> <asset>`, `CF_TOKEN`, `CF_ACCT`).**
- **R17** Refuses `[VERSION_SKEW]` (R12) and `[VERSION_ARGUMENT_DISAGREES]` when `<version>` is not the resolved version; exits 2 with its usage line when an argument, `CF_TOKEN` or `CF_ACCT` is missing; refuses (exit 3) a slug that names a non-plane worker (`pdf-worker`; K3807: no deploy names the old `civicos` Worker, which is deleted, and no refusal message points to the old interface's deploy script); refuses `[BINDING_TARGET_MISSING]` or `[PREFLIGHT_UNREADABLE]` unless every service target other than the slug (R14) is found in the account.
- **R18** Uploads the asset with R13's bindings and R15's limits, keeping the instance's `secret_text`, `durable_object_namespace` and `service` bindings, and states whether each instance token was sent without printing it. It reports success only when the script read back from the account hashes to the asset's SHA-256 (up to four attempts) and R15's read-back is `MATCH` (`[LIMITS_MISMATCH]` exits 1); when the bytes never match it exits 1 saying nothing was applied. When the deployed bytes already match, the instance serves `<version>` and the limits match, it uploads nothing and exits 0. After success it waits up to 60 seconds for `/version` to answer `<version>` and says so either way, without failing. (T51 fix round 6, G1; K4565, K4566, K4570) **The plane's schedules.** After the uploaded bytes and the limits read back, the deploy sets the script's cron schedules, `PUT .../workers/scripts/<slug>/schedules` with `[{cron}]` for each cron of the plane's `wrangler.jsonc` `triggers.crons` (none declared: none), and reads them back (GET); it reports success and waits on the rollout only when the script holds exactly those crons. A PUT that fails or is rejected exits 1 `[SCHEDULES_NOT_SET]`, a read-back that cannot be read `[SCHEDULES_UNREADABLE]`, one that lacks a cron or holds another `[SCHEDULES_MISMATCH]`, each as "REFUSING TO REPORT SUCCESS", never a note. A `triggers.crons` that is not a list of at most three distinct five-field cron strings is refused `[INVALID_CRONS]` before any request. `deriveCrons(cfg)` and `schedulesReadBack(held, want)` are provided beside R15's functions and make no request. Test: the deploy against a stub account whose script PUT clears schedules: the schedules PUT follows the script PUT and a read-back follows that; each refusal above exits 1 with no rollout line; a config with no cron sets none; controls: invalid lists refuse before any request.

  (T51, G54; K4711) The upload carries `observability` from R15 (a raw script upload that sends none turns Workers Logs off), and the deploy reports success only when the script's settings, read back (up to three reads) after the bytes and R15's limits and before the schedules are set, report `observability.enabled` as sent: `[OBSERVABILITY_MISMATCH]` (off, absent or different) or `[OBSERVABILITY_UNREADABLE]` exit 1 as 'REFUSING TO REPORT SUCCESS', with no schedules set and no rollout wait. A `wrangler.jsonc` that does not state `observability: { enabled: true }` is refused `[NO_OBSERVABILITY]` (or `[UNKNOWN_OBSERVABILITY_KEY]`) before any request. Test: `g54-observability.test.mjs`.
**Deploy a fleet member (`node bio-plane/scripts/deploy-fleet.mjs <member> --instance <slug> [--dry-run]`, `CF_TOKEN` or `CLOUDFLARE_API_TOKEN`).** It reads no limits back. The plane's deploy (`deploy.mjs`, R18), when R15's read-back is `UNDETERMINED` (the account's settings are unreadable or state no `limits.subrequests`), prints that the ceiling sent is not confirmed, never prints `verified` for the limit, waits on the rollout and exits 0: the bytes are deployed, and only the limit is unconfirmed (K761).
- **R19** Refuses `[NO_MEMBER]`, `[NO_INSTANCE]` (no default), `[NOT_A_FLEET_MEMBER]` (no `fleet-member.json`; its message names no deploy for the old interface, K3807), `[NO_CONFIG]`, `[UNPARSEABLE_CONFIG]`, `[ACCOUNT_NOT_PINNED]` (no `account_id`), `[NO_TOKEN]`, and `[BINDING_TARGET_MISSING]` or `[PREFLIGHT_UNREADABLE]` for a service target not found in the account. The `bio-plane` service target becomes the slug and every other is kept as written; it prints the member, instance, account and each binding.
- **R20** With `--dry-run` it deploys nothing and exits 0. Otherwise it deploys through `wrangler deploy` from the member's directory with a generated config that is removed afterwards whether or not the deploy succeeded; the tracked `wrangler.jsonc` is never written. It exits with wrangler's failure, or waits up to 60 seconds for the member's `/version` to answer its declared `VERSION` and says so either way.

**Rebuild stale bundles (`node bio-plane/scripts/bundles.mjs [--check]`; `run({check})`).**
- **R21** Surveys every guarded bundle (R1's members and the plane) by R6 and names each finding. With `--check` it writes nothing and exits 1 when any is stale, 0 when none. Otherwise it rebuilds each stale member by the member's own `npm run build`, reports it rebuilt only when the artifact's or the manifest's bytes changed (and which), surveys again, and exits 1 when any is still stale or a build failed, 0 otherwise.

**Assemble a release (`node bio-plane/scripts/release-assemble.mjs [--dry-run] [--version V] [--emit-payload F] [--sign | --fleet-sig F]`).**
- **R22** Refuses unless every member's committed artifact is proved fresh by R7 and its manifest (`[NO_ARTIFACT]`, `[NO_MANIFEST]`, `[GUARD_CANNOT_RUN]` when the byte check cannot run, `[STALE_OR_UNINSTALLABLE]`, `[MANIFEST_DISAGREES]`), every declared part is present, hashed, typed and equal to its manifest hash (`[MEMBER_PART_MISSING]`, `[MEMBER_PART_UNHASHED]`, `[MEMBER_PART_UNTYPED]`, `[MEMBER_PART_DISAGREES]`) and every member states its compatibility (`[MEMBER_COMPAT_UNSTATED]`); refuses `[VERSION_SKEW]` (R12), `[VERSION_DISAGREES]` when `--version` is not the resolved version, and `[VERSION_ALREADY_RELEASED]` when `release/RELEASE.json` holds that version with a different plane SHA-256. The fleet payload is signatures' `fleetStatement` (R8) over the plane and every member. `--emit-payload` writes it; `--dry-run` writes nothing else and exits 0.
- **R23** With `--sign` (`BIO_RELEASE_SEED`, else `[NO_SEED]`; `[SIGNING_FAILED]`) it signs the plane asset in `bio-release` and the payload in `bio-release-fleet` (signatures R33); otherwise the fleet signature comes from `--fleet-sig` and the plane's from the current `RELEASE.json`. It refuses `[NO_PLANE_SIG]`, `[NO_FLEET_SIG]`, `[PLANE_SIG_DOES_NOT_COVER_ASSET]` and `[FLEET_SIG_REJECTED]` unless stock `ssh-keygen -Y verify` accepts each signature over its exact bytes for the release's `signer`. Only then does it copy each asset, and each part under `<member>/<path>`, into `release/`, and write `RELEASE.json` with `version`, the plane's `sha256`, `bytes`, `asset`, `sig` and `signer`, `fleet` (each member's `member`, `asset`, `sha256`, `bytes`, `compat`, `services`, `parts`) and `fleetSig`.

**Container members** (T34-6; K1601, K1678 (1), K1705)
- **R24** (N578) A member whose `fleet-member.json` has `"kind": "container"` and an `image` block is a *container member*: R1 discovers and lists it with its kind and its `image`, and it is not bundle-guarded, so R6, R7, R21 and R22's freshness proofs never report it stale, unguarded or missing an artifact for want of a Worker bundle.
- **R25** (N610; K1678 (1)) The release assembly (R22, R23) emits for each container member its `container.json` part, type `Container`: `{class_name, image, scheduling_policy: "default", max_instances, bind}`, `image` written `<repository>@sha256:<64 hex>` from the member's `fleet-member.json` (whatever registry the repository names; R35 states the real fleet's), the other fields as that marker states them, so the fleet signature covers it as it covers every part. A container member whose marker states no image digest in that form, or lacks a field of the part, is refused `[CONTAINER_UNDESCRIBED]` naming the field, before anything is written. (rev. 2 §2 R10; `file-scanner`) A container member whose marker states more than one container class, each with its own image, is emitted one `container.json` part per class, each under its own path and as above for that class (its `class_name`, its own `image`, and the other fields as the marker states them for that class), so the fleet signature covers each; a class lacking any of them is refused `[CONTAINER_UNDESCRIBED]` naming the class and the field. A member with one class is emitted as before. (N772; K2155) A member whose `wrangler.jsonc` binds R2 buckets or states crons is also emitted one `worker.json` part, type `Worker`: `{r2_buckets: [{binding, bucket}], crons}`, `bucket` named by its role (`captures` or `published`), never by an account's bucket name, and `crons` as the member states them, so the fleet signature covers it and an installer installs the buckets and the schedule; a bucket whose role is not one of the two is refused `[WORKER_UNDESCRIBED]` naming the binding; the statement's format is unchanged.
- **R26** (N624; K1705) `deploy-fleet.mjs` deploys a container member: it pushes the member's image to Cloudflare's registry with the account's token, for the project's own copy, then deploys the member's Worker and its container from its own configuration, as R19 and R20 say for every member. (N1242; K3805) It pulls the image by the digest the member's marker names, from whatever registry the marker names (Docker Hub as well as the GitHub copy), and states the address it pulled. A token that cannot reach Containers is refused by name (`[CONTAINERS_UNREACHABLE]`), saying what the account lacks, before anything is pushed or deployed; with `--dry-run` it pushes and deploys nothing.

**Third-party code** (T35-6; K1881; `plan/draft-T35-security-review.md` F20, F21)
- **R27** (F20) The release assembly (R22, R23) adds to each container member's `container.json` part (R25) a field `packages`: every npm package the member's image installs, each `{name, version}`, one per installed copy, sorted by name and then version, as the member's own `package-lock.json` resolves a production install (its packages not marked `dev`). The fleet signature covers it as it covers the part; R25's other fields are unchanged, so an install reads the part as before. A container member whose `package-lock.json` is missing or does not parse, or names an installed package without a version, is refused `[CONTAINER_PACKAGES_UNREAD]` naming the file or the package, before anything is written. (rev. 2 §2 R10) For an image whose packages are not npm's (system packages, as `file-scanner`'s ClamAV, LibreOffice and Poppler are), `packages` is read, in place of a `package-lock.json`, from the member's committed package statement for that image: each package it states, `{name, version}`, sorted as above, the statement pinned with the base image digest it was taken against, which is the base digest the member's marker pins. A statement missing or not parsing, a package without a version, or a statement naming no base digest or another than the marker's is refused `[CONTAINER_PACKAGES_UNREAD]` naming the file, the package or the digest, before anything is written. With more than one class (R25) each part carries its own image's list.
- **R28** (F21) `thirdPartyInventory(root?)` → `{packages, unread}` lists the third-party code the release ships, each entry `{ecosystem, name, version, shippedIn}` (`ecosystem` one of `npm`, `crates.io`, `PyPI`, or the system-package ecosystem a container member's package statement names (R27; T36, rev. 2 §2 R10); `shippedIn` the sorted names of the members, or `bio-plane`, that ship it), one entry per ecosystem, name and version, sorted by ecosystem, name and version. Its sources are: (a) each package the plane's or a member's lockfile resolves for a production install (packages not marked `dev`); (b) each container member's R27 list; (c) each source in the module's own declaration of committed third-party code, an entry naming the member that ships it and either one package `{ecosystem, name, version}` (code generated or copied from a package and committed, as `tesseract-wasm`'s is in `ocr-worker`) or a lock file whose packages it lists (a `Cargo.lock` from which a committed wasm is built, its root crate left out; a pins file of vendored packages, as `court-citations/pins.json` is). A source that is missing or does not parse is named in `unread`, never left out silently. Makes no request; never throws.
- **R29** (F21) `node bio-plane/scripts/release-advisories.mjs [--out F]`, run at each release: for every R28 entry it asks a public advisory database for the advisories known against that ecosystem, name and version, and prints each entry with its advisories (each one's id, summary, severity and fixed version where the database states them), then names every package the release would ship with a known advisory, and the database and the time it was asked. `--out` also writes the report as JSON to `F`. It exits 0 when every entry was checked, whether or not any advisory was found; when R28's `unread` is not empty, or the database cannot be reached or answers unreadably for an entry, it names each one as not checked, never as free of advisories, and exits 1. It writes nothing else and refuses nothing; whether a release proceeds over an advisory is the operator's.

**Assembling apart from signing** (T36-2; K1936 Q4 step 2; N713)
- **R30** A release is assembled apart from its signing. Sessions assemble and never sign: assembly (R22) runs every check and writes what is to be signed (the plane asset and the fleet payload) without the release seed, and no command a session runs reads `BIO_RELEASE_SEED` or writes a signature. Signing runs only in the repository's GitHub Actions environment that holds the seed as its secret and waits for Bob, its required reviewer: one approval signs one release, the plane asset in `bio-release` and the fleet payload in `bio-release-fleet` (R23), and the release is completed from those signatures only when R23's checks accept them. The module names, each by its usage line, the commands the workflow calls, in order; the workflow (`release-sign.yml`) is BOB's, not this module's. (T47; N944, K2937) With `--sign`, the release's `signer` is the public key of the seed in use, derived from it: R23's checks verify both signatures against that key and `RELEASE.json` is written with its line. When the current `RELEASE.json` names a `signer` with a different key, the run refuses `[SIGNER_DISAGREES]`, naming both keys and nothing secret, before signing or writing anything, so a key rotation is the act that edits `signer` (Distribution §10) and never a signing run refused as `[PLANE_SIG_DOES_NOT_COVER_ASSET]`.
- **R31** (N840, K2547) `fleetbundles` also checks, for every fleet member, its built artifact's uncompressed size against a budget, warning past 32 MiB and failing past 48 MiB (Cloudflare's limit is 64 MiB per Worker), and measures the time to evaluate its global scope (a fresh import in the test process), warning past 500 ms (the platform allows 1 s); each member's size and time are printed, so BOB reports them at each layer close.

**The release notice** (T48-4; N1047; K3158; `build/plan/draft-updates.md` §1)
- **R32** (T48; N1047; amends R22, R23, R30) The release assembly also writes, beside the assets, `release/NOTICE.json`: `{version, date, manifest, security, notes, sig, signer}`, the notice each group's Civicsmith checks for (`instance-setup`, T48-62). `version` is the release's (R12); `manifest` the SHA-256 of the fleet payload (R22), so the notice names the whole release it announces; `date`, `security` and `notes` (`{members, administrators, must_do}`: what changed for members, what changed for administrators, and what an administrator must do, in members' words) are read from the committed `release/notes/<version>.json`, `{date, security, notes}`; `sig` is the armored signature over `signatures.releaseNoticeStatement` of the first five fields (its R47) in `signatures`' `NS_RELEASE_NOTICE` (its R46), so the notes are inside what is signed; `signer` the release's `signer` line (R23, R30). Refusals, before anything is written: `[NO_NOTES]` when the notes file is absent; `[NOTES_UNREADABLE]` naming the field when it does not parse or `releaseNoticeStatement` refuses it (`version` disagreeing with the release's included). `--emit-notice F` writes the statement to be signed, as `--emit-payload` does (R22). With `--sign` the notice is signed in the same run as the plane and the payload (R23); otherwise its signature comes from `--notice-sig F` (`[NO_NOTICE_SIG]` when absent). `[NOTICE_SIG_REJECTED]` unless the signature verifies over the statement's exact bytes in `NS_RELEASE_NOTICE` for the release's `signer`. Sessions assemble and never sign the notice, as R30 says. Publishing the notice at the project's fixed public address, and the workflow step that signs and publishes it, are the workflow's (BOB's, `not_product`), not this module's. Test, against R23's fixture repository with a throwaway key: a notice is written whose signature `signatures.verifyReleaseNotice` accepts; controls: a notes file with an empty `members` is `[NOTES_UNREADABLE]`, and a signature over other bytes is `[NOTICE_SIG_REJECTED]`, each writing nothing.
- **R33** (T50; N1170; K3535) The container part of R25 also carries `instance_type`, read from the member's `wrangler.jsonc` container block (each class's own, where a member states several classes), so a team installed from the release runs each container at its declared size, as a fleet deployed by R26 does; a block that states none is emitted without the field (the platform's default), never a guessed one. Test: a member whose configuration names `standard-1` is emitted with it inside the signed part; control: a member naming none is emitted without it.
- **R34** (T50; N1153; K3448; amends R18) The plane's deploy uploads nothing only when the deployed bytes match, `/version` answers `<version>`, the limits match, **and** the bindings R13 derives (each service, R2 bucket and `plain_text` it would send) are all present on the deployed script with the same targets and values; a derived binding missing or different makes the deploy a metadata deploy (the same script, the new bindings), reported as such. Any deploy keeps every `plain_text` binding already on the script that R13 does not derive (`JURISDICTION_PROFILES` and the like), unchanged.
