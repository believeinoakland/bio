## Public

### Purpose

Performs the steps of an AI run for the Worker shell. Given a run's identity and the credential it acts under, it reads the run from the plane, holds it to the account and the pack that serve it, and walks `agent-harness`' control-flow table: for each row it makes the row's plane calls, runs the judgement's model turns and the level sub-sessions when a model is handed to it, ticks the plane after every step with what was observed and spent, and closes the run through the plane. It decides no step (the table does), words none of the shell's refusals (the shell's functions do, handed in as the host), writes nothing itself (every change is made by the plane under the run's credential) and keeps nothing between calls. It also holds the small readers the shell shares with it: how a plane answer is read, what a read tool hands a model of a file, which pack layers a model may load, and the model half a conversation's usage is kept in.

### Provides

Terms. A **refusal** is `{ok:false, reason, code, detail, worker, …extra}` with `reason` equal to `code`, answered as a response by the shell's `host.refusal`. The **plane** is reached only through `host.askPlane`. A plane answer is **silent**, **refused** or a **result** as R44 says. A **segment** is one invocation of `driveHarness`: it walks the table until the run ends or the segment meets a bound of its own (the turns or bytes of the model's meter, the wall `deadline`, `maxSteps`), and the run goes on after a bound of the segment's.

**`driveHarness(host, env, {runId, store, credential, judgements, maxSteps, account, model, deadline, progress, preflight})`.** Answers `{ready: true}` (`preflight`, after R1–R5 have passed), `{refusal}` (a response from the host's functions) or the segment's result: `{mode, trace, passes, ended, logged, submitted, target, refusals, adjusted, verbatimResubmits, resumedFrom, logRefused, presentUnbacked, fanout, reportsTaken, reportsRefused, citationsReread, holdings, budget, segmentStopped, segmentEnd}`, from which the shell assembles `agent-worker` R28's answer. Its facts come from the record, never the caller:

- **R1** (moved from `agent-worker` R9) `op=airun` for the run: silent 502 `PLANE_SILENT`; refused 403 `PLANE_REFUSED`; no session 404 `NO_SUCH_RUN`. Mode, budget, pass limit and context are read from it; a `mode` in the body has no effect.
- **R2** (moved from `agent-worker` R10) When the run's recorded account holder (`session.principal.ref`, ai-runs R52: the member whose act opened it, never `principal.claude`, which names the paying owner; K2494; or a standing question's author) is not the member whose act the arrived account serves (`agent-worker` R6; an account of `level` `group` serves that member's act, never the group's own, K1755): 409 `RUN_NAMES_A_DIFFERENT_PAYER` with `recorded` and `supplied` (member ids, never a secret), before any step.
- **R3** (moved from `agent-worker` R11) `op=airunlog` for the run: silent 502, refused 403. `resumed_from` is the number of entries it holds, and a resumed run continues rather than restarting. A resumed run continues at the state `op=airun` publishes (`session.state`, ai-runs R19) when it is not null, and starts from the `resume` step otherwise.
- **R4** (moved from `agent-worker` R12) The target is the run's context: an inquiry context's id; for a project context, the one question in its published `context.questions`; otherwise `null`, with a `basis` stating why (UNDETERMINED: none, several, not published, or an unread context kind). Never a project id.
- **R5** (split from `agent-worker` R48; N695, K1864, K2063 (9); R34) **The pack a run's model is instructed by is the one the plane publishes, held to the run's record, before any turn.** When model turns run (a `model` is passed), after the payer check (R2) and before the log read (R3), the segment reads the rendered pack apart from the rest of what the plane publishes, `op=agentpack` under the run's credential, and takes it only when it carries a version, a resident layer and a disclosed map (`publishedPack`: a partial pack is never used, its version being undetermined) and its version equals the skill version the run recorded (`session.principal.skill`). Otherwise it ends the segment before any turn: a pack that differs gives 409 `SKILL_VERSION_MISMATCH` with `recorded` and `rendered` (both versions); an answer with no usable pack gives the same code with `rendered` null, `rendered_basis` `UNDETERMINED` and `pack_absent` (the plane's own, else the reason it names); a read the plane refuses is passed on as `host.planeRefused` and one it does not answer as `host.planeSilent`. Each of the three runs R34 (the run is not left to lapse silently). The pack is the model's system instruction (`agent-model`'s parent system), its layers are offered as R46 says, and until turns run this changes nothing. Test: a stub plane publishing a pack of another version than the run's: 409 with both versions and no model call; a plane answering `pack: null` with `pack_absent`: 409 with `rendered` null and the plane's reason; a plane refusing the read: its refusal, unchanged; control: the same version proceeds to the first turn and the request the model receives carries the pack's system text; with `judgements` (no model) no `op=agentpack` is sent.

What each row does against the plane:
- **R6** (moved from `agent-worker` R17) `fanout`: one `op=airunspawn` (`half=search`) per level, in the order `meaning`, `content`, `document`, `internet`. A payload carrying a `bias` field: 502 `SPAWN_PAYLOAD_CARRIES_LENS` with `level`; none: 502 `SPAWN_PAYLOAD_MISSING`; refused: 403 `PLANE_REFUSED`. Each sub-session's contract is built key by key (`level, run, context, mode, skill, standard_pair, standard, scope, returns`), frozen, shares no object with another, has `scope` `["meaningrows"]`, and is published. Spends 4 `subsessions`.
- **R7** (moved from `agent-worker` R18) `fanout`, the internet level: one `op=capturerequest` `{run, target, address}` per judged target at level `internet` (its own target, else the run's); each refusal is published; spends one `fetches` per request. This member never fetches.
- **R8** (moved from `agent-worker` R19) `collect`: every returned report is held to the report contract (`agent-harness` R5); a refused one is published in `reports_refused` with its level and code and never becomes an absence. Each distinct cited address (at most 20) is re-read by address through `op=meaningrows` (`rows=leg`, `ids=[address]`); `citations_reread` counts reads that answered.
- **R9** (moved from `agent-worker` R21) `collect`, holdings: each cited address is looked up as a held bundle (`op=search`, `id:"…"`) and its source address, or taken as an address, and read through `op=versionchain`. `holdings` counts each document once by the record's `address_norm`, never by title or text; an item with no chain counts as itself; a refused read leaves that citation's document UNDETERMINED and published.
- **R10** (moved from `agent-worker` R22) `compose`: one `op=meaningrows` read (`rows=leg`); its note says the meaning layer was NOT READ when refused and UNDETERMINED when no rows list came back, never zero. One `level-empty` candidate per level a report found `LOOKED_ABSENT`, made by the table: `level` in the suggestion spelling (`document` → `documents`), `name` `level-empty-<level>`, `observed_at`, the run's target, and a description composed from those facts, with the report's summary appended when it has one.
- **R11** (moved from `agent-worker` R23) `dedup`, before any write: reads `op=basisversions` for the target and drops candidates aimed there whose name is held; candidates aimed at another question go on uncompared, counted in the note. A refused read sends every candidate on and the note says they were compared against nothing.
- **R12** (moved from `agent-worker` R24) `submit`: one candidate at a time, as formed, through `op=suggest` with the run and its target; a refusal goes to `adjust`. A verbatim resubmit the plane reports (`repeated: true`) is counted in `verbatim_resubmits`.
- **R13** (moved from `agent-worker` R25) `adjust`: the candidate is resent only when its canonical bytes differ from the refused submission; otherwise it is dropped and never resent, and the rest of the queue is still written.
- **R14** (moved from `agent-worker` R26) After every step, one `op=airuntick` carries the spend, with `runtime` = the plane calls of that step + 1, and a log entry `{level, subject:"<step> -> <next>", state, governed, condition, terminal, bound, detail}` (`detail` at most 500 characters) only when the step's judgement states a look, or when the step writes a candidate (R33's write entry); a step that looked at nothing and wrote nothing sends none, and no entry carries `NEVER_LOOKED` (observation-log R3, K148; K181). A step judged `PRESENT` is logged `LOOKED_INDETERMINATE` with the stated reason and counted in `present_unbacked`. `logged` counts entries the plane appended; each entry it refused is in `log_refused` and `refusals`. When the tick reports the run ended, the segment stops and `ended.by` is `"the plane's own exit"`. (N588; K1621) The tick's `usage` is a list with one entry `{mode, model, usage, calls}` per conversation that reached the provider since the last tick, `usage` and `calls` exactly as `agent-model` R6 answers them (a `null` passed as `null`), so the plane (`ai-runs` R48) counts each model call, never a conversation as one; a tick after no such conversation carries no `usage`.
- **R15** (moved from `agent-worker` R49) (N293) The `state` a tick publishes (R3's resumable scratch) stays within `run-rules`' `AI_RUN_STATE_MAX_BYTES` (its R10). A tick refused `AI_RUN_STATE_TOO_LARGE` is recorded as a refusal (in `refusals`, at `airuntick`, with its code and check), never read as a failure of the plane.
- **R16** (moved from `agent-worker` R27) `close`: `op=airunclose` names the bound; `ended` is `{bound, by:"the table"}` only when the plane accepted, and `null` with the refusal published when it did not. `max_steps` (at most 400) bounds one invocation and is never reported as a run's bound.
