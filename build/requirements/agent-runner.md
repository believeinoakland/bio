## Public

### Purpose

The container in which a member's Claude subscription runs a model conversation for the plane's fleet: Claude Code, unmodified, with every built-in tool, settings source and disk persistence off, so the model sees only the tools the Worker relays and the Worker's table decides every call. A member's own instance may also hold that member's own Claude sign-in, made and stored by Claude Code itself and serving only that member; nothing else survives a call, and it reaches nothing but Anthropic and the connection it was called on.

### Provides

Terms. The **caller** is `agent-model`'s `signin` path (its R2), through the Container Durable Object. A **conversation request** is `{credential: {kind: "signin", member}, model, system, prompt, tools: [{name, description, input_schema}], max_turns}`. A **relay** is `{tool_use: {id, name, input}}` sent to the caller, answered by `{tool_result: {id, content, is_error?}}`. The **connection** is a WebSocket the caller opens with `fetch("https://agent-runner/conversation", {headers: {Upgrade: "websocket"}})`; its first message is the conversation request, and relays, results and the end (R4) travel on it (K1600). (T37) **The member's instance** is the one `AgentRunner` instance (R12) its caller names by a member's id (`agent-worker` R66); **the sign-in** is Claude Code's own login, run by the unmodified binary in that instance (AT-14, AT-18); **the stored sign-in** is what the binary writes where it runs (AT-27).

**The run, logging and words (T53; AD8, SR50-SR54)**

- **R43** *(not yet met: T53)* (T53; SR54; AD8) The run's surface, all JSON, all refusals `{ok: false, code, trace, detail}` with `detail` read by key (R41):
  - `POST /run` takes `{declared, key, tiers, parts, ceiling, estimate}` (R44, R47, R51) and answers 202 `{ok: true, run, state: "running"}` once the challenge is fetched (R49) and the run has started; `run` is a UUID.
  - `GET /run/status` answers `{ok: true, state, tier, items_done, items_total, incomplete_reason?}`, a closed list of non-secret fields; `state` is `running`, `done`, `incomplete`, `approved`, `discarded` or `expired`.
  - `GET /run/manifest` answers the plaintext manifest once `state` is `done` or `incomplete`; `NO_MANIFEST_YET` before.
  - `POST /run/approve` records that the manifest was shown and approved (R54).
  - `GET /run/bundle` answers the sealed bundle bytes only after approval (R54).
  - `POST /run/discard` wipes the run (R55) and answers `{ok: true, state: "discarded"}`.
  A second `POST /run` on an instance answers 409 `RUN_IN_PROGRESS` (R55); any route on an instance with no run answers 409 `NO_RUN`. Test: each route against a stub issuer and stub provider answers the shape above; every refusal carries `trace` and a `detail` with no place word and no sentinel. Control: `GET /run/bundle` before approval answers `MANIFEST_NOT_SHOWN` with no bytes.

- **R45** *(not yet met: T53)* (T53; SR54; AIR15) **Per-run egress.** At `POST /run` the egress allow-list becomes exactly two hosts, the issuer's (from R10) and the declared provider host, each by exact name, no wildcard and no address (but R58), and is fixed for the run: nothing widens it after the first call, and a host reached by redirect, by an item's record text, by a tool or by the provider's answer is refused. Test: a stub provider redirecting to another host finds the second request refused (R34's line) and the run's record counting it; a request to a third host is refused; the list after the run is one name. - **R46** *(not yet met: T53)* (T53; SR54) **One door out.** Every outbound request of the image, the adapters' included, goes through a single in-process function that checks the host against R45's list before opening a connection, strips nothing and follows no redirect itself; the image opens no socket any other way. It is a second layer beneath the platform's list (R13). Test: a scan of `src/` finds no network call but through that function; a request to an unlisted host through it is refused before a connection and logged (R34); control: the listed host passes. Where the platform cannot vary the list per run (see For BOB), this function alone enforces R45 and says so in `capabilities`.

- **R47** *(not yet met: T53)* (T53; SR54; AIR15) **The key lives in memory for one run.** The `key` arrives only in `POST /run`'s body and is held as bytes in one object of the run's instance; it is never set in an environment variable, argument or file, never logged, never echoed, never in the manifest, payload or any answer, error or trace. It is handed to the adapters only through `agent-model`'s credential resolver for that run's account (BR16: no ambient credential, so a key of any provider in the container's environment is never used), and its bytes are overwritten when the run ends, is discarded or expires. Test: a sentinel key, its base64 and its percent-encoded forms appear in no answer, line, file under the writable paths, manifest or (opened) payload; a sentinel key placed in the environment under each provider's usual name is never sent. - **R48** *(not yet met: T53)* (T53; BR30; SR50) **Raw-exchange capture is a second logging mode, and exists only here.** The image is built with a constant `CAPTURE` true (the production adapters in `agent-worker`'s path never are); in it each call's request body as sent (credentials removed), response body, status and headers, timings, usage and outcome (`ai-gate` R55) go into one in-memory buffer that is bound for the sealed payload alone: never stdout, a log line (R29), a file, an answer, the manifest or a trace. - **R49** *(not yet met: T53)* (T53; SR80; PROCESS §8.3) **The challenge.** At `POST /run`, before any provider call, the container generates its run key pair and asks the issuer (`POST /ai/challenge`, `ai-issuer` R9) for a challenge, sending `{provider, plan, entry_id?, declared_model?, image_digest, bank_version, run_public_key}`; the answer is `{challenge_id, nonce, bank_version, selection_seed, issued_at, expires_at}` (no items and no signature: the container draws its items from the public bank it carries with `ai-gate` `selectItems` over the `selection_seed`, and checks the challenge with `ai-gate` `verifyChallenge`). With no challenge there is no run: an unreachable issuer answers 502 `ISSUER_UNREACHABLE`, a refusal by the issuer 409 `CHALLENGE_REFUSED` with its code, a challenge `verifyChallenge` refuses (another bank version, expired, malformed) 502 `CHALLENGE_INVALID`, each calling no provider. A challenge is used by one run only. Test: a stub issuer's good challenge starts the run; a challenge for another bank version, an expired one, a refusal and an unreachable issuer each answer their code with the provider stub receiving no request. Control: the stub issuer receives the declared plan and the run's public key and no key of the team's provider.

- **R50** *(not yet met: T53)* (T53; BR12; AIR18) **Host pin and served identity, in the container.** Every call goes through `agent-model` with the pin its entry or declared plan requires (only the declared provider, no fallbacks, collection denied, zero-retention routing where offered); a response whose served identity (provider, host, model version) differs from the declared is refused, recorded with its provider request id as `identity_mismatch` in the run record and counted in the manifest, and the run stops where `ai-gate` R18 says. Test: a stub serving another model, or from another host, is refused and recorded, and the manifest's count is 1; control: a faithful stub records none.

- **R51** *(not yet met: T53)* (T53; SR41; AIR16) **Ceilings.** The run carries the ceiling of R44 and enforces it itself: before each call `ai-gate` `meter` answers `ok` or `stop`; on `stop`, or when `seconds` have passed or `calls` are made, it issues no new call, ends the run `incomplete` with `incomplete_reason` (`ceiling_spend`, `ceiling_calls` or `ceiling_time`) and still seals what it holds (R53). Maximum output is capped for each call so that the overshoot past `spend` is bounded by one call's high estimate, which the manifest states. Test: a stub provider whose reported cost reaches the ceiling stops the run with the reason and a sealed bundle marked incomplete; a stalled stub provider stops it at the time ceiling. Control: a run below every ceiling completes `done`.

- **R52** *(not yet met: T53)* (T53; SR52; BR15) **Scrub, then scan, before sealing.** The key and any resolved secret are scrubbed from bodies, headers and error text, in the forms R47 names, then `ai-gate` `scanForSecrets` scans the whole payload and manifest with the exact key, the `key_shapes` of the entry's host profile (`ai-catalogue` R53; for a declared plan, none) and the image's generic shapes. A hit after scrubbing ends the run `incomplete` with `incomplete_reason: "secret_in_payload"`, emits no bundle (R54 answers `SECRET_IN_PAYLOAD`) and wipes the run. Test: a stub provider echoing the sentinel key in an error body gives a payload where it is scrubbed and a clean scan; a stub whose scrub is disabled in the test gives `SECRET_IN_PAYLOAD` and no bytes. Control: a clean run seals.

- **R53** *(not yet met: T53)* (T53; SR60–SR62; AD8) **The bundle is built and sealed inside.** At the run's end the container builds the payload and manifest with `ai-gate` `buildManifest`, `sealPayload` and `signBundle`: the payload sealed to Civicsmith's public key, which the image carries with its key id, so the team cannot open it; the manifest and payload hash signed by the run key, which also signs the image digest declared (R59) and the nonce. It then drops the plaintext payload and the raw buffer (R48); what remains is the manifest and the sealed bytes.
