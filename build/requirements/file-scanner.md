# file-scanner — requirements

**Status** · In force: a new module and fleet member (layer 1, last), by Bob's K1913, K1928, K1929, K1939 and K1949, packaged by BOB (K2008, K2063), entered at T36's opening; every requirement met (FILE-SCANNER #1, K2085).

**Size (P6).** About 600–900 lines with tests for R1–R18, plus two container images (built artifacts, PROCESS-MECHANICS §14); the provider contract and catalogue (R19–R31) add about 1,500–2,500 lines.

## Public

### Purpose

A fleet member in the group's own Cloudflare account, reached only through the plane's `FILE_SCANNER` binding. Given a capture's digest, it reads a duplicate of the stored bytes itself and answers ClamAV's verdict with its signature versions, or a safe view rendered as page images; it keeps ClamAV's signatures mirrored daily in the group's R2. It also holds the **provider contract** for outside security tools of five kinds (file scanners, safe-copy makers, sandboxes, web reputation, log forwarding): each tool's descriptor and data-handling statement, the catalogue of tools offered and refused, and one adapter per tool, which sends a file's bytes, an address's hash prefix or a counts record only to a tool the plane names per call. It holds no record and no key, and never writes, moves or changes a capture (K1888, K1892, K1895, K1913, K1929, K1939).

### Provides

**Terms.** A **target** is `{capture_sha, parts}`: `capture_sha` 64 hex; `parts` `null` for a single object or `[{sha256, bytes}]` in order (`provenance.partsNamed`). A **store** is `"bio"` or `"scratch"`. A **verdict** is `{capture_sha, tool, engine, engine_version, signatures, scanned_at, result, findings, reason?, detail?, vendor_ref?, latency_ms}`: `tool` the descriptor's `provider_id` (`"clamav"` for the built-in scan); `engine` the engine's name as the tool reports it, or the descriptor's single engine; `engine_version` as reported, else the string `"not reported"`; `signatures` an object as the engine states it, or `null`; `result` one of `clean`, `found` (with `findings`, a non-empty list of names), `suspicious` (a sandbox's or heuristic's warning short of a finding, with `findings`), `unknown` (the engine could not decide, `detail`), `not_scanned` (with `reason`); `findings` is `[]` for any other result; `vendor_ref` the tool's id for its result, never a file name. A **descriptor** and a **tool spec** are R19's and R21's.

**POST /scan** `{store, targets}` → `{ok:true, verdicts}` | `{ok:false, code}` (the built-in ClamAV)
- **R1** Request checks, before R2 is addressed: `store` exactly `"bio"` or `"scratch"`, else `NAMESPACE_UNKNOWN` (400); `targets` an array of 1 to `SCAN_BATCH_MAX` targets, else `BAD_BATCH` (400); a target with a malformed digest or parts is answered `not_scanned` with `reason:"BAD_TARGET"`; no `CAPTURES` binding answers `R2_NOT_CONFIGURED` (503).
- **R2** Each target is read from R2 (`${store}/captures/<sha>`, or each part in order with its own digest checked) into the container as a copy; the SHA-256 of the whole must equal `capture_sha`. Otherwise `not_scanned` with `reason` `NOT_FOUND`, `DIGEST_MISMATCH` or `TOO_LARGE` (over `SCAN_MAX_BYTES`, nothing read). (N753; K2099) A target may carry `area: "derived"`: it is then read from `${store}/derived/<sha>` (a rendered view or safe copy that `file-safety` stored, R11, R33), checked and answered exactly as a capture is, so a derived copy is scanned by ClamAV before it is released; any other `area` is `BAD_TARGET` (R1). *(not yet met: T37)*
- **R3** One verdict per target, in request order, from ClamAV (`tool:"clamav"`, `engine:"clamav"`, `engine_version`, `signatures` `{main, daily, bytecode, published}` as the loaded set states them, `scanned_at` an ISO instant). A failure on one target never fails the batch. Archives and documents are scanned inside (ClamAV's archive, OLE2, PDF and HTML scanning on); a file over ClamAV's own size or recursion limits is `unknown` with `detail:"LIMIT:<name>"`, never `clean`.
- **R4** Only the mirrored signatures are used (R6). With none mirrored every target is `not_scanned`, `SIGNATURES_ABSENT`; when the newest set was published more than `SIGNATURES_MAX_AGE_MS` before the scan, `SIGNATURES_STALE`. The set is loaded once per request.

**Outside tools: the provider contract** (K1929 (1)–(3), DEC-168)
- **R19** **The descriptor.** Every outside tool is described by a frozen object `{provider_id, vendor, product, kinds, transport, reach, hosts, engine_family, credentials, test_probe, handling, mode_required, mode_check, licence_note, source_urls, read_on}`: `kinds` a non-empty subset of `scan`, `cdr`, `sandbox`, `url_reputation`, `log_sink`; `transport` one of `https`, `icap`, `syslog_tls`, `azure_blob`; `reach` `public` or `tunnel`; `hosts` the hosts it may reach, by region where the tool has regions; `engine_family` a non-empty list of engine-family names (R31); `credentials` the names of the credential fields, never values; `config` the settings its adapter reads, `[{name, label, required}]` (an empty list when it reads none), so a settings page asks each one by name (N777; K2161) *(not yet met: T37)*; `handling` `{sends, never_sends, recipient, sub_processors, region, file_retention, result_retention, sample_sharing}`, each a stated value or the exact string `"not stated"`. `validateDescriptor(d)` → `{ok:true}` or the first refusal: `DESCRIPTOR_MALFORMED` (with the field); `PROVIDER_SHARES_SAMPLES` when `sample_sharing` is `third_parties` or `public` (K1929 (3)); `HANDLING_NOT_STATED` when `sample_sharing` is `"not stated"` (K1949); `NEVER_SENDS_INCOMPLETE` unless `never_sends` includes `file_name`, `member_identity` and `ip_address`; `ADDRESS_WOULD_LEAVE` for a `url_reputation` descriptor whose `handling.sends` includes `url` or `hostname` and whose `recipient` is not Cloudflare (S12: only a hash prefix, or Cloudflare's lookup within the group's own account); `PRIVATE_MODE_UNVERIFIABLE` when `mode_required` is set and `mode_check` is not (S11). `sample_sharing` is one of `none`, `vendor_internal_research` (S10), `third_parties`, `public`, `"not stated"`. Pure; never throws.
- **R20** **The catalogue** (K1932, DEC-168), exported frozen: `PROVIDERS`, the descriptors offered, each passing R19, exactly: scan, `scanii`, `metadefender-cloud` (private mode), `metadefender-core`, `icap` (generic), `defender-storage`, `sophos-intelix` (`vendor_internal_research`, S10); cdr, `opswat-deep-cdr` (Cloud and Core), `glasswall-halo`; sandbox, `joe-sandbox` (Light and above), `vmray`, `falcon-sandbox` (community access forced off), `wildfire` (`vendor_internal_research`, S10), `sophos-intelix` (dynamic); url_reputation, `cloudflare-intel`, `google-web-risk` (Update API, hash prefixes); log_sink, `splunk-hec`, `sentinel`, `google-secops`, `elastic`, `syslog-tls`, `https-webhook`. `REFUSED_PROVIDERS`, frozen, each `{provider_id, reason}` with R19's code or `NOT_OFFERED`: `virustotal-upload`, `jotti`, `hybrid-analysis`, `joe-sandbox-basic`, `urlscan-io` (`PROVIDER_SHARES_SAMPLES`); `any-run` (`NOT_OFFERED`, S11); `virustotal-url-submit`, `google-web-risk-lookup`, `sophos-intelix-url`, `metadefender-url` (`ADDRESS_WOULD_LEAVE`, S12); `cloudflare-url-scanner` (`NOT_OFFERED`: it visits the address); `cloudflare-logpush` (`NOT_OFFERED`: per-request logs show who opened which file, K1892). `HELD_PROVIDERS`, frozen, each `{provider_id, missing}`: `trend-vision-one`, `votiro`, `checkpoint-threat-extraction` (`HANDLING_NOT_STATED`). A generic transport (`icap`, `syslog-tls`, `https-webhook`) is a template whose `hosts`, `engine_family` (scan) and `handling` the administrator supplies; R19 validates the result. Every catalogued descriptor's `handling` is the study's statement with its `source_urls` and `read_on` date.
- **R21** **The tool spec**, sent by the plane with every outside call: `{provider_id, tool_id, region?, host?, config, credentials, handling_confirmed, monthly_limit_left?}`. Checks before anything is read or sent, each answering `{ok:false, code}` (400) and sending nothing: `PROVIDER_UNKNOWN` (not in `PROVIDERS`, or a generic template with no `host`); `PROVIDER_REFUSED` (in `REFUSED_PROVIDERS`, with its reason); `PROVIDER_HELD`; `KIND_NOT_OFFERED` (the endpoint's kind not in the descriptor's `kinds`); `CREDENTIALS_MISSING` (a named field absent); `HANDLING_NOT_CONFIRMED` when `sample_sharing` is `vendor_internal_research` and `handling_confirmed` is not `true` (S10); `REACH_NOT_BOUND` for `reach:"tunnel"` with no Workers VPC binding installed. The credentials are used for that call only: never stored, written, logged or echoed (R13). Also refused or answered by name (K2085): `TOOL_SPEC_MALFORMED` (no `tool_id`), `REGION_UNKNOWN`, `MONTHLY_LIMIT_REACHED` (`monthly_limit_left` 0 or less), `HOST_NOT_ALLOWED`; a scan whose image cannot be reached or loaded is `not_scanned` with `SCANNER_UNAVAILABLE`; `/provider/refresh` for a tool with no local list answers `NO_LOCAL_LIST`, and R23's result call without `vendor_ref` or an ISO `submitted_at` answers `BAD_RESULT_REQUEST`. (N777; K2161) The spec's `config` holds only fields its descriptor's `config` (R19) names, each `required` one present, else `CONFIG_MISSING` naming the field, nothing sent; a field the list does not name is never sent. *(not yet met: T37)*
- **R22** **Private mode, per call** (S11). For a descriptor with `mode_required`, every request carries the mode's parameters, and the descriptor's `mode_check` runs before the file's bytes or the address's prefix are sent; when it does not confirm the mode, nothing is sent and the answer is `not_scanned` with `reason:"PRIVATE_MODE_UNCONFIRMED"`. When the vendor's answer states a mode other than the one required, the call answers `{ok:false, code:"PRIVATE_MODE_NOT_HONOURED", provider_id}` and no verdict. A stub test drives each such adapter through confirm, refuse-before-send and contradict.

**POST /provider/scan** `{store, target, tool}` → `{ok:true, verdicts}` | `{ok:false, code}`
- **R5** R1 and R2's checks for one target, then R21 and R22; then the bytes are sent to the tool's host for the region the spec names, with the credentials in a header or the transport's own authentication, never in an address (K1874). The request carries the bytes and the tool's required parameters and nothing else: no file name (a fixed neutral part name), no address, no member, no callback, no metadata. Answer: one verdict per engine the tool reports (a single-verdict tool, Scanii, answers one, `engine` its descriptor's), `result` `found` when the engine names any malware finding, else `clean`; `not_scanned` with `TOO_LARGE` (over the descriptor's size limit, nothing sent), `SERVICE_REFUSED` (with the status), `SERVICE_UNREACHABLE` or `TIME_LIMIT` (over `PROVIDER_TIMEOUT_MS`). An asynchronous scanner is polled within the call up to `PROVIDER_TIMEOUT_MS`, then `not_scanned` `TIME_LIMIT`. (N764; K231) An outside tool's address carrying a user name or password is refused `TOOL_ADDRESS_HAS_CREDENTIAL`, a code of this module's own (admission's `CREDENTIAL_IN_ADDRESS`, C-38.10, is another condition) *(not yet met: T37)*.

**POST /provider/sandbox** `{store, target, tool}` → `{ok:true, state:"submitted", vendor_ref, poll_after_ms}` | `{ok:false, code}`; **POST /provider/sandbox/result** `{tool, vendor_ref, submitted_at}` → `{ok:true, state:"running", poll_after_ms}` | `{ok:true, state:"done", verdicts}` | `{ok:false, code}`
- **R23** Submission as R5 (its checks, R21, R22, nothing but the bytes and required parameters). The result call answers `running` until the tool reports done, then one verdict per engine, `result` `found` for a malicious verdict, `suspicious` for a suspicious one, `clean` otherwise, `findings` the behaviour or family names reported. A result asked for more than `SANDBOX_TIMEOUT_MS` after `submitted_at` with the tool still running answers `done` with `not_scanned`, `TIME_LIMIT`. The member keeps nothing between the two calls (R14).

**POST /provider/cdr** `{store, target, tool}` → the rebuilt file | `{ok:false, code}`
- **R24** Checks as R5. The answer's body is the tool's rebuilt file; headers state `x-derived-sha256` (its digest), `x-of` (`capture_sha`), `x-output-type` (its content type), `x-removed` (a JSON list of what the tool reports removed, `[]` when it reports nothing) and `x-tool`. Refusals by name: R5's, and `CDR_UNSUPPORTED_TYPE` when the tool declines the format. The rebuilt file is never written to R2 by this member.

**POST /provider/reputation** `{address, tool}` → `{ok:true, listed, categories, risk, source, lookup_privacy}` | `{ok:false, code}`
- **R25** (S12) `address` a public `https:` or `http:` address, else `BAD_ADDRESS`. Only two lookups exist: `cloudflare-intel` sends the address to Cloudflare's intelligence API in the group's own account (`lookup_privacy:"cloudflare_account"`); `google-web-risk` computes the address's hash prefixes and compares them with its local list (R26), and only on a local match sends the matching prefix, never the address, to the vendor to confirm (`lookup_privacy:"hash_prefix"`). `listed` is `true` exactly when the tool names a threat type or risk; `source` the `provider_id`. No list mirrored for a hash-prefix tool answers `REPUTATION_LIST_ABSENT`; one older than `REPUTATION_LIST_MAX_AGE_MS`, `REPUTATION_LIST_STALE`. A stub test asserts that no request body or address carries the address for `google-web-risk`.
- **R26** `POST /provider/refresh` `{tool}` (a `url_reputation` tool with a local list) fetches the tool's list update, writes it under `reputation/<tool_id>/` in the group's bucket, replacing the previous list only once the new one is complete and checks against the vendor's stated checksum, and answers `{ok, list_version, fetched_at, error?}`. A failed run keeps the last good list.

**POST /provider/forward** `{tool, record}` → `{ok:true, sent_at}` | `{ok:false, code}`
- **R27** (K1892, K1929 (4)) `record` is exactly `{period:{from, to}, counts}`: `from` and `to` ISO instants, `from` before `to`; `counts` an object whose every key is in the frozen `LOG_COUNT_KINDS` and every value a whole number ≥ 0. Any other key, any string value, or any value not a whole number is refused `COUNTS_RECORD_INVALID`, naming the key, and nothing is sent. The record is sent in the tool's transport shape (HEC event, Logs Ingestion array, `ImportLogs`, `_bulk`, RFC 5424 over TLS, JSON POST) and nothing else is added: no file digest, name, member, address or request detail.

**POST /provider/test** `{tool}` → `{ok:true, passed, detail}` | `{ok:false, code}`; **GET /providers** → `{ok:true, offered, refused, held, transports}`
- **R28** The test runs the descriptor's `test_probe` through the same adapter and checks: `scan` and `sandbox`, the EICAR test file answers `found`; `cdr`, a fixture document with a macro answers a rebuilt file with `x-removed` non-empty; `url_reputation`, the vendor's documented test address answers `listed:true`; `log_sink`, a test record (`LOG_COUNT_KINDS` each 0) is accepted. `passed` is `true` only when the check holds; `detail` names what failed. No capture is read.
- **R29** `GET /providers` answers `PROVIDERS` (each descriptor whole, without `credentials` values, which it never holds), `REFUSED_PROVIDERS`, `HELD_PROVIDERS` and the generic templates, for the plane's Settings screens; each descriptor's and each generic template's `config` list (R19) is in it (N777) *(not yet met: T37)*.

**Transports and engines**
- **R30** `icap`: RFC 3507 RESPMOD over TCP or TLS (`connect()`); `204` or a `200` with no infection header is `clean`; `X-Infection-Found` or `X-Virus-ID` is `found` with its names; any other status `unknown` with `detail:"ICAP:<status>"`. `syslog_tls`: RFC 5424 over TLS. `azure_blob`: the file is written to the organization's blob container named in the spec, its scan-result index tag read until present or `PROVIDER_TIMEOUT_MS`, and the blob deleted after; `No threats found` is `clean`, `Malicious` `found`, anything else `unknown`. A port the platform blocks (25) answers `PORT_REFUSED`.
- **R31** (K1929: "a second, different engine") Every verdict's `engine` is in its descriptor's `engine_family`; `engineFamily(provider_id)` answers that list. `differentEngine(a, b)` (exported, pure) is `true` exactly when two verdicts' families share no name; `clamav`'s family is `["clamav"]`; a verdict whose `engine_version` is `"not reported"` still has its family; a generic tool's family is the administrator's statement, and a generic `icap` tool's family includes `"clamav"` when its statement names ClamAV.

**The mirror**
- **R6** Once a day (the member's own scheduled trigger) and on `POST /mirror`, it fetches ClamAV's signature databases from the official database service, as `cvdupdate` does (never `curl` scripts, freshclam FAQ), checks each file's digital signature, and only then writes the set under `clamav/` in the group's bucket, replacing the previous set only after the new one is complete and verified. A failed run leaves the last good set and is stated in `/version` (R8). `POST /mirror` answers `{ok, versions, published, error?}`.

**POST /render** `{store, target, route}` → a PDF | `{ok:false, code}` (the safe view; K1888 (4))
- **R7** `route` is `"pdf"` or `"office"` (Word, presentation, ODF text). The answer is a new PDF whose every page is one image of the source page rendered at `SAFE_VIEW_DPI`, and nothing else of the source: no text layer, script, action, link, form, attachment or metadata. Headers state `x-derived-sha256`, `x-pages`, `x-source-pages` and `x-truncated` (pages beyond `SAFE_VIEW_PAGES_MAX` are not rendered). Refusals by name: R1, R2's, `ENCRYPTED`, `NOT_RENDERABLE`, `TIME_LIMIT`, `RENDER_FAILED` (with the converter's message, at most 300 characters).

**GET /version**, anything else
- **R8** `GET /version` answers `{ok:true, name:"file-scanner", version, clamav_version, signatures:{versions, published, mirrored_at, last_attempt, last_error}, providers:{catalogue_read_on, offered, refused, held}, reputation_lists:[{tool_id, list_version, fetched_at, last_error}], renderer_version, bounds}`; `version` from the running build; no answer carries a credential.
- **R9** Any other method or path is refused 404 `UNKNOWN`.

**The fleet member**
- **R10** The module defines the Worker hosting two container classes: `FileScanner` (ClamAV; `standard-1`, 4 GiB) and `SafeViewRenderer`; R1–R9 and R19–R31 answer through the binding. Its `fleet-member.json` states `kind:"container"`, each image by a digest-pinned reference with its base pinned by digest, in a registry Cloudflare Containers pull from and published as `agent-runner`'s image is (N773; K1898, K2155; never `ghcr.io`, which Containers cannot pull) *(not yet met: T37)*, `bundle`, `class_name`s, `max_instances`, `bind` (`FILE_SCANNER`) and the scheduled trigger, as `agent-runner` R13–R14 do, so `bundler` lists, describes and deploys it. It states an optional Workers VPC binding (`SECURITY_VPC`), absent by default, which the installer adds for a `reach:"tunnel"` tool.

### Invariants

- **R11** It never writes, moves, renames, tags or deletes an object under `captures/`; its only writes are R6's, under `clamav/`, and R26's, under `reputation/`. A test reads every storage call in its sources and finds no other key.
- **R12** Egress: the scanning and rendering containers open no connection; the mirror run reaches only ClamAV's database host; an outside call reaches only a host in its descriptor's `hosts` for the spec's region, or the spec's `host` for a generic template, and no other. A test with a recording `fetch` and `connect` drives every adapter and finds no other host.
- **R13** Nothing but what the descriptor's `handling.sends` names leaves (R5, R23–R27). The credentials arrive per call and are never written, logged or echoed, nor kept past the call; a sentinel-credential test finds them in no output, log line, R2 object or answer.
- **R14** It holds no record and nothing survives a request but the mirror and the reputation lists: each scan, render or outside call runs on a fresh temporary copy, deleted when the request ends. The same bytes and signature set give the same ClamAV verdict.
- **R15** The namespace set is exactly `["bio", "scratch"]`, exported frozen as `NAMESPACES`, with `PLANE_OPS` (empty), as `sheet-worker` R11.
- **R16** Limits, exported by name and stated in `/version`'s `bounds` (R8); its bundle's `bio-member-limits/1` statement carries only the Worker's own Cloudflare limits, equal to its configuration's `limits` (as `sheet-worker` R17): `SCAN_MAX_BYTES` 268,435,456; `SCAN_BATCH_MAX` 200; `SIGNATURES_MAX_AGE_MS` 259,200,000 (72 h); `SAFE_VIEW_DPI` 150; `SAFE_VIEW_PAGES_MAX` 500; `PROVIDER_TIMEOUT_MS` 120,000; `SANDBOX_TIMEOUT_MS` 3,600,000; `REPUTATION_LIST_MAX_AGE_MS` 86,400,000; `LOG_COUNT_KINDS` (frozen list, `file-safety` R35's kinds); and the time budgets measured at the job.
- **R17** Tested offline: the EICAR test file is `found`; a clean corpus PDF, a `.docm` and a ZIP holding EICAR give `clean`, `clean`, `found`; each catalogued adapter runs against a stub of its vendor's documented API that asserts no file name, member or address is sent and that R22's mode parameters are; every `REFUSED_PROVIDERS` and `HELD_PROVIDERS` id is refused by name; the renderer's PDF holds images only. A live call to each outside tool is a release measurement.
- **R18** No place is named in its behaviour or outward text.
