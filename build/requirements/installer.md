## Public

### Purpose

How a group gets its own Civicsmith. The installer is a Worker a group opens in a browser. It installs the signed release, the plane and its fleet, into the group's own Cloudflare account, under a scoped, short-lived permission it never stores. It proves that each part is serving that release before it says so. It updates the group's Civicsmith later without touching its credentials or its record. With it come the page that invites a group to start, and the step that embeds a signed release into the installer.

### Provides

Terms. The **slug** is the copy's name, and becomes its worker name, its address and its recorded group (instance-setup R2). A **member** is a fleet worker the release's signed fleet statement names. A **step** is one emitted line on the progress page, which ends ok or not.

**The routes: `GET /`, `GET /update`, `POST /begin`, `GET /callback`**
- **R1** `GET /` serves the install page and `GET /update` the update page. Any other path is answered 404 with a plain page. No route stores anything.
- **R2** `POST /begin` takes `{mode, slug, instanceAi?}`. `mode` is `update`, or else `install`. A slug outside `GROUP_SLUG_RE`, or equal to `newgroup`, is refused 400 with the grammar in words. An `instanceAi` that is present but not 16–512 printable characters without spaces is refused 400 by name. Otherwise it answers `{ok: true, authorize}`: the authorize address with a PKCE S256 challenge, a fresh `state`, exactly the five scopes (`workers-scripts.write`, `workers-r2.write`, `account-settings.read`, the Containers write scope, under the name Cloudflare's scope list gives it, M-Q8, and `connectivity-directory.bind` for R45's binding, K2155) and exactly the registered redirect. No field of `/begin` carries a Claude credential (R36). It sets an `HttpOnly; Secure; SameSite=Lax` cookie for 15 minutes, holding the verifier, the state, the slug, the mode, the time and any `instanceAi`. (T51-128; N1151, K3818) **A sixth scope, once it is registered:** `account-logs.read`, the scope that reads Logpush jobs (R46), is asked as the sixth, and "exactly the five" reads "exactly the scopes registered on the OAuth client": it is added to `CFG.SCOPES` only after it is registered there (`CFG.SCOPES` is exactly the scopes registered on the client, nothing more; an unregistered one would fail on Cloudflare's side before the founder returns, where no message of this installer can say so), the registration being Bob's act (K3815: the session's token cannot change the client). Until then the five stand and R46 reads the list without it. Test: `/begin`'s authorize address carries the registered set exactly; control: it carries no scope the client does not hold. *(not yet met: T51; waits on the registration, K3818)*
- **R3** `GET /callback` always clears the cookie. An `error` answers "Permission was not granted" and creates nothing. A missing code, a missing or unreadable cookie, a state mismatch, or a cookie older than 15 minutes answers "could not be verified" and creates nothing. Otherwise it streams the progress page and runs the install or the update.

**The install** (steps `auth`, `acct`, `fresh`, `plan`, `r2`, `rel`, `gen`, `install`, `fleet`, `bind`, `ai`, `addr`, `verify`)
- **R4** A refusal at any step before `install` says that nothing was created, and nothing was: the plan probe script is deleted or, when it cannot be, named. The first account the permission lists is used, and it is named on the page.
- **R5** `fresh`: an existing script named for the slug is refused, and nothing is changed. A lookup that fails is refused.
- **R6** `plan`: the plan is found by upload, never by reading a field. A probe upload carrying `limits.cpu_ms` that is refused with code 100328 means Free, and the install is refused, saying that Workers Paid is needed and how to enable it. Any other failure means unknown, and the install is refused. Paid is confirmed.
- **R7** `r2`: both evidence buckets exist afterwards ("already exists" counts), or the install is refused, saying that a payment method is needed.
- **R8** `rel`: the repository's release is installed only when it is newer than the built-in one, its bytes hash to its manifest's `sha256`, and (with signers armed) its `sig` verifies in the release namespace against `ARMED_SIGNERS`. Otherwise the built-in release installs, and the page says why: integrity failed, unsigned, signed by an untrusted key, or unreachable. Nothing that failed verification is ever installed.
- **R9** `gen`: five fresh 32-byte random credentials (the one-time password `ADMIN_TOKEN`, `MEMBER_TOKEN`, `PROBE_TOKEN`, `DAEMON_TOKEN`, and `ACCOUNT_SEAL_SECRET`, the key `credentials` seals members' account references with; K1541, K1678). `INSTANCE_AI_TOKEN` is bound only when the operator supplied a valid one; the installer never generates it. (T36) `gen`: four fresh 32-byte random credentials (the one-time password `ADMIN_TOKEN`, `PROBE_TOKEN`, `DAEMON_TOKEN`, and `ACCOUNT_SEAL_SECRET`); no `MEMBER_TOKEN` is generated (the shared member key is retired; members sign in with their own sessions). R10's "the five credentials" reads "the four credentials".
- **R10** `install`: the plane is uploaded with its `Store` Durable Object (SQLite, migration `v1`), `VERSION`, `INSTANCE_NAME` (the slug), the five credentials, `INSTANCE_AI_TOKEN` when supplied, both buckets, a `SELF` service binding to the slug, `BROWSER`, the members the account already holds, the release's limits (R20) and the plane's compatibility date and flags. When the upload is refused, it retries once without `SELF`, and on success says that the re-check part was left out and the updater adds it. Otherwise it is refused, and nothing is left behind.

Third, only when a member was added, the plane is re-uploaded in the update's shape, bound to every member now present. A refusal of that re-upload is named, and the members stay installed.

The real-size test runs at 29 MB for the install and the update, against the built-in release and a repository release, with the read-back's hash equal byte for byte and a changed byte still named; controls: a built-in release that does not expand to the signed bytes is never uploaded, and a repository release whose bytes do not hash to its manifest is never installed.
