## Public

### Purpose

Reads CSV bytes into `format-registry`'s I7 entry contract: detection from the declared content type (never from the bytes alone; `isDelimitedText` judges name, type and head together), the I2 structure shape and the I2 text shape, the dialect (encoding and delimiter, found by signature and recorded), and typed cells. It also builds the `sheet-cell` and `sheet-range` element references (and the A1 column letters) that `office-readers` and `odf-reader` reuse for the same kinds. It holds no record, reads nothing beyond the bytes it is handed, and writes nothing.

### Provides

One registry entry, the shape `format-registry` requires: `format` (a string), `detect(bytes, contentType)`, `parts(bytes)`, `structure(partsOrBytes)`, `text(partsOrBytes)` and `dialect(bytes)`. `structure` and `text` accept either raw bytes or `parts()`'s own output, so a caller that already paid for `parts()` does not pay twice.

- **R1** (office-readers R1, R6 in part) The entry's `format` is `"csv"`.
- **R2** (office-readers R3) `csvEntry.detect(bytes, _)` returns `null` for every `bytes` value, always — a CSV has no magic bytes, and the shape a byte signature would need is a shape prose can wear (measured, not assumed: OFFICE-FORMATS.md "CSV"). `detect(null, contentType)` returns `{format:"csv", confidence:"likely", signals}` when `contentType`, case-folded, is `text/csv`, one of the older synonyms `application/csv` / `text/comma-separated-values`, or `text/tab-separated-values` (a TSV is read by this entry, its delimiter R7's); else `null`. A file declared `text/plain`, `application/vnd.ms-excel` or `application/octet-stream` is judged by R21, not by this slot.
- **R3** (office-readers R6) `csvEntry.parts`: `{ok:false, why:"empty_body"}` for zero-length bytes; `{ok:false, why:"decoder_unavailable:<encoding>"}` when the bytes declare (by BOM) an encoding the runtime has no `TextDecoder` for. Otherwise `{ok:true, ...}` always, regardless of what the delimiter or encoding signature could determine — an undetermined dialect is carried on the result, never refused. (K4868) The entry's optional second argument `{windowBytes, declared}` (on `parts`, `structure`, `text` and `dialect`, and in `cellsIn`'s query): `windowBytes`, an integer of at least 16, scales the read window (tests and the corpus's smallest case); `declared` names a legacy charset the source declared; the registry passes neither.
- **R4** (office-readers structure() intro, R10 csv arm) `structure()` returns `{ok, container:"csv", links, counts:{anchor,intra,deferred,refused,undetermined}, evidentiary, notes[], sheets}`, or `{ok:false, container, reason}` when `parts` failed. `links` is `[]` and every count `0`: the format has no relationships, embeds nothing and carries no metadata part, so the zero is a fact about the format and `notes` says so. `evidentiary` is always `{container:"csv", kinds:[], items:[], undetermined: [] | [guardMarker], counts:{}}`. `active` is `[]`. `dialect` is R7's.
- **R5** (office-readers R11 csv arm) `text()` returns `{ok, container:"csv", document, undetermined, counts, images, sheets}`, or `{ok:false, container, reason}` when `parts` failed. `images` is always `[]` (the format has no media directory to have looked in — a zero of the format, not of a walk). `document` equals the one sheet's `text`. `sheets` is one entry, `{sheet:0, name:CSV_SHEET_NAME, hidden:false, rows:null, cols:null, usedRows, usedCols, range, text, undetermined}` — `rows`/`cols` are `null` (RFC 4180 fixes no maximum, so the format has no capacity to state, unlike xlsx's fixed grid; the bounds a read refuses above are the table's, R6 and R22). Row 1 is always row 1: no record is consumed, skipped or reinterpreted as a header. An empty field is a measured emptiness (no cell, no undetermined entry), distinct from a field the encoding could not read. Under an undetermined encoding, the grid still stands (delimiters, quotes and line breaks are ASCII); only a field holding bytes the dialect's encoding cannot decode is `undetermined`, named by its own `sheet-cell` reference with a `null` value — never mojibake. (Fix round 9, G131a) A field the encoding can decode is never `undetermined` and never loses a character: Latin-1 supplement, Cyrillic, curly quotes and dashes, CJK and emoji in a UTF-8 file are cells with their text. (G131d) An empty field keeps its column: `P100,,100` has cells at columns A and C, and the row's line in `text` keeps one delimiter-separated slot for every column up to the row's last non-empty one, so no value shifts left. (K4868) `counts.replaced` counts the characters decoded as U+FFFD; an `undetermined` entry's reason is an encoding reason, `unterminated_quote` (with `row` and `bytes`) or `over_cell_bound` (with `length`).
- **R6** (office-readers R13; fix round 9, G124f, G131i, G129f; K4834: the light kinds reach the standard in Stage 1) The size guard judges the BODY's own byte length (after any BOM) against the `csv` bytes row of runtime-limits' `READ_BOUNDS` (50 MB, the standard's figure, taken through `boundOf`; no numeric literal here) and the record count against its `csv` rows row (1,048,576). `MEASURED_CSV_TEXT_BOUND_BYTES` is that figure, no longer 20 MiB or 17 MiB. A body at either bound is read; one above is refused whole, stated with its size and the limit: `structure()` and `text()` carry in `undetermined` the marker `{ok:false, text:"undetermined", why:"over_size_bound", size, bound, boundName, metric, final:true}` (`metric` `"body_bytes"` or `"rows"`; for the rows bound `size` is the count reached, one past the bound; and `encoding` for a UTF-16 body) and `sheets: []`. The dialect (R7) still stands, because it is read from the head. There is no lower bound under which a body is held whole and no piecewise state: R9's windows read every body.
- **R7** *(not yet met: T51)* (office-readers R14; fix round 9, G131a, G131c; X9; K4628 reversed) `csvEntry.dialect(bytes) -> {encoding, encodingConfidence, encodingSignals, delimiter, delimiterConfidence, delimiterSignals, assumed, disagree, undetermined:[...]} | null`. This is the SAME computation `structure()`/`text()`'s own `dialect` field uses (one builder), so a dialect read at intake and a dialect read from a later full parse of the same bytes cannot disagree. **Encoding** (decided by this module window by window, because ooxml's `decodeText`, its R36, decodes whole bytes and cannot stream windows; on a whole body the two decisions agree, which a seam test checks; K4868): a BOM decides it at `"certain"`; UTF-16 without a BOM is recognised and decoded as UTF-16; valid UTF-8 beyond ASCII is `"utf-8"`; a declared or detected legacy charset (windows-1252, ISO-8859-x) is used; bytes all below 0x80 give `"us-ascii"` at `"likely"` only (a later window may differ); otherwise `encoding:null` with `undetermined` including `"encoding_undetermined"`. `assumed` is true when no BOM or declaration decided the encoding, and `screens-inquiry` R134 draws it. **Delimiter:** exactly one of comma, semicolon, tab and pipe being consistent over the first 1,000 complete lines or 1 MiB (the lesser) gives that delimiter at `"certain"`; a delimiter is consistent when it occurs outside quotes, at least once, on the majority of those lines (more than half), whatever its count on each line, so a file whose every row is ragged still has one; where more than one is consistent the one whose most common per-line count holds on the most lines wins; a quoted newline, a ragged row, a title block, CR-only endings or a first line over 1 MiB do not fail it; two or more still equal after that give `delimiter:null` with `"delimiter_undetermined_tied"`; none consistent `"delimiter_undetermined_none_consistent"`; fewer than 2 complete lines in the whole body `"delimiter_undetermined_too_few_lines"`. **Per window:** the encoding and delimiter are also decided on each read window; `disagree` lists the byte offsets of the windows whose decision differs from the file's (`[]` when none), and the dialect then also states `"windows_disagree"` in `undetermined`. Returns `null` when the bytes are empty or their BOM-declared encoding has no runtime decoder. (Fix round 10, cause 20; K5053) Test: a 3,000-row, five-column CSV with a title block and ragged rows reads with `delimiter` comma, five columns, and its last mark in column A of a five-field row; controls: ragged rows alone and a title block alone read as before.
- **R8** (office-readers R30, R31, R32 csv arms; K1448, K1505 (11), K1888) `csvEntry.text()` gives its sheet a `cells` list, `[{source, value, type, declared, cached, formula}]`, one per field holding a value, in row then column order. `source` is the cell's `sheet-cell` reference (R10). `value` is the field's decoded text, never re-rendered; `type` is `text` for every field (the format declares no type); `declared`, `cached` and `formula` are `null`. A field under an undetermined encoding (R5) keeps its entry with `value: null` and stays in `undetermined`. Where the size guard stops the read, no sheet is made (`sheets: []`); past `inlineCellsMax` (R17), a sheet's `cells` is `null`, never `[]`. `cells` is the contract `odf-reader` R46 gives `.ods` sheets, field for field. `text()`'s `metadata` is always `null` (the format carries none) and `active` is always `[]` (the format can carry none), in `structure()` and `text()` alike.
- **R9** (fix round 9, G131i, G129f, G131e; replaces G41's "a body is never read in pieces"; K4834) **A body is read in byte windows with a carry, to the standard.** Any body within R6's bounds is read in byte windows (R19) with the unfinished field, record, quote, multi-byte character or CRLF carried across the window edge: the sheet's `text`, `lineRows`, `cells` and counts equal those of reading the same bytes whole, at the window edge and one byte either side of it, and the bytes pulled are at most twice the file's. The `undetermined` list of a sheet names at most 200 unreadable cells (each by its `sheet-cell` reference); `counts.undetermined` is the whole count, and the address of any cell is recoverable by `cellsIn` (R18). A sheet's `cells` is `null`, never `[]`, past `inlineCellsMax` (R17).
- **R16** (T51 fix round 6, G15; K4579; amends R5, R8, R9) `text()`'s sheet carries `lineRows`: an array with one 1-based row number per line of `sheet.text` (lines split on `"\n"`), the same length as the lines, for the whole-file and the windowed paths alike. A row is the record's number as `cells` and `usedRows` count it; empty records add no line, and each line of a record whose quoted field holds a line break carries that record's row. `[]` when the text is empty. Where the size guard stops the read there is no sheet. Test: `line-rows.test.mjs`.
- **R17** (G41, K4636, K4642) Held cells. `text(partsOrBytes, opts)`: with `opts.inlineCellsMax` (bytes; reading-pipeline's number) the sheet lists `cells` only while their JSON is at most it; past it `cells` is `null` and the sheet carries `cells_held: true`; `lineRows`, `text`, `usedRows`, `counts.cells` are those of the whole read. Without the option every cell is listed and there is no marker; a sheet whose cells fit has no marker. Test: `g41-held.test.mjs`.
- **R18** Optional slot `cellsIn(partsOrBytes, {sheet, fromRow, toRow, fromCol, toCol, maxCells})` (async; `sheet` absent, `0` or `"csv"`): `{ok:true, cells, rows:{from,to}, next_row?}`, the typed cells of exactly those rows and columns in row then column order, each identical to `text()`'s (an unreadable field a cell with null value). It stops after `toRow`, or before the row that would pass `maxCells` (whole rows; a first row alone over `maxCells` is given whole): then `next_row` is that row and `rows.to` the row before. `toRow`/`toCol`/`maxCells` absent mean no limit. Never throws: `{ok:false, why}` with `no_such_sheet`, `bad_range`, `empty_body`, `decoder_unavailable:<enc>`, or the R6 marker. Call shape for reading-pipeline and extraction: `entry.cellsIn(bytes, {sheet: "csv", fromRow, toRow, maxCells})`, then continue from `next_row`. (Fix round 9, G131e; S-20) The bytes a call reads are bounded by the rows asked for and one window, not by the offset of `fromRow`: rows 699,998 to 700,000 of an 8.9 MiB file are answered from access points the whole read left, without walking from byte 0. Test: `g41-held.test.mjs`.
- **R19** A body of any size up to the bound is read without a record list (walked in 1 MiB windows over 64 KiB, `SHEET_WINDOW_MIN_BYTES`), holding about its text: an 8 MiB body reads in a 64 MB old space (lowest surviving 33 MB). Test: `g41-memory.test.mjs`.

#### Reference builders (reused by `office-readers` and `odf-reader`)

Moved here so that `office-readers` may use `csv-reader` and not the reverse (the module order). `office-readers` re-exports them from `formats-xlsx.mjs`, so their users are unchanged.

- **R10** (office-readers R17) `sheetCellRef(sheet, cell) -> {kind:"sheet-cell", ref:"<sheet>!<cell>", sheet, cell}`.
- **R11** (office-readers R18) `usedSheetRange(name, usedRows, usedCols) -> {kind:"sheet-range", ref:"<name>!A1:<colLetters(usedCols)><usedRows>", sheet:name, range} | null`. `null` when `usedRows`/`usedCols` are not both positive integers — nothing was measured, or the measured extent is empty; never a range over an unmeasured or empty sheet.
- **R20** (fix round 7, G82; K4743) **A long text read yields.** `text(partsOrBytes, {inlineCellsMax, yieldNow})`: when `yieldNow` is a function, `text()` awaits `yieldNow()` between its 1 MiB windows, so no synchronous stretch of one call covers more than one window; its answer is identical to the call without `yieldNow`. Without `yieldNow` it behaves as before.

- **R21** (fix round 9, G130b; S-10; rA G6) `isDelimitedText(name, type, head) -> boolean`, exported, the one judgement of whether bytes are a CSV or TSV that format-registry calls. True exactly when all three hold: `type`, case-folded, is `text/csv`, `application/csv`, `text/comma-separated-values`, `text/tab-separated-values`, `text/plain`, `application/vnd.ms-excel` or `application/octet-stream`; `name`'s extension, case-folded, is `.csv`, `.tsv`, `.tab` or `.txt`; and `head` (the first bytes of the file, up to 1 MiB) is delimited text: it decodes as text under R7's encodings, holds no binary signature (a ZIP, OLE compound file, PDF or picture signature, or a NUL byte in a decoded 8-bit head), and R7's delimiter rule finds one consistent delimiter in it. Bytes never override a binary format: a head with a binary signature is false whatever the name and type say; a plain note with no delimiter is false (it is read as text). Never throws; false for an empty head or a non-string name.
- **R22** (fix round 9, G124e; S-13) A body with a record of more than 16,384 columns (the table's protective column bound) is refused whole, stated with the count and the limit, in the form of R6's marker with `metric:"columns"`. A cell longer than 32,767 characters is kept to 1 MiB and stated in `undetermined` as `over_cell_bound` with its own `sheet-cell` reference and its length; its value is cut at 1 MiB, and no other cell is affected.
- **R23** (fix round 9, G131b; S-5) A double quote opens quote mode only at the start of a field; inside an unquoted field it is an ordinary character (`12" pipe,1` is the fields `12" pipe` and `1`). A quote left open when the file ends is stated in `undetermined` with the row it opened on and the bytes it covers, and the rows before it are read; one stray quote never swallows the rest of the file.
- **R24** (fix round 9, G131c) The dialect is decided on each window and the file's by majority (R7); a window that differs is stated (`disagree`), never silently read under the file's, and a read of a window uses the dialect that window was decided to have.
- **R25** (fix round 9, G131i; K4834) A UTF-16 body (with or without a BOM), a UTF-8 body and a body in a declared legacy charset are all read to the standard's bounds through R9's windows; a character split across a window edge is not lost, and a replacement character appears only where the encoding could not decode (counted in `counts`, with `assumed` stated, R7).

Errors: none of R1–R11 ever throws. A precondition this module cannot verify is answered as a stated `undetermined`/`ok:false`, never an exception and never a guess.

## Private

### Uses

- `ooxml`: `decodeText` (its R36: the whole-body decision R7's per-window decision agrees with, checked by a seam test; K4868). `csv.mjs` uses nothing else of it: a CSV is not a container.
- `runtime-limits`: `boundOf` and `statement` (its R29-R31), for R6's bounds and R22's, with no numeric literal for a ceiling kept here (K4835 (1)).
- `test-support`: `sheetgen` with its truth, `zipChunks64` and the fixture cache (its R19, R21, R23), for this module's tests at the standard's sizes.
- `setup-words`: `word`, `localize` (the words rule: a sentence people read is read by key; K3930, K3943, K3949).

### Invariants

- **R12** (office-readers R20) Pure: no store, no network, no clock in any output. The same input bytes always give the same answer.
- **R13** (office-readers R21, R22) Never throws; every failure this module can name is a returned `{ok:false, ...}` or a carried `undetermined` entry. Never invents: a dialect, a character or a cell this module cannot establish is a STATED `undetermined`, never silently dropped and never guessed.
- **R14** (office-readers R24) Asserts nothing about MEANING (that judgment belongs to `content`/`entities`, through I2); a URL in a cell is text, not a link; writes nothing to the record.
- **R15** (office-readers R25) No place is named in this module; it holds no jurisdiction-specific behaviour to take from a profile.
