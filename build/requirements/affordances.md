## Public

### Purpose

The plane-sourced act pre-flight (DEC-8): for one object as it stands and one caller as they are, which acts exist, each with the capability it needs, how it is reached, its set-application weight, its rung on the ladder and the wording that must accompany it; and, for every surface, the vocabularies, the rung ladder and the set acts, so no surface holds a copy of a rule. It publishes what the acting modules enforce and computes no refusal of its own.

### Provides

Terms. An **act** is `{id, label, weight, types, applies(facts, type), prompt?}`. A **decorated act** is `{id, label, weight, needs, mode, rung, rung_absence, prompt}`. A **gate** is `{needs(op), mode(op)}`, which the control plane supplies from its own tables (`NEEDS`, `SESSION_OPS`); `mode` is `session`, `admin-session` or `machine`. A **weight** is `refuse`, `report`, `single` or `per-item`. **Facts** are R14's answer.

**The catalogue** (module constants; pure)
- **R1** `ACTS` holds exactly these object-directed acts and weights: `refuse`: release, retire, dispose, sever, reinstate; `report`: cite; `single`: conclude, reopen, publish, inquirydivide, inquiryground, actionmove, actioncorrespond, actionlaws, actionrisktier, versionaccept, versionreject, versionconsider, versionrevert, versioncurrent, withdrawconclusion, versionhide, projectinvite, projectjoin, projectleave, projectremove, projectowneradd, projectownerremove, projectownerrescue, projectvisibilityset. `CAPTURE_ACTS` holds attest, monitor and attesttext, with no weight. `PER_ITEM_ACTS` holds proposedispose, taskresolve, taskforward and resolve, weight `per-item`, set key `items`, with their identity groups (`item_keys`) and shareable fields (`shared_keys`): proposedispose `[[key], [progressionKey, stageKey], [project, finding]]` / `[to, reason, kind, definitionVersion]`; taskresolve `[[id]]` / `[]`; taskforward `[[id]]` / `[to]`; resolve `[[captureSha], [captureSha, ref]]` / `[ref]`.
- **R2** `RUNG_LADDER` is `reversible, reasoned, terminal, attested, irreversible`, low to high. `RUNGS` assigns: irreversible publish; attested attest, ratify, caseratify; terminal retire; reversible actionlaws, cite, projectvisibilityset, versionaccept, versioncurrent, versionhide, versionrevert; reasoned actionmove, actionrisktier, adminremove, aliaswithdraw, aspirationdepart, aspirationretire, biasdebtresolve, conclude, connectionassert, discharge, dispose, filemembershipjudge, goalclose, inquirydivide, inquiryground, narrow, projectownerremove, projectownerrescue, proposedispose, reevaluationrecord, reinstate, relationdeclare, relationwithdraw, release, reopen, sever, themewithdraw, triage, versionconsider, versionreject, withdrawconclusion (K221). `IRREVERSIBLE_CORRECTION_PATH` states that correction moves forward and nothing is erased (DEC-19).
- **R3** `RUNG_ABSENT` names every other op that writes (a totality checked against the control plane's table by R12's service), each with one ground of `RUNG_ABSENCE_GROUNDS` (`substrate`, `credential`, `caller-owned`, `observational`, `undetermined`), each ground carrying its sentence. No op is in both `RUNGS` and `RUNG_ABSENT`.
- **R27** No new rung is added for an act corrected forward (K102). An op that writes and is corrected forward by a further act of the same kind is `reasoned` when it requires an authored reason, and `reversible` when a published act takes it back; it is graded `undetermined` only where neither holds. The 42 ops graded `undetermined` today (among them `versionaccept`, resolving and forwarding an obligation, creating an entity, minting content, threading a progression and the action acts) are reassigned by BOB on this rule.
- **R4** `VOCABULARIES` carries exactly `action_kind`, `law_levels`, `dispositions`, `subject_positions`, `basis_roles`, `entity_kinds`, `relation_kinds`, `stage_requiredness`, `action_basis_kinds`, `correspondence_directions`, `correspondence_stages`, `correspondence_outcomes`, `resolutions`, `risk_tiers`, `version_states`, `version_edges`, `version_reason_required`, `rung_ladder`, `rung_correction_path`, `rung_absence_grounds`, `sufficiency_claim_states` and `content_mint_states`; each fixed value is the very object the enforcing module refuses against (the same reference, never a copy); `action_kind`, which depends on the active profiles, is the value `actions` answers at the moment of the call (its R40), never a copy held here.
- **R5** `inquirydivide` carries `DIVIDE_PROMPT`, `inquiryground` carries `GROUND_PROMPT`, `attest` carries `ATTEST_FENCE`; every other act's prompt is null. `ATTEST_FENCE` is DEC-39's wording verbatim with its two grade letters composed from the capture ceiling and the grade above it; `ACQUIRE_GRADE_NOTE` is composed the same way. `attestFence(c, u)` and `acquireGradeNote(c, u)` throw when either letter is absent, so the module fails to load rather than publish a sentence it cannot make true. `GROUND_PROMPT` and every label use none of "AND", "OR", "disjunction", "branch" or "ground" (DEC-32 clause 1).
- **R6** `DISPOSITIONS` is `inquiry`'s object (the one `op=dispose` refuses against, R4; K208), `STAGE_REQUIREDNESS` `progressions`', `ENTITY_KINDS` and `RELATION_KINDS` `entities'`, `REOPENABLE_FROM` `promotion`'s and `PER_ITEM_MAX` (100) `record-core`'s, re-exported unchanged.
- **R7** `MACHINE_REFUSALS` maps each act whose method refuses a machine credential by name to that code: release, conclude, withdrawconclusion (`MACHINE_CANNOT_CONCLUDE`), reopen, publish, inquirydivide, inquiryground, actionmove, actioncorrespond, actionlaws, actionrisktier and the six version acts (`MACHINE_CANNOT_MOVE_VERSION`). `NON_ACTS` gives every other op the control plane gates its reason, a reason beginning `capture-directed:` exactly for the members of `CAPTURE_ACTS`.

**deriveActs(facts) → act[]** (pure; never throws on a well-formed facts object)
- **R8** With `type` the normalised `object_type` and "an edge to X" meaning the declared type's state machine (read through the catalogue's own vocabulary lookup, by `declared_type`) has an edge from `current_state` to X, an act is returned exactly when: release: information, edge to verified; retire: information, edge to retired, no confirmed citation into it; dispose: inquiry, not a case member, an edge to a disposition; conclude: inquiry, an edge to concluded, or state concluded with `concludes_for_project === true`; reopen: inquiry, an edge to open, and state in `REOPENABLE_FROM` or a case member; publish: inquiry, state concluded or `concluded_for_project === true`, not a case member unless `edition_warranted_for_project === true`, and `project_owner !== false`; inquirydivide: inquiry, an edge to divided, not a case member, at least one leg, nothing working resting on it; inquiryground: inquiry, at least one leg, not a case member, not divided; actionmove: action with any edge; actioncorrespond, actionlaws, actionrisktier: any action; versionaccept, versionreject, versionconsider, versionrevert: inquiry where some reading's state has a version-machine edge to accepted, rejected, considering, suggested respectively; versioncurrent and withdrawconclusion: some reading accepted; versionhide: at least one reading.
- **R9** cite: information not retired, a project unless `project_participant === false`, or any inquiry; sever: an information or inquiry cited by a project (confirmed), or a project with a confirmed citation of its own unless `project_participant === false`; reinstate: an information (not retired) or inquiry with a severed citation from a project, or a project with a reinstatable severed citation unless `project_participant === false`. The roster acts: invite, remove and owner-add when the caller owns this project; join when the caller holds a roster state other than joined; leave when the caller is joined and is not an owner or the owner floor is clear; owner-remove when an owner and the floor is clear; rescue when the rescue is open to the caller; visibility-set when the caller owns this project (`project_target_owner === true`).
- **R10** A fact that is null never narrows an act and never offers a roster act (roster acts are offered only on a stated `true` or a stated state). With `actor_is_machine === true`, every act in `MACHINE_REFUSALS` is withheld; with null, nothing is.

**decorate(act, gate) → decorated act** (pure)
- **R11** `needs` is `gate.needs(id)` or null, `mode` `gate.mode(id)`, `rung` `RUNGS[id]` or null, `rung_absence` the ground in `RUNG_ABSENT[id]` or null, `weight` and `prompt` the act's or null (the key is present, never omitted). A queue item's option and an `op=affordances` act for the same subject are the same object shape from this one function.

**unaccounted(opTable) → {unpublished, unranked, stale}** (pure)
- **R12** Given the control plane's table of ops, each `{op, mutating, gated}` (`gated`: the op has a `NEEDS` row; a row without the key is gated): `unpublished` lists the gated ops in none of `ACTS`, `CAPTURE_ACTS`, `PER_ITEM_ACTS` or `NON_ACTS`; `unranked` the mutating ops in neither `RUNGS` nor `RUNG_ABSENT`; `stale` the keys of `NON_ACTS` the table does not carry as gated, and of `RUNGS` and `RUNG_ABSENT` it does not carry as mutating (K211). All three empty is the totality DEC-8 and FW-14 require.

**affordanceFacts({target, viewer, identity, author, by}) → facts or refusal** (`op=affordancefacts`, in-process)
- **R13** `NO_TARGET` when no target; `NO_SUCH_BUNDLE` for an absent bundle and for one the viewer may not see, alike. Never writes.
- **R14** Otherwise `{ok, target, object_type, declared_type, current_state, criticality, case_member, project_owner, project_target_owner, project_participant, roster, actor_is_machine, concludes_for_project, concluded_for_project, edition_warranted_for_project, basis_legs, rested_on {working, frozen, severed}, basis_version_states, basis_versions, cites_in {confirmed, severed}, cites_out {confirmed, severed, severed_reinstatable}, cited_by_case {confirmed, severed}}`. Each fact is asked through the predicate the corresponding act's refusal runs: live citations through `connections.citesInto`; reinstatable through `citation.retiredNotCitable`; what rests on an inquiry through `inquiry.restsOnLive`; the case relation through `publication`'s fact; ownership, participation, the owner floor and the rescue through `membership`'s predicates; machine through `isMachineIdentity` on `author`. `declared_type`, `basis_legs` and the reading states come from the document's own front matter.
- **R15** Positional facts are asked of who the caller is, not of what it may see: `project_owner`, `concludes_for_project`, `concluded_for_project`, `edition_warranted_for_project` and `project_participant`/`project_target_owner` of `identity` (a session's member; an `ai` credential's member principal); `roster` of `by`. Each is null on a target of the wrong type and for a caller with no roster position; `actor_is_machine` is null when no `author` was sent.
- **R16** Facts are counts, never ids: no answer names a bundle other than the target. *(not yet met: N176, `cites_in` passes ids)*

**The action vocabularies** (N65 (3), K92 (2))
- **R26** `risk_tiers` in `VOCABULARIES` is `actions`' `RISK_TIERS` (the same reference, R4). `action_kind` answers the kinds `actions` accepts (actions R10): its product kinds, then the `action_kinds` of the active profiles' combined view (`jurisdictions.combine`); with no profile active, the product kinds alone. No kind is held here. *(not yet met: N65; both are read from `legacy-checks`' `RISK_TIERS` and `ACTION_KINDS`, which names local kinds)*

**affordances({target?, viewer, identity, author, by, gate}) → answer** (`op=affordances`)
- **R17** With no target: `{target: null, catalog, vocabularies, capture_acts, set_acts, detail}`, `catalog` each act decorated with `appliesTo` (its types), `set_acts` each decorated with `set_key`, `item_keys`, `shared_keys` and `max_items` (`PER_ITEM_MAX`). With a target: R13's refusal as given, else `{target, object_type, current_state, acts, vocabularies, capture_acts}`, `acts` being R8–R10 decorated. `capture_acts` is never filtered by the target.

### Invariants

- **R18** A published act is not refused for the target's state or type, or for the caller's class or position, when the same caller performs it with well-formed parameters (DEC-8: the pre-flight never disagrees with the refusal it fronts). In particular `projectleave` is offered to an owner only while another owner is committed (not `leaving`), which is when `membership` R35 accepts it. *(not yet met: N45 — offered on the owner floor alone)*
- **R19** A rung is backed by the enforcement it names: every `reasoned` op, called without its authored reason where the act revises what stands, is refused with a code in `JUSTIFICATION_REFUSALS` (an act that replaces nothing, such as `inquiryground`'s first grouping, asks none; K212); `terminal` is given only while `STATES.information.edges.retired` is empty; `irreversible` only to the op that publishes.
- **R20** `MACHINE_REFUSALS` equals, both ways, the set of acts whose method answers a machine credential with a `MACHINE_*` code, and each code is that answer.
- **R21** No surface-facing text here is composed by a surface: every prompt, label, ground and vocabulary a surface renders comes from this module or the module it re-exports (DEC-8; UI-KICKOFF "Refusals teach").
- **R22** Nothing here writes: every service is a read or pure.
- **R23** The three joined-project predicates are asked only for the caller's own member id, over projects the viewer can see.
- **R24** `rung: null` never reaches a caller without a non-null `rung_absence` for a mutating op (R3, R11).
- **R25** No place is named in this module's behaviour or outward text; `NON_ACTS.idmatch` names no local identifier system or publisher.
