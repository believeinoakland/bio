## Public

### Purpose

The member interface's page and frame. It signs a member in through the setup page's session, loads the member's words, draws the working frame and the path, routes among the screens the screen modules register, and gives every screen one way to read, to act, to explain and to refuse. Pure: it reads no table and writes nothing; every read and act is an op the plane serves, called from the browser.

### Provides

Terms. A **screen** is a registry screen (`docs/development/ux-substrate/screens/registry.json`, carried by `wizard-scripts` as `SCREEN_REGISTRY`, its R13). An **act** is a control that calls one op; a **read** is a call of a non-mutating op. **Words** are the interface's keyed words (R5). A **screen module** is one of `screens-settings`, `screens-intake`, `screens-daily`, `screens-inquiry`. The **phone width** is a viewport of 760 px or less (`civicsmith.css`' breakpoint). These terms are read by every screen module.

**The page: `interfacePage(screens)`**
- **R1** `interfacePage(screens)` answers one HTML document: `<html lang>` the member's language once known (`en` before), one `<link rel="stylesheet" href="/app/assets/civicsmith.css">`, icons referenced from `/app/assets/icons.svg` (no inline copy of the sprite), and one `<script>` carrying the nonce slot `__CSP_NONCE__`, composed from the shell's own functions and each registered screen's. The page holds no member-facing text outside its words (R5) and no secret.
- **R2** The page names no resource on another origin in any `src`, `href`, `@import`, `url()` or fetch, and loads no typeface but `interface-assets`' (DEC-122 (3)). It has no inline event-handler attribute, no `javascript:` address and no script made from a string (`answer-envelope` R6; `setup-page` R28's rule). A test serves the page through the door and finds every script element carrying the response's nonce.

**The session** (handed over by the setup page)
- **R3** On load the page reads the session record `setup-page` R31 names (`SESSION_STORE_KEY`). With none, or one whose expiry has passed, it goes to `/` (the setup page's sign-in) and draws nothing else. With one, it sends `op=whoami` (`control-plane` R18); an answer without a member session (`session` false or `member` empty) is treated as none. A `401` answer to any request clears the record and goes to `/`. The session token travels only in each request's `Authorization: Bearer` header: never in an address, a query, a body, a link drawn or the browser's history (`setup-page` R26's rule; `admission` R20). A test drives every screen with a sentinel token and finds it in each request's header and nowhere else.
- **R4** The masthead's member initial opens a menu with "Sign out": it sends `op=signout`, then clears the session record and goes to `/`, whatever the answer.

**Words** (DEC-179)
- **R5** Every member-facing string the interface draws is a word read by key: a key of `setup-words`' `WORD_ROWS` (its R1), or a key of a module's own `SCREEN_WORDS` (frozen `[key, en, protected]` rows; a screen's keys `screen.<id>.<part>`, the shell's own `shell.<part>`, each with `{placeholders}`; DEC-179 (5)), never text written into a render function. After `whoami`, the shell reads `op=interfacewords` (`instance-setup` R74: the member's language, the group's shown translation, else the English); a key it does not answer, or a read that fails, is drawn in the English of `WORD_ROWS` or `SCREEN_WORDS`. `w(key, fills)` fills each `{name}` with the screen's data, HTML-escaped. A key of `WORD_ROWS` whose English names the group's Civicsmith bare (DEC-149) or is untrue on an arm a screen draws it for is not drawn from `WORD_ROWS`: the module that draws it holds its own row under the same key in its `SCREEN_WORDS`, in DEC-149's form and true on every arm, until a later `WORD_ROWS` carries a conformed word; in T46 these are `mark.gap.refused.means`, `mark.origin.search.means`, `ai.refused.limit.unjudged`, `queue.step-cost-shared.detail`, `act.memberlanguageset.does`, `act.groupkeyremove.does`, `act.owed_subscriptionsignin.does`, `act.pagetranscribe.does` (each names Civicsmith bare) and `handle.fixed` (untrue under DEC-197: every handle is fixed, published case or not). A test renders every screen in every state and finds each drawn text node equal to a word's text, filled, or to the record's own data (names, titles, quotes, dates, counts); a key no list holds fails it.
- **R6** Dates are drawn by `date.daymonth` and `date.daymonthyear` with `date.month.*` (DEC-191, DEC-192); no date is drawn in ISO form.

**The frame and the path** (DEC-139 (1), DEC-154, DEC-155)
- **R7** Every screen is drawn in the working frame: the masthead (the group's name, read once through the public `op=groupidentity`, `instance-setup`; search, opening `finder`; the explanation-level control, R17; the assistant button only while the assistant is reachable for this member, R20; the count of the member's To do items from `op=queue`; the member's initial, R4); the band, `mark.band.means` with `mark.path.working.*` (DEC-106); the rail's seven places in the order Home, Queue, Find, Add, Projects, People, Settings (`rail.<k>.name`, guidance `rail.<k>.holds`); one column of work; and the dock (R20). At the phone width the rail gives way to the five tabs Home, Queue, Add, Find, More (`tab.more.*`) and the dock to a sheet above them. A place whose screens are not yet built (People) is shown and opens a screen saying, in its words, that it comes later.
- **R8** Every screen opens its main area with its path, at the same place: from its rail place to the screen's own name, last, marked as the current page, each earlier step a link; the heading below names the thing shown (a question's words, a document's title). Each screen's path is `docs/development/ux-substrate/screens/mock-shell.js`' `PATH` for its id at `3f40899950` (members: Settings › Members; held: Add › Held captures; document: Projects › <project> › Document), a project's step its title as read.
- **R9** The router maps `/app` to `home` and `/app/<screen>[/<subject>]` to that screen with that subject id, keeps the browser's history (back and forward redraw the screen), and answers an unknown screen, or a subject the read does not find, with the screen's "Nothing here" state (`state.empty`, R10), never a blank page. `/app/review` maps to `review-outside` (`screens-publish` R17; K3137, T47).
- **R25** (Bob's K2893: Home) The Settings place offers "Group settings", a link to the setup page's panel (`/`), where the settings sections not yet redrawn are served (who the group is, places and offices, security tools, translations, recovery codes); the setup page's own link back to `/app` is `setup-page` R32's.
- **R26** (N673; DEC-155) The rail's width is the member's on each device: 184 px by default, from 64 to 320 px, set by dragging its edge or by the keyboard, kept on the device (the browser's storage) and never sent in any request or written to the record; at the phone width the tabs are unchanged by it. A storage that cannot be read or written leaves the default.

**Reads and their states** (DEC-98)
- **R10** Every read is drawn in one of four states: still loading (`state.loading`), empty (`state.empty`, or the screen's own empty sentence), could not read (`state.failed` with the refusal's words as `{reason}`, R13), or its data. A read that failed is never drawn as empty, and an empty one never as failed. A test answers each read of each screen in turn as pending, empty, refused and failed (no answer), and finds the four states drawn.

**Acts: weight, friction and the gate** (DEC-82, DEC-87, DEC-143, DEC-181, DEC-122 (1))
- **R11** Every act is a button labelled `act.<op>.label.<screen>` (or the registry's label's key where the screen has one), carrying its weight's pips and name (`weight.<w>.name`): the weight read from `op-grades`' `RUNGS` (`attested` drawn as `weight.signed`), an op whose `RUNG_ABSENT` ground is `undetermined`, or that neither names, drawn as reasoned (DEC-87: an undetermined rung is treated as reasoned). An op in `RUNG_ABSENT` under another ground (`substrate`, `credential`, `caller-owned`, `observational`: not an act on the record, `op-grades` R2) carries no weight mark and runs on press, any confirmation its owner requires drawn by its screen (K3002); so does a read (an op `OPS` declares `mutating: false`), whatever the tables hold (K3011). Friction follows the weight: reversible acts run on press; reasoned acts open a reason field in place and send only with a reason, except that an act whose screen names a `reasonField` sends the member's own words in that field as its reason and asks no second one (DEC-88: an act's own authored words serve as its reason); terminal and signed acts open a dialog stating what the act does (`act.<op>.does`) and who signs, and send only on its confirm. An act that leaves the group carries `mark.outward.means`. At the phone width a signed or irreversible act is drawn with what it does and a sentence saying where to finish it, and is not sent (DEC-181). No T46 screen offers an irreversible act.
- **R12** An act is drawn only when the session may do it: `NEEDS[op]` is `null` or among `whoami`'s `capabilities`; the op is in `SESSION_OPS.member` (or `SESSION_OPS.admin` for the founder's session); and, for an act its owner refuses to a member who does not administer (`membership`'s administrator acts, `credentials`' group-key acts, `aikeepaway`), `whoami`'s `administer` is `true`. An act not drawn is absent, never greyed (DEC-139 (7)). Before `whoami` answers, no act is drawn.

**Refusals**
- **R13** A refusal (`ok: false` at the top level or in `result`, or an HTTP error) is drawn beside the act or read it answers, never in place of the screen: the word `refusal.<code>` (or a screen's own key for that code) when one is held; else the answer's `translation` (`answer-envelope` R2); else `state.failed` with the code. A form keeps what the member typed; nothing on the screen changes but the refusal. A test drives every act of every screen with a refusal of each kind and finds the words drawn and the form kept.

**Explanations** (DEC-159 to DEC-163, DEC-175, DEC-177)
- **R14** Every mark, name and reference explains itself (level 1, marks and names); every screen heading, section heading, rail place, tab and act explains itself at level 2 (guidance: `screen.<id>.purpose`, `rail.<k>.holds`, `act.<op>.does`). An explanation opens after the pointer rests 0.5 s (level 1, and level 2 at "Explain promptly") or 1.5 s (level 2 at "On a longer pause"), at once on keyboard focus or a tap; stays while the pointer is on the element or the explanation; closes 0.5 s after it leaves both, or on Escape; one at a time; announced as the element's description. Nothing is hidden at either level.
- **R15** No explaining element sits inside another (DEC-177 (1)): a control or a mark with no label of its own absorbs those inside it, said after its own; a title naming a particular thing explains that thing first. A test renders every screen in every state, at both widths, and finds no element carrying an explanation inside another that carries one.
- **R16** Every item the record holds that a screen names (a document, a passage, a question, a project, a member, a capture) is a link opening its screen where one is built, and shows a card on hover or focus with what it is and the facts the screen's read answered for it (DEC-160 (1)–(3)); an item whose screen is not yet built carries its card only.
- **R17** The explanation level is the member's: the masthead control shows the current value (`level.prompt.name`, `level.pause.name`) and switches it in one click, as do Alt+Shift+I and the account screen (`screens-settings`). It is sent as `op=infolevelset` and read with `op=infolevel` (`instance-setup` R79); while either does not answer, the level is kept on the device, default "Explain promptly". A new member starts at "Explain promptly"; after their first month the shell asks once whether to keep it (DEC-162 (2)), the answer recorded through the same op.
- **R18** Appearance is "Follow my device", "Light" or "Dark", kept on the device; print is always light (DEC-122 (2), DEC-138 (6)).

**Rows, picks and the hold strip** (DEC-176; canon §S)
- **R19** A table of rows offers each row's acts in a panel opened beneath it (by its name or the keyboard), never elsewhere on the screen; ticking rows brings the hold strip with its count, the acts that apply to every picked row, and "Unpick all"; sorting keeps each open panel with its row; at the phone width each row reads as a card with every value labelled.

**The dock** (DEC-139 (1), (7))
- **R20** The assistant is **reachable** for this member when `op=assistantstate` answers `on: true` and either `op=accountreference` holds the member's own reference, `op=subscriptionsignin` `{step: "state"}` answers `connected: true`, or `op=groupkeystate` answers held and on. While reachable, the masthead's assistant button opens the dock with the panel `screens-inquiry` registers, beside the screen it serves; while not, no assistant control is drawn anywhere (absent, not greyed). Each read that does not answer is taken as not reachable.

**The screen contract**
- **R21** A screen module exports `SCREENS`: per screen `{id, reads, render, acts, words}`. `id` is a `SCREEN_REGISTRY` screen id. Each act names one op; every op a screen's acts name is in `OPS`, and is the op the registry lists for that screen or one of the three re-points `draft-T46-interface.md` §3 names (`capture` → `captureupload`; `connect`'s owed sign-in → `subscriptionsignin`, its disconnect also `subscriptiondisconnect`; `answers`' "Ask" → `ask`), or `owed:infolevelset`'s op `infolevelset`. `interfacePage` throws, naming the screen, for a screen whose `id` is not in `SCREEN_REGISTRY` or whose act names an op `OPS` does not hold, so a broken screen is never served.
  - (K2996, K2998; the contract every screen module and this shell build to, as INTERFACE-SHELL #1 J1 fixed it) 1. `SCREENS`: `[{id, reads, render, acts, words}]`, every function self-contained (only its parameters, `cs`, and the language's own globals: `JSON`, `Math`, `String`, `Number`, `Array`, `Object`, `Date`). `words`: the keys the screen may draw: a string is a key of `WORD_ROWS` (or the shell's), a `[key, en, protected]` row is the module's own `SCREEN_WORDS` row (the shell takes its English from it). Optional `place(view)` → `{project: {id, title}}` for the path's project step (R8). 2. `reads(view)` → `{name: {op, query?, body?, empty?(value)}}`; `view.data[name]` = `{state: "loading"|"empty"|"failed"|"ok", value, refusal}` (`refusal` `{code, words}` when refused; `value` the answer's `result`). 3. `render(cs, view)` → HTML string; `view` = `{subject, data, me (whoami), ui, reachable}`; `cs.set(name, value)` sets `view.ui[name]` and redraws. 4. `acts`: `[{op, label?, send(view, el, cs, extra) → {query?, body?, raw?} | null, done?(view, answer, cs), rereads?: [names], refusals?: {CODE: key}, dialog?: [{name, label}], outward?: true, reasonField?: "reason"}]`. The screen draws `cs.act(op, {label, data, tone})` ("" when R12 refuses it); `el.dataset` carries `data`. Friction by weight is the shell's: a reasoned act's reason is added to the body as `reason` (or `reasonField`), a dialog's fields arrive as `extra.fields`. `null` from `send` sends nothing; `{refuse: key}` draws that word beside the act. After success, `done`, then the reads named in `rereads` (all when absent). 5. `cs`: `w(key, fills)`, `esc`, `state(outcome | readName, inner(value), {empty: key})` (also `state(readName, view, inner)`), `act`, `can(op)`, `go(screen, subject)`, `set`, `value(id)`, `file(id)`, `ref(kind, id, text, facts[])`, `mark(family, value, fills)` (`mark.<family>.<value>.name`/`.means`), `grade(scale, letter)`, `due(iso, state)`, `hint(text?)`, `date(iso, {year})` (R6), `row`, `rows({cols, items, key, cells, acts, pick})` (R19), `sec(titleKey, inner, {help})`, `sheet`, `field(id, labelKey, {area, value, rec, help})`, `choice`, `checks`, `title(text, {thing})`. (K2998; SCREENS-INQUIRY #1 J2) Also: `cs.call(op, {query, body, bearer})` answers a promise of the parsed answer, `bearer` absent meaning the session, present replacing the session token in `Authorization` for that one request and appearing nowhere else (no session token on such a request); a screen's `ui` is kept in page memory across redraws of the same page and never written to storage, the address or the record; and the shell calls a screen's optional `closed(cs, view)` when the member closes it or leaves the page (`pagehide`).
  - (K2999; SCREENS-INTAKE #1 J2) Also: an act's `send` may answer a promise, which the shell awaits; `cs.download(op, {query, body})` answers a promise of `{ok, answer}` and, on a byte answer, hands the bytes to the browser as a file (an object address released once the download starts, `setup-page` R26's form); a picked-rows act receives the picked keys as `extra.picked`; `send` may answer `{query, raw}`, `raw` sent as the request body as it is, under the session header, with no JSON content type.
  - (K3002; SCREENS-SETTINGS #1 J2, SCREENS-INTAKE #1 J3) Also: a screen may carry optional `parts: {name: fn}`, each self-contained, which the shell serialises beside the screen's functions and hands in as `view.parts`; `view.origin` is the page's origin; a refusal's word is filled from the refusal's own fields (`{detail}`), and a `refusals` value may also be a function `(refusal, cs)` → HTML; `send` may answer `{refuse: key, fills}`, the word filled as `w(key, fills)`; `cs.value(id)` answers a checkbox's `checked` (`true`/`false`), a radio's likewise (a group read through its checked one's id), any other field's value; `cs.rows`' `cols` are the header word keys, `cells(item)` the row's cell HTML list, `acts(item)` the HTML of the row's panel (R19), `key(item)` the row's key; `cs.digest(text)` answers a promise of the lowercase hex SHA-256 of the text's UTF-8 bytes; `cs.now()` answers the page's clock in milliseconds (the harness's fake clock in tests). An answer served as `application/x-ndjson` (`ask`, agent-worker R54) is handed to `done` and `cs.call` as its list of parsed events, the answer being the last (K3011). An act's `done`, when it answers a promise, is awaited before the reads named in `rereads`; after an act succeeds every password field its screen drew is cleared, while a refused act keeps what was typed (K3009). The shell opens no address itself: a screen draws an outside address as a link with `target="_blank" rel="noopener noreferrer"`.

### Suggestions

- **How screen code reaches the browser** (`draft-T46-interface.md` §1.3, §7 T1, BOB's): each screen module exports self-contained browser functions, each referring only to its parameters and the kit object `cs` handed in, never to a module-scope import; the shell composes the page's one script from their `toString()`, as the setup page embeds `deriveInquiryTitle`. The functions run unchanged in node for tests and in the browser.
- **The kit** `cs` handed to screens holds `read`, `act`, `w`, `state`, `row`, `ref`, `mark`, `grade`, `due`, `sheet`, `sec`, `field`, `choice`, `checks` (the mockups' `mock-kit.js` names). - **Tests** (§4, §7 T2): the served page through a DOM stand-in with a scripted `fetch`, as `setup-page`'s `fixture.mjs` does; one small shared stand-in owned by this module's tests and imported by the screen modules' tests (no new dependency). R14's timings with a fake clock.
- **Routes** are path routes with history (§7 T6), so a link survives a reload and can be shared inside the group.
- The page may pass `store=scratch` to each op for live verification. A failed `interfacewords` read is retried once on the next screen change.
