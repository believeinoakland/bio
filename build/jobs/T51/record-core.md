It answers SQLite's own `total_changes()` for the object's connection, a whole number that rises by at least one for every row any statement on the object's storage inserts, updates or deletes, by any path, and never on a read. **Design points BOB may overrule.**
1. *First built, then dropped:* a persisted `record_counter` row stepped by triggers on every declared table (never falls across a restart, counts committed changes only). Run over the 2032 user test files it failed 46 tests in 20-odd other modules that snapshot every table and assert "nothing else written" (calculations, citation, docket, doorbell, hypotheses, publication, case-checker and more), which I may not edit. A table in the store is visible to them; `total_changes()` is not (no table, no trigger, no write cost).

R89 as written says "never falls" and "committed change"; I propose the wording below. If BOB wants the persisted form, the 46 tests need their jobs' CHANGE first.
