**Decided in my module (no question needed)** · A zlib stream cut inside well-formed chunks is `CORRUPT`, not `TRUNCATED`: the inflater tells cut from damaged only in its own words, which differ between node and workerd, so the code would not be pure across platforms; a file cut short is always `TRUNCATED` by its chunks (the real-world case), and the detail carries the inflater's words. An ancillary chunk the decoder does not read is not CRC-checked and bytes after IEND are ignored (the standard allows both; Pillow does the same); excess image data inside the stream is refused (bounds a decompression bomb).
