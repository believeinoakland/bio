# M3 · Module requirements: the documents modules

Unit M3, phase 1 (PROTOCOL.md §R). Scope: `build/requirements/<module>.md` for acquisition, capture, capture-sources, sources, site-profiles, docprofile, doctypes, budget-doctypes, court-doctypes, legistar-reader, roster-reader, extraction, reading-pipeline, content, text-chain, provenance, office-readers, pdf-reader, workbooks, format-registry, link-sweep, monitoring. Product tree pinned at `SOURCES-PIN` (c30c6ca521). Paths below are relative to the product root.



## 1. The documents path in one picture

The 22 modules form one pipeline, in layer order (each file's Status line names its layer):

| stage | modules | what it does for an investigation |
|---|---|---|
| bring in | `acquisition`, `capture`, `capture-sources`, `sources`, `link-sweep`, `monitoring` | fetch a document by public address (direct, Drive export, web archive, rendered), hash and keep it with a provenance chain; doorbell for handed-over material; scoped sweeps of a site; watching for change |
| know what it is | `format-registry`, `docprofile`, `doctypes`, `budget-doctypes`, `court-doctypes`, `site-profiles` | byte-level format; document type (agenda, minutes, budget, opinion …) from signals; per-site facts |
| read it | `pdf-reader`, `office-readers`, `workbooks`, `legistar-reader`, `roster-reader`, `text-chain`, `extraction`, `reading-pipeline`, `content` | text with locations, tables, cells; structured readings of known platforms; extraction runs that propose and are accepted |
| say where it came from | `provenance` | receipts, grades, the register, the document's home project |

Each section below gives purpose, the services an investigation engine would use (name, inputs → outputs, Rn), built vs specified, limits, and what I checked in code. "Built" follows PROTOCOL rule 3: the module is in `build/modules.json` and the R carries no *(not yet met)* mark.

## 2. Per module

### 2.1 acquisition (layer 3; `build/requirements/acquisition.md`)

**Purpose.** "The acquisition act": fetch a document from its public address (direct, Google Drive export, web archive, or rendered), hash and store it as it arrives, write a receipt, profile what it is, capture supporting files, request co-attestation, and return the provenance document a caller promotes (acquisition §Purpose). It **does not read** the document: "its answer carries no `reading` or `text_units`. Reading from the stored capture is `extraction`'s (K49)" (R8).

**Services an engine would use.**

| service | in → out | R |
|---|---|---|
| `acquire(store, body, {cls, member, …})` | `locator` (+ `via: "archive.org"`, `render`, `subresources`, `authority`) → `{ok, existed, document, …}`: a provenance document (not yet filed) | R1–R23 |
| archive arm / `archiveLookup({address, at?})` | a document's own address, optional past instant → a memento chosen by `selectCapture`, with the instant asked and the memento's own datetime both stated | R3, R32, R35 *(R35 not yet met: T33-21)* |
| `document.profile` | automatic on every acquire: `docprofile.identify` + `doctypeFor` + `format-registry.detectFormat` | R17 |
| authority | body `authority` → `determined` with a dated basis; absent → `undetermined` and one `authority-undetermined` task enqueued | R15 |
| `keyedFetch`, `citationLookup` | group-keyed outside service, off by default; CourtListener citation lookup, "labelled as the service's answer and never as verified" | R36, R37 *(not yet met: T33-21)* |
| conditional re-fetch | `captureRequest.heldSha` → `304` answers `unchanged: true`, no capture | R22 |
| credentialed fetch | a member-supplied credential, only to its own host; `reproducible_by_public: false` | R23 |

**Recorded on every capture** (R13, R16): one receipt; `provenance_chain` (first hop this instance; archive or Drive hop); `capture.grade` (`EARNED_CAPTURE_CEILING` direct, `ARCHIVE_CAPTURE_GRADE` archive; R18); `actor_class` and `actor`; `origin` (`named_request` or `sweep` with `matched_sweep`); `attestation_attempts` (trusted timestamp + co-archive at every capture, R20).

**Invariants that bind an engine.** "No intake path writes live state: `acquire` returns a provenance document and writes no bundle … the caller promotes" (R25). "The raw bytes as served are the primary evidence … never rewritten" (R26). "A provenance fact a caller can hand in is one a caller can invent" (R27): an AI or a member cannot assert a hop or grade. "Fetching is policy-governed, never caller-governed": public locator, host governor, a user agent naming the purpose (R28, R9, R24).

**Built vs specified.** Built (module merged; R1–R30, R33–R34 carry no mark). R31–R32 were marked T23 L3 in the Status; R35–R37 were folded "not yet met (T33-21)" but ACQUISITION #10 merged on `tranche/T33` with "R35–R37 met, marks struck" (`build/rulings.md` K1551). Built on the tranche branch, not yet on `main`.

**Limits for an investigation.** Only public `https:` locators (R2); there is no notion of *why* a document was fetched beyond `origin` (named request or sweep) and the `purpose` string in the user agent (R9). The past-date archive ask still requires the address be fallback-eligible (unreachable now) (R35; Suggestions T33: "Whether a past-date ask should lift R3's fallback-eligibility rule … is left as it is"). That matters for investigations: asking "what did the district's project page say in 2023?" of a page that is still live is refused `NOT_ELIGIBLE` *(inference from R3 + R35)*.

### 2.2 capture (layer 3; `build/requirements/capture.md`)

**Purpose.** The capture store and its acts around acquisition: source reachability (R8), the event queue (R15), the evidence store by digest (R21), capture sessions (R22), the platform ceiling (R23), site assets and reuse (R24–R26), outbound links and their verdicts (R27–R29), the render allowance (R39–R40), the **doorbell** (anyone may hand the group material without an account; R30–R32, R53–R54, R65–R67, R80), late co-attestation and the capturing member's account (R68–R69), and **held captures** (R77–R82). `acquire` here is a pass-through to `acquisition` (R73).

**Services an engine would use.**

| service | in → out | R |
|---|---|---|
| `getCapture(sha, range?)` | digest → bytes or `EVIDENCE_NOT_HELD` | R21, R63 |
| `sourceReachability({addressNorm})` | address → counts, eligibility for archive fallback, basis | R8 |
| `linksTo({address_norm})`, `resolveLinks({sourceCapture})` | which held captures cite an address; each link's three-valued verdict (`contemporaneous`/`superseded`/`undetermined`, `offsite` when nothing held) | R27 |
| `links` table read contract | `source_capture`, `address_norm`, `partition` (`deferred` = not yet followed) — read by `retrieval` R40's frontier and `connections` R29 | R57 |
| `heldCaptures({member?, project?, …})` | the documents at `collected` (captured, not yet released/ratified), with project, age, batch eligibility | R77, R78 |
| `setAside` / `restoreHeld` | member-only, reasoned, append-only | R79, R81 (C-118.8: "Setting held material aside … is a member's own act") |
| `pullKnock` | a doorbell knock → a provenance document with `source: {kind: "knocker", …}` and `knocker_note: {…, evidence_of_truth: false}` | R65 |
| `reattest`, `recordCaptureAccount` | late timestamp ("proves the bytes existed by <at>, not at capture"); the capturing member's signed account | R68, R69 |

**How a document is tied to a question here.** The Suggestions say the held-captures page's "link them to a question" act "is `op=cite` over the selection onto the inquiry, with one stance for the whole batch (`citation` R1–R3; `retrieval` R18's selection) (K1019)" (capture §Suggestions, Held captures). So the tie from a captured document to an *inquiry* is a citation with a stance, owned by `citation`, not by capture. A document's *project* is `provenance.homeOf` (R32's sort, R77).

**Built vs specified.** Built; Status names R17/R29/R41 not met but those moved to acquisition; DEC-88/95/97/108 folds (R31, R32, R47–R53, R66, R76–R81) were "not yet met (T22)" then "met K1037" for the C-118 rows (table heading). R82 added T23. No inline *(not yet met)* marks remain on the Rs themselves.

**Limits.** Held captures are listed by member and project, not by inquiry or question; "nothing about held captures is notified" (R77). The doorbell knock carries a note but "a knock is not a capture and not a bundle" until pulled (R32).

### 2.3 capture-sources (layer 3; `build/requirements/capture-sources.md`)

**Purpose.** "The source-specific halves of capture that decide what a fetch from a particular kind of source is and what its record says": the rendered-page record and the in-plane CDP renderer (R1–R26, R54), the web archive (CDX R27–R36; Memento RFC 7089 R37), Google Drive (R38–R46), and member-supplied credentials for a refused capture (R55–R63), the one thing it stores.

**Services an engine would use (indirectly, through acquisition).** `selectCapture(rows, {notAfter})` (newest usable row at or before a time, R30–R31); `timeMapCandidates(timemap, {notAfter})` (R37.6) — the building block of "what did this page say on date X"; `renderedAuthority` (R16–R17: a rendered page is `determined` as the host's only when every data origin is same-host and no third party ran code); `readDriveAddress` (folders and unknown shapes "named, never silently skipped", R40); `credentialSupply`/`credentialsForFetch` (member, project or group scope; R55–R56).

**Doctrine.** "What could not be observed is stated `undetermined` or `null` with its reason, never an empty list or a default that reads as measured" (R49). "Completeness and authority are separate axes, and neither touches the grade" (R50). "Equality that costs nothing is not evidence" (R52). The archive hop "is a dated third-party claim trusted, not verified" (R34).

**Built vs specified.** Built (R37 met T22, K1034). R55–R63 (credentials) were "not yet met (K103, K109)" at fold; no inline mark remains on them *(the Status sentence is the only mark; I did not verify their code)*. R26's quiet-window rule "is off until N is measured".

**Limits.** No fetch of folders (a Drive folder of bid documents is refused `DRIVE_FOLDER_NOT_A_DOCUMENT`, acquisition R4); an investigation must enumerate files itself *(inference)*.

### 2.4 sources (layer 3; `build/requirements/sources.md`)

**Purpose.** "Holds each source, meaning the knocker, the person who handed material over, and later the person revealed behind them, as a dated, attributed history of disclosures, never as one overwritten field (DEC-78 item 5). It also answers what of a source may be published, and to whom." (§Purpose)

**Services.** `sourceOf({captureSha, viewer})` (R1); `recordDisclosure` with `how ∈ {self, filing, third_party, hostile}` and required evidence (R2); a hostile disclosure is always "not confirmed by the group" (R3); `publishableAt({source, audience})` — "The group is never the first to make a detail more public" (R8); `rungOf` ladder (R9); `markKeyedResult` / `keyedResultOf` for a paid people-search result, cited one grade lower (`grade_cap`), "never bulk-imported", never by a machine (R16–R18, *not yet met: T33-22*).

**For an investigation.** A whistle-blower inside the school district who knocks with a change-order log is a *source*; the system tracks what is known about them separately from the document. R12: "The capturing member is never recorded as the source of what someone else gave them." R18: "No act here runs unattended" and "Nothing records what a member searched for." An AI researcher may therefore never mark keyed results, and the planner may not run paid lookups *(inference from R18 + acquisition R36 "never one a daemon uses")*.

**Built vs specified.** Built R1–R15 (met T16, SOURCES #1, K541); R16–R19 built on `tranche/T33` (SOURCES #11, "R16–R19 met, marks struck", K1550), though the file's Status still reads "not yet met".

### 2.5 site-profiles (layer 1; `build/requirements/site-profiles.md`)

**Purpose.** "Recognises which host-technology stack served a captured document (`identify`) and, under that stack's handler, reduces its bytes to three digests that separate machinery, furniture and substance (`digests`, `compare`); judges whether a rendition is faithful enough to show (`fidelity`) …. It also holds the one recogniser registry and confidence ladder every recognition axis is built on, and the one significance-graded event catalogue." Four stack handlers: `aspnet_webforms`, `wordpress`, `client_rendered`, `conservative`.

**Services.**

| service | in → out | R |
|---|---|---|
| `identify(ctx)` | headers, locator, content type, text → `{handler, confidence, signals, considered, kind?, why?}`; always a handler, `conservative` at NONE when nothing matched | R1–R3 |
| `CONFIDENCE` ladder | CERTAIN, LIKELY, POSSIBLE, NONE — "the ONE ladder shared by every axis" | R4 |
| `makeRegistry` | the generic recogniser registry (key, label, version, `detect → {match, confidence, signals}`) | R5 |
| `digests` / `compare` | identity, rendition, evidentiary digests; verdict `identical/undetermined/changed/restyled/unchanged` | R6–R10 |
| event catalogue | `EVENTS` with fixed significance `event > notice > routine`; `isMeaningful` | R13–R14 |
| `profileRecord` | "A judgment's author and version are always named, so a later session can find and revise it" | R12 |

**Relevance.** The registry (R5) is *the* extension shape for recognising a new kind of document — any new doctype (an RFP, a bid tabulation, a change order) would be a registry member (Content Framework §4, cited in Satisfies). The confidence ladder is the vocabulary an engine should use for "what kind of document is this".

**Built.** Every R moved without change of meaning from `docprofile` (built, T2); R5, R10, R13–R15 new ids for existing services. Module listed in Status as split at T19 *(I did not confirm its `modules.json` entry; see §4 below)*.

**Doctrine.** "The failure asymmetry … a handler applied without CERTAIN confidence never asserts 'unchanged'" (R18); "Every 'no' … says which kind of no and why; absence is never reported as sameness and never as non-existence" (R19).

### 2.6 docprofile (layer 1; `build/requirements/docprofile.md`)

**Purpose.** "Recognises which content type a captured document is (`doctypeFor`) … and, given two captures of the same address, says what changed between them in LAYERS … (`assess`) …. It gives extraction the one entry point that runs the same recognisers over text from any container (`readText`)." Every content type's vocabulary comes from the active jurisdiction profiles, not code.

**Services an engine would use.**

| service | in → out | R |
|---|---|---|
| `doctypeFor(ctx)` | stack id + text + `view` → `{type, confidence, signals, considered, also}`; always a type, `generic` at NONE as fallback; `also` names every other type that also matches ("about one in twelve") | R4, R5 |
| `readText(supplied, ctx)` | text (bare or interface I2: `document`, `pages[]`, `paragraphs[]`, `undetermined[]`) → `{determined, partial, text_from, stack, doctype, parsed | parse_error, position_parts}`; `determined: false` when mostly undetermined | R18, R19, R37 |
| `flattenText`, `makeLocator` | a total `locate(offset)` → the segment's `source` (page/paragraph) or null | R21–R25 |
| `assess(before, after, ctx)` | two captures of one address → layered verdict L1–L6 with `stopped_at` and `trail`; `meaningful` true only for `changed` | R11–R17 |
| `CONTRACT` | how a type is watched: `SUBSTANCE`, `MEMBERSHIP`, `UNMONITORABLE` | R29 |

**How an unfamiliar document is handled.** This is the answer to Bob's first key question at this layer: an unfamiliar document gets the `generic` type at confidence NONE (R4), its stack is `conservative` at NONE "with `why` stating that nothing was recognised" (site-profiles R1). It is still read as text with positions (R18–R25), but no structure beyond pages/paragraphs is recovered, because structure comes only from a registered type's `parse`. There is no step that says "this is probably an invoice; let me look for its line items" — recognition is by deterministic, profile-supplied vocabulary, not by purpose (R30, R31: "Deterministic over its inputs"). *(inference from R4, R19, R31)*

**Positions.** "An entity's position (`source`) is only ever what `ctx.locate` returned … never composed, never guessed" (R34). A reference read twice is one entity with `occurrences` (R34, D-454).

**Built.** Built (all met T2); R36 (no content type here) not yet met (T33-12), with the seven types moving to `doctypes`.

**Gaps.** Content types are keyed to civic-meeting documents (calendar, minutes, agenda, staff report, regulation, directory). R11's layers "L1 (stack) through L6 (connections)" decide *change*, not *meaning for a question*.

### 2.7 doctypes (layer 1; `build/requirements/doctypes.md`)

**Purpose.** "The seven content types: what kind of document a capture is (a meeting calendar, minutes, an agenda, a staff report, an ordinance or resolution, a staff directory, or none recognised), what is in it, and whether a change between two readings of it is meaningful." The `regulation` type also reads sections, headings, definitions, exceptions (R9–R19, new in T33).

**Services.** `DOCTYPES` in load-bearing order (R1); each type `{key, label, version, contract, detect, parse, assess}` (R3–R8). `regulation.parse` → `form` (`instrument`|`code`), `sections` `{path, number, heading, start, end, source}` (R10) — "the `portion` extents `standards` keys on"; `definitions` `{term, start, end, source, section}` (R13); `exceptions` with `cites` (R14).

**Structure recovered.** For a regulation: a section tree with exact extents, definitions, exceptions. "Where the text read cannot be divided … `sections` is empty with `sections_why`, never one section standing for the whole" (R11). "Definitions and exceptions are readings, never law relations: nothing here records `defines` or `excepts`; a member does, in `standards`" (R15) — a direct instance of machine reads / member adopts.

**Built vs specified.** The Status says "Every id is not yet met", but DOCTYPES #1 merged on `tranche/T33` with "R1–R24 met, marks struck; 83/83 section boundaries on the captured code and Charter" (K1527, K1539). Built on the tranche branch (code `doctypes/`, checked: `regulation.mjs`, `sections.mjs` present).

**Gap for Bob's scenario.** No type for procurement documents: an RFP/RFQ, a bid tabulation, a contract, a change order, a progress or status report, an invoice. The `staff_report` type would catch a board item recommending the award (by its template section headings from the profile: "recommendation, background, fiscal impact"; docprofile §Uses), but nothing reads an RFP's table of contents or a contract's terms *(inference from R1's list)*.

### 2.8 budget-doctypes (layer 1; `build/requirements/budget-doctypes.md`)

**Purpose.** "Reads a government's financial documents as tables: annual comprehensive financial reports (ACFRs) from their PDF text layer, budget books …, and budget line-item tables published as CSV or workbooks. Each table keeps every figure exactly as printed …. Reading is not extraction: nothing is written to the record."

**Services.** Three types `financial_report`, `budget_book`, `budget_table` (R1). Tables `{title, page, period_as_written, scale, columns, rows, usable, modal_share, why, method}`; each cell `as_read`; "No figure is parsed, scaled, signed or totalled here" (R2). Usability: ≥ 85% of figure rows at the modal cell count (R3). Image-only tables read only from a supplied OCR transcription, else listed `unread` "never as an empty table" (R6). Budget lines keyed on fund and org codes; departments as dated groupings "never carried from one period to another" (R7, R8). `assess` events `outcome_changed`, `item_added`, `delisted` (R9).

**Doctrine.** "A figure becomes a money fact only through `calculations`' ingest at a member's request (K1468), and a total is a calculation (K1471), never a reading" (R10). "Every figure given is as printed: no figure is inferred, corrected, scaled, rounded or completed" (R11).

**Built vs specified.** Status says "not yet met … Code today: none", but BUDGET-DOCTYPES #1 merged ("R1–R14 met, marks struck", K1539); code in `budget-doctypes/` (checked: `tables.mjs`, `lines.mjs`, `figures.mjs`). Built on `tranche/T33`.

**For the school rebuild.** A district's capital-projects budget table or ACFR capital-assets schedule could be read as tables; tracing a project's budget across years would need the project code keyed (R7 does key `project`) and member ingest into `calculations` *(inference)*.

### 2.9 court-doctypes (layer 1; `build/requirements/court-doctypes.md`)

**Purpose.** "Reads a proceeding's register (its list of entries) as published by three systems: a CourtListener docket page, a CPUC proceeding card with its documents report, and an eCourt register of actions captured by a member in their own browser." `assess` diffs rows so "a new filing or order shows as a new row. It registers no proceeding and writes no event."

**Services.** Types `courtlistener_docket`, `cpuc_proceeding`, `ecourt_roa` (R1); `parse` → `{proceeding, parties, rows, key_basis, complete, page, provisional}` (R3–R8); fee-bearing links "marked `fee: true` and never followed" (R5); `ecourt_roa` only from "a member's own capture made in their own browser" (R2); `sealing` "the row's statement, never this module's finding" (R9); row diff with `possibly_delisted` when not complete (R10–R12).

**Doctrine.** "Everything given is what the register states … a row not on the page is never read as a filing that did not happen. Registering a proceeding (`entities`) and writing a row as a `filing` or `order` event (`events` R38) are their modules' acts" (R14).

**Built vs specified.** Status stale; COURT-DOCTYPES #1 merged ("marks struck", K1527); code in `court-doctypes/` (`courtlistener.mjs`, `cpuc.mjs`, `ecourt.mjs`). Built on `tranche/T33`; `ecourt_roa` still `provisional: true` by R7.

**For an investigation.** A contractor dispute (a stop-notice or mechanics' lien suit, a bid protest) would show on a court register; this module reads it once captured. Suggestion: a register that only grew is `item_added` (ROUTINE), so "Following a proceeding … needs new rows surfaced … Neither is in the plan" (§Suggestions).

### 2.10 legistar-reader (layer 1; `build/requirements/legistar-reader.md`)

**Purpose.** "Reads captured Legistar Web API JSON as content: bodies, persons, office records (seats only), events, event items, votes, and matters' enactment fields. Its rows carry the source system's own identifiers at both ends, so what it reads is a system-rule assertion the machine may write (DEC-52; K1443), dated 'as recorded by Legistar', never as truth. It drops every contact field."

**Services.** `legistar_api` type (R1); rows `{kind, key, ids, facts, source, assertion: "system", basis}` (R2); per endpoint: bodies (R4), persons with `same_name_as` and nothing merged (R5), seats (R6), events (R7), last-published "an upper bound, never a first posting" (R8), event items with mover/seconder and votes (R9), matters with `MatterFile`, enactment number/date (R10); paging (R11); `assess` events `scheduled`, `cancelled`, `rescheduled`, `agenda_published`, `outcome_changed` (R12).

**For an investigation.** For Bob's school case, if the school board publishes on Legistar, the award vote (event item, `passed`, votes per member, the matter's file number) is read with source identifiers. This is the best-structured path to "when was the contract awarded and who voted" *(inference)*. Note: many school districts use other board platforms (BoardDocs, Simbli) for which no reader exists *(general knowledge)*.

**Built vs specified.** Status stale; LEGISTAR-READER #1 merged ("R1–R16 met, marks struck", K1515). Built on `tranche/T33`, tested on captured JSON; "the live acquisition waits for the release" (Status).

### 2.11 roster-reader (layer 1; `build/requirements/roster-reader.md`)

**Purpose.** "Reads rosters, organisation charts and staff directories for who is in an organisation and in which post, as the documents state it." Types `staff_roster`, `org_chart` (R1–R3); `rosterColumns` names a payroll/roster table's columns (R6); `directoryPersonRefs` gives each directory contact a `match_grade: "C"` name ("a name alone … can never resolve a person above grade C", R7).

### 2.12 extraction (layer 4; `build/requirements/extraction.md`)

**Purpose.** "Makes readings from captured bytes. It has `reading-pipeline` produce a capture's text through the tier ladder …, compose the transcription chain as it goes and run the content type's reader over the text, and records the reading with its provenance, its references as they appear, its text units and its text-source projection. It keeps every distinct reading of a capture and attributes a re-read that disagrees; re-reads a capture at a member's request …. It measures no engine (`calibration`'s). It mints no content (`content`'s), resolves no reference to an entity (`entities`'), fetches nothing from outside, and writes no bundle."

**Services an engine would use.**

| service | in → out | R |
|---|---|---|
| `read(document, env)` | an acquired document → `{reading, text_units}`; bytes only from the evidence store, "no field the caller sends supplies text" | R1, R18 |
| `writeReading(…)` | at promotion: reading row, references (raw `kind:key`, unresolved, with positions), name terms, text-source row, text index | R19–R22 |
| reading history | every distinct reading kept, with `compareProvenance` against the previous | R23 |
| `onReading` listener | later modules (content's stale mark, observation-log) run in the same transaction | R24 |
| `readingFor(captureSha, viewer)` | reading, reader, provenance, history | R27 |
| `documentsByReference(ref, viewer)` | every captured document whose reading carries `ref` (e.g. a file number), with positions | R28 |
| `unitsOf(captureSha)` | text units with extents (page, paragraph, slide, sheet-range), index state `whole`/`partial`/`none`/null | R36 |
| read contracts | `readings`, `reading_refs`, `reading_ref_terms`, `capture_text_skipped`, `reading_text_source` joinable by later modules (entities, connections, retrieval's frontier, search) | R58 |
| re-read (`op=pdfstructure&ocr=1`) | a member with `contribute` asks OCR for unread pages; an `ai` credential is refused `REEXTRACT_AGENT_REFUSED` (C-51.2) | R31–R35 |
| agenda containment | `membership` of file links in agenda items, `grade: C, standing: inferred, established: false` | R52 |
| `indexTestimony` | a member's authored observation indexed as its capture's own text | R61, R65 |

**The AI extraction vocabulary (how machine extraction is accepted).** The EXTRACT role's vocabulary lives here; "the act that uses it is `ai-runs`'" (R41 heading). `EXTRACT_FUNCTIONS` holds exactly `propose-reading` (R41). "`proposedReadingGrade(entry)` is computed, never taken: a kind and key earn B, a label alone C, nothing earns null"; refusals include `GRADE_OFFERED` (a caller-offered grade) and `PROPOSAL_ABOVE_CEILING` (stronger than B) (R42). `proposalChain` appends an `ai(fn, version)` step to the capture's chain — so an AI reading is a weaker derivation on the same transcription chain (R43). The proposal store itself (`extractPropose`, `proposed_readings`) "goes to `ai-runs`" (Status, Size). So: the machine *proposes* a reading, graded by rule at most B; acceptance is elsewhere (`ai-runs`, and a member's citation through `content`/`inquiry`).

**Doctrine.** "No machine mints a grade … a proposal's grade is computed (DEC-4)" (R44). "A reading that finds nothing is a failed reading … never backfilled; absent, empty and null stay three facts" (R45). "A reference is carried as it appears, never resolved here" (R46). R21: a reading this instance did not compose "is recorded as the caller's assertion … its standing is the caller's standing".

**Built vs specified.** Built (approved K102; met through T14/T19). R69 (after-read hook call, T33-23a) has no mark but is new at T33 *(unverified)*. R65–R67 were "not yet met (T19 layer 4)" in Status.

**Limits.** A reading is whatever the content type's reader extracts; for a `generic` document that is text units with positions and no entities *(inference from reading-pipeline R1: `found` exactly when an entity was read)*. No reading is ever made *for a purpose*: `read` takes a document and the jurisdiction view, never a question or task.

### 2.13 reading-pipeline (layer 4; `build/requirements/reading-pipeline.md`)

**Purpose.** "Produces a capture's reading from its stored bytes, for `extraction`, which stores it. It runs the tier ladder: the format entry in the plane, the `pdf-worker` member, and the `ocr-worker` member. It composes the transcription chain as it goes, runs the content type's reader over the text, and states the reading's provenance, its text counts, its container and its text units. It is pure."

**The tier ladder** (how a document's text is recovered):

| tier | what | when | R |
|---|---|---|---|
| 0 | text read as text → content type's reader | a textual single-part type with no format entry | R1 |
| 1 | format entry in the plane (`format-registry`) | any registered format | R2 |
| 2 | `pdf-worker` | a PDF whose undetermined markers outnumber its glyphs (not a pure scan) | R3 |
| 3 | `ocr-worker` | pages with `no_text_layer`, none `encrypted`; up to 24 calls; a member's answer taken only with engine, version and a measured `cap` | R4–R9 |

**Structure recovered.** `page_count`, `container_extent` (sheets with used ranges, paragraphs, slides, tables, images by `{page, rect}`), `page_boxes` (R12); `dialect` for delimited text (R13); `reading.provenance` (`reading-provenance/1`: per-page tier, producer, text digest) (R14, R18); text counts (R17); text units one per page/paragraph/slide/sheet-range, 512 KiB on the wire (R15); for workbooks, `metadata` and typed `cells` (R28, T33-24).

**After-read hook.** `onRead(module, fn, {captureClasses})` / `afterRead(…)`: a later module opts in per capture class and runs *after* the reading commits, its failure never undoing the reading; "A hook never runs inside `read`" (R25–R27, T33-23, not yet met). This is the substrate's only "when a document of kind X is read, do Y" seam — the natural place for an investigation engine to be told "a document in the case file has been read" *(inference)*. `events` R4 keeps its class list "empty until a member's recorded act widens it" (R25).

**Built vs specified.** R1–R24 built (moved from extraction in T25). R25–R28 built on `tranche/T33` (READING-PIPELINE #4, "R25–R28 met, marks struck", K1557; the registry is per storage, `readHooksOf(ctx)`, K1555); extraction calls `afterRead` (EXTRACTION #13, R69 met, K1558).

### 2.14 content (layer 4; `build/requirements/content.md`)

**Purpose.** "Content is the unit the record points at: a reference to a part of a captured document, up to and including the whole. This module holds the extent grammar (which part of a document), the content address (`hash(capture, extent, chain)`), the content row minted over it … and a member's typed transcription of a part, which a second member attests. It says, for one cited passage, whether a newer capture exists and whether the passage is carried into it, without moving anything. It never moves a reference: the record points where a member pointed."

**This is how a document is tied to a question.** Citations from "the modules whose edges cite (inquiry, basis versions, cases, actions)" are checked and resolved here: `citationRefusals(citations, label)` and `resolveCitation({target, extent?, content_id?})` → `{content_id, minted}` (R27, R28). The leg-side `cite` act itself "is `inquiry`'s and `basis-versions`'" (Suggestions, What stays out). So a document reaches a question only as a member's citation edge from an inquiry to a content row (a passage of a capture under a chain).

**Services.**

| service | in → out | R |
|---|---|---|
| extent grammar | eight kinds: `document`, `pdf-page {page, rect?}`, `sheet-cell`, `slide-shape`, `doc-para`, `sheet-range`, `doc-table`, `image`; plus `envelope` (office metadata items) | R1–R10, R33 |
| `contentIdFor` | SHA-256 over capture, canonical extent, chain — "one passage of one capture under one chain has exactly one id" | R3 |
| `mint` / `contentMint` | mint or find a content row; never rewritten | R12–R15 |
| mint label | `member_marked`, `plane_minted`, `machine_marked` ("machine work, never attested by a machine, and part of a finding only when a member cites it") | R16 |
| `contentRead` | row, label, transcription axis, attestations, capture axis | R17–R19 |
| `markStale` / `onStale` | a re-read with a different chain marks rows stale, graded A/B/C/NOT_FOUND/UNDETERMINED, members citing told; "nothing moves by itself" | R22, R41 |
| `transcribe` + `transcriptionAttest` | a member types a passage (e.g. a scanned bid form); a *different* member attests with a note | R23–R26 |
| `attestText` / `attestationsFor` | a member attests a machine transcription over an extent; raises the transcription ceiling | R43, R44 |
| `passageNotice` / `noticeForRow` | is there a newer capture of this document, and is the cited passage carried into it (A byte-identical, B moved, C Dice ≥ 0.7) | R29–R31, R47 |
| `passageText`, `cellsAt`, `officeMetadataOf` | the text at a row's extent; typed cells; an office file's author/modified metadata | R46, R52, R53 |

**Doctrine.** "A row is first-class: never rewritten … and the record never moves a reference's target without a member's act, even when the passage is byte-identical" (R34). "Two graded facts, never one: the capture grade is the document's (`provenance`) and the derivation cap is the row's" (R35). "A machine credential may mark a passage citable, labelled (R16), and never attests (C-35.10) or types (C-52.1)" (R36). "Every act and read naming a document or row answers one the viewer may not see exactly as an absent one" (R37).

**Built vs specified.** Built (all met by CONTENT #2, T7, K180); R25/R43 note (DEC-88) not met at T22 fold; R48–R51 at T19 L4; R46 amendment and R52–R54 built on `tranche/T33` (CONTENT #12, "R31, R46, R52–R54 met", K1560).

**For the school case.** A citation of "the contract's completion clause, page 14" is a `pdf-page` extent content row; when the district republishes the contract, `passageNotice` says whether the clause is carried into the new copy (R29–R31) *(inference)*. There is no extent kind for "section 7.2 of the contract" by its own numbering: `doc-para`/`pdf-page` are container positions; `doctypes` R10's `sections` give extents only for regulations.

### 2.15 text-chain (layer 1; `build/requirements/text-chain.md`)

**Purpose.** "Holds the transcription provenance CHAIN: what a derivation step (a decode, an OCR pass, an AI clean-up, a conversion, a member's typing) may claim, the rule that a chain can only weaken as it grows, per-region confidence honesty, the image-region anchor a machine reading must carry, member attestation and the extent it is scoped to, and the reading-position/extent geometry that bounds what an extraction or a citation may claim." Pure; never throws (R82, R83).

**What it gives an engine.**

| service | meaning | R |
|---|---|---|
| `STEP_KINDS` | the step kinds (layer, ocr, ai, convert, typed, attested …), each `derivation` or `verification`; `ocr` and `ai` are `machine: true` | R1–R3, R91 |
| `appendStep` | refuses `TEXT_CHAIN_STRENGTHENS` (C-35.6) when a derivation step claims a stronger cap than the chain — "rule 2": a chain only weakens | R12–R14, R85 |
| `derivationCap(chain, {page})` | the weakest measured cap over the steps covering the page; null when any covering step is unmeasured or unreadable | R25–R30 |
| `checkConfidence` | a confidence is a number only with `basis: "engine"`; otherwise refused `TEXT_CONFIDENCE_PSEUDO` (C-35.7) — "the fence is on WHO produced the number, never on its value" | R40–R43 |
| `checkAnchor` | a machine reading must anchor to `{kind: "pdf-page", page, rect}` | R47, R48 |
| `checkAttestation`, `extentCovers`, `gradeCeiling` | a member's attestation (never a machine's, C-35.10) over a region/page/document lifts a passage's ceiling to `EARNED_CAPTURE_CEILING` | R49–R57 |
| `captureBound` | "Transcription fidelity BOUNDS the capture axis (DEC-4): never a third scale"; an unmeasured engine's output gives null | R58–R60 |
| reading positions and extent algebra | `readingSource`, `readingPositionInExtent`, the eight extent kinds, A1 ranges, `describeExtent` | R61–R72, R92–R98 |
| `chainKindFor` | a page covered by two different derivation kinds reads `mixed` | R81 |

**Relevance.** This is how AI reading of a document is bounded in grade. An `ai` step must name its engine (R8); its cap can never be stronger than what precedes it (R13); an LLM's self-reported confidence is not a confidence (DEC-35 via R42) *(inference: an LLM is not "a classic engine" in DEC-35's sense as R42's Satisfies words it — "a number is only a number when a classic engine computed it")*. A passage an AI read can be lifted only by a member's attestation (R56).

**Built.** "Every id met and tested in T2"; R87–R103 later folds (N98, N102, N104, N416), no marks.

### 2.16 provenance (layer 3; `build/requirements/provenance.md`)

**Purpose.** "Holds the record's trust root: the register, which says which bundle is the one home of each captured byte sequence; the plane's own acquisition receipts, which say which bytes it fetched from which address, by which route and when; the capture grade a capture's route earns; and a member's firsthand observation …. A hop attests bytes, address and time, never the credibility of the content." Chains of hops and route markers are `provenance-routes`'; timestamps and the instance key `attestation`'s (N512).

**Services.**

| service | in → out | R |
|---|---|---|
| the register (at promotion) | one row per capture: home `bundle_id`, path, bytes, `registered`, `authored` — "One capture, one home" (C-53.13) | R1–R3 |
| `homeOf(captureSha)` | the bundle that is the capture's home | R4 |
| `capturesOf(bundleId)` | a bundle's captures in the order first held | R12 |
| `recordReceipt` / `receipts` | one receipt per (address, capture, via); `observation` `new`/`unchanged`/`changed` read from the record | R13–R16 |
| `onReceipt` | a later module's work on each receipt (observation-log) | R47 |
| `versionChain({addressNorm, at})` | every held version of one document address, ordered by first retrieval, with predecessor | R17, R18 |
| `captureGrade(captureSha)` | direct → B (`EARNED_CAPTURE_CEILING`); archive → C; no route → authored letter, undetermined; doorbell → `CAPTURE_RECEIVED_NOT_FETCHED`; testimony → no capture letter, `TESTIMONY_GRADE` D | R24–R27, R51 |
| `testify({words, observedAt, …})` | a member's firsthand observation as a new information bundle at `collected`; the author stamped, never supplied | R28 |
| `declareOrigin` / `originOf` | a member's dated declaration of the system a document came from ("a host is not an origin") | R29, R30 |
| read contract | `register`, `captured_locators` joinable in SQL | R48 |

**How a document is held.** A captured document's home is one *bundle* (an information bundle created by promotion) — the register says which (R1, R4). There is no "case file" or investigation container here: the only grouping of documents is the bundle and, through `bundleInfo`, its project (capture R77 uses `provenance.homeOf` for project) *(inference)*. A member's own account of a site visit ("the construction fence has been empty for three months") is a `testify` observation at grade D (R27, R28).

**Gate checks (C-18).** A `collected → verified` transition is authored by a named member, never a machine; a sweep-origin bundle reaches `verified` only through such a transition (R42). A `crucial` document without co-archive or timestamp is flagged (R44).

**Doctrine.** "The register is the only thing that proves bytes" (R35). "Undetermined is stated, never rounded" (R37). "No letter above `EARNED_CAPTURE_CEILING` is ever earned" (R27).

**Built vs specified.** Built (approved K67; PROVENANCE #6 met T16). Status lists not-yet-met marks for R12, R21–R26, R29–R30, R47 at the 2026-09-26 draft and later folds R52–R58; no inline *(not yet met)* marks remain on the Rs *(I did not verify which were met since; R29–R30 `declareOrigin` matters to the engine)*.
