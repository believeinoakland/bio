**How the work is done elsewhere, and how it fails.** Newsrooms already ask document sets questions (DocumentCloud's GPT add-on, https://www.muckrock.com/news/archives/2023/apr/10/release-notes-introducing-documentcloud-ai-credits-gpt-3-add-ons-bulk-editing-add-ons-and-more/; citymeetings.nyc makes council meetings navigable with an LLM, https://civictech.guide/projects/citymeetingsnyc), and the AP treats any generative output as "unvetted source material" (https://ds.svcs.associatedpress.com/standards-around-generative-ai). The failure modes are measured and severe exactly where Bob wants the assistant to go: legal research tools built on retrieval still produced incorrect answers 17–34% of the time (Stanford RegLab/HAI, https://hai.stanford.edu/news/ai-trial-legal-models-hallucinate-1-out-6-or-more-benchmarking-queries); general models hallucinated 58–88% on verifiable case-law questions and failed to correct false premises, with the risk highest for people without lawyers (https://arxiv.org/abs/2401.01301v1); judges had addressed more than 1,450 filings with AI-fabricated authority by mid-2026 (https://www.malaymail.com/news/tech-gadgets/2026/06/16/do-your-job-global-courts-face-rising-tide-of-ai-generated-fake-cases-and-quotes/223865); New York City's own chatbot told landlords they could refuse Section 8 vouchers and bosses they could take tips, both illegal, and is being shut down (https://themarkup.org/news/2024/03/29/nycs-ai-chatbot-tells-businesses-to-break-the-law, https://themarkup.org/artificial-intelligence/2026/01/30/mamdani-to-kill-the-nyc-ai-chatbot-we-caught-telling-businesses-to-break-the-law); 45% of assistant answers about news had a significant problem, sourcing the commonest (https://www.infodocket.com/2025/10/22/bbc-largest-study-of-its-kind-shows-ai-assistants-misrepresent-news-content-45-of-the-time-regardless-of-language-or-territory/). Needs D–I are therefore where a careless assistant does the most harm, and the design below is built around that.

## 3. What exists now

### 3.1 The answer to Bob: what is and is not true today, and why

**True.** Bob ruled the assistant on 2026-08-03 (DEC-27, archive src 1784–1932): a tag on every surface opening a dialog that takes free text and voice, three request kinds (FIND, CREATE, ACT), and the rule that it *"gets its understanding of the rules from the server"* and holds no copy of them (DEC-8 applied). The member-facing flow is designed (ASSISTANT-PILOT §2–§3; Interaction Constructs §P), the panel is ruled (DEC-90), its voice (DEC-125), wizards and labelled drafts (DEC-120, DEC-121, K1364), and journey 9's front door is *"Opening the panel and asking in plain words"*. Beneath it a different AI function is built: the investigative session (IS plan 43/43) — the `ai` credential class, the bounded run, its observation log, the skill pack (rendered in production through `op=affordances`), suggestion-only writes, capture requests, and `agent-worker`, whose `model.mjs` is the one place in the repository that calls a model (Anthropic Messages API) and whose sub-sessions already translate an intent into query-language strings (`model.mjs`:215–226).

**Not true.** No member can ask a question in plain words, on any copy, through any screen:
1. **Nothing to ask into.** No tag, panel, prompt box, INTERPRET step, classifier or FIND flow exists (ASSISTANT-PILOT Status, 2026-09-14; AIR §8: "DESIGNED, not built"; design HANDOFF §4, 2026-10-02: "no member-facing panel, prompt box or wizard exists"). No op takes a natural-language question (M5); no requirement file mentions natural language (M3); UC-092 "Ask the assistant in my own words" has no requirement (D1). The wizard module is built but `SCREENS` and `CIVICSMITH_LIBRARY` are empty, so no wizard can run (M5). The legacy interface never opens, lists or reads the log of a run (`app.html`:22850–22851).
2. **What is built is not a question-answerer.** The one deployed mode, `check`, reads an existing conclusion adversarially and writes suggested basis versions; *"as built the assistant is a bounded, adversarial evidence-checker that writes suggested basis versions and answers no question in prose"* (X155).
3. **It cannot run.** Only `check` is deployed (`run-rules/deployment.mjs` `DEPLOYED_MODES` = `["check"]`; `agent-worker/src/harness.mjs` `MODES`). No plane path starts a run's first segment: the plane calls `agent-worker` only on a wake after capture requests complete, and only for a run the instance's organisation `ai` credential opened; a member's run is withheld (`MEMBER_PRINCIPAL_RUN`, `ai-runs/index.mjs`:1590). The installer never sets a model key (`INSTANCE_CLAUDE_TOKEN` appears in `newgroup/` only inside the embedded plane bundle, `release.mjs`, never in the installer's own code) and never generates the `ai` credential (`newgroup/src/index.mjs`:391–405, "it NEVER GENERATES ONE"), so a new install answers `NO_ACCOUNT_RESOLVED` / `NO_INSTANCE_AI_CREDENTIAL`; the plane's `AGENT_WORKER` binding is "INERT UNTIL DIST DEPLOYS THE MEMBER" (`bio-plane/wrangler.jsonc`); no deployed copy runs model turns and releases are held (HANDOFF §4). Whether model turns run at all is itself in conflict: the code runs them when an account resolves (`agent-worker/src/index.mjs`:1457) while the file header (l.34) and the requirement's Status say they do not (M3).
4. **Even running, it could not reach the constructs.** The worker's whole plane reach is `whoami, airun, airunlog, airunspawn, meaningrows, basisversions, search, versionchain, affordances, airuntick, suggest, capturerequest, airunclose` (agent-worker R37): no standard, determination, consequence, clock, local fact, profile or organisation read. The only mode designed to read law, deadlines and consequences is `plan`, which proposes plan options, takes no question, and is `deployed: false` (M1, X140).
5. **The account the design names is the wrong one.** The journeys' setup page "now says 'Claude subscription'" (journeys §6), but the worker authenticates with `x-api-key` (`model.mjs`:43), i.e. an Anthropic API key billed per use; and Anthropic does not permit products to route requests through Free, Pro or Max subscription credentials (https://code.claude.com/docs/en/legal-and-compliance).

**Why.** (a) Sequencing, deliberately: the investigative session was built first and CHECK-first (DEC-55, D-199); DEC-27 was enacted as "nothing queued yet: S12 and its wizard are parked"; the member interface is frozen awaiting the redesign (K633), whose step 5 brings "the assistant panel early (its back end is built and waits on design)". (b) Doctrine: measure before widening (D40; ASSISTANT-PILOT §7), and `investigate` waits on CHECK's first live run verified on a deployed copy (VF-4, DS-4). (c) Deployment: sovereign instances hold their own keys (D201) and the installer never invents a credential (DS-3), but nothing yet carries a group's key in. (d) The constructs themselves: the plane "encodes no law's rules" and the assistant holds no copy of any (X74), and law, time and calculation live in layer 9 with no member surface and no AI path (X23, X191). Bob's sense of the product is right — DEC-27 *is* his plain-language assistant — but it exists as a ruling and a design over a built checker, not as something a member can use.

## 5. Proposed architecture

**Target: L3, reached in stages 1–3; L4 in bounded steps; L5 only as doctrine allows.** The core needs (A–E) sit at L1–L3; investigation-sized questions (G, I) at L4 reuse the investigative session that already exists; L5 meets the standing-run prohibition (D13) and is not proposed.

**Adopted from practice.** (1) *Grounded, closed-book answering with abstention*: answer only from material and rules supplied in this exchange, and say when there is none — the FACTS Grounding standard of "fully grounded in the provided document" (https://arxiv.org/pdf/2501.03200) and abstention as a first-class output (https://arxiv.org/abs/2407.18418v2), which is this product's own "undetermined" and four-level absence. (2) *Structured citations*: the worker hands reads to the model as `search_result`/document blocks with citations enabled, so citations come back as data, not prose (https://docs.anthropic.com/en/docs/build-with-claude/search-results). (3) *Show the query*: the model writes the query-language string; text-to-query is still well short of expert accuracy (best ~82% vs ~93% for humans on BIRD, https://beancount.io/bean-labs/research-logs/2026/06/06/bird-benchmark-text-to-sql-real-database-gap), so every answer shows what was actually asked of the record. (4) *Indirect prompt injection is the top LLM risk* (OWASP LLM01, https://coralogix.com/ai-blog/owasp-top-10-for-llm-applications/): record content is data, and the asking credential writes nothing. (5) *Legal information, not legal advice* — the line courts' self-help services draw (https://judicature.duke.edu/articles/legal-information-vs-legal-advice-a-25-year-retrospective/), drawn against the ABA model definition, "application of legal principles and judgment with regard to the circumstances or objectives of a person" (https://www.americanbar.org/groups/professional_responsibility/task_force_model_definition_practice_law/model_definition_definition.html).

**The rule, extended (DEC-8, DEC-27).** Every rule the assistant applies comes from the plane, and the model supplies no fact and no rule. Four kinds of rule, one source each: *system* rules (what an act refuses) from `op=affordances` and the dry runs; the *group's* rules (bar, lens, declared flows, adopted standards) from their reads; *jurisdiction* rules (deadline grammar, holidays, hours, records laws, offices, venues and their evidence standards) from the profile through plane rule services; *law's text* (captured, versioned, in force at a date) from `standards`. The model's own knowledge is used only to understand the member's words, write queries, read and quote what the reads returned, and translate. Where the plane holds no rule, the answer says so by level ("not held: no standard declared for OMC §13.04; no document held that contains it") and offers the act that would find it — never an answer from memory.

**Data model (nothing new in the record).**
- *Interpretation* (shown before anything is created; Surface rules "what it understood"): the question as read, claims as read, people and bodies named (registry candidates, labelled), the kind (FIND, HELP, CREATE, ACT, DELEGATE), at most one clarifying question (ASSISTANT-PILOT §2).
- *Answer*: `summary` sentences, each bound to `support[]` (a record address, a rule result id or a vocabulary key); `holdings` (address, title, grades, verbatim quote); `rules_applied` (service, rule reference, basis — citation, profile fact, standard id and version, definition version (D264) — inputs, result or `undetermined {why}`, status researched/confirmed/UNMEASURED, `as_of`); `looked` (per level: state in the five look states, searched, not searched, tally — skills R2's shape); `bound` and `truncated` (DEC-64), `out_of_view` (DEC-36), the lens in force (DEC-45 det. 6), `could_not_establish` (DEC-57); `query_shown`; `next_acts` (producer-declared options: open a question, record a lead, start a run, open a wizard, ask a member with declared expertise); label "machine work", model id, skill version, "at <member>'s request" (DEC-90, DEC-125).
- *Persistence*: none in the record. The exchange is a device-local transcript, TTL'd, deleted at publication, held under a litigation hold (DEC-61, DEC-113). An ask writes no observation row and no run row (a member's own looking is not an observation, OLD §4.6, observation-log R24, D158/D161). What a member keeps enters by the member's act (a question, a lead, a cite, a run). Use is measured only as unattributed daily tallies — asks, clarifications, abstentions by reason, levels cited, answers followed by an act (the K1364 precedent), replacing ASSISTANT-PILOT §7 step 6's attributed log. Time: every rule result names its `as_of` and version; every answer says "as of <instant>, the record as you can see it".

**Plane rule services** (non-mutating reads returning a value or `undetermined {why}` with basis — DEC-8's dry-run family widened from refusals to rules): law — `standards`, `standard`, `standardinforce`, `profiles` (exist; no UI, no AI scope today); time — `deadlinecompute` (new: profile rule or held period, start event, office → due date with calendar status; owed by TIME, since `computeDeadline` has no op and hard-codes the weekend), `factstatus` (exists); organisations — `entity`, `entitybyalias`, `resolutions`, `concerns`, profile counterparties (exist), holders over time when ORGANISATIONS builds them; figures — a non-persisting computation over cited figures (owed by ANALYSIS; `consequences` computes only after a noncompliant determination); the record — `search`, `meaningrows`, `frontier`, `contentaxis`, `inquirystrength`, `versionstrength`, `strengthbarof`, `basisversions`, `versionchain`, `leadlist`, `queue`, `intentproposals`, `airunlog` (exist); system — `affordances`, `whoami`, the dry runs. **Excluded** from the asking scope: `sources*` (who a source is stays inside the instance and never reaches a third party, in keeping with DEC-78.5's protection of sources), member read or search history, admin and export ops.

**Module changes.**
- **New `answers` (layer 6, between `skills` and `agent-worker`)** — purpose: the answer contract and the plane's delivery checks for anything the assistant says in prose; the asking read scope, declared once; the interpretation shape; the tallies. Its checks, each a named refusal with a canned translation (DEC-49): a citation must resolve under the asker's view and have been returned by a read in this ask (`ANSWER_CITES_UNREAD`); every number, date, amount and citation string in the summary must occur in a quoted holding or a rule result (`ANSWER_FIGURE_UNSOURCED`); a rule result must match one a plane service returned in this ask (`ANSWER_RULE_NOT_PLANE`); a statement of absence must carry its level (`ANSWER_ABSENCE_WITHOUT_LEVEL`, skills R19). An unsupported sentence is withheld and the answer says so; holdings and quotes always show. Uses record-grammar, membership, query-language, retrieval, observation-log, run-rules, skills; layer-9 rule results reach it by registration (`registerRuleService`, the ai-runs R47 pattern, D214). Used by agent-worker (pure checks, tested at build), control-plane, plane, affordances. These checks are strings and ids: they cannot judge meaning, so a paraphrase can still be wrong — which is why quotes always sit beside the summary ("never only an AI summary", UI-KICKOFF L77).
- **run-rules**: mode `ask`, read-only, interactive, deploying apart like `plan` (its own flag), bounds: model turns, bytes, wall time.
- **agent-worker**: an `ASK_FLOW` table (interpret, clarify, plan reads, read, rule services, compose with citations, self-check, return). It is 3,766 lines, so this needs a split (§8 Q4).
- **membership/credentials**: at the member's act of asking, a short-lived `ai` grant with the asking scope and that member as viewer (DEC-55 det. 3: minting is a member act; the machine sees no more than its principal, MA §7.9).
- **affordances, op-declarations, control-plane**: `op=ask` in the member session (who may: any member who may start a run under DEC-63 as amended 2026-09-18, never a view-only reader); the dispatch starts the worker at once and returns the checked answer while the browser waits; work that outgrows an interactive exchange becomes a run, shown in the running-session surface.
- **skills**: an `ask` layer — the answer contract, the closed-book rule, the legal-information line, absence by level, voice, wizard use.
- **wizard-scripts**: the screen registry and the Civicsmith library filled (DEC-121's required wizards; J5 "write every wizard now").
- **installer and update**: accept the group's API key as `INSTANCE_CLAUDE_TOKEN`; say per member when the assistant is unavailable and why (D-297, DIST rule 4).
- **The panel**: the new interface's (DEC-90), from the UX stream.

**Total order.** `answers` is inserted at layer 6 after `skills` (index 54) and before `agent-worker` (55); nothing moves, so no dependent is affected (`build/modules.json` checked). **QUESTIONS does not require moving `standards`, `consequences`, `action-clocks` or `local-facts`:** the worker is a separate Worker that reaches the plane only through ops, so the barrier is which ops a mode may call, not import order (X26, agent-worker R44). If LAW, TIME or ANALYSIS move them below layer 6 for inquiry's own sake, `answers` imports them and drops the registration.

**The AI's role.** *Proposes*: an interpretation, a clarifying question, an answer from held material and plane rules, a proposed structure built from the member's own words (CREATE), labelled drafts, a run worth starting, a standard worth declaring (`standardpropose`, the Legal/Policy Lookup the requirements name and no code holds). *Decides nothing*: it never commits, concludes, determines, files, sends, chooses the question, writes a member's reason, or states a law (DEC-24 rules 1–4; DEC-27 limits; D274). Run modes: `ask` (new, read-only, interactive); `check`, `investigate`, `extract`, `plan` (existing), started from the panel only by the member's act.

**Doctrine kept**, each by citation: the machine looks, the member concludes (DEC-24); never commits, structures what was said, proposes defaults and never sets them (DEC-27 limits 1–3); holds no copy of the rules (DEC-27 clarified; DEC-8 as amended by DEC-49); describes the system only from what the plane publishes — "a confidently wrong assistant is worse than none" (ASSISTANT-PILOT §1, D48); a skill is instructions, a fence is code (IS §14b.4); own `ai` credential, the endpoint is the fence (DEC-55); transcripts are notes (DEC-61, DEC-113); the bound on every answer (DEC-64); withheld whole (DEC-36, DEC-85); act and say what could not be established (DEC-57); the five absence terms (DEC-86, DEC-98); machine work labelled, "I" in conversation and "the assistant" in records (DEC-90, DEC-125); wizards point, members press; labelled drafts only (DEC-120, DEC-121, K1364); no single confidence score (PS VIOLATE, skills prohibitions); bias never shapes searching (D104); no jurisdiction in product code (D196); profile facts sourced to primary pages (D197); offices, never private persons (actions R9, D176); neutral on policy (OP1, D380); legal tools shown as facts, never recommendations (D279); no machine-invented legal text filed (D255); no standing AI run (D13); measure before widening (D40).

**Runtime and deployment.** Workers Paid allows up to 5 minutes of CPU per request and no wall-clock limit while the client stays connected; Durable Object alarms get 15 minutes; 10,000 subrequests by default (https://developers.cloudflare.com/workers/platform/limits/). An ask is mostly waiting on the model and on plane reads, so it fits one connected request; anything longer becomes a run on the existing alarm-driven wake. Each group pays for its own model use with an Anthropic API key from the Console — the code sends `x-api-key`, and Anthropic forbids routing a product's requests through Free, Pro or Max subscription credentials (https://code.claude.com/docs/en/legal-and-compliance). Estimated cost per answer, at 60–150k input tokens (mostly cached) and 2–5k output: about $0.10–0.20 on Sonnet 5.5 ($2/$10 per million) and $0.25–0.50 on Opus 5 ($5/$25), the worker's default model (https://platform.claude.com/docs/en/about-claude/pricing). Five active members asking five questions a day (about 750 a month) would cost roughly $75–150 a month on Sonnet 5.5 and $190–375 on Opus 5, roughly 15 to 75 times the $5 Workers fee (DEC-42). Stage 1 must measure this. BOB decides the model per mode and records the API's `usage` on every answer, which nothing records today. Turning the assistant on sends questions, and the record material read to answer them, to Anthropic under the group's own key. That is already true of the built session (DEC-55, DEC-63). The enabling act says so at the act (D311).

## 6. How to proceed

**Stage 0 — make any assistant runnable (precondition; deployment, no new module, about 6–10 requirement changes).** Correct the setup fact (an Anthropic API key, not a subscription); let install and update carry the group's key as `INSTANCE_CLAUDE_TOKEN` and say per member when none is set; deploy `agent-worker` (DIST; the binding is inert); settle the model-turn conflict (code runs turns; agent-worker R40/R41 and the file header say not); record the API's `usage` on every call; CHECK's first live run verified (VF-4, the gate `investigate` already waits on). *Measure first:* one model turn on a deployed copy — latency, CPU, cost — and that the cascade resolves a group key. *Unlocks:* nothing a member sees; every later stage becomes testable.

**Stage 1 — L1 "ask the record" (read-only).** `ask` mode, the `answers` module, the asking scope and the member-minted short-lived grant, the skill's `ask` layer, `op=ask`, the panel (UX step 5), the wizard screen registry and the Civicsmith library. *Unlocks:* journey 9's front door for FIND and HELP; journey 3 (a newcomer asks what "Undetermined" means here); journey 4 steps 1–2; UC-092 (find and help), UC-008 in plain words; DEC-27's own FIND example. *Size:* one new module (~1,500–2,500 lines), extensions to about seven (run-rules, agent-worker or its split, membership/credentials, affordances, op-declarations, control-plane, skills), wizard content, about 30–40 requirements, plus the panel. *Measure first:* a set of at least 150 real questions (journeys §3, the auditor's forum list, the use cases), each with its held answer or its correct absence by level; measure grounding (share of summary sentences supported), correct abstention ("not held" when not held), level-statement correctness, query mistranslation, false refusals by the `answers` checks, latency and cost per answer on two models. Members see it only once grounding and abstention clear a bar BOB sets before measuring (the DEC-77 / K491 precedent: nothing goes live before its prompt is measured).

**Stage 2 — L2 (trigger: stage 1's bar met in use; `investigate` verified live).** CREATE from the member's words, conducted acts with labelled drafts, wizards planned on the fly, starting CHECK, investigate and extract runs from the panel, translation and message drafts, and — if Bob rules §8 Q7 — suggested first questions from material the member brought. No new module; about 15 requirements.

**Stage 3 — L3 plane-applied rules (trigger: TIME, LAW, ORGANISATIONS and ANALYSIS have shipped their first services, and the first profile's facts are sourced — today it holds one deadline, `UNMEASURED`, and holidays for 2026 only (M2), so most rule answers would read "undetermined").** `deadlinecompute`, standards in the asking scope with the "not held → propose a standard or request a capture" path, office reads, figure arithmetic; the legal-information line in the skill and in the answer's kinds. *Unlocks:* "explaining a charge or a rule", "when is it due", "who is responsible", "actuals against budget". About 10–15 requirements on this side, by registration.

**Stage 4 — L4 (trigger: the tallies show many answers ending in "not held" or "start a run").** The question-to-run hand-off across all four levels with capture requests; the backward question as a work list (D-165's trigger: members answering it by hand); questions over court cases once COURTS has objects. **Stage 5** is not proposed: it waits on Bob lifting the provisional NO on standing runs (D13; AIR §7.3 point 7).

**Risks and containment.**
1. *Invented law, deadlines or facts* (17–34% even in legal retrieval tools; MyCity) → the closed-book rule, rule services, the `answers` checks, quotes beside every summary, the stage-1 gate.
2. *Mistranslated questions* (text-to-query below expert accuracy) → the shown interpretation, one clarifying question, the query shown, absence by level.
3. *Silent absence* → `ANSWER_ABSENCE_WITHOUT_LEVEL`; the five terms (DEC-86).
4. *Leaks across sight* → reads under the asker's view only; counts gated (retrieval R29); every address re-checked under that viewer.
5. *Injection from captured documents* → the asking grant writes nothing; record data is data (ASSISTANT-PILOT §6).
6. *Practising law* (Upsolve v. James, 2d Cir. 2025, https://www.probonoinst.org/2025/10/07/setback-for-justice-advocates-in-upsolve-litigation/; the FTC's DoNotPay order, https://www.ftc.gov/node/87474; a March 2026 suit calling ChatGPT "an unlicensed lawyer", https://www.probonoinst.org/2026/07/28/access-to-justice-ai-and-the-unauthorized-practice-of-law/) → the information-only line (§8 Q2), no advice kind of answer, routing to counsel and expert members.
7. *Over-reliance* ("accepting without reading", DEC-68) → nothing enters the record without a member's act; the tally of answers followed by acts is the steering signal (DEC-77).
8. *Surveillance of members* → no observation or run rows for asks; device-local transcripts; unattributed tallies.
9. *Cost to volunteer groups* → per-ask bounds; a model per mode; `usage` recorded; spend visible to administrators (§8 Q5).
10. *Vendor terms* → an API key; the disclosure when it is turned on.
11. *P6* → the worker split (§8 Q4).
12. *Describing the system wrongly* (D-106) → the assistant speaks only from published vocabularies, the surface registry and the scripts.

## 7. Interfaces with the other constructs

- **TIME** — *needs:* `deadlinecompute` (a profile rule or a held period × start event × office → due date or `undetermined {why}`, with calendar status, basis, the jurisdiction's time zone and roll-forward); as-of reads; progression findings in the asking scope. *Supplies:* plain-language date questions; tallies of what members ask; DEC-98's wait line ("Waiting on the City Clerk's reply, due 14 October") in answers.
- **ORGANISATIONS and obligations** — *needs:* office and body reads with aliases, holders over time, graded and cited responsibility relations (X102), and obligations as a readable object (who owes what to whom, by when, under what authority). *Supplies:* INTERPRET's "people and bodies named" as registry candidates, labelled (a machine may resolve, machine-attributed, DEC-52); the office-never-person check on anything addressed.
- **LAW** — *needs:* standards in the asking scope with captured text, version, in force at a date, and sections and definitions once built; the profile's standard sources and records laws. *Supplies:* the Legal/Policy Lookup the requirements name (standards R9) — proposing a standard from held or newly captured text, labelled; plain readings of held text, labelled machine work; the "not held → find it" path; the information-only line.
- **COURTS** — *needs:* case and docket objects and their reads. *Supplies:* plain questions over filings. A court ruling is applied as a rule only when held as a standard of kind `court`.
- **ANALYSIS** — *needs:* a non-persisting calculation over cited figures and datasets, its method recorded and its grade the weakest input's. *Supplies:* the member's question turned into a proposed calculation, labelled; the assistant never computes a number itself.
- **Across all six** — the DEC-8/DEC-27 rule and the information/advice line bind every construct's machine help; the `answers` checks are the one fence any construct's prose can reuse (LAW's plain readings, ANALYSIS's method text).

## 8. Decisions for Bob

**Q1 · Doctrine: does "the assistant gets its rules from the plane" (DEC-27, DEC-8) extend to law, deadlines and facts?** As ruled it covers the system's own rules (refusals and pre-flight). (a) **Closed book:** no fact and no rule from the model's knowledge; "not held" plus an offer to find it. (b) Allow the model's general background, labelled "unverified". (c) Allow it for law, with a disclaimer. **Recommend (a).** Disclaimers do not stop retrieval-backed legal tools from being wrong one time in six or more, or a city's own bot from teaching illegal practice (§1). And "a confidently wrong assistant is worse than none" (ASSISTANT-PILOT §1).

**Q2 · Policy, and a risk carrying your name: where does explaining law end?** (a) **Information only:** what held law and the record say, plane-computed deadlines with their basis, plain readings labelled; never a member's legal rights, a predicted outcome or a legal course to take. (b) Add procedural facts from the profile, as a court's self-help desk gives them: which form, which venue, which deadline, each shown as a fact and never as a recommendation (D279). (c) An attorney-supervised mode with deeper help. **Recommend (a) with (b) now; (c) deferred, with the trigger "a group with a licensed lawyer member asks to supervise".** This keeps the product on the information side of the ABA model definition and of Upsolve. It also keeps `filings`' Tier 1–2 drafts as they are: governed templates whose blanks are filled from the record (filings R18) and adopted by a member, with no argument from the machine and no Tier 3 template (D280).

**Q3 · Doctrine: what the record keeps of asking.** (a) **Nothing:** the exchange is a device-local transcript under DEC-61/113, an ask writes no observation or run row, and use is counted only as unattributed tallies; a member keeps an answer by an act (a question, a lead, a cite, a run). (b) Record asks as run-authority looks in the observation log: better evidence of where the group looked, but a log of members' searching that legal process can reach (OLD §4.6, DEC-68). **Recommend (a).** A member who wants a search on the record already has the lead (observation-log R24).

**Q4 · Architecture: one new product module, and a split.** (a) **Add `answers` (layer 6, after `skills`), and split the asking and planning flows out of `agent-worker`** (3,766 lines; P6). (b) Fold the contract into `run-productions`, `skills` and `agent-worker`. **Recommend (a).** Answers are not record writes, so `run-productions` is the wrong home. The plane's delivery checks need one owner. Other constructs' prose (LAW, ANALYSIS) reuses the same fence. No module moves.

**Q5 · Meaning of a requirement, and UX: the assistant's account.** "The Claude account the assistant runs on" means an Anthropic API key, paid per use by whoever holds it under the existing cascade (member → project → group). It does not mean a Claude subscription: the code requires a key, and Anthropic's terms forbid subscription credentials here. An administrator turns the group's key on, at setup or later, and is told at that moment that questions, and the material read to answer them, go to Anthropic under the group's account. **Recommend:** confirm this meaning; administrators see monthly usage per mode; members see no per-answer cost. The alternative, members' own keys only, leaves newcomers without the assistant that journey 9 promises them.

**Q6 · UX: an answer's shape in the panel.** (a) **A one-line answer, the level line and the bound always visible; quotes and citations one tap away; the query and the rules applied on expansion** (minimum visible complexity, principles §2; DEC-64's bound on every answer). (b) Everything shown at once. (c) The summary alone. **Recommend (a).** (c) breaks DEC-64 and "never only an AI summary".

**Q7 · Doctrine: may the panel suggest questions or claims the member did not state?** DEC-27 limit 2 still binds the pilot. The journeys promise first questions suggested "one per requirement in a code section", and Content Framework §12 lets an assistant open a focus as `surfaced`. (a) Keep limit 2: structure only what was said. (b) **Allow labelled suggestions derived only from material the member brought or chose (a captured code section, a document), each adopted only by a member's act, never from the model's own curiosity (DEC-24 rule 2).** (c) Give the panel DEC-60's full licence. **Recommend (b).** It is what the journeys need, and it keeps the question the member's.

*Decided by BOB, reported rather than asked (P17):* the asking mechanism — a short-lived member-minted grant with that member as viewer, and no run row; the asking scope (§5) and its exclusions; the check and refusal names; bounds per ask; the model per mode, chosen by stage-1 measurement; recording `usage`; progress streaming; the tally list. Layer placement of law, time and calculation is left to the LAW, TIME and ANALYSIS studies: QUESTIONS works with either.
