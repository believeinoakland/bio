## Cross-construct observations
- State Rules' closed edge vocabulary (§5.1) covers only evidentiary dependency between record objects (cites, corroborates, supersedes...); it carries no world relation (person–person, event–event, money flow). So PEOPLE/EVENTS/MONEY relations cannot be added as record `references` without a spec revision; they belong to a content-side construct (entities' constitutive relations, ruled `lines`). Edge status proposed/confirmed/severed and DEC-70's "connection informs, never binds" give a ready pattern for machine-proposed person/event/money links.
- PEOPLE vs members: Membership deliberately keeps a member's civil identity out of the record (cover is a label, handle a pseudonym; the cover-to-handle table is a legal-process exposure). K1452/K1455 move the opposite way for SUBJECTS (any personal fact a cited document states may be held). A PEOPLE design must keep the two populations separate in the model (a member is never automatically a person-record, and vice versa), or a person-record of a member would defeat §3's pseudonymity. Yet PEOPLE's "group's own members' ties to those it examines" needs exactly that join; it must be held under at least the cover-pairing protection (admin-only sight, per-member publication decision) and probably narrower (LEAD-style author/shared-to sight, src 809–813). Neither source designs it.
- Credentials: Membership §1.3/§10's declared-vs-confirmed, one-row-per-claim, withdrawal-supersedes model is a direct template for PEOPLE credentials, posts and memberships: each claim a row with its asserting source (here: the document that states it) separated from any member's confirmation, dated, append-only. It matches State Rules' accretive law and the "a standing statement with nobody's name on it is not a statement" doctrine (Membership §4.10).
- Visibility across the nine: evidence (and therefore every person/event/money fact a document states, and entities ENT/REL with counted ids) is SHARED corpus (Membership §7.9; BOB #32); a project's hypotheses (who knows who, suspected flows, event chains) are project thinking, hidden from the uninvited; reverse indexes ("which projects look at this person/fund") must be viewer-filtered (§7.9, §11 item 1); counts and sequential ids disclose existence (BOB #16) — so any per-viewer-withheld PEOPLE/EVENTS/MONEY object takes an opaque id.
- Relations: State Rules §5.1's closed record-edge vocabulary carries only evidentiary/record relations (cites, corroborates, supersedes, derived_from, elevated_into, initiates, action_basis, responds_to, references). World relations among people, events and money (employed_by, paid, authorises, amends, follows) have no home there; adding them would need a spec revision and would collide with the 1 MB bundle.md edge ceiling (~12,000 edges). They belong to content-side constructs (entities' constitutive relations; ruled `lines`), keeping State Rules' proposed/confirmed/severed edge status and DEC-70 (severed connection informs, never binds).
- Time: State Rules holds record time (created, last_updated, state_history timestamps, write order by rowid) and some world-time (Action clock dates with basis; recheck trigger dates; as_of on claims; source_status changes). It has no valid-time for world facts (a post held from/to, an amount as of a fiscal period); EVENTS/MONEY/PEOPLE need the as-of model from the first study's civil-time/chronology, not these frontmatter fields. D-256's "a stored string is a fact about when it was written" is the record-time half of a bitemporal model.
- Money: the founding use case in State Rules' examples is money (Sewer Service Fund transfers relabelled as cost allocation; ACFR vs OpenGov transfers-out disagreement; franchise fee; one-time insurance true-up in ACFR note 14). The record stores financial tables only as Information data/*.json in tidy/long form with a hashed normalized dataset; no money model (fund, account, stage, flow) exists in these sources.
- Actions vs events vs people: the group's own Action addresses an office, never a private individual (Action amendment; actions R9) and its clock is the only "should have happened by" register; world events (a reply, a non-response) enter only as responds_to/references edges onto the group's action. EVENTS must not reuse "action" (taken) and must let the group's action reference world events without becoming one.
- Expunge (I-19, drafted, unbuilt) is the only path by which personal data could ever be removed from append-only history (may-not-hold rail; reason_class unlawful | confidential | recorded-decision). Holding people fully (K1455) raises the stakes of that gap.
