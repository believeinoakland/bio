## What these documents are (3–6 lines each)
- jurisdictions: requirements for the layer-1 profile module (APPROVED K102; widened K608, K921–K925). Holds every local fact as data with a basis (measurement/ruling/UNMEASURED/TEST): identifier spaces, publishing systems, crosswalks, vocabulary (bodies, member titles, codes), practice, and the action sections (standard sources, counterparties by role, action kinds, deadlines, holidays, hours, time zone, legal organisations). list/get/validate/combine; combine never chooses between disagreeing profiles.
- id-spaces: requirements for the layer-1 judge of shared identifiers (enactment, project, fund, parcel): recognise/normalise, coverage reach, parcel standing, systemOf, judgePair (form → value → system independence → fund name → referent). Pure; every "no" says which kind of no.
- docprofile: requirements for the layer-1 content-type recogniser (split T19, K617: stack axis, digests, event catalogue moved to `site-profiles`). `doctypeFor` (minutes, agenda, regulation, staff report, staff directory, meeting calendar), `assess` (layered change verdict between two captures of one address, with `events[]` and `connections[]` referential/temporal), `readText`/`flattenText`/`makeLocator` (position discipline). All local vocabulary from the jurisdiction view.
- office-readers: requirements for the layer-1 DOCX/PPTX/XLSX/CSV readers (I7 entries): detection, I2 structure (links, IC-1 element references) and the DEC-5 evidentiary envelope (tracked changes with author/date, comments, core properties, speaker notes, hidden slides/rows/cols/sheets, formulas with cached values), I2 text, size guard, CSV dialect, and the reference builders reused by odf-reader. Pure; asserts nothing about meaning (R24).
- odf-reader: requirements for the layer-1 OpenDocument reader (.odt/.ods/.odp; Google Drive export format per CAP-8/COFF-10), projecting into the same I2/DEC-5 shape as the OOXML siblings, plus `odfEvidentiaryDigest` (D-351) for substance stability. Repeat-expansion bound (R45, N30). Pure, no local fact.
- extraction: requirements for the layer-4 module that makes and records readings (APPROVED K102; pipeline split to `reading-pipeline` N513/K1193): writes `readings`, `reading_refs` (raw `kind:key` references with positions/occurrences), `reading_ref_terms` (name-term fold), text index, text-source chain, reading history; re-read (`op=pdfstructure&ocr=1`); agenda item/file membership by containment (R52); drift obligations; EXTRACT role vocabulary (R41–R43); testimony indexing (R61–R65). Resolves no reference (R46).
- content: requirements for the layer-4 module of the citable unit (APPROVED K102): the extent grammar (document, pdf-page, sheet-cell, slide-shape, doc-para, sheet-range, doc-table, image, + envelope R33), the content address `hash(capture, extent, chain)`, mint-or-find rows, member transcriptions and attestations (DEC-88 note), stale marking on re-read, the passage notice against newer captures (graded A/B/C/NOT_FOUND/UNDETERMINED), and the citation resolver for inquiry, basis versions, cases and actions. Never moves a reference (R34).

## Cross-construct observations
- jurisdictions is where any jurisdiction-specific rule for PEOPLE (official titles, directories), EVENTS (meeting/minutes practice, deadlines' start events) and MONEY (fiscal year, thresholds, fund forms) would have to live as data; today only titles, fund forms, minutes-due and deadlines exist.
- docprofile's `events[]` (significance-graded document changes) and `connections[]` temporal (`expected_by`) are the nearest built shapes to EVENTS; the word "event" is already used for document-change significance (site-profiles R13), so the EVENTS construct needs a distinct name or explicit disambiguation.
- office-readers' envelope joins PEOPLE (authors, initials, lastModifiedBy), EVENTS (dates of edits/comments, created/modified) and MONEY (formulas with cached values) at one evidentiary layer; none is indexed (`envelope` extent kind designed, not built), so none reaches entities or connections today.
- extraction's R52 is the one built machine "part of" relation between events (agenda item) and documents, already carrying the grade/standing/established vocabulary (grade C, inferred, not established) that any EVENTS relation would need; the containment rule is profile-driven (links patterns).
- content is the citation substrate all nine constructs share: a PEOPLE fact (a name in a roster), an EVENTS fact (a vote in minutes) and a MONEY fact (a cell in a budget) are each a content row with two grades; the passage notice is the built mechanism for "the source changed after we relied on it", which EVENTS (amendments) and MONEY (revised budgets) both need.
