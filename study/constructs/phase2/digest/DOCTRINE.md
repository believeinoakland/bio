### System requirements stated in these sources (K1460)
- [DOCTRINE] Scale and storage, OBS §7 L505; Incomplete §7 L65 (M-14) — growth is bounded by an EDGE-TRIGGERED rule, not by retention. The naive rule would write 43,283 rows a day (~15.8M a year); the edge rule writes 15.14 rows a day, with a 2,713-row busiest day "that is what the table is actually sized on". The volume was measured before the writer landed. Any high-volume people, event or money writer (roster monitoring, ledger sweeps) is held to this precedent: measure first, log transitions only, cache the steady state. — "Growth is bounded by an edge-triggered rule, not by retention."
- [DOCTRINE] Performance and bounded reads, OBS §6 L272 — every reader is "envelope-bounded (REC-57)", and `op=airunlog` reads within IC-24's bound. OBS §6 L305–309 and L381 name the AMPLIFICATION class that `derivation-bounds.test.mjs` instruments: "a LINEAR read over an unbounded scan is NOT in the class; this class is amplification, not size". Per-row resolvers inside a read are refused, which bears on any traversal of people, event or money relations (lines walked bounded).
- [DESIGN] Performance and fail-safe truncation, OBS Incomplete §6 L58–59 (D-389, REC-174) — `truncated` is computed from the full-fetch bit and every viewer reads the same bit. "A supply of exactly the fetch size over-reports, the fail-safe direction."
- [DOCTRINE] One home and one writer, OBS §3 L118–119; §4.4 L218 — "a log per level is the D-164 failure (built three times, drifts)"; "two writers is not" acceptable. Every writer goes through ONE append site. One vocabulary is one exported constant, and "a divergent spelling is a build error" (head L7).
- [DOCTRINE] Privacy and disclosure, OBS §6 L272; L28; L353 — "a subject discloses a project's interest", so withholding is ROW-WHOLE across the fence. "The count of withheld rows is deliberately NOT published, because that count is the disclosure". "A COUNT is a disclosure of existence" (BOB #15, for leads). Any people index or count is held to the same rule.
- [DOCTRINE] Privacy and legal reach, OBS §4.6 L231 — "the record is what a legal process can reach". What the record holds about members' interests is a design choice made conservatively, because "rows written cannot be unwritten".
- [DOCTRINE] Purge semantics, OBS §7 L504; DIST §6 rung 6 L97–106 — purge of a bundle leaves its observations; a whole-store purge clears them; identity is purged only on scratch. Any people data must state its own purge class.
