**DESIGN GAP (stated, not hidden):** the ruling says the capture is registered and "already in the record". The register
has ONE writer — `promote` — and a register row names the bundle it was registered against, so nothing can register a
capture against a bundle BEFORE that bundle's creation. Built: the provenance BYTES must already be held (uploaded through
`op=capture` before any promote — `migrate.mjs` always did this) and the provenance is REGISTERED by the creation itself,
in its own transaction; the check reads the held bytes, never the request's copy. A pre-existing register row alone does
not admit (the creation must register it). If BOB wants registration to be a PRIOR act, that needs a register-only write
(a new op or a store-internal door), which is a design question.

**THE ROOT OF TRUST IS OUT OF SCOPE** (Membership §DEC-2, deferred): an admin who uploads and registers a fabricated
provenance capture listing its own bytes is admitted, and nothing the record holds can tell.
