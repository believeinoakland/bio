### The change, on the wire

- `CASE_DOCUMENT_FORMAT` is `bio-case-document/3`: every case document `op=publish` authors from this landing carries `format: bio-case-document/3`. `bio-case-document/2` (`CASE_DOCUMENT_FORMAT_V2`) and `/1` stay in the accepted set and ratify as written (rule 1: what already crossed stays crossed). `caseDocumentStatesMemberBlocks` answers yes for /2 and /3.
- **Four keys are REQUIRED of a /3 document**, refused by name under C-41.13 (`CASE_DOCUMENT_FAMILY.DISCLOSURES`, inside the C-41 family), and only under /3 (`caseDocumentRequiresDisclosures`):
  - `bias_manifest` — a map with a boolean `in_force`; in force, a 64-hex `statements_sha`; not in force, the stated sentence;
  - `bias_manifest_bundles` — the list of pinned (bundle, revision) pairs;
  - `completeness.acknowledged` — an integer, `0` legal;
  - `completeness_acknowledgements` — the list, empty legal.
- op=publish already wrote all four (D-84, D-150); what moves is that the gate now refuses their absence instead of the writer happening to stamp them.

### Consumer impact

- A consumer that matched `format === "bio-case-document/2"` for a freshly published case now reads `/3`; one that accepts the published set (`/1`, `/2`, `/3`) is unaffected. No /2 document is refused. `d150-statement-acknowledgement`, `d442-publish-writes-nothing` and `casesign` correct their superseded /2 assertions with dated reasons; construct-status 7.manifest-stamped, 13.member-untouched (its /2 probe re-aimed) and 13.statement-ack state it.
