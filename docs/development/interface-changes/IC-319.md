## IC-319 · I3: `op=attribute` (the attribution act); a case document reaching a member's observation states each observation's attribution; `op=reviewcopy` lists the observations an edition reaches; MK-1's publication fence (C-53.10–.12) is LIFTED for an observation in §4.1's form and narrowed to one that still names its author · ACCEPTED 2026-09-25, MAJOR — I3 125.0.0, I5 7.7.0 (MINOR) (resolved by CONDUCT #22 at c22-batch29; MK-7)

- **Interface:** I3 (the control plane's ops). No I5 change: the register's shape is untouched; one new store table (`observation_attributions`) that no other interface reads.
- **Design:** `docs/development/MEMBER-KNOWLEDGE-DESIGN.md` §4.2–§4.6 (BOB #19, 2026-09-21), §7, §8's row for MK-3's replacement (ii).
- **What changed:**
  1. **NEW `POST op=attribute`** body `{ caseId, edition, observation, level }` — classes admin/member, SESSION route, capability `contribute`, mutating. `by` is stamped by the control plane from the session (a machine credential stamps `class:<cls>`, refused C-92.1). `level` ∈ `group | project | cover | name`, REQUIRED (C-92.2, C-92.3). Only the observation's registered author may take it (C-92.4, C-92.5; not the project owner, not an administrator), only while an active member (C-92.6), only at a PREPARED and UNSIGNED case document at `(caseId, edition)` that reaches the observation at any depth (C-92.7 — one answer for no such edition and one that does not reach it; C-92.8 for a signed edition), and `name` only with a handle (C-92.9). Answer: `{ ok, existed, observation, caseId, edition, level, shown, previous, case_document: { reauthored, doc_sha, read }, stated }`. The act RE-AUTHORS the unsigned case document (`#reauthorAcknowledgements`' rule), so its `doc_sha` MOVES and a signature over the old bytes is refused CASE_RATIFY_STALE.
  2. **A case document (`bio-case-document/3`, no format bump) that reaches ≥1 authored observation gains** the frontmatter key `observation_attributions: [{observation, level, shown, chosen_at_edition}]` (`level`/`shown`/`chosen_at_edition` `null` while unchosen) and the body section `## Whose Words These Are`. A case reaching no observation is authored byte for byte as before. ADDITIVE: no key removed or changed in meaning; no case reaching an observation could be ratified before this change, so no signed document is affected. A later edition INHERITS each level from the latest earlier edition until the author acts again.
  3. **`op=reviewcopy` gains `observations: [{observation, chosen, stated}]`** — every observation the draft's findings reach, its state only (never the level). ADDITIVE; always present (possibly `[]`).
  4. **`op=caseratify`:** C-53.12 `TESTIMONY_CASE_UNPUBLISHABLE` now refuses ONLY a case reaching an observation that still names its author in its own files (pre-MK-6), with `observations[]` in place of `rests_on`; its translation is corrected. NEW refusals: `ATTRIBUTION_UNCHOSEN` (C-92.10, 409, `unchosen: [{observation, why}]`) and `ATTRIBUTION_STATEMENT_STALE` (C-92.11, 409, `observations[]`). A case whose every reached observation is chosen now RATIFIES.
  5. **`op=ratify`:** C-53.10 / C-53.11 now refuse only an observation in the pre-§4.1 form, and a finding resting on one. NEW `ATTRIBUTION_UNSTATED` (C-92.12, 409): an observation's own bytes are refused until a RATIFIED case document states its level. An observation in §4.1's form whose case is signed now RATIFIES as that case's evidence (D-431 (b)).
- **Classification (the builder's statement; CONDUCT resolves):** **MAJOR by the refusal-code rule, otherwise additive.** Items 1–3 are additive. Items 4–5 change WHICH code the same input receives: a caller that matched `TESTIMONY_CASE_UNPUBLISHABLE` / `TESTIMONY_UNPUBLISHABLE` / `TESTIMONY_CITED_UNPUBLISHABLE` for a post-MK-6 observation now receives `ATTRIBUTION_UNCHOSEN`, `ATTRIBUTION_UNSTATED` or (a loose finding) D-431's `RATIFY_FINDING_NOT_IN_A_RATIFIED_CASE`, and a request that was always refused can now SUCCEED. Recommend MAJOR, on MK-2's IC-142 precedent that a changed answer to an unchanged request is not additive.
