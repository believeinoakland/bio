## IC-196 · I3: `op=promote` STATES AN INLINE FILE'S SIZE IN UTF-8 BYTES — each inline file's `bytes` is computed from its UTF-8 encoding and a differing supplied value is OVERRIDDEN (never stored); `OVERSIZE_INLINE` judges that figure against `INLINE_MAX`, not `text.length` · PROPOSED 2026-09-23 (REC-178, minted with `node tools/mintid.mjs IC` BEFORE the entry was written; IC-193, IC-194 and IC-195 were minted past because other clones' branches and claims already name them) — the version bump, the classification and the RESOLUTION are CONDUCT's

- **Interface:** I3 (the op contracts). I5 does not move (no table, no column).
  **Base read off THIS TREE (`origin/main` @ `0e5f7054`): I3 60.0.0 (IC-192).** Read the base AT RESOLUTION.
  **Proposed I3 MAJOR, BREAKING** — 60.0.0 → 61.0.0 on this base. **Why BREAKING:** a request that answered `ok: true` is
  now refused — a promote carrying an inline file whose UTF-8 encoding exceeds `INLINE_MAX` (1,048,576 B) while its
  `text.length` (UTF-16 units) does not: a non-ASCII file up to ~3× the limit used to land. IC-176/IC-177/IC-192's

  platform error — measured by the control's `keepgiven` arm); a supplied figure that differs is overridden, not refused;
  `OVERSIZE_INLINE`'s `bytes` field now reports the UTF-8 figure.

**THE SHAPE.** `store.mjs` `promote`, immediately after REC-175's `DEC-49 REGION is-promote-digest` (nothing inside it
moved), before the transaction: every file for which `Store.#inlineBytesOf(f)` answers (an inline file — the byte length of
`new TextEncoder().encode(text)`, the UTF-8 of the string `files.content` stores) is given that figure as `bytes`. The
`OVERSIZE_INLINE` loop inside the transaction judges the same `#inlineBytesOf` figure. `digestCensus`'s `bytes_disagree`
reads it too, so the door and the census cannot disagree about what a size is. A blob-backed file's `bytes` is untouched
(its bytes are in R2, which promote does not read — D-45; judged at RATIFY, `PLANE_SIZE`).

**WHY OVERRIDE AND NOT REFUSE (decided by the worker, stated at the site).** A digest that disagrees says the caller holds
OTHER bytes than it sent — a claim about identity, refused (REC-175). A byte count that disagrees over bytes whose digest
AGREES is a unit error and nothing else: the content is not in question and the plane holds everything needed to state the
true figure. Refusing would also make every internal act that carries a stored row forward (`bytes: r.bytes`, 42
sites in `store.mjs`) refuse over any row the census counts as wrong — a misstated figure would become an unwritable
document. The caller's figure is never stored and never judged. **Reversal cost:** swap the `map` for a refusal region; the
suite's section 3 and 4 arms then fail by name.

**THE WIRE.** Unchanged except: `files[].bytes` optional on an inline file; `OVERSIZE_INLINE` `{ ok: false, reason, path,
bytes }` — `bytes` is now UTF-8 bytes; a non-ASCII inline file over the limit in bytes is refused where it landed.

**CONSUMERS (measured on this tree, `git grep`).** The writers named by the row now send the UTF-8 length:
`bio-plane/src/setup.mjs` (4 sites, a `utf8Len` helper), `civicos-ui/app.html` (6 sites, a `utf8Len` helper),
`bio-plane/src/livefire.mjs` (2), the monitor tick in `bio-plane/src/index.mjs` (2), `tools/fw21-onpoint-probe.mjs` (3).
In-plane writers that could approach the limit already measured UTF-8 (the acquire budget in `index.mjs`, `cite`'s
`CITATION_TOO_LARGE`, the group stamp and mint). **Test fixtures (197 files under `bio-plane/test/` carry the `text: x, bytes: x.length` shape) still send `text.length`; they are
unaffected** — the figure is overridden — and none sends a non-ASCII file near 1 MiB. `agent-worker/test/harness.test.mjs`
likewise. No consumer reads `OVERSIZE_INLINE.bytes` as a unit (grep: livefire and this suite assert only `reason`).

**THE CENSUS (stated, never rewritten).** Method: REC-175's `op=digestcensus` (admin, probe), unchanged in shape, whose
`files.bytes_disagree` counts every live inline row whose stored `bytes` differs from its content's UTF-8 length, listing
each with `bytes_stored`; `history` holds no bytes column. **On the suite's own store:** 0 through the door; a planted
`text.length` row counted 1, listed, rewritten 0, and a revision carrying it forward lands and stores the true figure.
**On a deployed instance: NOT RUN — UNDETERMINED.** Running it against the real record is an administrator's act on that
instance after DIST deploys a build carrying `op=digestcensus`; expected non-zero on any instance where a member promoted a
non-ASCII inline file through setup or the UI (every such file was stored with its UTF-16 count).
