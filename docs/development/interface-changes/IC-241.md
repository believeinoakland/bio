### I3 — what a caller sees

- **`op=themedeclare`** (POST; admin, member; mutating; `contribute`; a session op) — `{ name, test }`. The declarer is stamped
  from the credential (`declarer`, never the body's). Answers `{ ok, theme_id: "THEME-YYYY-MMDD-hex", name, test, at, declared_by,
  declared_by_handle, evidence: false, says }`. Refuses `THEME_NOT_A_MEMBER` (C-81.2, any machine stamp), `THEME_NO_TEST` (C-81.3),
  `THEME_NO_NAME` (C-81.4), `THEME_TOO_LONG` (C-81.5, over `CAPTURE_TEXT_UNIT_CAP`).
- **`op=themeplace`** (POST; admin, member; mutating; `contribute`; a session op; viewer-stamped) — `{ theme, target, note? }`,
  `target` a bundle id (a document) or a content id (a passage). Membership: `state: "member"`, `grade: "D"`, `placed_by` stamped.
  On a standing HUNCH it CONFIRMS (`confirmed_hunch: true`, `proposed_by` kept); on a member it changes nothing (`already: true`).
  Refuses `THEME_PLACEMENT_NOT_A_MEMBER` (C-81.7, any machine stamp), `THEME_NOT_FOUND` (C-81.6), `THEME_TARGET_NOT_FOUND`
  (C-81.8 — one answer for an absent target and one the viewer cannot see), `THEME_REASON_TOO_LONG` (C-81.9).
- **`op=themepropose`** (POST; admin, member, probe, and `ai` through the DEC-55 floor; mutating; `contribute`; a session op;
  viewer-stamped) — the same body. A HUNCH: `state: "hunch"`, `grade: "C"`, `membership: false`, `proposed_by` stamped
  (`class:<cls>`, `class:ai/<tokenId>`, or the session's member). Never demotes a member and never overwrites a first proposer.
  Refuses C-81.6 / C-81.8 / C-81.9 as above; `THEME_NO_PROPOSER` (C-81.10) is defence in depth and NOT reachable through
  the ops, since every route stamps a proposer (stated in the suite, pinned by its row).
- **`op=themeread`** (GET; admin, member, probe; read; viewer-stamped) — `id=` answers one theme with `members[]` and `hunches[]`
  APART, each placement `{ target, target_kind, document, state, membership, hunch, grade, placed_by, placed_at, note,
  proposed_by, proposed_at, proposal_note }`, gated per placement by the viewer's sight of the document (a hidden one is omitted
  with no count); without `id`, the list of themes, `q=` a case-insensitive phrase over name and test. Bounded 200/2000 with
  `truncated` / `members_truncated` / `hunches_truncated` published.
- **C-81.1 `THEME_NOT_EVIDENCE`** at `checkInquiryBasis` (basis[]), `basisVersionFindings` (version legs) and
  `actionBasisFindings` (action basis), beside C-54.1: a leg whose `target` or `content_id` is a THEME id, or a membership address
  (`THEME-…#…`, `/…`, `:…`, `?…`), or a leg carrying a non-empty `theme` / `themes` key. A leg citing a DOCUMENT that is a member
  of a theme is NOT refused.
- **`op=purge`**'s `removed` gains `themes` and `themePlacements`; `before` / `after` gain the same two counts (purge's proof
  only). `op=stats` is unchanged.

### I5 — what the store holds

- `themes (theme_id PK, declared_by, name, test, at)` — no `bundle_id`: the whole-store purge clears it.
- `theme_placements (theme_id, target, target_kind ∈ {document, content}, bundle_id, state ∈ {hunch, member}, grade ∈ {C, D},
  proposed_by, proposed_at, proposal_note, placed_by, placed_at, placement_note; PK (theme_id, target))`, index on `bundle_id`;
  rides `op=purge`'s TABLES list, so a per-bundle purge takes a document's placements with it.

### DESIGN GAP (for BOB, through CONDUCT)

§8.4 fence 1 says a theme is declared "under that member's COVER, which every reading of the theme shows", and UI-76's row says
"the declarer's cover shown on every theme". **Membership v2 §3 rules the opposite for every non-administrator:** members and the
public see HANDLES, and only administrators see cover and handle together — a cover beside the declarer's handle is the pairing
§3 withholds. Built PROVISIONALLY as the record's attribution: every reading shows `declared_by` (member id) and
`declared_by_handle`, and never the cover. Reversing it costs one column in `#themePerson` and a projection on the `administer`
stamp (`memberList`'s pattern). Recommendation: read "cover" in §8.4 as "the member's own name in the record", i.e. the handle,
and amend the sentence.
