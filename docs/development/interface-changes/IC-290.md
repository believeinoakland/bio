## IC-290 · I3: a progression finding carries the member's decision about it on op=instance and op=captureprogressions · PROPOSED 2026-09-24 (D-552)

- **Interface:** I3 (`op=instance`, the `op=thread` and `op=discharge` echoes that return op=instance's read, and
  `op=captureprogressions` answers gain keys). No I5 change: the read is of `proposal_dispositions` as REC-184 left it.
- **Classification (proposed; the integrator classifies):** MINOR, ADDITIVE — no key removed or renamed, no refusal
  minted, no finding added or removed from any list. `finding_count` is unchanged in meaning (it counts every finding).
- **What moves:**
  1. Every entry of `findings[]` on `op=instance` / `op=thread` / `op=discharge`, and every entry of
     `instances[].findings[]` on `op=captureprogressions` (both `missing_predecessor` and `overdue_successor`), gains
     `disposition`: `null` where no member has decided the finding's (progression_key, stage_key), else
     `{ state, reason, decided_by, at, definition_version, definition_version_state, applies, applies_because }` —
     the fields and values of `op=proposals`' `dispositions[]` rule (IC-255), computed by `#dispositionVersionView`.
  2. `op=instance` / `op=thread` / `op=discharge` gain `open_finding_count`: the findings whose `disposition` is null
     or does not apply.
- **The seam with `prior_disposition`:** `op=proposals`' `proposals[].prior_disposition` (REC-184) and op=queue's
  finding item (D-527) publish the SAME object with the same keys. It is named `disposition` here because on these reads
  the decision may still govern (`applies: true`, the finding aged); `prior_disposition` is by construction the case
  `applies: false`. The suite asserts the two are equal, key for key, when they describe the same decision.
- **Viewer:** `#redactInstance` is unchanged and still withholds only bundle ids a viewer may not see (REC-30). A proposal
  disposition is instance-wide (DEC-16), a fact about the shared record, so no viewer these ops admit reads less of it:
  `decided_by` reads as op=proposals and op=queue publish it (a member id, or `class:<cls>` for a machine credential).
- **Why:** framework §8.2 and §12 "age rather than vanish" (D-79): the progression and document pages listed a dismissed
  finding as an open question while the record held the decision.
- **Consumers, measured 2026-09-24 by grep over the tree at `9f8b69e6` plus this change:**
  - `civicos-ui/app.html` `progPaintInstance` and the document page's captureprogressions read render `findings[]`; no
    site reads a key this change adds, and no site depends on a key being absent. Painting the decision is UI-108.
  - Tests: no existing suite changed; `bio-plane/test/d552-instance-disposition.test.mjs` is new.
- **Evidence:** `bio-plane/test/d552-instance-disposition.test.mjs` (19 assertions through the ops; five control arms on
  its NEGATIVE CONTROL line).
