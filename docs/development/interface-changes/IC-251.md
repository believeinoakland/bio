**THE SHAPE.** `GET /api/?op=homecensus[&limit=N]` — classes `admin`, `probe` (probe confined to `scratch` by
`scopeFor`, as `digestcensus` / `snapkeycensus` / `registeraudit` beside it). `store.mjs` `homeCensus`: the register is
read once (`LEFT JOIN bundles`), each row whose bundle exists becoming the HOME of its lower-cased `capture_sha`; then
`files` and `history` are walked and a row is DISPLACED when the register homes its lower-cased `sha256` at a bundle other
than the row's own. Answer:

```
{ ok: true,
  register: { rows, home_absent },          // home_absent: register rows whose bundle no longer exists — no home, never listed
  files:    { rows, displaced },
  history:  { rows, displaced },
  shas,                                       // distinct displaced shas (whole)
  listed: [ { capture_sha, home: { bundle_id, path },
              held_by: [ { table: "files"|"history", bundle_id, path, snap_key? } ] } ],   // bounded by limit
  first_holder: "UNDETERMINED", rewritten: 0, note }
```

`limit` default 50, clamped 0..500, bounds `listed` only; every count is whole.

**WHAT IT DOES NOT CLAIM.** `home` is the register's CURRENT holder and nothing more — which bundle held the bytes
first is not recorded and is stated `UNDETERMINED`. A row a bundle carried WITHOUT registering it, whose bytes another
bundle registered, reads exactly like a moved one and is listed the same. A sha several bundles carry that the register
assigns to none of them is NOT listed (only the register decides a home). The same content in different bytes is not
reached. Nothing is repaired; repair is neither designed nor rowed.
