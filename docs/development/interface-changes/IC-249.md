## IC-249 · I3: `op=promote` refuses a machine credential that SETS or CHANGES an action's risk tier (`MACHINE_CANNOT_SET_RISK_TIER`, C-32.19) · PROPOSED 2026-09-24 (REC-189; the id was minted with `node tools/mintid.mjs IC` for REC-189 and written at integration by CONDUCT #19's c19-batch10, the worker's branch carrying no IC file)

- **Interface:** I3 (the op contracts), `op=promote` over an action. I5 does not move (no table, no column).
- **Proposer:** WORKER REC-189 (cloud), 2026-09-24; the entry is written from the branch's diff and commit messages at integration.
- **Owner to land it:** `RECORD`
- **Design:** `docs/architecture/BIO_Case_Making_v0_1.md` §2, `risk_tier` (D-182, RULED by BOB #21: *"Only a member's authored act sets 1, 2 or 3"*); `construct-status.json` 8.risk-tier.

### The change, on the wire

- `op=promote` of an `object_type: action` bundle (not a replay), when the author stamp is a machine identity or absent (REC-46's one predicate, as `actionMove`'s fence asks), and the revision states `risk_tier` 1, 2 or 3 that differs from the tier the version it replaces states (a creation replaces none, so any stated tier is a change), answers `{ ok: false, reason: "MACHINE_CANNOT_SET_RISK_TIER", risk_tier, held, detail }` before any write. Both sides are read through `riskTierState`, so a respelling of the same value is not a change.
- A machine's revision that carries a member's tier forward unchanged lands.
- Catalogue row `MACHINE_FENCE_CHECKS.MACHINE_CANNOT_SET_RISK_TIER`, **C-32.19**, `where: src/store.mjs promote > is-machine-set-risk-tier`. Minted C-32.18 on the branch; renumbered at integration because D-149's `MACHINE_CANNOT_SET_LAWS` holds C-32.18 on the batch.
- Not registered in `affordances.mjs` `MACHINE_REFUSALS`: that table is keyed by ACT and `promote` is a NON_ACT (the worker's report).

### Consumer impact

- Fixtures that stated tier 1 through a deploy (machine) token — `affordances.test.mjs`, `counterparty.test.mjs` — now state undetermined; `risk-tier.test.mjs`'s "member's act sets 2" was driven by a machine stamp and is corrected, never exempted. The harvest suites (`fence-e2e`, `aicredential`, `refusal-wire`, `machinefences-dec49`) carry the fifteenth fence on the batch.

### Evidence

`bio-plane/test/machine-fences.test.mjs` block (xv) drives the fence under a complete payload, with the liar's arm (a machine's carry-forward must land) and the member arm (the same payload lands for a signed-in member).
