### The change, on the wire

- `op=reviewcopy` (both doors: a member by session, a recipient by the grant's secret) — the `case` object
  gains one key:
  - **before:** `case: { case_id, edition, identity }`
  - **after:** `case: { case_id, edition, identity, newCase }`
- `newCase` is a **boolean, always present**: `true` when the draft asked for a NEW case (D-309's third route,
  `newCase` in the draft's stored params), `false` when it named a case and `false` when it said nothing.
- **It is answered AS THE GATES READ IT.** `publishCase` consults `newCase` for truthiness alone, so the
  answer is `!!params.newCase`. That is exactly route-preserving for every value a caller may have stored
  (`"false"` is truthy here as it is there), and an absent field is the DERIVATION route, not an undetermined
  one — there is nothing undetermined to state.
- **It sits in `case` and not in `authored`** because it is the other half of ONE choice — name a case, or ask
  for a new one, which `publishCase` refuses TOGETHER as `CASE_IDENTITY_AMBIGUOUS`. `case.case_id` cannot
  stand in for it: `case_id` is `null` both for a draft that asked for a new case and for one that said
  nothing, and those two drafts publish into DIFFERENT cases.
- **The in-band quartet moves, by construction and not by accident.** REC-148's `inband.sha256` is taken over
  the answer as served minus `inband` (`inbandQuartet`, `bio-plane/src/inband.mjs`), so one more key means a
  different digest for the same draft. Nothing pins a digest literal: `reviewcopy-inband.test.mjs` re-computes
  it from the served bytes, and it re-computes green (measured 2026-09-24 on this tree: reviewcopy-inband 22/0). A holder of an OLD copy comparing its
  hash against a fresh read will see them differ — which is what a review copy's hash is for, and the same
  thing a comment or an edit already does to it.
- `op=casedraft`, `op=casedrafts` and `op=publish` are **unchanged**: `casedraft` already accepted and stored
  the field, `casedrafts` carries `#draftIdentity`'s three keys and not this one (it is a list of identities,
  not of authored arguments), and `publish` is the act that consumes it.

### Consumer impact, measured

- **`civicos-ui/app.html` — the only client.** `rvcFormFromCopy` is the read-back this ruling is about: it
  rebuilds the draft form from `op=reviewcopy`'s answer, and its own comment says *"the one thing the answer
  does not say back is whether a draft naming no case was marked as a new one, so that choice starts unmade
  rather than guessed"*. The answer now says it. **NOTHING BREAKS** — the UI ignores keys it does not read —
  and **nothing improves until UI reads it**: `rvcFormFromCopy` still leaves `caseMode` unset for such a
  draft, so a member who re-opens and saves it still drops the intent at the surface. That is a DELEGATION to
  UI (`CLAIMS.md`), not a gap in this landing, and the stale comment is UI's to correct.
