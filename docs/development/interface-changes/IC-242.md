## IC-242 · I8: the plane's CALLING SIDE exists — FL-4's wake dispatches a woken run to `POST /run` under the instance's organisation `ai` credential, ONLY when that credential opened the run; I8 leaves PROVISIONAL · PROPOSED 2026-09-23 (D-260; id taken past the remote max, IC-236 read on `land/*`, `main` and `coord` with `git ls-remote` + `git grep`; CONDUCT resolves the version)

*Minted as IC-237 by D-260's clone; renumbered IC-242 at integration by CONDUCT #19 (2026-09-24) — IC-237 is D-456's (the security train, on main).*

- **Interface:** I8 (plane ↔ agent-worker). **I3 does not move** — no op is added, removed or reshaped; the one read whose
  bytes change is `op=airunlog`'s `detail` on a WAKE entry, which gains one trailing sentence (`Resumption: handed to
  agent-worker …` or `Resumption: NOT dispatched — <why>.`), prose inside an existing string field. **I5 does not move**
  (no table, no column; the wake's SELECT gains `principal_plane`, a column that exists).
- **Design:** `docs/architecture/BIO_Assistant_and_AI_Roles_v0_1.md` §6, the D-260 paragraph (BOB #22, 2026-09-21): an
  instance MAY hold ONE organisation-principal `ai` credential as a deploy secret and hand it to `agent-worker` to resume a
  woken run THAT CREDENTIAL OPENED; a member's run is never resumed by it, and says so. *"I8 leaves PROVISIONAL when that
  caller lands."*
- **What changes (the plane's side of I8, which had no implementation until now):**
  1. **The caller.** `Store#aiRunWake` (the `ai-run-wake` alarm consumer, FL-4) is now async and, after every wake entry
     and stamp is written, calls `env.AGENT_WORKER.fetch("https://agent-worker/run", POST)` once per woken run that passes
     the gate — bounded by `AI_RUN_DISPATCH_WAIT_MS` (default 30 000 ms, env-overridable), outside any transaction.
  2. **The body the plane sends**, within I8's existing `In:` shape and naming nothing new:
     `{ run_id, store, credential, claude_accounts: { instance: { token, ref: "instance" } } }` — `store` is the namespace
     the Durable Object IS (`ctx.id` compared with `idFromName("bio")` / `idFromName("scratch")`, never defaulted);
     `credential` is the `INSTANCE_AI_TOKEN` secret; `claude_accounts` carries the INSTANCE level only
     (`instanceClaudeToken`, DS-3), `{}` for that level when the instance has no account, so agent-worker's cascade states
     the absence (one enforcement point: the plane does not pre-judge the payer, and a run whose recorded payer is another
     level is refused by agent-worker's `RUN_NAMES_A_DIFFERENT_PAYER` and recorded as item 5 says — driven by the suite's REFUSED-DISPATCH arm).
  3. **The gate, one comparison of two plane stamps:** the run's `principal_plane` must EQUAL `<principal>/<tokenId>` built
     from the instance credential's own `ai_credentials` row (resolved by SHA against the `bio` object, as `index.mjs`
     resolves every `ai` credential). The credential must be on record, not revoked, and `principalKind: organisation`.
  4. **Withheld resumptions are STATED**, in the wake entry's sentence and in the tick answer's per-wake `resume`:
     `MEMBER_PRINCIPAL_RUN` (the ruling's stated limitation), `NOT_THE_INSTANCE_CREDENTIALS_RUN`, `AGENT_WORKER_UNBOUND`,
     `NO_INSTANCE_AI_CREDENTIAL`, `INSTANCE_AI_CREDENTIAL_REVOKED_BY_PUBLICATION`, `NAMESPACE_UNDETERMINED`,
     `CREDENTIAL_RECORD_SILENT`, `INSTANCE_AI_CREDENTIAL_NOT_ON_RECORD`, `INSTANCE_AI_CREDENTIAL_REVOKED`,
     `INSTANCE_AI_CREDENTIAL_NOT_ORGANISATION`. These are statements in a log, not refusals of a caller: no op answers them,
     so they carry no C-number and no DEC-49 row.
  5. **The outcome of a dispatch** is on the tick answer (`wakes[].dispatch: { state: DISPATCHED | REFUSED | SILENT,
     status, reason }`, and `airunwake.dispatched`, the count) — never the credential. A dispatch that did not complete
     appends ONE entry to the run's log saying so (`Resumption: the dispatch to agent-worker did not complete (…)`).
  6. **A new Worker secret, `INSTANCE_AI_TOKEN`** (`tokens.mjs` `INSTANCE_AI_BINDING`, read only there; denylisted on
     publication like every token). Carrying it through install and update is DIST's half of D-260 and is NOT built.
- **Unchanged:** agent-worker's code and wire (no byte of `agent-worker/src` moved; its committed bundle is byte-identical
  and its manifest's input hash for `bio-plane/src/tokens.mjs` moved, rebuilt with `node scripts/build.mjs`). An instance
  with no `AGENT_WORKER` binding or no `INSTANCE_AI_TOKEN` behaves as FL-4 did and says why on every wake entry.
