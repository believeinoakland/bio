## IC-283 · I2 MINOR, ADDITIVE: a reading states the DIALECT it was read under — `dialect` on the `csv` entry's `structure()` and `text()` · PROPOSED 2026-09-24 by the FW-23 worker (CONDUCT #20, `land/worker/FW-23`; minted with `node tools/mintid.mjs IC` before building) — the version bump and the RESOLUTION are CONDUCT's

- **Interface:** I2 (content → framework), currently **2.7.0**. **MINOR, ADDITIVE.** One key is added to two return shapes of ONE entry. No key is removed, renamed or re-typed, and no other entry's output moves by a byte.
- **Design:** `docs/development/OFFICE-FORMATS.md` §"CSV — BUILT 2026-09-24 by FW-23", on BOB #32's ruling of 2026-09-24 02:30Z: *"delimiter and encoding found by signature and RECORDED on the reading, undetermined when they cannot be told."* The RECORDING is the interface change; the signature is the entry's own business.
- **Proposer:** the FW-23 worker, 2026-09-24. **Owner:** FRAMEWORK (I2's consumer). **Proposed version:** I2 **2.7.0 → 2.8.0** on `origin/main` e9b21be6's line. CONDUCT takes the bump and the resolution; if another branch has taken I2 in parallel, only the NUMBER moves, never the classification.

### What changes

`csvEntry.structure()` and `csvEntry.text()` each carry one new sibling key:

```
dialect: {
  encoding:            "utf-8" | "us-ascii" | "utf-16le" | "utf-16be" | null,
  encodingConfidence:  "certain" | "likely" | "none",
  encodingSignals:     string[],
  delimiter:           "comma" | "semicolon" | "tab" | "pipe" | null,
  delimiterConfidence: "certain" | "none",
  delimiterSignals:    string[],
  undetermined:        string[]     // "encoding_undetermined", "delimiter_undetermined_tied", …
}
```

- **A NULL is the STATED undetermined, never a default.** `encoding: null` means the bytes do not tell — measured on a real corpus body (`data/20230609update2.csv`: byte `0x96`, no BOM, an en dash in windows-1252 and the letter ñ in Mac Roman, and the two disagree about what the character IS). `delimiter: null` means no candidate was consistent, or two were tied; the reason is in `undetermined` by name.
- **ONE BUILDER.** `structure().dialect` and `text().dialect` come from the same function over the same `parts`, so the two projections cannot state two dialects for one body; the suite pins them byte-identical.
- **Why it is not a per-format field nobody else needs:** every other entry on this axis reads a CONTAINER that declares its own encoding (`<?xml … encoding=?>` inside an OPC or ODF package) and has no delimiter at all. A CSV's reading is the only one whose own correctness depends on two inferences, so it is the only one that must publish them. An entry that has nothing to say emits no key — the `own()` pattern the acquire wire already uses for `tables`, `images` and `deckLength`.

**Nothing else in I2 moves.** `csv`'s `text()` returns the same `{ok, container, document, sheets[], undetermined, counts, images}` the two sibling spreadsheet containers return, with the same four extent keys per sheet (`rows`/`cols` NULL, for `.ods`'s reason — RFC 4180 fixes no maximum — beside a measured `usedRows`/`usedCols`), the same IC-124 `sheet-range` unit, the same IC-2 evidentiary envelope, and NO new member of IC-1's union: cells are `sheet-cell`.

### Why MINOR

By IC-25's test. A consumer that does not read `dialect` is byte-for-byte unaffected: the key is new, on one entry, and no existing key's name, shape or value domain changed. Nothing is refused that was admitted, and nothing that read `false` now reads `true`.

### RESIDUE, stated rather than left to be found — and it is the same shape COFF-11 found

**`dialect` IS EMITTED AND IS NOT PERSISTED.** BOB #32's ruling says the delimiter and the encoding are *recorded on the reading*, and they are recorded on the reading the ENTRY returns — but the acquire wire's `containerExtent` projection (`index.mjs`, the block that builds `{container, levels, sheets, paragraphs, slides, …}`) writes a named key list, and `dialect` is not in it. So today the dialect reaches a consumer that calls the entry and does NOT reach the record. That is exactly COFF-11's finding one construct over — six keys emitted and unfed until COFF-12 landed the passthrough — and it is named here so nobody reads the key's existence as evidence it arrives.

**The fix is nameable and is NOT this item's:** carry `dialect` onto the acquire document beside `container_extent` (or on the readings row), which is an `index.mjs` change in another area's path and takes an I1 half of its own. **The one design question inside it is WHICH field carries it** — `container_extent`, which is about extents rather than about how bytes were decoded, or a `reading.dialect` of its own. FW-23 routed this to CONDUCT in its report for placement.
