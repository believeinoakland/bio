- **Interface:** I3 only. No table changes — `proposal_dispositions.definition_version` is REC-184's column and is unmoved (I5 untouched).
- **Design:** `docs/architecture/BIO_Content_Framework_v0_10.md` §8.2, "The declared flow, and its revisions", and BOB #32's ruling of 2026-09-24 ~03:14Z, owed at REC-184's integration and paid here: *"a disposition binds the definition version the member SAW: the act carries definitionVersion; if the definition has moved since, it is refused DEFINITION_MOVED by name, and the member re-reads and acts again. - **Proposer:** the REC-211 worker, 2026-09-24. **Owner:** RECORD. **Resolved by:** CONDUCT (the version bump and the resolution are the integrator's).

### What a caller sees

`op=proposedispose`'s FIRST key shape — `{ key | progressionKey+stageKey }`, the instance-wide disposition of a derived proposal — now takes `definitionVersion`, a positive integer (a numeric string is accepted; a boolean, object or array is not read as a number). Two refusals are added, each minted at one site inside its own DEC-49 region, each with a canned translation:

| code | check | when |
| --- | --- | --- |
| `NO_DEFINITION_VERSION` | C-33.42 | the act names no version the record can read |
| `DEFINITION_MOVED` | C-33.43 | it names one, and it is not the version standing now — in either direction |

Both are asked AFTER `NO_SUCH_PROGRESSION` and `BAD_STAGE`, on D-128's own precedent one op over ("judged after every stage, so a bad stage is still heard first"), and before anything is written: a refusal writes no disposition row and moves no proposal. Both carry `progression_key`, `stage_key`, `definition_version` (what was sent, or null) and `current_definition_version` beside `reason`/`code`/`check`/`translation`/`detail`.

On success every key is unchanged, `definition_version` included: the store still writes its own number, and the act has simply proved first that it is the same number the member read.

**The SECOND key shape is untouched.** A `{ project, finding }` judgment-layer disposition ages a finding in one team's feed; no declared flow governs it, there is no version to name, and neither refusal can be reached from it. Measured: `test/d266scope.test.mjs` is green over calls that name no version.

**The set form carries it.** `definitionVersion` is a SHARED field of an `items` set, spread onto each item by `#perItem` before the item's own fields, so a set over one progression names it once and a set spanning several gives each item its own.

**`op=queue` publishes what the act now needs.** Each dispositionable instance-scoped item's `disposition` block gains `definition_version` (the version the finding was derived against, read off the item the producer already stamped — no second query and no second answer to "which version is current") and `requires: ["definitionVersion"]`. That is additive, and it is what keeps the block's own sentence — that Adopt, Defer and Dismiss are acts a member "can actually complete" — true: DEC-8 lets a surface RENDER a refusal and never compute one, so it must hold every argument.
