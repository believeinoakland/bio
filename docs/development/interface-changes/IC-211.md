### The change, on the wire

- `op=partitionindependence&id=<INQ-…>&partition=<JSON>` — classes `admin`, `member`, `probe`; `mutating: false`; the
  control plane stamps `viewer` exactly as for `op=versionstrength`. `partition` may also arrive as a POST body field.
  - `partition` is a non-empty list of groups over the question's `basis[]` POSITIONS (the `ord` `inquiry_basis` keys on):
    each group either a list of positions (`[[0,1],[2]]`, filed as `part 1`, `part 2`, …) or `{label, legs}` so a caller
    that will write the partition under names reads back the SAME `shared[].a/b`. It must cover every reason exactly once.
  - **Answer:** `{ ok: true, inquiry, partition: [{label, legs, targets}], legs_read, wrote: false, independence }`, where
    `independence` is `Store#independenceOf`'s own shape — `{checked, parts, shared: [{a, b, through}], complete, limit}` —
    the same object `op=versionstrength` publishes. No strength, no grade, no pair.
  - **Refusals, family C-71 `PARTITION_INDEPENDENCE_CHECKS`**, every one `{ok:false, reason, code, check, translation,
    detail, inquiry…}` and read through region `partitionIndependence > is-partition-independence`:
    `PARTITION_INDEPENDENCE_NO_INQUIRY` (C-71.1), `…_NOT_AN_INQUIRY` (C-71.2 — also a question the gate hides, byte-identical
    to one that does not exist), `…_UNREADABLE` (C-71.3), `…_UNKNOWN_LEG` (C-71.4), `…_LEG_TWICE` (C-71.5),
    `…_NOT_TOTAL` (C-71.6, with `unplaced`), `…_TOO_MANY_LEGS` (C-71.7, with `limit: 500` = `BASIS_VERSION_LEGS_MAX`).
