### The act

`POST op=contradictionpropose` with `{ run, proposals: [{ key, a, b, label, reason }], at? }`.

- **Classes:** `admin`, `member`, `probe` (a session), and the `ai` class through `AI_RUN_ACTIONS` — `extractpropose`'s
  cut. It is in `RUN_PRODUCTION_ACTIONS`: the principal is the control plane's stamp. The proposer is stamped
  server-side (`proposedBy`) exactly as `extractpropose`'s; the viewer is stamped and fails closed. Capability:
  `contribute`.
- **Checked, whole batch, before anything is written, in this order:** a proposer stamped (C-93.1); a run in the
  viewer's sight (C-93.2, answering exactly as an absent run), whose principal is the caller (REC-152's
  `AI_RUN_NOT_PRINCIPAL`, relayed), and running (C-93.3); a non-empty batch (C-93.4); every label one of §5's five
  (C-93.5); every reason non-empty (C-93.6); every proposal names a pair the plane ITSELF forms for this viewer now,
  by key and both sides — a claim side must carry the claim text it judged (C-93.7, `cut_keys` naming any key whose
  read was truncated at its bound).
- **Answer:** `{ ok, run, proposed, written, unchanged, candidates[], says }`; each candidate is the row as STORED
  (read back), plus `new`.

### The row (`contradiction_candidates`, I5)

| column | carries |
| --- | --- |
| `candidate` | sha256 of `{v:1, key, sides}` — the key and both sides as `kind|ref@version`, sorted: the idempotency key |
| `key` | K1–K4, from the PLANE's formed pair |
| `a_kind`/`b_kind`, `a_ref`/`b_ref`, `a_version`/`b_version` | a `claim` is `inquiry|version name`, at the sha256 of its claim text; a `leg` or `extent` is its content id (or capture), at its capture sha |
| `a_bundle_id`/`b_bundle_id` | where each side lives, so a purge of either end takes the row (D-113; both purge arms) |
| `run`, `proposed_by` | the run named, and the server-stamped proposer |
| `label`, `reason` | §5's label and its one sentence (≤ 2000 chars) |
| `state` | `proposed`, the only state until PRESENT and RESOLVE are designed |
| `origin` | `machine` — every row is labelled machine work (DEC-24) |
| `at` | when written |

**Append-only, one site:** `Store#appendContradictionCandidate` is the only insert (`INSERT OR IGNORE` on `candidate`);
nothing updates a row; only purge deletes. A re-run over the same two referents at the same versions writes nothing —
whatever its run or label; a changed side is a new row and the old one stays.
