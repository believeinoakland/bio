## IC-269 · I3: an acknowledgement of a case's exclusion statement is matched by the CASE IDENTITY it was recorded at, and never by its statement's bytes (§3 rule 13's narrowing) · PROPOSED 2026-09-24 on I3 87.0.0 — MAJOR, BREAKING

- **Interface:** I3 only. **No table or column changes (I5 untouched)** — `statement_acknowledgements` already
  carried `case_id`, `edition` and `draft_id`; what changes is which of them the reads consult.
- **Design:** `docs/architecture/BIO_Publication_v0_1.md` §3 rule 13 (BOB #32, 2026-09-23): *an acknowledgement
  binds to ONE case identity. It never matches another case whose statement is byte-identical, because reading
  A's statement is not reading B's.* Rule 11's "As built" paragraph and §9's frontier table are updated in the
  same landing.
- **Proposer:** the REC-194 worker, 2026-09-24. **Owner:** RECORD. **CONDUCT takes the version bump and the
  resolution.**
- **Minted** with `node tools/mintid.mjs IC` (a CAS push to `origin/coord`, tip `8a8dfb79`).

### I3 — what a caller sees

- **`op=publish`** (a new case): `completeness.acknowledgements` no longer carries a reading taken through the
  draft the case was prepared from, and `completeness.acknowledged` is `0` where it was the count of those
  readings. **THE KEYS AND TYPES ARE UNCHANGED; the VALUES narrow.** It ADDS
  `completeness.acknowledgements_unbindable_to_this_case` (an integer, present only when non-zero): the readings
  of this exact statement, in this project, at this edition, recorded at NO case identity, which this record
  cannot attribute to this case.
- **The CASE DOCUMENT's prose** gains a paragraph beside the completeness block whenever that count is non-zero,
  stating the readings as UNDETERMINED and counting them, never naming them. **The `/3` FRONTMATTER SHAPE IS
  UNCHANGED** — `completeness.acknowledged` stays an integer ≥ 0 and `completeness_acknowledgements` a list, so
  `C-41.10` (the count agrees with the list) and `C-41.13` (a `/3` carries both) are true as written and neither
  check moves. The flat sentence *Nobody but its author acknowledged it* is now printed only when there is
  nothing unbindable to state; otherwise the document says *Nobody acknowledged it FOR THIS CASE* and the tail
  carries the rest.
- **`op=statementack`**: the act is unchanged and no refusal is added or removed. It ADDS `bound_to_a_case` (a
  boolean) and its `listed` sentence now says which of two things happened. `case_documents` is `[]` for a draft
  that names no case — it was every unsigned edition-1 document of the project carrying the same sentence, each
  re-authored. `case_documents_limit` and `case_documents_truncated` are unchanged in shape.
- **`op=reviewcopy`**: `statement_acknowledgements.acknowledgements` for a draft naming no case lists the
  readings taken through THAT DRAFT, matched on `draft_id`. It listed every reading of the same sentence in the
  project at edition 1 — another draft's included.
- **`op=caseratify` and `op=publishedcase`** are unchanged: they commit and serve whatever the signed bytes say.

### What was wrong, and why it is I3 rather than a defect fix alone

`#statementAcknowledgements` read `(case_id IS ? OR (case_id IS NULL AND edition=1))`. A draft naming no case
records no case identity (a case id is minted only by publication, DEC-12), so the second half of that OR made
every such reading match EVERY edition-1 document of the project carrying the same statement bytes. Two cases of
one project with byte-identical statements therefore listed each other's second readers — **in the SIGNED
completeness block, under the owner's signature.** The draft door had the same shape one altitude down:
`acknowledgeStatement`'s document read was `(case_id=? OR ? IS NULL)`, so acknowledging one draft RE-AUTHORED
every other case's unsigned edition-1 document of the same sentence, putting a name into bytes those owners then
signed. Both reads now name the identity, and the document read names `case_id` AND `edition` — which are
`case_documents`' PRIMARY KEY, so it returns at most one row.

### Classification (the proposer's; CONDUCT decides)

**I3: MAJOR, BREAKING.** No refusal is minted, so IC-25's refusal test is not what makes it breaking: what makes
it breaking is that a caller who received a list of second readers now receives an empty one, and a case document
that NAMED them now does not. A consumer that read `completeness.acknowledgements` as *everyone who read this
sentence* is wrong after this landing in a way no key tells it. Proposed on I3 87.0.0.

### The DESIGN GAP this narrowing makes load-bearing (for BOB, routed by REC-194)

**Nothing binds a draft to the case it produced.** `op=publish` does not name the draft it publishes, and no
other record links them. So a reading given for a NEW case's draft is bound to no case identity and reaches no
case document at all — and a review-copy RECIPIENT, who holds no session, cannot use the case door either, so
their reading of a new case's draft can reach no signed document by any route. Rather than attribute such a
reading to whichever case later carries the sentence (the defect above) or write *nobody* over a record that
holds it, the plane COUNTS it and STATES it as undetermined. **The fix is one act: `op=publish` naming the draft
it publishes**, which would bind the reading at that act and make this entry's `unbindable` count normally zero.
It is Bob's to rule because it changes what a signature covers, and it is a further I3 change.
