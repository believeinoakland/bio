### The change, on the wire

`op=promote`'s action block opened on `normalizeType(meta.object_type) === "action"` — the type the CALLER puts in the
envelope. Nothing downstream of the write reads the envelope for the tier: `Store#projectRow` writes
`action_risk_tier: fm.object_type === "action" ? num(fm.risk_tier) : null` off the promoted BYTES, and `query.mjs` maps the
`risk:` search onto that column. The block's guard now asks BOTH — the envelope's type OR the promoted document's own — and
the change is a **UNION, never a swap**: every promote refused before is refused still.

- **Newly refused** (`{ ok: false, reason: "MACHINE_CANNOT_SET_RISK_TIER", check: "C-32.19", risk_tier, held, detail }`,
  the existing shape, byte-identical to REC-189's): a promote from a MACHINE identity (REC-46's one predicate: no author
  stamp, or a machine one) whose `bundle.md` says `object_type: action` and states a determined tier that differs from the
  version it replaces — or that removes a member's — **while `meta.object_type` names some other type**. Before this change
  such a promote LANDED.
- **Unchanged:** the envelope-says-action shape REC-189 built (refused exactly as before, same reason and detail); a
  machine's unchanged carry-forward; a machine stating no tier where no member has set one; every promote by a signed-in
  member; `pkg.replay` (exempt with the block, see RESIDUE below).
- **Also newly reached, as a consequence and not as a separate act:** the same block's `ACTION_BASIS_REFUSED` and
  `CORRESPONDENCE_REFUSED` shape arms now run on a document whose own bytes say action under a divergent envelope. They are
  the catalogue's own functions over the same document, so what they refuse is what `op=audit` already reports for it; a
  member's conformant action is untouched either way. The battery measures the blast radius: `N/N` green.

**RESIDUE, reported and not fixed here** — `pkg.replay`. A machine credential that puts `replay: true` in the promote body
still lands a stated tier: measured on this tree, and PINNED by arm (ix) of section 7 rather than smoothed, so the day it is
closed the arm goes red and is INVERTED rather than deleted. The exemption is deliberate at the site (a replayed promotion
is the record re-stating its own past, and the record contains actions written before these rules) but it is
**caller-asserted**, which no reasoning at the site addresses — *a provenance hop a caller can hand us is one a caller can
invent* (`CLAUDE.md` §5). The named fix is REC-173's precedent one op over: admit `replay` only where the SERVER can verify
it, or refuse a `replay` asserted by a machine identity outside the admin class. It spans every replay-exempt arm in
`promote`, not this one, so D-505 routes it to BOB (doctrine: may a caller-asserted flag exempt a machine fence?) with a
copy to SCHEDULER, rather than widening this landing.
