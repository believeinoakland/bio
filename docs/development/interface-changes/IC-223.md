## IC-223 · I3 + I5: the group's display name and verified domain — `op=groupnameset`, `op=groupdomainset` (an administrator's session act) and `op=groupidentity` (public read); tables `group_identity_history` and `group_domain_checks` · PROPOSED 2026-09-23 (REC-164; the row left the IC to the integrator, and CONDUCT #18 minted it with `node tools/mintid.mjs IC` at c17-batch7) — the version bump, the classification and the RESOLUTION are CONDUCT's

- **Interfaces:** I3 (the op contracts) and I5 (the store schema).
- **The change.** Three NEW ops. `op=groupnameset` and `op=groupdomainset` reach an administrator's own signed-in session: a bearer is refused by name (C-64.4), `by` is stamped by the server after the caller's parameters are copied, and the store asks the live roster for an active administrator (C-64.5). The display name is one line of at most 120 characters (C-64.6), written into no signed bytes; a domain is a bare host name (C-64.7), recorded with the address the session reached, then checked by fetching `https://<domain>/.well-known/civicos-group.json` through the per-host governor, with a dated verdict `verified` / `absent` / `mismatched` / `undetermined`; the reconciling alarm re-checks the current claim once a day (`group-domain-recheck`). `op=groupidentity` (classes null) answers a stranger the slug, the display name only beside a recorded slug, and a domain only while the latest verdict on the current claim is `verified`; a credentialed reader also gets the claim, its latest verdict and both histories. Two NEW tables, `group_identity_history` and `group_domain_checks`, both purge-exempt as identity on `instance_group`'s reasoning.
