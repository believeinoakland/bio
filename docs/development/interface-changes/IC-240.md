- **Interface:** I3. I5 does not move: no table, column or index is added. One existing WRITE gains a site:
  `promote()` now UPDATEs `bias_adoptions.bundle_sha` (and DEC-54 (d)'s `source_url`, `retrieved`, `source_sha256`,
  copied from the same bytes) for every adoption of a bias set, in the transaction that mints its `adopted` revision.
- **Classification (proposed):** MAJOR, BREAKING BY MEANING. Every key keeps its name and type; what the values
  REFER to changes, which is the breaking kind a key-diff cannot see. CONDUCT resolves the version.
  - `op=biasmanifest` `bundles[].revision`, the case document's `bias_manifest_bundles[].revision`, and
    `op=biasadopt`'s stored pin after promotion: was the sha `op=biasadopt` took (the set standing at `proposed`),
    is now the sha the promotion to `adopted` minted.
  - `statements_sha` (op=biasmanifest, the case document's `bias_manifest`, a run's recorded manifest): was a hash
    over the `bias_statements` PROJECTION, i.e. the HEAD revision's statements; is now over exactly the statements
    in each PINNED revision's bytes. The formula is unchanged; the input set is.
  - `in_force`: was "an adoption row AND the HEAD at `adopted`"; is now "an adoption row whose PINNED revision stands
    at `adopted`, of a set whose head is not `retired`". A later revision merely PROPOSED no longer lifts the lens
    (before, a case published then signed `no manifest was in force`). A pin at `proposed` bytes is not in force —
    the fail-closed half is unchanged.
  - `residue[]` is read from the pinned revision's `## What This Does Not Enforce`, not the head's.
  - NEW, additive: `in_force: null` with `unresolved_pins[]` and a `stated` sentence beginning `undetermined:` when a
    pin names bytes the record cannot produce; the case document carries `in_force: null` and that sentence. Not
    reachable through the ops (promote() snapshots every outgoing revision to `history`).
