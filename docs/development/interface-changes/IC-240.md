### The change, on the wire

- `op=acquire`'s `document.profile.digests`, for a single-part capture whose FORMAT axis reads `odt`/`ods`/`odp` and that was not read as text, is now computed over the CONTAINER by `odfEvidentiaryDigest` (`bio-plane/src/odf.mjs`) through the one gate `substanceDigests` (`bio-plane/src/index.mjs`):
  - **`.ods`, detected with CERTAINTY from the bytes, `content.xml` referencing no package member:** `{ determined: true, rendition: null, evidentiary: <sha256 of content.xml's inflated bytes>, over: "content.xml", container: "ods", boundary_missed: false, basis }`. Recomputable from the artifact with `unzip -p x.ods content.xml | sha256sum`.
  - **`.odt`, `.odp`, or an `.ods` whose `content.xml` references a member (`Pictures/…`, `Object N/`):** `{ determined: false, rendition: null, evidentiary: null, container, basis }`, the basis naming the unmeasured normalisation or the member.
  - **`capture_sha` is unchanged — the envelope's, the trust root.** The container digest is checked against it (the bytes digested must hash to `capture_sha`) exactly as the text arm checks `identity`.
- `op=monitor` asks the same gate of the bytes it fetches (bounded at 8 MiB) and compares evidentiary digests only between equal `over` values; its `compared_basis` names `content.xml` when it compared the container arm.
- The C-18.3 fold (`checkRegisterIntegrity`) is UNCHANGED: it already buckets any `determined: true` string `evidentiary`. It now reaches three exports of one unchanged `.ods`.
