### The change, on the wire

- `op=partitionindependence&id=<INQ-…>&version=<name>` — same classes (`admin`, `member`, `probe`), `mutating: false`, and the
  same control-plane `viewer` stamp and store-side `#bundleGate` on the inquiry as `op=versionstrength`, applied BEFORE any leg
  is read.
  - **Answer:** `{ ok: true, inquiry, version, version_state, legs_read, legs_complete, wrote: false, independence }`, where
    `independence` is `Store#independenceOf`'s own shape and EQUALS `op=versionstrength`'s `independence` for the same version
    (same legs table, order and bound; same `parts` count; the same one call). **No strength key at any depth**: no `pair`, no
    axis, no grade, no `state_set`, `what_if` or `filter`.
  - **NOT state-gated.** `op=versionstrength` refuses a version outside its state set (default `accepted`); this arm answers for
    a version in any state and serves `version_state` as a fact. A state set filters a STRENGTH (§6 rule 6), this answer carries
    none, and the reading a member affirms at the accept ceremony is by construction not yet accepted.
  - **New refusals, family C-71 `PARTITION_INDEPENDENCE_CHECKS`**, region `partitionIndependence > is-partition-independence`:
    `PARTITION_INDEPENDENCE_TWO_SUBJECTS` (C-71.8 — `version` and `partition` both named; neither is silently preferred) and
    `PARTITION_INDEPENDENCE_NO_SUCH_VERSION` (C-71.9 — no reading by that name belongs to the question; carries `version`).
    C-71.8/.9 are numbered on inside the already-minted C-71 family, not a new C.
  - The `…_UNREADABLE` (C-71.3) detail for a request naming neither now also points at `version=<name>`; code, check and
    translation are unchanged.
