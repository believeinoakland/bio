### The change, on the wire

- **I2 — `text()` of the two deck entries gains ONE key, `deckLength: <int | null>`**, the slides the DECK has, never the ones the reader could open:
  - `.pptx` (`pptx.mjs`): the number of `<p:sldId>` SLOTS `ppt/presentation.xml` declares — an unresolvable slot counts, as `deckOf` already numbers it. Emitted on the normal branch AND the over-the-size-bound branch, because `presentation.xml` is structural and read regardless of the text guard. **NULL** when the deck-order declaration cannot be read — never counted off slide PARTS, which is the filename convention the entry refuses everywhere else. Orphan slide parts outside the declaration do not lengthen it.
  - `.odp` (`odf.mjs`): the `<draw:page>` count. Every page lives in the one `content.xml`, so once the body is read the length equals the slide list; **NULL** on the two branches that did not read the body (over the bound; no `<office:presentation>`). The row's phrase *"an honestly NULL length if the format cannot answer"* is exactly those two branches — when the body is read the format CAN answer.
  - No other key, unit or reference moves. `structure()` is unchanged (its `slides:<int>` count is a different, pre-existing figure).
- **I1 — `container_extent`**, when the container itemises slides:
  - `slides[]` is now **as long as the deck**: `max(unit count, highest slide number, deckLength)` — `deckLength` JOINS COFF-12's floor and never replaces it, so a stated length can only lengthen the record. The trailing unreadable slides occupy their own `{ shapes: null }` slots.
  - A new key **`deckLength: <int | null>`** beside the list: present-and-null when the entry answered that it cannot say, ABSENT when no entry ever answered (a capture acquired before this change).
  - **An over-the-size-bound deck now carries a slide list** — `deckLength` slots, every `shapes` NULL — where before it carried `slides: null`. The store names the missing inner half by name (`#containerExtentForCapture`'s `empty_level`, whose wording now includes the over-bound case).

### Behaviour, and the classification question for CONDUCT

- **Admits what it refused:** a citation of an unreadable TRAILING slide (it was refused C-45.1 as past a deck recorded too short). This is the defect being closed.
- **Refuses what it admitted — one case, flagged for the classification:** on an OVER-THE-BOUND deck captured AFTER this change, a citation of a slide PAST the deck is now refused C-45.1 (the record held no slide list for such a deck, so every slide number minted unbounded). No existing check or refusal code changes; C-45.1 is REC-85's rule, now FED on a capture it could not see. CAP-12's feeding of the outer bound was booked MINOR on the same reasoning. Captures acquired before this change are untouched (no backfill; their `container_extent` carries no `deckLength` and the old list).
