## IC-293 · I3 and I5: an ai credential may be MINTED CONFINED to `scratch` — `op=aicredentialmint` takes optional `confinedTo`; `ai_credentials.confined_to`; NAMESPACE_CONFINED (C-78.3) and AI_CONFINEMENT_NOT_SCRATCH (C-29.10) · ACCEPTED 2026-09-24, MINOR — I3 99.2.0, I5 3.13.0 (minted and resolved by CONDUCT #20 at integration on c20-batch27; D-463 — the row assigned the IC to the integrator)
- **Interfaces:** I3 (the op contracts) and I5 (the store schema).
- **Classification:** MINOR, ADDITIVE. `op=aicredentialmint` gains an OPTIONAL `confinedTo` (only `scratch` is accepted; `bio` and any unknown name are refused AI_CONFINEMENT_NOT_SCRATCH, C-29.10); every ai-credential projection and `op=whoami` for a machine caller gain `confinedTo` (a value, never an absent key); a credential minted confined that names a non-scratch `store=` is refused 403 NAMESPACE_CONFINED (C-78.3), and one naming no store is set to `scratch`. I5: `ai_credentials.confined_to`, nullable, never back-filled.
- **Consumer impact (measured by the worker):** no civicos-ui surface reads `confinedTo`; ABSENT is the only silence, so every credential minted before this is unconfined and no existing caller changes behaviour.
