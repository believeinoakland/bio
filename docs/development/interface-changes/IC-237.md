### The change, on the wire

- `op=casedrafts&project=<PROJ-…>[&limit=<n>]` — classes `admin`, `member`, `probe`; `mutating: false`; NEEDS `null` (the
  single read takes no capability); the control plane stamps `viewer` (the fail-closed stamp, beside
  `op=contradictionpairs`).
  - **Answer:** `{ ok: true, kind: "review-drafts", project, drafts: [{ draft_id, case: { case_id, edition, identity },
    created_by, created_at, updated_by, updated_at, read: "op=reviewcopy&draft=<id>" }], count, total, limit, truncated }`
    at 200. `limit` is the caller's clamped to [1, 500] (`REVIEW_LIST_MAX`, the copy's own list ceiling) and PUBLISHED as
    applied; `total` is a `COUNT(*)` over the project's drafts; order is `created_at, draft_id`. `case` is
    `#draftIdentity`'s — the edition read from the published record, as `op=reviewcopy` answers it.
  - **Refusal:** every caller the fence refuses, and every project that does not exist, receives `op=reviewcopy`'s own
    dead answer — `{ ok: false, reason: "NO_REVIEW_COPY", detail }` at 404, byte for byte (no new code). A caller holding
    no credential is refused by the op table before any fence (the op is gated; `reviewcopy` is not, for its recipient
    door, which this list does not have).
  - **Who the fence admits** is exactly the single read's member door, because it is the SAME function: a machine class
    unfiltered; an identified member who is a PARTICIPANT of the project (invited or joined) or an active administrator;
    nobody else. Measured caller by caller in `reviewcopy.test.mjs` block 9: iris (owner), ella (joined), pat (invited, not
    joined), uma (joined, no `contribute`), omar (administrator, no participant) and the machine credential admitted by
    both reads; vic (member, no position) refused by both.

### DESIGN GAP (for BOB, via CONDUCT)

BOB #32's parenthesis reads *"(joined participants)"*, but the single read's fence as REC-126 built it admits every
participant (an INVITED-not-joined member too), an active administrator who is no participant, and a machine class
(measured: `the single read's admission, printed` in block 9). The ruling's operative words are *"fenced exactly like
reading one draft"*, and the row's liar clause forbids a second fence, so the list CALLS the single read's fence and
inherits its admission. If joined-only is what is meant, the fix is ONE edit — narrow `Store#seesProjectDrafts` — and it
moves both reads together, which is itself a change to `op=reviewcopy`'s member door (Membership v2 §7.5 gives an invited
member VIEW rights, and §4 gives administrators sight of every project), so it needs the ruling.
