### The change, on the wire

- **Request:** `POST ?op=acquire` with `render: true` (admin, member, probe; daemon on its existing two arms). `render: false`
  or an absent key is the plain capture, unchanged. Any other value → 400 `RENDER_FLAG_MALFORMED` (C-83.1).
- **Admission, before the shell is fetched** (one governed span, `fetch > is-render-admit`): `render` with `via:
  "archive.org"`, a Google Drive export or `continue` → 400 `RENDER_ARM_CONFLICT` (C-83.2); no renderer → 501
  `RENDER_NO_RENDERER` (C-83.3) with `renderer: "none" | "browser-binding-without-driver"`; the host cooling off → 429
  `RENDER_HOST_COOLING_OFF` (C-83.5); today's allowance spent → 429 `RENDER_DEFERRED` (C-83.4) with
  `render: { state: "deferred", content: "undetermined", allowance: {day, spent_ms, allowance_ms, renders, deferred} }`.
  Nothing is fetched on any of these.
- **After the shell is fetched** (`fetch > is-render-result`): a shell that is not a single-part HTML page → 422
  `RENDER_NOT_A_PAGE` (C-83.6); a renderer that produced no document → 502 `RENDER_FAILED` (C-83.7) with `shell_sha256`,
  `filed: false`. The shell's bytes are then held content-addressed and UNREGISTERED (as `TOO_LARGE`'s parts are); nothing is
  filed as a document.
- **Success — the document (I1):** `file` = `snapshots/<name>` and `capture.sha256` name the RENDERED document;
  `capture.method: "rendered"`; `capture.grade` is the ordinary direct-capture grade (Bob's grade ruling); `capture.transport`
  is ABSENT on a rendered capture (the HTTP exchange belongs to the shell). New keys:
  - `pair: { primary: "rendered", rendered: {file, sha256}, shell: {file, sha256} }`
  - `shell: { file: "snapshots/<name>.shell.html", sha256, bytes, method, content_type, transport }`
  - `render: { of, engine, engine_version, viewport, dpr, locale, timezone, wait: {asked, fired}, elapsed_ms, navigated_to,
    status, requests: {made, completed, failed, blocked, blocked_by, outcome_unstated} | null, data: [{address, type, origin,
    host, sha256|null, reported_by: "renderer"}] | null, scripts_executed: [origin] | "undetermined",
    third_party_executed: [origin] | "undetermined", asked, at, undetermined: [string] }`
  - authority by CLIENT-RENDERED.md item 3: `determined` (as the shell's asserted authority) ONLY when the shell was asserted,
    every `render.data` entry is `same_host` and `third_party_executed` is `[]`; otherwise `undetermined` with a dated
    `authority_basis` naming each other origin and its axis ("supplied data" / "ran code"), and `authority_other_origins`.
  - The answer's top-level `files` names the shell file beside the primary.
  - The address filed in `captured_locators`, the D-98 task, subresource capture, the profile and the reading all run over the
    RENDERED document. The D-98 task is now raised whenever the RENDERED capture is undetermined, including when the shell's
    authority was asserted.
- **I5:** `render_allowance (day PK, spent_ms, renders, deferred, last_at)`, exempt from `purge` as an operational budget
  (hygiene's list, beside `runtime_observations`). DO routes `renderadmit`, `renderspend` (internal).
- **Config: UNCHANGED, and that is a finding.** D-64 added `"browser": { "binding": "BROWSER" }` to `bio-plane/wrangler.jsonc`
  and took it back out in the same landing: DIST's deploy derivation refuses the `browser` binding class by name
  (`deploybindings.test.mjs`: `REFUSED [UNKNOWN_BINDING_CLASS]: wrangler.jsonc declares browser`), so the line would have
  refused EVERY plane deploy for a binding nothing can drive yet. The render arm is served by a `RENDERER` service binding
  speaking the answer shape documented in `src/render.mjs`; an instance that binds `BROWSER` by hand is answered
  `renderer: "browser-binding-without-driver"`. No deployed instance has a renderer, so every live `render: true` answers
  501 `RENDER_NO_RENDERER`.

### Consumer impact, measured

- `civicos-ui`: its one acquire call (`app.html`, `recPostR("acquire", { locator, authority, subresources: true, … })`) sends
  no `render`. No surface moves. A surface for the rendered pair is not built.
- `agent-worker`, `pdf-worker`, `ocr-worker`, `tools/`, `newgroup/`: `grep` for `render: true` / `"render"` in a request body
  finds none. The capture-request drain (`Store#captureRequestDrain`) sends none.
- `newgroup/` (DIST's): the installer does not declare a browser binding. An instance it installs has no `BROWSER`, which the
  plane answers as `renderer: "none"`. Teaching it the binding is DIST's (owed act, below).
- `check-refusal-codes.mjs --strict`: the floors this item moved are listed in its commit, each from the guard's own print.
