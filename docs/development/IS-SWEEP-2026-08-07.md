## 1 · CORRECTIONS — the design said something the record contradicts

### 1.1 A CLAIM is not an object, and IS-1's subject was misnamed

`OBJECT_TYPES` (`bio-checks.mjs:26`) is `{information, inquiry, project, action}` — there is
no claim type, no claims table, no claim op. **Case Making ruled it** (2026-08-01): a claim
is a **FIELD of an inquiry**; concluding is the inquiry ADOPTING a claim, carrying the basis
and the falsifier; `focus`/`finding`/`case` are phase names on the one recursive type
`inquiry`.

**So IS-1 versions the BASIS OF AN INQUIRY, not the legs of a free-standing claim object.**
The design's intent survives intact — a version is a complete alternative composition of
`basis[]` with its description — but the build target is the existing inquiry construct:
`bundle.md`'s `basis[]` as the authority, `inquiry_basis` as its projection (one write site,
inside `promote`'s transaction, `store.mjs:7288`; a directly-written version table would be
the second-place-to-state-a-fact D-21 forbids).

**A version must also carry the GROUND partition, not only the legs.** `inquiry_basis`
already has `ground` and `role` columns; DEC-32 (grounds, OR-max) is still open with the
columns already real. A version that is a flat leg set cannot express plurality — the
version IS the composition, and the ground partition is part of the composition.

### 1.2 The bias read: half ruled, half forbidden — and D-215 closes

- **RULED, and this session missed it when raising D-215:** *"An assistant-surfaced focus
  must carry the bias manifest in force when it was surfaced… unlike a member it will not
  remember. Without the manifest… bias debt cannot be computed against it"*
  (`Content_Framework:1129-1141`). The run-carries-its-bias-context question was answered
  before it was asked. **D-215(2) is therefore RULED YES for the bias component.**
- **FORBIDDEN, and the design drifted toward it:** *"bias never shapes what is captured or
  monitored, only how conclusions are weighed"* (`Content_Framework:1283`) — the coupling is
  *forbidden rather than documented*. §3's "net bias" read is legitimate only as the thing
  the run CARRIES and the weighing it discloses — never as an input to what the session
  searches for. This sharpens Bob's own §11 ruling (minimise bias effects in the skill) into
  a structural rule: **the search half of the run must not receive the bias at all.**
- **AND THE OBJECT TO READ DOES NOT EXIST:** `object_type: bias` is absent from the check
  catalogue (D-84); `Declared_Bias_v0_1` is a DRAFT — *"no check exists, no code implements
  it."* The net bias is the design's **second unbuildable read**, beside D-222's meaning
  layer. Until D-84 lands, the run's manifest-carrying obligation is dischargeable only as
  "no manifest was in force," stated.

### 1.3 An AI-suggested leg's grade is EARNED or ABSENT — never assigned

The apparent tension between Bob's §5 ("the AI… assigns strength values that when calculated
are supported by the evidence") and §8.1 (grade states HOW the connection was established,
and nothing else; the ASSISTANT construct forbids *"a grade asserted rather than earned"*)
**dissolves under three standing rulings, and no new ruling is needed:**

- §8.1: a leg's grade is a fact about METHOD — the source's own identifier (A), an identifier
  matched in content (B), correspondence (C), testimony (D).
- DEC-18: an ungraded leg is INERT, contributes nothing, **and every ungraded leg is
  NAMED** — inert must never mean invisible.
- DEC-15: a HUNCH is a member act. The AI may not propose one.

**Therefore: the session COMPOSES legs and the grades arrive from the record** — from the
resolutions the legs rest on (`earnedBasisRegistry`, `store.mjs:8808`), exactly as `op=cite`
already fills them. Where the record has earned nothing, the leg is ungraded, inert, and
named as such in the version's description. "Assign strength values" means composing legs
whose earned grades produce a supported calculation — not minting numbers. This also gives
§10's safe-to-be-wrong property (which recogniser, which version, what confidence, what
signals) a path to every machine-suggested leg.

### 1.4 The state set exists nowhere, and the proposal rules the design rebuilt are already written

`suggested/considering/accepted/rejected` has no analogue anywhere in the plane — not in
`STATES` (five machines, `bio-checks.mjs:127`), not in task states (`open/forwarded/
resolved`), not in proposal dispositions (`deferred/dismissed`, with adoption explicitly "an
authored act, not a disposition," `store.mjs:10730`). IS-2 builds the sixth machine. Three
consequences the design missed:

- **The interaction-construct PROPOSAL rules apply and answer D-217(a) better than dedup
  did:** a machine proposal is **adopted / deferred WITH a recorded reason / dismissed WITH a
  recorded reason**; proposals **AGGREGATE, never multiply**; they **AGE rather than
  vanish**; and they must visibly **LOOK derived** (D-82 — and D-78 records that both
  existing writers hardcode `surfaced_by: human`, so the field the design relies on is
  broken today; Step 8b, which fixes it, is UNSCHEDULED).
- **The member-side transitions are ACTS and owe the four beats** (choose · see what will be
  refused BEFORE it runs · author the reason · receipt). The design treats accept/reject/
  make-current as bare state flips. Rejection at minimum carries a reason (the rejection
  record is the anti-omission instrument — it is worthless without one).
- **The new machine must publish itself through `op=affordances`** (a NEEDS/NON_ACTS row) or
  every surface showing version states holds a second copy of the rule — the drift class
  DEC-8 closed.

### 1.5 The capture-request door does not exist, and opening it crosses two recorded decisions

§4's fence — "the AI requests; the daemon captures" — has **no mechanism on the request
side.** Verified: `taskenqueue` is absent from the OPS table *deliberately, with the
reasoning written into the table itself* (`index.mjs:295-299`: no control-plane route may put
an event in the queue on its own account); `taskEnqueue` refuses any kind outside
`TASK_KINDS = ["authority-undetermined"]`; and the daemon class holds exactly TWO verbs
(`acquire` — archive arm only, direct refused by name at `index.mjs:2687` — and `monitor`),
per DEC-37's own words: *"scope it to exactly the two verbs it needs today and widen by
decision, not by drift."* **→ DECISION ITEM for Bob (§4 below).**

### 1.6 Published case vs pruned versions — R4's disclosure rule reaches here

R4 (division): *a published child names its parent and its siblings*, because division
without disclosure is *"a laundering path with a tidy name."* The versions design lets a
member prune rejected ancestor versions (D-217a) and publishes ONLY the current version
(§13). Structurally identical hazard: **a published case that discloses nothing about
alternative accounts considered and pruned.** The exclusion-statement machinery
(`inquiry_exclusions`, completeness statements scoped to an edition) is the existing idiom.
**→ DECISION ITEM for Bob (§4).**

## 3 · WHAT THE EVIDENCE-GATHERING HALF INHERITS (from the design-docs sweep, recorded here so it reaches the builder)

- **The UA string is measured, not stylistic** (`SOURCE-ACCESS.md:133-169`): removing the
  contact URL flips admission 200→403 uniformly; `purpose` distinguishes capture from
  monitoring — an investigation fetch introduces or reuses a purpose token deliberately.
- **An observation log that says "source unreachable" when the truth is "our governor held
  us" manufactures a false absence** (D-104; `source-unreachable-governed` exists in the
  vocabulary to keep these apart). The log must make the same distinction.
- **Client-rendered portals produce evidentially empty captures with no signal** —
  `client-rendered-shell` is catalogued with NO producer; `CLIENT-RENDERED.md` is a draft
  whose open question 4 is precisely whether an unattended sweep may capture such a source.
  The run must treat a shell capture as `LOOKED_INDETERMINATE`, not `PRESENT`.
- **Archives are a BACKUP source only** (three consecutive failures or fourteen days), the
  fallback is built and idle, and CDX has three measured traps (compressed-size `length`,
  the empty-body digest, non-200 rows).
- **TREC 2011 measured searchers estimating their own recall and it failed badly** (+95/−87
  points, premature termination from false belief of high recall) — the direct evidential
  case for §14b.4's rule that THE MODEL NEVER DECIDES WHEN THE LOOP STOPS.
- **The two 2026 AI-review cases** (Schulte; James v. Cerebras) — where law imposes nothing,
  parties who care negotiate **prompt-level disclosure with change tracking**. The skill
  version the run records (§14a) is a requirement, not an analogy.
- **The placeholder defect is the machine-speed overclaim**: the UI satisfies a non-empty
  check with the literal `counterparty: to be named` (`PROCESS-INVENTORY`). An AI filling
  required fields to clear a gate is the same defect at scale — a skill-layer prohibition
  and a §14b.5 check (a version whose description or reason field is boilerplate is not
  proposed).
- **The PRACTICE-SURVEY "deliberately violate" list is the skill's prohibition set** — no
  generated justification anywhere (a generated one is a fabricated attribution); the one
  permitted auto-composition is assembling the member's OWN prior words (Zotero's line); no
  single confidence score; no connection-density ranking; machine-proposed connections never
  presented as connections.

**(4) DEC-52's remaining yes/no** — unchanged from before the sweep, sharpened by 1.3: the
