### A surprising green found while arming, and what it changed

An earlier arm on the civicos-ui suite made `signerAdd`'s BAD_KEY site a bare `{ ok:false, reason:"BAD_KEY" }`, and
the suite stayed green. A direct probe showed why: the answer still carried `code`, `check` and `translation`,
because the control plane's `dec49Decorate` (index.mjs) attaches a family row to EVERY refusal carrying that code, at
ANY site. That broke this item's first design, which assumed only the sites I governed would carry the sentences.
Without the change below, a member would have been told something false at three other sites:

- `promote`'s EXISTS would have read "Someone is already on this group's roster under that member id".
- `projectOwnerAdd`'s CONSENSUS_REQUIRED would have spoken of administrators.
- `adminRemove`'s *target* NOT_AN_ADMIN would have told the caller they are not an administrator.

The fix: EXISTS and CONSENSUS_REQUIRED are now worded to be true at every site that mints them, and `adminRemove`'s
target case has its own code (C-96.9).
