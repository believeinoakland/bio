Node says ~12× the body in heap, which against Cloudflare's documented 128 MiB isolate limit — **their
claim, not our measurement** — makes the bound too HIGH. Local workerd read the whole 73 MB body
without dying, which makes it too LOW; but **local workerd does not apply the production memory cap**,
so that instrument cannot see the limit it would need to see, and a run that does not die is not a run
that fits.

plane reading a > 20 MiB CSV in its own scratch namespace under production limits; deploying is DIST's
(CLAUDE.md §4) and was not this item's to do. Until it is taken the bound stays at the one figure the
plane already enforces for text a reader must hold, because a second, differently-derived bound for the
same resource is how two answers to one question learn to disagree.
