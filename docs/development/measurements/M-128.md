## M-128 · 2026-09-24 · D-487 — THE DOORBELL SUITE'S WALL-CLOCK EXPOSURE, AND WHAT A PINNED `Date.now` IN THE ISOLATE DOES AND DOES NOT MOVE

D-487 (`QUEUE.md`), design `docs/development/VERIFICATION.md` — *a suite's verdict must not depend on the
wall clock*. Measured on `land/worker/D-487`, base `origin/main` 548eb2c5, in this worker's own clone.
**This entry sets no cap and raises no floor. It measures three things the fix rests on.**

**Headline.** The suite as it stood at 548eb2c5 carried a losing interval of **87–148 ms per run against a
600,000 ms bucket — worst case 1 run in 4,054**. That is the whole of the flake: real, bounded, and far
rarer than "flaky" suggests. **No instance of it actually firing was found in the record** (`RATE_IP`
appears nowhere in `docs/` but an archived research note), so the row rests on the shape, not on a
sighting — which is the honest statement of it.

### 1. The losing interval

`src/index.mjs` bins a knock by `win = Math.floor(Date.now() / KNOCK.windowMs)`, `windowMs = 600,000`, and
the per-source count is a SQLite row named for that bucket. A bucket edge landing anywhere between the
flood's first knock and the last arm that reads that bucket splits the count in two, every knock is
accepted, and three arms go red while the limiter is behaving exactly as designed.

Instrument: the span from the first flood knock to the last rate arm, unpinned clock, warm isolate,
three repetitions, sequential `dispatchFetch` — the old suite's shape exactly.

| rep | span |
| --- | --- |
| 1 | 148 ms |
| 2 | 94 ms |
| 3 | 87 ms |

**148 / 600,000 → 1 run in 4,054 at the worst rep; 1 in 6,900 at the best.** The figure is a span, not a
rate: it says how wide the losing start window is, and the run-in-N reading assumes a gate starts at a
uniformly random instant, which is the assumption a cron-less, human-started gate best fits.

The instrument is reproduced here rather than committed, because the shape it measures is no longer in
the tree — after D-487 the flood runs on a pinned clock and this span cannot lose:

```js
const t0 = Date.now();
for (let i = 0; i < 14; i++) await (await P({ contentText: "flood " + i }, "198.51.100.7")).json();
await (await P({ contentText: "unrelated" }, "198.51.100.8")).json();
await P({ contentText: "one more" }, "198.51.100.7");
spans.push(Date.now() - t0);
```

### 2. What a prepended `Date.now = () => <k>` moves in a workerd isolate — and what it does not

The fix pins the clock by prepending one line to the script the suite already hands Miniflare, so nothing
under `src/` changes. **What that reaches was measured, not assumed:**

- **It moves `Date.now()`.** Driven: with the pin stepped one bucket on, a source refused `RATE_IP` a
  moment earlier is served. That is the arm *a new window starts a new count for the same source*, and it
  is in the suite precisely so a pin that silently stopped arming cannot pass as an ordinary green.
- **It does NOT move `new Date()`.** Measured: with the clock pinned to an epoch months away, the knock id
  still came back `KNOCK-2026-09-24-…` — V8 takes the host clock for the `Date` constructor and only the
  `Date.now` property was replaced. So knock ids, `received` stamps and anything parsing them stay real.
  **This is the reason the pin is placed in the middle of the CURRENT real window rather than at a fixed
  epoch**: pinned and real readings coexist in one isolate, and holding them within five minutes of each
  other keeps every elapsed-time comparison sane. A fixed epoch would have been more deterministic and
  less honest.

### 3. `setOptions` reloads the worker and KEEPS the Durable Object's state

The straddle control and the new-window arm both need the clock to move mid-run against the SAME store.
Measured: after `await mf.setOptions(<same options, new pin>)`, `op=inbox` still returned **all 14 rows**
written before the reload. That is what lets the control drive a bucket rollover deterministically instead
of sleeping for one.

### What this does not say

It does not say the fixed-window limiter is right. A source that times its burst across an edge gets
**24 knocks in a moment** rather than 12, which is a property of the limiter and not of the suite; D-487's
scope excludes it and it is reported to SCHEDULER as its own finding. It does not measure any other suite:
the class sweep for wall-clock-dependent verdicts is in D-487's report.
