### What disagreed with the design's I2 shape, and the fix for each

1. **`text.pages[].tier` is emitted and is not in I2.** On the three documents merged page by page (73545, 73550,
   d4b345d7), every page entry is `{page, text, undetermined, tier}`. I2's text extension defines
   `{page, text, undetermined}`. The field comes from `mergeTier2Text` (`textchain.mjs`, CPDF-20, `1240af81`,
   2026-09-14). No IC in `INTERFACE-CHANGES.md` names it. It is ADDITIVE, and a reader that ignores it loses nothing,
   but it is an as-built shape with no contract. **FIX:** file the IC recording `text.pages[].tier ∈ {1,2}`, present
   only when a tier-2 merge ran page by page (I2 MINOR). CONTENT-PDF owns the producer and CONDUCT resolves it.
2. **§16's closing table says the per-page tier-2 rule is ABSENT, and it is BUILT and serving.**
   `BIO_Content_Framework_v0_10.md` §16, "What is specified, delegated, and absent", and its front matter's
   incomplete-sections line list *"a per-page rule for tier-2 replacement"* as ABSENT. D-283 is closed, CPDF-20 is done,
   and this measurement watched the rule decide pages live. `node tools/status.mjs` finds no claim for it. **FIX:**
   correct the §16 row and the front matter to BUILT, citing CPDF-20. Add a `construct-status.json` claim under
   construct 5 probing `/export function mergeTier2Text\(/` in `bio-plane/src/textchain.mjs`.
3. **After a WHOLESALE tier-2 read, the document-level `encrypted` marker leaves `text.undetermined`** (978ac0c8:
   tier 1 had `[{page:null, reason:"encrypted"}]`, live has `[]`). Encryption is still stated in `notes: ["encrypted"]`,
   `text.producer.why` and `imagesWhy`, and `tier: 2` says the member read it. This is by construction:
   `mergeTier2Text`'s wholesale branch returns the member's own text, and `tier2Note` returns null for it. **Not a
   defect**: the record claims nothing more. It is recorded because I2's marker prose reads as if the marker persisted.
4. **The row's namespace.** Named in the second paragraph above: `biosmoke-pdf` is an instance `PARALLELISM.md`

   Also correct `CONTENT-PDF.md` step (5) and `PARALLELISM.md` "one instance per area" to say `store=scratch` on
