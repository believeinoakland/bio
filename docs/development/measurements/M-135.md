### Stated plainly: what this instrument can and cannot see

- The ENCRYPTED branch keys on the extractor's OWN `undetermined[].reason === "encrypted"` marker, read off the
  trailer's `/Encrypt` without decrypting anything. **It never infers encryption from the zero.** A document whose
  bytes are encrypted in a way CPDF-4 does not name would still read `NO-TEXT-LAYER`, and this probe would not know.
- `encrypted` occurs in **exactly 2 of the 14 documents**, both of which read NO-TEXT-LAYER before the change, so on
  this corpus the branch reclassifies nothing that decodes. **On a corpus where a document is both encrypted AND
  partially decodable, this branch would call it ENCRYPTED and hide a real coverage figure** — it sits before the
  coverage arms deliberately (D-493's scope), and that is the cost. No such document exists in this sample.
- `FAILED` still merges two different things: a fetch that never happened and a document Tier 1 read to ~nil. The
  `--urls` preflight (D-166) is what separates them, and it is a separate run.
- 14 documents is CPDF-5's PURPOSIVE sample across classes, not a random draw. This entry re-states buckets; it does
  not widen the sample.
