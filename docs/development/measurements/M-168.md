### 2. What this establishes

- **NO MEMORY WALL anywhere on the walk.** `memoryUsageBytesP99` reads 120.9 → 107.8 → 122.7 → 94.7 MB while the
  transcript grows 0.68 → 2.34 MB. Zero `exceededMemory`. The figure does not track the workload, which is D-312's
  point: FL-1's "120.4 MB at 200 turns" was this same plateau, not a wall ~200 turns away.
- **CPU TRACKS THE CUMULATIVE BYTES RE-SERIALISED**: 7.7 · 7.1 · 10.4 · 9.6 ms per MB at the four fully observed
  points (slightly super-linear, GC). FL-1's own points fall on the same line: 144.1 MB → 757.65 ms (5.3 ms/MB) and
  568.8 MB → 4,488.9 ms (7.9 ms/MB). So the 30 s default fits roughly **3–4 GB re-serialised**. This is an
  EXTRAPOLATION beyond 1.65 GB / 15.7 s, labelled as one.
- **In turns, that ceiling depends on bytes per turn**, as cumulative ≈ turns² × bytes-per-turn ÷ 2. At this corpus's
  1.69 KB it is ~1,900–2,150 turns. **At FL-1's 7.2 KB it is ~900–1,050 turns**, and that agrees with FL-1's own
  ~1,100 extrapolation.

### 3. The bound, re-checked

`DEFAULT_MAX_TURNS_PER_SEGMENT = 120` is **SAFE**. At FL-1's payload size, 120 turns re-serialise ≈ 52 MB, which is
~0.3 s of CPU (FL-1's 100-turn point billed 189 ms): **~1/8 of the turns the ceiling fits**. The margin is not the
~1.7× that the "of 128 MB" reading implied. **Its stated basis was false**: it named a memory wall that does not
exist. The corrected basis is in the code (`BOUND_SOURCE`), in INTERFACES.md §"The segment bound", and in the
suite's assertions.

**The value is KEPT, not raised**, for three reasons:
- The payload size of a REAL run (model output plus tool results) is **UNMEASURED**, and a larger one lowers the
  ceiling as its square root. At ~30 KB per turn it is ~450–500 turns.
- The two-fold client cut above means no point past 1,400 turns was observed complete.
- Raising a shipped bound is FLEET's call.

**The right unit is BYTES, not turns.** A turn count is right for exactly one payload size. **D-611** names the fix:
bound a segment on its cumulative bytes re-serialised, with a margin under the ~3 GB this entry locates. It is
sent to SCHEDULER for FLEET.
