## M-115 · 2026-09-23 · REC-175's digest census — rows whose stored sha256 disagrees with their own stored bytes

Instrument: `op=digestcensus` (REC-175; `Store#digestCensus`, read-only, admin and probe), driven through the control
plane in miniflare by `bio-plane/test/rec175-digest.test.mjs` section 6, `node` 26 in the cloud container, worktree
`agent-a6f377d2e96aa24af` on `origin/main` @ `14faa089` plus the REC-175 change. Every figure below was PRINTED by a run.

**What it counts.** Over `files` (the live image) and `history` (the append-only snapshots): an INLINE row is recomputed
over the UTF-8 bytes of its stored `content` by the same `#fileDigestOf` that `op=promote` now judges with; a BLOB row
compares its `sha256` with its `blob_sha`. `bytes_disagree` (UTF-8 length against the stored `bytes`) is counted beside it
for `files` only — `history` has no `bytes` column. It lists up to `limit` (default 50) rows per table and REWRITES NONE.

**THE DEPLOYED FIGURE IS UNDETERMINED.** No instance serves `op=digestcensus` until DIST deploys a build carrying it. The
method: `GET /api/?op=digestcensus&store=bio&token=<ADMIN>` (probe is confined to `scratch` by `scopeFor`, so only the admin
class reads the real record), optionally `&limit=500`. It is a whole-table scan of `files` and `history`, so on a large
record it is one long read. Before this landing EVERY `files.sha256` was the caller's figure unchecked, so the deployed count
is a real unknown, not a formality.

**The CALLER census, measured the same day (the class sweep).** Of the plane's own writers (`setup.mjs`, `civicos-ui/app.html`,
`livefire.mjs`, `migrate.mjs`, `tools/fw21-onpoint-probe.mjs`, every `store.mjs`/`index.mjs` internal re-promote), every
one computes the digest over the bytes it sends (UTF-8 of the text; `migrate.mjs` over the raw buffer it decodes as text
only when `isUtf8`), so no deployed writer is expected to have stored a false one. **Test fixtures did:** 15 sites in 10
battery files sent a digest that is not the SHA-256 of their text — 14 sending `"a"`×64 or a register capture's sha
reused (`airun`, `inbox` ×2, `observation-log` ×4, `skilldoctrine`, `skillpack`, `task-drain-alarm` ×2, `task-fence`,
`task-machine`, `agent-worker/test/harness`), and `readingname`'s one site sending `sha("x")`/`sha("y")` — computed, but over OTHER strings, which a
regex sweep for literals could not see and the battery did. Three probes outside the battery carried the same shape
(`rec113-identity.mjs`, `rec93-fold-digest.mjs`, `rec93-migrate-probe.mjs`). All corrected to send no digest.

**A separate finding, counted and not refused: `bytes`.** `setup.mjs` (L896, L1105, L1129), `civicos-ui/app.html`
(L3273, L3276), `livefire.mjs` (L57, L92), `index.mjs`'s monitor tick (the `bytes: text.length` beside `textSha`) and `tools/fw21-onpoint-probe.mjs` (L58–59, L93) send `bytes: text.length` — UTF-16
code units, not UTF-8 bytes — and `op=promote` stores it as given, so any non-ASCII inline file on a deployed record
carries a false `bytes`. `OVERSIZE_INLINE` likewise judges `f.text.length` against a 1 MiB byte limit.
