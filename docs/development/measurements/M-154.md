## M-154 · 2026-09-25 · D-531 — BLANK CONTENT UNITS: EMITTED AND INDEXED BEFORE, NEITHER AFTER; ONE REAL PAGE IN THE CORPUS

**Headline.** Both content-unit emission sites judged "this unit has text" by `u.text.length`, so a unit of
pure whitespace was emitted at acquire (`index.mjs`, the `arm` helper) and written to `capture_text` at
promote (`store.mjs`, `#writeCaptureText`'s ordering filter). Both now read `glyphCount(u.text) > 0` (D-514's
counter). **The worst BEFORE figure is the claim, not the count:** a capture whose every unit was whitespace
read `indexed_full` over 3 indexed units; AFTER it reads `indexed_none` over 0. Over the seven committed real
Oakland PDFs, **1 of 51 tier-1 pages** is whitespace-only (`legistar-73550` p1, 39 characters, 0 glyphs,
M-140's own witness), so a fleetless instance's PDF units fall **48 → 47**. **Retrieval figures do not move**:
a whitespace-only row contributes ZERO tokens to the product's FTS5 index, so no query ever matched one. What
the defect moved was the unit count and what the content axis SAID about the capture.

### Retrieval

7 whitespace-only rows in an FTS5 table built on the product's own arguments contribute **0 distinct
tokens** (`fts5vocab`, `row`). No `MATCH` can return such a row, so passage retrieval's hit sets are the same

content-axis `indexed` state and its sentence (`N unit(s) indexed`).

### What this measurement can and cannot see

**CAN:** both emission sites through the ops a caller reaches (`op=acquire`, `op=promote`), and every page of
the seven committed real PDFs at tier 1.

**CANNOT.** (1) **Which units the WIRE hands `arm` for a real PDF on an instance WITH the fleet**: there the
page-wise merge (D-514) gives `legistar-73550` p1 tier 2's or tier 3's text, so the 48 → 47 figure is the
FLEETLESS (tier-1-only) case, which is every sovereign instance until the fleet is deployed to it. (2) **The
live record.** No op reads `capture_text` rows by content, so how many whitespace-only units the project's
own instance holds TODAY is UNDETERMINED; this change stops new ones, and a re-promote of a capture replaces
its units (`#writeCaptureText` deletes first), but nothing sweeps the units already written. (3) Office
containers in the wild: the repository commits no real DOCX/PPTX/ODF, so the office arm is driven by a
synthetic fixture only.
